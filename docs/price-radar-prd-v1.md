# FunBox 菜价雷达 产品设计方案 V1

> 版本：V1 完整版
> 日期：2026-08-04
> 状态：待评审
> 定位：查真实菜价，不猜价。以官方公开批发/零售价格为基准，叠加附近用户上传的凭证报价与合作商户正式开放数据；异议、讨论、凭证核验与后台审校一期一次性交付。
> 数据原则：所有展示价格必须来自真实数据源；任何数据源不可用时显示错误、重试或 stale 标记，绝不回退到 mock 或演示数据。

## 1. 背景与问题

用户想知道“生菜现在多少钱”时，常见的做法是打开买菜 App、看新闻、问邻居，结果往往不一致：

| 现状 | 问题 |
| --- | --- |
| 买菜 App 只显示自己平台的价 | 覆盖不全，看不到附近菜市场 |
| 新闻只有“菜价上涨”这种结论 | 没有具体品种、市场、日期和单位 |
| 问家人朋友 | 只有口头印象，没有凭证，无法验证 |
| 搜索批发价格 | 普通人分不清批发价、零售价、元/公斤与元/斤 |
| 看到低价/高价截图 | 不知道图片真假、何时购买、哪家店，无法反驳 |

FunBox 已经有一批行情与生活工具，缺一个“把菜价讲清楚”的入口。菜价雷达要解决的不是“多一个价格网页”，而是让每一条价格都有来源、有单位、有日期、有位置，并且允许用户用真实凭证参与修正。

## 2. 对原始想法的补充

原始想法是：输入“生菜”，查询附近商场或菜市的生菜价格；其他用户发表意见或反驳查询结果；用户上传发票/小票证明价格不一致。

在此基础上补充十点：

1. 三层真实价格模型，不把所有价格混为一谈：官方批发参考、官方零售监测/合作商户价、用户凭证报价。每一层独立展示、独立标注，禁止把用户报价伪装成官方价。
2. “附近”只展示真实可达的位置数据。官方批发市场按市场所在地归类；用户报价必须有商户名、购买日期和凭证；合作商户价必须来自正式授权接口。没有数据时展示真实空态，不生成附近门店。
3. 不抓取未授权商户数据。买菜 App、商超小程序的页面价格如果没有官方开放接口或授权，不属于可展示范围；宁可空，不可假。
4. 商品名称做标准字典。生菜、叶用莴苣、圆生菜等别名归一到一个品种，字典来自官方品种表与运营维护的别名映射，不编造新品种。
5. 单位与口径全程保留。批发价默认元/公斤，零售监测默认元/500克，用户凭证按原单位填写；所有换算都保留原值和换算口径，不在前端静默改单位。
6. 凭证不是装饰，而是状态机。用户上传后先进入“待核验”，后台人工核验后变为“已核验”或“已驳回”；待核验内容默认不进入“已确认价”统计。
7. 异议是独立对象，不是普通评论。用户可以对某条价格提交“价格不符、单位不对、品种不对、凭证与商户不符”等异议，可附图片；后台处理后保留原记录和决议，形成可追溯的修正链。
8. 讨论与异议分离。讨论区用于补充购买经验、质量描述等；异议必须走结构化表单，不能靠一句评论把价格“反驳掉”。
9. 隐私与内容治理前置。上传、评论、异议都要求登录；凭证图片默认公开展示、可切换为仅核验可见；支持举报、删除、限流与黑名单。
10. 一期全量交付，不设分期。查价、官方基准、附近报价、凭证、异议、讨论、数据来源页、后台核验、异常兜底全部在一个版本内完成。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户输入菜名后，1 秒内看到官方批发参考与附近真实报价情况；没有用户报价时不显示任何编造门店。
2. 每条价格都能追溯：来源类型、来源机构、更新/购买日期、单位、位置、状态。
3. 用户可以用真实凭证报价格、提异议、参与讨论，形成“官方数据 + 用户证词”的双层可信结构。
4. 后台完成凭证核验与异议处置，未核验内容绝不标记为已确认。
5. 一期一次交付，不把核心能力拆成多期上线。

### 3.2 设计原则

- 真实优先：官方数据、合作商户数据、用户凭证分别打标，缺数据时显示空态。
- 可追溯：每条价格都显示来源、时间与单位，点击进入数据来源页。
- 可反驳：任何价格都可以被结构化异议，异议必须能附凭证，不能被普通评论淹没。
- 状态透明：用户报价分为待核验、已核验、已驳回、已下线，所有状态在界面上可见。
- 风格一致：沿用 FunBox 浅蓝背景、白色表面、深藏青 `#151b3b` 重点、主蓝 `#4b6bff` 操作、绿色 `#24b36b` 工具强调，圆角不超过 8px。
- 一期全量：所有功能模块在同一版本上线，无分期、无 mock 回退。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 日常买菜用户 | 想知道今天附近生菜什么价 | 输入菜名，先看官方批发参考，再看附近真实用户报价 |
| 比价用户 | 想比较超市和菜市场价 | 按商户类型筛选，查看凭证和核验状态 |
| 热心用户 | 刚买了菜，发现价格与 App 显示不同 | 上传小票，提交真实报价，参与修正 |
| 质疑用户 | 认为某条价格不准 | 提交结构化异议并附图片，查看后台处理结果 |
| 谨慎用户 | 担心价格数据造假 | 查看数据来源页、更新时间、核验规则，拒绝 demo 数据 |

## 6. 核心流程

```text
进入菜价雷达
  → 授权定位或手动选择城市/区
  → 输入菜名（生菜）
  → 后端按品种字典归一化
  → 返回：官方批发参考 + 附近用户报价 + 合作商户价（如有）
  → 查看商品详情：官方参考、附近报价、凭证、讨论
  → 上传凭证 / 提交异议
  → 后台核验 / 异议处置
  → 结果回流到详情页，状态可追溯
```

兜底路径：

| 异常 | 行为 |
| --- | --- |
| 官方数据源不可用 | 显示可重试错误，或返回最近一次成功快照并标记 stale，不展示 mock |
| 用户拒绝定位 | 手动选择城市/区，距离相关能力不可用时隐藏距离 |
| 附近没有用户报价 | 展示真实空态与“上传凭证”入口，不填充附近门店 |
| 单条用户报价待核验 | 标“待核验”，不计入已确认统计，默认列表不置顶 |
| 凭证图片加载失败 | 展示图片占位，不影响价格文字与来源信息 |
| 商品字典没有该菜名 | 展示“暂无该品种数据”，并提供“反馈补品种”入口 |
| 异议处理中 | 异议保持“处理中”状态，原价格记录不自动消失 |

## 7. 功能设计

### 7.1 查价首页

- 顶部品牌区：菜价雷达 + “查真实菜价”副标题，右侧提供定位与数据来源入口。
- 定位行：展示“上海市 · 静安区”这类真实城市/区，支持切换；未授权时提供手动选择。
- 搜索框：输入菜名，如“生菜、菠菜、土豆”，按品种字典匹配，不展示编造热搜词。
- 真实数据徽标：`农业农村部信息中心`、`地方价格监测`、`用户凭证`，点击进入数据来源页。
- 官方批发参考：默认展示当前城市最近的一个官方批发市场价，显示市场名、价格、单位、更新日期与来源；同城其他市场作为二级参考。
- 附近用户报价：按距离展示真实用户凭证报价，默认只展示已核验；可切换“含待核验”。每行显示商户名、商户类型、距离、价格、单位、购买日期、核验状态。
- 真实空态：附近无报价时显示“附近还没有用户凭证报价”，并提供“上传凭证”按钮，不生成假门店。
- 今日官方品种价：展示同一官方数据源下真实品种价格 chips，例如上海农产品中心批发市场 2026-08-04：生菜 5.20、菠菜 9.50、油菜 2.80 元/公斤。
- 底部导航沿用 FunBox 现有首页 / 工具 / 消息 / 我的。

### 7.2 商品价格详情

- 头部：返回、商品名、分享按钮。
- 价格摘要卡：
  - 商品名与别名，如“生菜（叶用莴苣）”；
  - 官方批发参考：当前城市最近市场价、更新日期、来源；
  - 明确文案“官方批发价不等于门店零售价”，避免用户误解。
- 分段控件：附近价格 / 凭证 / 讨论。
- 附近价格：真实用户报价列表，按距离和核验状态展示；无数据时显示空态。
- 凭证：已核验凭证的图片流与原始元数据；待核验凭证单独标注；用户可选择仅核验可见。
- 讨论与异议：讨论按时间倒序；异议按结构化原因展示，带处理状态；空态时显示“还没有讨论，去发表第一条意见”。
- 同市场其他品种：展示同一官方数据源同一市场的其他真实品种价格，点击可进入对应商品。
- 底部操作：上传凭证、提交异议。

### 7.3 上传凭证 / 提交异议

- 模式分段控件：报价格 / 提异议。
- 报价格表单：
  - 商品名（默认带入当前商品，可修改）；
  - 凭证照片：相机或相册，最多 3 张，支持原图；
  - 商户名称；
  - 商户类型：超市 / 菜市场 / 社区店 / 其他；
  - 单价；
  - 单位：元/500克、元/公斤、元/斤、元/份；
  - 购买日期；
  - 位置：自动定位或手动填写，解析失败不估算。
- 提异议表单：
  - 选择目标价格记录；
  - 原因：今日价格不符 / 单位不对 / 品种不对 / 凭证与商户不符 / 其他；
  - 说明文字；
  - 可选凭证图片。
- 提交前规则条：“提交后进入人工核验，核验前不会标记为已确认价；请上传真实原图凭证。”
- 提交按钮：报价格提交待核验；提异议提交处理中。

### 7.4 数据来源与规则

- 数据源列表：
  - 农业农村部信息中心·全国农产品批发市场价格信息系统：批发市场日度价，单位元/公斤；
  - 地方发改委/商务局价格监测：城市或区级零售均价，单位元/500克，以官方发布为准；
  - 合作商户开放接口：仅展示正式授权商户，未接入不展示；
  - 用户凭证：人工核验后展示，状态可追溯。
- 每条来源显示：数据内容、更新方式、最近同步状态、来源链接。
- 真实数据原则卡：官方基准 / 合作商户 / 用户凭证 / 禁止 mock。
- 无 mock 保障：任何数据源不可用时显示错误、重试或 stale，不回退演示数据。
- 隐私说明：凭证图片默认公开展示，可切换为仅核验可见；支持删除与举报。

### 7.5 我的贡献

- 我提交的报价：显示商品、商户、价格、日期、核验状态，点击进入详情。
- 我提交的异议：显示目标记录、原因、处理状态。
- 支持删除未处理记录；已核验记录删除后从公开列表下线，后台保留审计。
- 空态：“还没有提交过报价或异议”。

### 7.6 后台核验

- 待核验队列：默认按提交时间倒序，展示凭证缩略图、商户、价格、单位、购买日期、位置。
- 核验动作：通过 / 驳回 / 需补充资料；每个动作必须填写核验说明。
- 异议处置：查看异议原因与凭证，处理为“支持异议”或“维持原记录”，处理后记录状态同步变更。
- 数据源运行状态：官方数据源同步时间、成功/失败、stale 状态，供运营确认数据健康度。
- 核验规则：图片清晰可识别、价格与凭证一致、商户与位置可对应、不修改用户提交值；管理员只能改变状态，不能偷偷改价格。

## 8. 真实数据方案

### 8.1 数据源

| 数据层 | 数据源 | 内容 | 展示规则 |
| --- | --- | --- | --- |
| 官方批发参考 | 农业农村部信息中心·全国农产品批发市场价格信息系统 | 全国主要批发市场按品种、按日价格，单位元/公斤 | 按城市/区展示最近市场，保留来源与日期 |
| 官方零售监测 | 地方发改委/商务局价格监测（如北京价格、上海发改委菜篮子） | 城市/区级零售均价，农贸市场与超市分列，单位元/500克 | 作为零售参考，不作为门店价 |
| 合作商户价 | 商超/电商官方开放接口（需正式授权） | 门店名称、地址、商品价、采集时间 | 仅展示已授权商户；未接入区域为空 |
| 用户凭证价 | 用户上传小票/发票 + 结构化信息 | 商户名、商户类型、价格、单位、购买日期、位置、图片 | 人工核验后进入公开列表，状态可见 |

官方入口示例：

- 农业农村部全国农产品批发市场价格信息系统：`http://pfsc.agri.cn/`
- 北京价格监测中心：`https://www.beijingprice.cn/`
- 上海发改委菜篮子价格监测：`https://fgw.sh.gov.cn/`
- 商务部生活必需品市场监测平台：`https://cif.mofcom.gov.cn/`

### 8.2 抓取与缓存

- 后端定时任务抓取官方数据，保存 `source_url`、`fetched_at`、`raw` 与同步状态。
- 官方数据源更新前，接口返回最近一次成功快照并标记 `stale`。
- 合作商户接口使用官方返回字段，不做页面抓取，不做反爬绕过。
- 用户上传图片进入对象存储，缩略图与审计信息分开保存。

### 8.3 品种字典

- 品种 ID 来自官方品种表初始化，运营可维护别名映射。
- 搜索时先归一化，再查询价格；未收录品种返回“暂无该品种数据”与反馈入口。
- 字典只存名称、别名、分类、默认单位，不存任何价格。

### 8.4 单位与换算

- 每条价格保留原始单位；列表展示原单位。
- 如需横向比较，后端统一换算到元/公斤并同时展示原值与换算值，例如“4.80 元/公斤（≈2.40 元/500克）”。
- 用户凭证单位缺失时不允许提交；后台可要求补充。

### 8.5 位置与距离

- 官方批发市场按市场所在地城市/区归属。
- 用户报价使用授权定位或手动填写位置，地址通过真实地图服务解析；解析失败时不估算距离。
- “附近”默认半径为 5 公里，可切换 2 公里 / 10 公里；范围内无数据时展示真实空态。

### 8.6 核验状态机

用户报价状态：

```text
待核验 → 已核验
待核验 → 已驳回
已核验 → 已下线（异议成立/用户删除/举报成立）
```

- 待核验记录默认不进入已确认统计，详情页可查看但需明确标注。
- 已驳回记录只对提交者可见，并显示驳回原因。
- 后台保留完整审计：谁、何时、做了什么动作、原因。

## 9. 数据模型与接口

### 9.1 核心数据对象

- `price_products`：品种字典，字段含名称、别名、分类、默认单位。
- `price_snapshots`：官方/合作商户价格快照，字段含来源、市场/门店、城市、价格、单位、抓取时间、来源链接。
- `price_reports`：用户报价，字段含用户、品种、商户、商户类型、价格、单位、购买日期、位置、状态、凭证。
- `price_evidence`：凭证图片，字段含原图、缩略图、可见性、上传时间。
- `price_objections`：结构化异议，字段含目标记录、原因、说明、图片、状态、处理结果。
- `price_comments`：讨论评论，字段含目标类型、目标 ID、内容、状态、时间。
- `price_sync_runs`：数据源同步任务记录。
- `price_review_actions`：后台核验与异议处置审计。

### 9.2 主要接口

- `GET /api/v1/price-radar/search?q=&lat=&lng=&radius=`：搜索品种，返回官方参考、附近报价、数据源状态。
- `GET /api/v1/price-radar/products/{id}`：商品详情。
- `GET /api/v1/price-radar/products/{id}/reports`：附近报价列表。
- `GET /api/v1/price-radar/products/{id}/discussions`：讨论与异议。
- `POST /api/v1/price-radar/reports`：上传凭证报价（multipart）。
- `POST /api/v1/price-radar/reports/{id}/objections`：提交异议。
- `POST /api/v1/price-radar/reports/{id}/comments`：发表评论。
- `GET /api/v1/price-radar/sources`：数据来源与同步状态。
- `GET /api/v1/price-radar/my-contributions`：我的贡献。
- `GET /api/v1/admin/price-reviews?status=pending`：后台待核验队列。
- `POST /api/v1/admin/price-reviews/{id}/decision`：核验决策。
- `POST /api/v1/admin/objections/{id}/decision`：异议处置。

## 10. 页面与交互设计

- 继续使用 FunBox 现有视觉体系：浅蓝背景、白色表面、深色 `#151b3b` 重点、主色 `#4b6bff`。
- 菜价雷达强调色使用绿色 `#24b36b`，与市场雷达、识花草区分。
- 内容容器最大 430px 移动宽度，宽屏居中。
- 使用开放列表与细分隔线，不新增嵌套卡片；圆角不超过 8px。
- 分段控件用于报价格/提异议、附近价格/凭证/讨论；图标按钮用于定位、分享、上传。
- 支持浅色与深色主题，文本在 320px、390px、430px 视口内不溢出。
- 所有价格数字保持固定宽度与单位标签，避免刷新时布局跳动。
- 空态文案必须真实，不写“加载中请稍后”之类的假反馈。

## 11. 一期范围与验收标准

### 11.1 一期交付清单

- 查价首页：搜索、定位、官方批发参考、附近用户报价、真实空态、上传入口。
- 商品详情：官方参考、附近价格、凭证、讨论、异议、同市场真实品种。
- 上传与异议：图片上传、商户表单、结构化异议、待核验提示。
- 我的贡献：报价、凭证、异议与状态。
- 数据来源与规则页。
- 后台核验与异议处置。
- 数据源同步、stale、错误兜底。
- 单元测试与接口测试，覆盖真实数据规则、空态、单位与核验状态。

### 11.2 验收标准

1. 输入“生菜”能返回真实品种数据；官方参考包含来源、日期、单位；无数据区域显示真实空态。
2. 附近报价只来自用户凭证或合作商户正式接口；待核验内容不进入已确认统计。
3. 用户可上传最多 3 张凭证图片并提交报价，提交后状态为待核验。
4. 用户可对任意价格提交结构化异议并附图片，异议处理结果可追溯。
5. 后台可完成通过/驳回/需补充，所有动作有审计记录。
6. 官方数据源不可用时显示错误或 stale，前端不回退任何 mock 数据。
7. 查价、详情、上传、来源、我的贡献、后台六个页面在桌面与移动视口无重叠、无空白、无控制台错误。
8. 浅色与深色主题均可用，320-430px 视口不溢出。

## 12. 明确不做

- 不做价格预测、AI 生成均价、AI 判断“哪家便宜”。
- 不抓取未授权的买菜 App、商超小程序页面价格。
- 不把用户凭证报价标记为官方价。
- 不用 mock、演示数据、固定示例列表回退。
- 不做分期：本方案所有页面与后台能力一期一次交付。
- 不重做 FunBox 主题、底部导航与工具注册体系。
