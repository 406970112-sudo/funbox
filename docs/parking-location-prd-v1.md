# FunBox 停车位置记录 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 状态：待评审
> 定位：一个“停好车后快速记录、取车前准时提醒”的个人停车位置管理工具。所有地图坐标、停车场名称、楼层区域车位、照片、时间与收费规则都来自用户真实操作或真实定位，不预置任何 mock、种子或演示数据。

## 1. 背景与问题

大型商场、写字楼和医院地下停车场通常面积大、楼层多、分区相似，用户停完车后很容易忘记车停在哪。常见现状：

| 场景 | 现状 | 问题 |
| --- | --- | --- |
| 逛完商场 | 只记得“环球中心 B3 层” | 不记得 C 区、328 号，找车要靠记忆 |
| 地下停车场 | 手机地图坐标漂移 | 单纯依赖地图定位无法指出具体车位 |
| 赶时间入场 | 拍一张照片后存在相册 | 事后无法把照片和楼层车位对应起来 |
| 停车时间久 | 没有记录入场时间 | 忘记是否超时，预估缴费靠猜 |
| 收费规则复杂 | 现场价目表只看一眼 | 不知道多久开始进入下一档费用 |

FunBox 已具备账号、JWT、SQLite、工具注册、本机存储、拍照、相册、通知等能力，新增该工具可以复用同一套基础设施，不需要引入新服务。

## 2. 对原始想法的补充

原始想法是“停好车后快速记录：地图位置、地下停车场楼层、区域编号、车位号、周边环境照片、停车时间、预计收费，并可设置停车后多久提醒缴费”。在此基础上补充十点：

1. 真实数据底座：停车场名称、地图坐标、楼层、区域、车位、标志物、照片、时间、收费规则全部来自用户真实录入、真实定位或真实操作；首启为空，不预置任何记录。
2. 地图与文字双层定位：地图记录地面层或入口的真实坐标；地下楼层、区域、车位、附近标志物用文字记录。两层同时存在，解决地下 GPS 不准的问题。
3. 拍照优先：支持拍照和相册上传真实环境照片，至少建议拍一张，但不强制；照片只作真实存档，不参与 AI 推断。
4. 收费规则可复用：用户可为某停车场录入真实收费规则，后续记录可复用；没有规则时绝不编造“预计收费”。
5. 真实预计收费：只有录入收费规则后才根据真实停车时长计算“预计收费”，并明确标注“以出口实际收费为准”。
6. 缴费提醒：支持“停车后 X 分钟”固定提醒，也支持按收费规则首段截止时间提醒；提醒基于真实停车时间和真实规则计算。
7. 取车闭环：用户点击“已取车”后记录真实取车时间，可选择填写实际缴费金额；停车中记录和已完成记录状态明确。
8. 搜索与回看：支持按停车场名称、楼层、区域、车位、标志物、备注搜索；历史记录按真实时间倒序展示。
9. 本地优先：未登录可完整使用，登录后同步到本人账号；位置、照片和缴费信息均为私密数据，不进公开场景。
10. 一期全量：首页、快速记录、地图、照片、收费规则、预计收费、提醒、取车、历史、搜索、设置全部同一版本完成，不拆二期。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户停好车后 30 秒内完成一次核心记录：停车场 + 楼层区域车位 + 至少一个标志物或照片。
2. 用户取车前能通过提醒、照片、文字三层信息快速回到车位。
3. 产品运行时没有任何假数据、mock 数据、种子数据或 AI 编造的位置。
4. 预计收费只在有真实收费规则时展示，并始终说明以出口实际收费为准。

### 3.2 设计原则

- 真实优先：所有字段都来自真实来源，缺失字段显示“未填写”或“未设置”，不补造。
- 双层定位：地图解决“哪个停车场”，文字和照片解决“停在哪个具体位置”。
- 一步可达：从首页到开始记录最多两次点击，照片和文字可混合使用。
- 一期全量：不设置任何二期拆分的功能项。
- 隐私克制：只做个人管理，不做公共分享、排行、组队或地图导航社区。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 商场/写字楼自驾用户 | 在大型地下停车场停完车后快速记录 | 地图定位 + 楼层区域车位 + 照片，快速保存 |
| 赶时间用户 | 入场时只想先拍照 | 只拍照也可保存，回来再补文字 |
| 高频出差用户 | 到不同城市不同停车场 | 每个停车场可保存真实收费规则，下次复用 |
| 长时停车用户 | 停在医院、机场、火车站 | 设置提醒，避免忘记取车或超出免费时长 |
| 记性一般用户 | 逛完商场找不回车位 | 用照片、标志物、楼层区域文字找车 |

### 5.1 入口

- 工具注册名：`parking-location`
- 工具名称：停车位置记录
- 分类：生活
- 路由：`/tools/parking-location`
- 入口图标建议：`car`（Material Community Icons）
- 状态：一期发布时直接注册为 `available`
- 权限：`normal / vip / svip / admin` 均可使用，V1 不做会员权益差异

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 首页“停车位置记录” | 搜索、当前停车中记录、最近记录、快速记录 |
| 快速记录 | 地图定位、停车场名称、楼层/区域/车位、标志物、照片、停车时间、收费规则、提醒 |
| 停车中详情 | 地图、照片、文字定位、停车时长、预计收费、提醒倒计时、取车/编辑/删除 |
| 取车确认 | 真实取车时间、实际缴费金额、备注，保存后归档 |
| 历史记录 | 按真实时间倒序展示，支持搜索和筛选 |
| 收费规则管理 | 用户录入的真实停车场收费规则，可复用、编辑、删除 |
| 提醒设置 | 默认提醒时长、通知权限、提醒开关 |

以上页面均为一期交付范围。

### 5.3 核心流程

```text
进入停车位置记录
  -> 首页：搜索 / 快速记录 / 当前停车中记录
  -> 快速记录：
     真实定位 + 停车场名称 + 楼层区域车位 + 标志物 + 照片
     + 停车时间 + 收费规则 + 提醒
  -> 保存后进入停车中详情
  -> 停车中：查看地图、照片、文字定位、预计收费、提醒倒计时
  -> 取车：记录真实取车时间，可选填写实际缴费金额
  -> 归档到历史记录，支持搜索与回看
```

## 6. 功能设计

### 6.1 首页“停车位置记录”

- 顶部搜索框覆盖停车场名称、楼层、区域、车位、标志物、备注。
- 有停车中记录时，顶部固定展示当前记录卡片，包含停车场名称、楼层区域车位、停车时长、提醒状态。
- 没有停车中记录时，只展示搜索框和“记录本次停车”主按钮，不预置任何历史记录。
- “最近记录”按 `parkedAt` 倒序取真实记录，最多 8 条。
- 首次使用为空态：只展示入口和简短说明，不展示演示车位、演示照片或演示收费。

### 6.2 快速记录

快速记录页按从上到下顺序：

1. 地图区域：展示设备真实定位或用户选点后的真实地图，显示定位精度；定位失败时允许手动填写停车场名称。
2. 停车场名称：优先来自真实地图 POI 搜索或反向地理编码；用户也可手动输入真实名称。
3. 地下楼层：文本输入或常用楼层选择，例如 `B1 / B2 / B3 / B4`，用户可修改。
4. 区域编号：文本输入，例如 `C区`，不预置固定选项。
5. 车位号：文本输入，例如 `328号`，不预置固定选项。
6. 附近标志物：文本输入，例如 `靠近蓝色电梯`，最长 40 字。
7. 周边环境照片：拍照或相册上传真实照片，最多 6 张；照片支持预览、删除、设封面。
8. 停车时间：默认使用保存时的真实系统时间；用户可修改为真实入场时间。
9. 收费规则：从用户已保存的真实规则中选择，或现场录入新规则；未录入时显示“未设置收费规则”。
10. 缴费提醒：可选“停车后 15/30/60/90/120 分钟”或自定义；可选“收费规则首段结束前 15 分钟”。

保存规则：

- 停车场名称必填；楼层、区域、车位至少填写一项。
- 未填写的字段在详情页显示“未填写”。
- 保存成功进入停车中详情；保存失败保留表单内容。
- 首次进入不展示任何默认车位、默认停车场或默认照片。

### 6.3 地图与地下定位

- 地图使用真实地图服务，优先调用设备定位；展示当前坐标、定位精度和真实 POI 名称。
- 地下停车场 GPS 不准确时，地图标记保留地面层/入口坐标，界面用“室内文字定位”区块承接楼层区域车位。
- 用户可在地图上拖动或搜索选择真实 POI，作为“停车入口/停车场位置”。
- 定位失败、拒绝权限或没有网络时，不展示假坐标；界面显示“定位不可用，可手动填写停车场名称”。
- 记录保存时保存真实经纬度、精度和地图 POI 名称；没有坐标时经纬度字段为 `null`。

### 6.4 照片

- 支持 `expo-camera` 拍照和 `expo-image-picker` 相册上传。
- 照片只作真实存档，不进行 AI 场景识别、车牌识别或文字识别后自动补全。
- 每张照片记录真实拍摄/选择时间；用户可设封面。
- 照片上传失败时保留表单内容，提示重试。
- 单张照片大小限制 10MB，最多 6 张；不压缩为低清缩略图，但可保存压缩后的真实照片副本。

### 6.5 收费规则与预计收费

收费规则字段：

| 字段 | 说明 |
| --- | --- |
| 停车场名称 | 真实名称，与记录关联 |
| 免费时长 | 可选，单位分钟，例如 30 |
| 首段规则 | 可选，例如“前 2 小时 6 元” |
| 后续规则 | 可选，例如“之后每小时 4 元” |
| 单日封顶 | 可选，例如“每日 40 元封顶” |
| 规则来源备注 | 可选，例如“现场价目表拍照”或“用户输入” |

计算规则：

- 只有用户录入真实收费规则后，才根据真实停车时长计算“预计收费”。
- 计算使用整段规则和真实 `parkedAt` 到当前时间或取车时间的差值。
- 结果统一显示为“预计约 X 元，以出口实际收费为准”。
- 没有规则或字段缺失时，显示“未设置收费规则”，绝不显示默认金额。
- 已取车且用户填写实际缴费金额时，优先展示真实缴费金额。

### 6.6 缴费提醒

- 提醒基于真实停车时间和用户选择的时间偏移计算，使用 `expo-notifications` 本地通知。
- 固定提醒：停车后 15/30/60/90/120 分钟或自定义分钟数。
- 规则节点提醒：当收费规则包含首段时长时，在首段结束前 15 分钟提醒。
- 通知内容包含真实停车场名称、楼层区域车位和提醒目的，不包含编造数据。
- 用户点击“已取车”后自动取消未触发的提醒。
- 通知权限未授权时，在详情页显示“通知未开启”，不伪造已提醒状态。
- 重复进入详情页时，根据真实时间重算提醒状态；已触发但用户未取车时，显示“已提醒”和真实触发时间。

### 6.7 取车闭环

- 停车中详情提供“已取车”主按钮。
- 取车时默认取车时间为当前真实系统时间，可修改为真实取车时间。
- 可选填写实际缴费金额，字段只接受用户真实输入。
- 保存后记录变为“已取车”，停车时长按真实时间差展示，取消未触发提醒。
- 取车操作可撤销，撤销后恢复为停车中状态并重排提醒。

### 6.8 历史与搜索

- 历史记录按 `parkedAt` 倒序展示，状态分为“停车中”和“已取车”。
- 搜索覆盖停车场名称、楼层、区域、车位、标志物、备注。
- 支持状态筛选：全部 / 停车中 / 已取车。
- 无结果时展示真实空态，保留搜索词，提供清除筛选和新增记录入口。
- 最近搜索只来自用户真实搜索词，最多保留 10 条，可清空。

### 6.9 真实数据机制

| 数据 | 来源 | 校验要求 |
| --- | --- | --- |
| 停车场名称 | 地图 POI 或用户真实输入 | 非空、长度 1-40 字 |
| 经纬度 | 设备定位或用户真实选点 | 无定位时可为 `null`，不造假 |
| 楼层/区域/车位 | 用户真实输入 | 至少填写一项，长度上限 20 字 |
| 标志物 | 用户真实输入 | 可选，最长 40 字 |
| 照片 | 拍照或相册上传 | 真实图片文件，大小和数量限制 |
| 停车时间 | 保存时系统时间或用户修正 | 不允许超过当前时间 24 小时 |
| 收费规则 | 用户真实录入 | 金额非负、时长为正整数 |
| 预计收费 | 真实规则 + 真实时长计算 | 无规则时返回 `null` |
| 实际缴费 | 用户真实输入 | 非负数字，可选 |
| 提醒 | 真实停车时间 + 用户设置 | 基于本地通知调度，不写假状态 |

禁止事项：

- 不生成任何种子记录、演示车位、演示照片或演示收费。
- 不由 AI 推断、编造或补全停车位置。
- 不在地图定位失败时展示默认坐标。
- 不在没有收费规则时展示“预计 X 元”。
- 不把照片识别结果自动写成楼层、区域或车位。
- 不在 API 或存储中返回虚假计数或虚假提醒状态。

## 7. 数据模型

```text
parking_records
  id, user_id,
  parking_lot_name, map_poi_id, map_poi_name,
  latitude, longitude, accuracy_m,
  floor_label, zone_label, spot_label,
  landmark_note, note,
  parked_at, leave_at,
  status,                        -- active / left
  fee_rule_id, reminder_minutes,
  reminder_mode,                 -- fixed / rule_boundary / none
  estimated_fee_cents, actual_fee_cents,
  created_at, updated_at

parking_photos
  id, record_id, user_id,
  file_url, thumb_url, taken_at,
  is_cover, sort_order, created_at

parking_fee_rules
  id, user_id, parking_lot_name,
  free_minutes,
  first_rule_minutes, first_rule_amount_cents,
  subsequent_minutes, subsequent_amount_cents,
  max_day_amount_cents,
  source_note, created_at, updated_at

parking_search_history
  id, user_id, query, created_at
```

时间规则：

- `parkedAt` 和 `leaveAt` 使用用户本地真实时间。
- 停车时长、预计收费、提醒倒计时都由服务端或前端基于真实时间戳计算。
- 未取车时 `leaveAt` 为 `null`。
- 未录入收费规则时 `estimatedFeeCents` 为 `null`。

## 8. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/parking-location/state` | 拉取当前账号停车位置全量状态 |
| PUT | `/api/v1/parking-location/state` | 全量保存停车记录、收费规则、提醒设置与最近搜索 |
| DELETE | `/api/v1/parking-location/state` | 清空当前账号停车位置状态 |

说明：

- 未登录时使用本机真实数据，登录后按 `updatedAt` 合并或覆盖账号状态；所有接口要求登录，沿用现有 JWT 鉴权与限流中间件。
- 新增模块放在 `backend/internal/parkinglocation/`，在现有 `httpapi` 注册路由。
- 照片以本机真实文件或本机 URI 保存，账号同步只同步照片元数据，不上传照片到公共目录。
- 服务端不生成默认停车场、默认车位、默认收费金额或默认历史记录。

## 9. 页面与交互设计

- 沿用 FunBox 视觉体系：浅蓝画布、白色表面、深藏青重点、品牌蓝主色；本工具补充停车语义色：定位蓝 `#4568f2`、停车绿 `#18a78f`、提醒金 `#e8a33d`、取车蓝 `#1c8ed8`。
- 内容区最大 430px 移动宽度，宽屏居中。
- 地图区域、表单、照片网格、按钮使用稳定尺寸控件；点击区域不小于 44px。
- 图标沿用 Material Community Icons 或现有 Lucide 图标体系。
- 支持浅色与深色主题；320px、390px、430px 视口下文字不溢出、元素不重叠。
- 不写教程式大段说明文字，空态只给可执行动作。

## 10. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 首次进入，无记录 | 空态 + 搜索框 + “记录本次停车”入口，不预置数据 |
| 定位不可用 | 显示“定位不可用”，允许手动填写停车场名称，不展示假坐标 |
| 地图加载失败 | 保留表单，提示重试；已填内容不丢失 |
| 拍照/相册权限拒绝 | 提示开启权限，允许先保存文字记录 |
| 通知权限拒绝 | 显示“通知未开启”，不伪造提醒状态 |
| 收费规则缺失 | “预计收费”显示“未设置收费规则”，不估算 |
| 保存失败 | 保留表单内容，提示重试 |
| 取车保存失败 | 保留取车时间与实际缴费，提示重试 |
| 同步失败 | 展示本机真实数据并标注更新时间，不展示 mock |

## 11. 一期交付清单

本方案不设分期，以下内容在同一版本一次交付：

- 首页空态、搜索、停车中记录卡片、最近记录、快速记录入口。
- 快速记录：地图定位、停车场名称、楼层/区域/车位、标志物、照片、停车时间、收费规则、提醒。
- 地图真实定位、POI 搜索/选择、定位失败降级、精度展示。
- 照片拍照、相册上传、预览、删除、封面设置。
- 收费规则录入、复用、编辑、删除。
- 基于真实规则和真实时长的预计收费。
- 固定提醒、收费规则节点提醒、通知权限处理、取车取消提醒。
- 取车闭环、实际缴费记录、取车撤销。
- 历史列表、搜索、状态筛选、最近搜索。
- 本机持久化、登录账号同步、导出 CSV/JSON。
- 空态、加载、错误、定位失败、通知未开启等状态。
- 浅色/深色主题与 320/390/430 响应式。
- 单元测试覆盖校验、收费计算、提醒调度、搜索、权限与同步。

## 12. 明确不做

- 不做 AI 车位识别、车牌识别、照片 OCR 自动补全。
- 不做室内蓝牙/UWB/室内地图定位。
- 不做停车场实时空位、预约、在线缴费或与第三方停车场系统对接。
- 不做公共分享、家庭协作、排行或团队管理。
- 不做种子数据、演示数据、mock 数据或示例记录。
- 不做会员权益差异，V1 所有角色可用。

## 13. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 用户不愿填写完整信息 | 停车场必填，楼层/区域/车位至少一项，其余可选 | 降低录入成本，保证可搜索性 |
| 地下 GPS 不准 | 地图只记录入口/地面坐标，室内信息用文字和照片 | 定位结果诚实，不假装精确 |
| 收费规则变化 | 规则带来源备注和更新时间，预计收费始终提示以出口为准 | 用户可及时更新真实规则 |
| 收费估算复杂 | 只做免费时长、首段、后续、单日封顶四类字段 | 覆盖大多数真实场景，不承诺精确结算 |
| 照片存储占用 | 限制单张大小与最多 6 张，复用私有存储目录 | 需评估存储配额 |
| 提醒可靠性 | 使用本地通知，进入详情时重算状态 | 应用未打开时仍可提醒，状态可回查 |
| 隐私风险 | 所有接口 JWT 鉴权，照片私有，不做公开访问 | 需要隐私评审 |

## 14. 验收清单

- 首次进入没有任何预置停车记录、停车场、车位、照片、收费规则或历史数据。
- 支持地图真实定位；定位失败时允许手动输入，不出现默认坐标。
- 支持停车场、楼层、区域、车位、标志物、照片、停车时间真实录入。
- 未录入收费规则时，“预计收费”不出现任何金额。
- 录入真实收费规则后，预计收费由真实停车时长计算，并标注“以出口实际收费为准”。
- 支持固定提醒和收费规则节点提醒；通知基于真实停车时间调度。
- 取车后记录真实取车时间、实际缴费，取消未触发提醒。
- 历史列表、搜索、筛选结果与真实数据一致。
- 320px、390px、430px 视口无文字溢出和元素重叠。
- 浅色/深色主题均可读。
- 接口全部带 JWT 鉴权，未登录返回 401。
- Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。
