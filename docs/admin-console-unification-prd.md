# FunBox 管理后台导航统一 产品方案

> 文档版本：V1.0  
> 状态：待评审  
> 适用端：Expo 移动端 / 管理后台 Web  
> 目标版本：MVP

## 1. 背景与问题

从当前后台页面与代码确认：后台由多个独立页面组成，桌面端只有「用户身份」页内置了左侧导航栏；「入口权限」「问题反馈」等页面只有顶部返回按钮。从「用户身份」页点击跳转后，左侧导航栏立即消失，管理员需要在模块之间反复返回，且不同页面的顶栏、面包屑、加载/空/错误状态都各自实现。

具体表现：

1. 桌面端导航不统一：只有部分页面有左侧导航，切换模块时框架消失。
2. 移动端没有后台常驻导航，仅靠返回按钮回到后台首页。
3. 后台首页、用户身份、入口权限、问题反馈、阅读管理的页面结构不一致。
4. 阅读管理拥有独立深色侧栏，与其他后台页面视觉不同。
5. 游戏入口目前未纳入「入口权限」配置：后端功能注册表只接受 `/tools/*` 路由，前端权限上下文也只过滤工具，首页游戏区和游戏详情页仍是硬编码展示。

## 2. 产品判断与目标

管理后台是一个连续工作空间，不是一组互相独立的页面。核心目标是「一个后台、一套框架、随时切换」。

三条原则：

1. 导航常驻：桌面端左侧导航、移动端底部导航常驻，切换页面不丢失框架。
2. 页面只换内容区：路由切换只更新内容区与导航高亮，顶栏、侧栏、底部导航保持不变。
3. 视觉收敛：统一顶栏、面包屑、卡片、表格、空/错/加载状态，后台页面共用一套组件语言。
4. 入口权限覆盖全部可配置入口：工具、游戏、阅读等统一纳入同一套配置能力，不只管理工具。

## 3. 导航统一方案

### 3.1 桌面端（>=900px）

- 左侧固定导航 216px，深色品牌底。
- 品牌区：FunBox 管理后台。
- 管理工具：后台首页、用户身份、入口权限、问题反馈。
- 内容运营：阅读管理（后续可扩展其他内容模块）。
- 底部：管理员身份标识 + 返回 FunBox。
- 内容区顶部 64px 顶栏：面包屑 + 当前页标题/副标题 + 管理员徽章 + 通知/更多操作。
- 选中导航项高亮，当前页标题与面包屑同步更新。

### 3.2 移动端（<900px）

- 不显示左侧导航，改为顶部顶栏（返回、标题、管理员徽章）+ 底部常驻导航。
- 底部导航固定 5 项：首页、用户、权限、反馈、阅读。
- 二级操作（用户详情、反馈详情、权限编辑）留在页面内抽屉/详情层，不跳新页面。
- 底部导航只在后台内显示，返回 FunBox 后回到用户端。

### 3.3 路由与结构

- 新增 `app/admin/_layout.tsx`（或 `AdminShell`），统一包裹现有后台路由：
  - `/admin/index` 后台首页
  - `/admin/users` 用户身份
  - `/admin/permissions` 入口权限
  - `/admin/feedback` 问题反馈
  - `/admin/reading` 阅读管理
- 根 Stack 只注册 `/admin` 一组路由，子页面不再各自实现返回按钮与顶栏。
- 深链接直接打开 `/admin/feedback` 时默认带完整框架；未登录或非管理员统一重定向到 `/profile`。

### 3.4 游戏入口配置范围

「入口权限」页面除工具外，必须支持游戏入口配置，覆盖当前游戏：

- 五子棋（`/games/gomoku`）
- 打砖块（`/games/brick-breaker`）
- 贪吃蛇（`/games/snake-brawl`）
- 俄罗斯方块（`/games/tetris`）
- 中国象棋（`/games/xiangqi`）

配置能力与工具入口完全一致：

1. 角色可见性：`normal / vip / svip / admin` 勾选配置。
2. 用户特批：按手机号单独放行指定用户。
3. 生效范围：首页游戏区、游戏详情页、最近使用记录统一按配置过滤；直接打开游戏深链接且无权限时给出统一受限提示。

实施要求：

- 后端：扩展 `feature_registry.json` 增加游戏入口，路由校验放宽到 `/tools/*`、`/games/*`、`/reading/*` 等受管前缀。
- 前端：`FeatureAccessProvider` 统一管理工具与游戏的可见性，首页游戏横滑和游戏详情路由都读取同一份可见 ID。
- 后台：入口权限页面按分类展示，游戏入口归入「游戏」分类，后续新游戏注册后自动出现。

## 4. 页面规范

| 模块 | 页面标题 | 副标题 | 核心内容 |
| --- | --- | --- | --- |
| 后台首页 | 管理控制台 | 后台各模块统一在此管理 | 指标概览、最近反馈、快捷入口 |
| 用户身份 | 用户身份 | 查询用户并调整普通用户 / VIP / SVIP 身份 | 搜索筛选、用户表格、身份调整抽屉 |
| 入口权限 | 入口权限 | 管理功能与游戏入口的角色可见性、用户特批 | 功能/游戏入口列表、角色配置、用户特批 |
| 问题反馈 | 问题反馈 | 查看用户提交的文字与图片 | 反馈列表、详情、回复/标记处理 |
| 阅读管理 | 阅读管理 | 导入、发布与隐藏阅读内容 | 书籍列表、导入入口、发布状态 |

通用规范：

- 页面工具区：搜索、筛选、主操作按钮位置固定。
- 数据区：统一卡片/表格/列表，分页样式一致。
- 状态区：加载骨架屏、空状态、错误重试按钮统一。
- 权限校验：admin 角色校验统一放在 Shell，子页面不再重复校验。
- 入口权限：工具、游戏、阅读入口在同一页面按分类管理，统一角色配置与用户特批。
- 主题：跟随 App Light / Dark，侧栏保持深色品牌底。

## 5. 交互与边界

1. 导航点击：仅内容区切换，页面回到顶部，标题、面包屑、导航高亮同步。
2. 移动端：底部导航图标 + 文字，选中项主色高亮。
3. 返回 FunBox：使用 `router.replace('/profile')` 而不是 `router.back()`，避免返回来源不确定。
4. 子模块详情：详情页不视为独立模块，不改变底部导航高亮。
5. 浏览器前进/后退：内容区同步切换，后台框架不丢。

## 6. 实施计划

Phase 1（约 1 天）：

- 新增 AdminShell，实现桌面侧栏与移动底部导航。
- 接入现有 5 个后台路由。
- 移除子页面重复返回按钮，统一顶栏。
- 游戏入口纳入入口权限：后端注册游戏 feature，前端首页与游戏详情按可见 ID 过滤。

Phase 2（约 2-3 天）：

- 统一页面头部、表格/列表、分页、加载/空/错误状态。
- 阅读管理并入统一框架。
- 补齐深链接与权限校验，回归现有后台功能。

Phase 3（可选）：

- 后台首页升级为工作台（待处理反馈、待发布内容、系统状态）。
- 增加导航角标（如未处理反馈数）、通知与操作日志。

## 7. 验收标准

1. 桌面端 1440px：任意导航切换，左侧栏始终存在且高亮正确；面包屑与标题同步；刷新或深链接后框架保留。
2. 移动端 390px：底部导航常驻，5 个模块可切换；二级详情不跳页；无横向滚动、无元素重叠。
3. 权限：普通用户访问 `/admin/*` 重定向；admin 正常进入。
4. 主题：Light / Dark 均可读，侧栏深色底不随主题翻转。
5. 回归：用户身份、入口权限、问题反馈、阅读管理原有功能与接口不变。
6. 游戏入口：每个游戏可在入口权限页面独立配置角色与用户特批；无权限用户首页看不到对应游戏，直接打开游戏深链接被拦截。

## 8. 待评审问题

1. 阅读管理当前是独立深色侧栏，本期是否并入统一侧栏？推荐并入，保证后台一致。
2. 后台首页是否升级为工作台（展示待处理反馈、待发布内容），还是维持入口卡片？
3. 移动端是否保持 5 个底部导航项，还是需要「全部」聚合入口？
4. 是否需要在侧栏/底部导航显示未处理反馈角标？建议二期再做。
5. 游戏是否单独一个后台管理模块？推荐本期只在「入口权限」页以「游戏」分类管理，不新增独立页面。
