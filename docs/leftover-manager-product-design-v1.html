Product Overview

定位：把冰箱变成一张真实可执行的清单

不猜还能不能吃，只按用户真实录入和服务器真实时间排序。

真实优先
首启为空，只保存用户真实录入的剩菜、外卖、食材、照片与金额。
到期驱动
优先吃掉按真实预计食用期限排序，临期、今天、明天、过期全部可解释。
食材匹配
今晚建议只使用真实冰箱记录和带来源的真实菜谱库，不做 AI 编造。
Real Data Principles

真实数据原则：硬性要求

以下每一条都会进入验收标准，任何环节都不允许预置假数据。

01
首次进入为空态，不展示任何预置剩菜、外卖、食材或统计。
02
名称、来源、分量、金额与备注全部由用户真实输入。
03
照片必须来自相机或相册，不提供占位图。
04
预计食用期限是具体真实时间，快捷项只生成具体截止时间。
05
优先吃掉只来自用户真实 active 记录，按到期时间升序。
06
今晚建议只匹配真实冰箱记录，命中为 0 时隐藏。

Data Model & Validation

数据模型与校验

冰箱记录与事件分离，菜谱库带来源且版本化。

对象 主要字段 校验规则
冰箱记录 名称、来源类型、商家、入冰箱时间、预计食用期限、存放位置、剩余分量、加热次数、照片、食材标签、成本金额、备注、状态 名称 1-40 字符；预计期限晚于入冰箱时间；剩余分量 1-100%；照片最多 3 张
事件流 记录 ID、事件类型、备注、服务器时间 事件类型固定：created / edited / reheated / eaten / discarded / deleted
菜谱库 菜谱 ID、名称、主食材、调味料、预计分钟、步骤、来源、版本 主食材不得为空；来源必须存在；版本变更可追溯
设置 提醒开关、提醒提前时间、通知授权状态、同步状态 通知授权状态来自系统真实结果，不手动写入
States & Constraints

状态与异常

空态、加载、错误、通知权限与同步失败全部本期完成。

状态 行为
空态首次进入不出现任何预置数据，只提供添加记录引导。
加载态读取本机与账号数据期间显示 PageLoadingFrame，不渲染占位数据。
错误态同步失败时保留本机真实数据，顶部提示“同步失败，已使用本机数据”。
通知未授权设置页显示真实状态，首页应用内待办继续可用。
删除态删除记录前二次确认；清空前要求再次确认。
Design Principles

方案要点

五条原则约束所有录入、排序、建议与统计流程。

01
真实录入
所有冰箱记录由用户输入，首启为空，不做任何猜测。
02
到期排序
优先吃掉按服务器真实时间和预计期限计算。
03
可解释建议
今晚建议展示命中记录、匹配度和缺少项。
04
动作留痕
加热、吃完、丢弃全部写入真实事件流。
05
一期完整
首页、记录、建议、提醒、统计、导出一次完成。
