# FunBox 会员开通「扫码收款 MVP」产品设计方案

> 文档版本：V1.0  
> 状态：待评审  
> 适用端：Expo 移动端 / 管理后台 Web  
> 目标版本：MVP

## 1. 背景与问题

FunBox 已具备完整的会员身份体系：

- 用户侧已有「会员中心」页面（`/profile/membership`），展示身份卡、我的权益、权益对比；
- 后台已有「用户身份」管理能力，管理员可以把普通用户调整为 VIP / SVIP，并保留变更记录；
- 身份是 `normal / vip / svip / admin` 单选项，直接决定入口权限可见性。

当前缺口是：**会员中心没有「开通会员」的入口，用户不知道如何付费，管理员也没有收款码配置能力。**

现阶段没有接入支付系统，因此本期采用最轻量的人工收款闭环：

> 用户选择套餐 → 展示管理员配置的收款二维码 → 用户扫码付款并在转账备注中填写手机号 → 管理员核对后，在后台手动把该用户调整为 VIP / SVIP。

## 2. 方案定位与目标

本期把能力定义为「会员开通引导 + 人工收款闭环」，不定义通用订单系统。

### 2.1 产品目标

1. 普通用户能在会员中心看到明确的 VIP / SVIP 价格和开通入口；
2. 支付流程可执行：用户能扫码付款，并且管理员能知道「这笔钱是谁付的」；
3. 管理员能自主维护收款码，不需要改代码或数据库；
4. 开通动作可追溯：每次人工开通都落在现有的用户身份变更审计里；
5. 页面结构和接口为正式支付系统预留位置，二期可平滑替换。

### 2.2 设计原则

1. **预期管理**：人工开通没有自动到账，所有文案必须明确「支付后等待管理员核实开通」，不承诺即时生效。
2. **可追溯**：收款码配置有变更记录，用户身份调整必须填写原因，形成「收款码 → 转账备注 → 身份变更」的完整证据链。
3. **双端一致**：用户端会员中心与后台共用同一套身份令牌、颜色和文案，不另起一套视觉。
4. **留好接缝**：价格、套餐、收款码、支付说明都以可配置字段承载，为正式支付系统预留数据结构和接口形态。
5. **安全收敛**：收款码仅管理员可上传，仅登录用户可见，未配置时直接展示「暂未开通」，不泄露任何内部信息。

## 3. 范围

### 3.1 本期范围

- 会员中心新增「开通会员」板块：VIP / SVIP 套餐卡与价格展示；
- 套餐选择后的「扫码支付」页面：收款二维码、应付金额、支付步骤、支付备注要求；
- 「我已支付」等待态：明确告知人工核实流程与预计时长；
- 后台新增「会员收款」页面：上传 / 更换 / 移除收款码、编辑支付说明、查看变更记录；
- 复用后台「用户身份」页面完成人工开通，并在调整原因中规范记录付款来源；
- 收款码未配置、未登录、非管理员访问等边界状态。

### 3.2 非本期范围

- 微信 / 支付宝 / 银联等正式支付渠道与自动回调；
- 订单、退款、发票、自动续费；
- 会员到期时间与自动降级（`membership_expires_at` 仅预留展示位）；
- 批量开通、批量导入收款记录；
- 按套餐分别配置多张收款码（本期共用一张码，二期可选）；
- 用户自行上传支付凭证到订单系统（可先用现有「问题反馈」作为人工沟通通道）。

## 4. 角色与核心流程

### 4.1 核心流程

```text
用户端
进入会员中心
  → 查看「开通会员」套餐卡
  → 选择 VIP / SVIP
  → 进入扫码支付页
  → 扫码付款，转账备注填写注册手机号
  → 点击「我已支付，等待开通」
  → 等待管理员核实

管理端
管理员在「会员收款」上传收款码与支付说明
  → 用户付款后，管理员核对转账备注 / 用户反馈
  → 在「用户身份」搜索该手机号
  → 调整为 VIP / SVIP，原因填写「付款来源 + 金额 + 时间」
  → 用户下一次回到前台刷新身份，会员中心展示新身份
```

### 4.2 闭环时序

| 步骤 | 动作方 | 动作 | 关键产物 |
| --- | --- | --- | --- |
| 1 | 管理员 | 上传收款码并保存支付说明 | 收款码配置 + 变更记录 |
| 2 | 用户 | 选择套餐，查看收款码与应付金额 | 套餐选择埋点 |
| 3 | 用户 | 扫码付款，备注手机号 | 转账流水（站外） |
| 4 | 用户 | 点击「我已支付」 | 本地等待态提示 |
| 5 | 管理员 | 核对转账备注，搜索目标用户 | 用户身份页匹配结果 |
| 6 | 管理员 | 调整身份为 VIP / SVIP | 身份变更审计记录 |
| 7 | 用户 | 回到前台 / 会员中心 | 新身份与权益即时刷新 |

## 5. 定价与套餐

本期固定两个套餐，均为单月购买、人工开通：

| 套餐 | 系统值 | 价格 | 说明 |
| --- | --- | --- | --- |
| VIP | `vip` | ¥2 / 月 | 解锁配置给 VIP 的功能 |
| SVIP | `svip` | ¥5 / 月 | 解锁配置给 SVIP 的功能 |

设计说明：

- 文案统一为「月卡」，避免歧义；
- SVIP 是否包含 VIP 权益沿用现有入口权限配置，本期不强行定义继承关系；
- 价格本期由后台配置承载（默认 2 / 5 元），不直接写死在前端；
- 由于没有到期时间，管理员开通后身份持续生效，直到管理员再次调整；页面保留「到期时间」占位，二期接入 `membership_expires_at` 后展示。

## 6. 用户端设计

### 6.1 会员中心新增「开通会员」板块

位置：现有身份卡之后、「我的权益」之前。

内容：

1. 板块标题「开通会员」，右侧说明「单月购买 · 人工开通」；
2. 两张套餐卡：
   - VIP：金色主题，「VIP 月卡」、`¥2 / 月`、「立即开通」；
   - SVIP：玫瑰主题，「SVIP 月卡 · 推荐」、`¥5 / 月`、「立即开通」；
3. 普通用户两侧按钮均可点击；VIP 用户只展示 SVIP 升级卡，VIP 卡变为「当前身份」态；SVIP 用户展示「已开通全部会员等级」。

### 6.2 扫码支付页

点击「立即开通」后进入 `/profile/membership/payment`，页面包含：

1. 订单摘要：套餐名（如「SVIP 月卡」）、金额（如 `¥5.00`）、购买说明；
2. 收款二维码：来自后台配置，居中展示，二维码下方注明「示例收款码，扫码付款」；
3. 支付步骤：
   - 扫码支付 ¥2 / ¥5；
   - 转账备注填写注册手机号（脱敏展示示例：`138****5678`），支持一键复制；
   - 点击「我已支付，等待开通」；
4. 主按钮「我已支付，等待开通」；
5. 辅助入口「联系管理员」：跳转到问题反馈页，可上传付款截图、备注手机号与套餐；
6. 底部说明：人工开通非自动到账，管理员核实后手动开通，通常 24 小时内完成。

### 6.3 支付后等待态

点击「我已支付」后：

- 主区域切换为「开通申请已提交」状态卡；
- 三步流程更新：扫码支付 ✓、备注手机号 ✓、管理员核实开通（进行中）；
- 展示提示：「请留意消息通知，管理员核实后手动开通；通常 24 小时内完成」；
- 按钮变为「刷新开通状态」与「联系管理员」；
- 本期不做真实状态上报，「我已支付」仅作为前端本地提示；正式支付接入后可替换为真实订单状态。

### 6.4 收款码未配置态

后台未上传收款码时：

- 会员中心套餐卡仍展示价格，但按钮不可用，文案「收款码暂未配置，请联系管理员」；
- 支付页不渲染二维码占位图，展示空状态：`收款码暂未配置，请联系管理员后重试`；
- 前端通过 `paymentInfo.enabled=false` 判断，不写死默认二维码。

## 7. 管理端设计

### 7.1 新增「会员收款」页面

后台侧边栏新增「会员运营」分组，入口「会员收款」，路由建议 `/admin/membership`。

页面结构：

1. 标题区：页面标题「会员收款设置」，副标题「维护收款码与支付说明」；状态徽标显示「已配置 / 未配置」；
2. 收款码卡片：
   - 二维码预览（后台实际渲染上传的图片）；
   - 上传 / 更换按钮（图片选择器，支持 png / jpg / webp，建议不超过 2MB）；
   - 移除按钮（清空收款码）；
   - 元信息：最近更新人、更新时间；
3. 支付说明卡片：
   - 「转账备注要求」多行文本，默认「转账请备注您的注册手机号，方便管理员核对开通」；
   - 定价信息：VIP `¥2 / 月`、SVIP `¥5 / 月`（本期只读展示，二期开放编辑）；
   - 保存按钮；
4. 开通处理指引卡片：
   - 三步文字：核对转账备注 → 在用户身份搜索手机号 → 调整身份并填写付款原因；
   - 「前往用户身份」快捷按钮；
5. 配置变更记录：展示每次上传 / 更换 / 移除收款码、修改支付说明的操作人与时间。

### 7.2 人工开通复用现有能力

- 入口：后台「用户身份」→ 搜索手机号 → 「调整用户身份」；
- 目标身份：VIP / SVIP；
- 调整原因规范示例：`2026-08-01 微信转账 ¥5 开通 SVIP 月卡，备注 138****5678`；
- 现有后端 `PATCH /api/v1/admin/users/{userId}/role` 与审计表继续承担开通记录职责，不重复造轮子。

## 8. 状态与边界

| 场景 | 用户端表现 | 管理端表现 |
| --- | --- | --- |
| 未登录 | 会员中心跳转登录页 | 不可访问 |
| 普通用户 | 展示全部套餐与开通入口 | 不可访问收款设置 |
| VIP 用户 | 展示 SVIP 升级卡，VIP 卡为当前身份 | 不可访问收款设置 |
| SVIP 用户 | 展示「已开通全部会员等级」 | 不可访问收款设置 |
| 管理员 | 身份卡进入后台，不展示开通按钮 | 可上传 / 修改收款码 |
| 收款码未配置 | 套餐卡禁用 + 空状态提示 | 状态徽标「未配置」 |
| 图片格式 / 大小非法 | 不涉及 | 上传失败并提示原因 |
| 网络失败 | 支付页提示重试，保留所选套餐 | 保存失败保留表单内容 |
| 重复点击「我已支付」 | 按钮置灰，防重复提交 | 不涉及 |

## 9. 数据与接口

### 9.1 数据设计建议（MVP）

新增 `membership_settings` 表（或复用现有配置表）：

| 字段 | 说明 |
| --- | --- |
| `id` | 配置 ID，单例 |
| `payment_qr_url` | 收款码图片地址，可空 |
| `payment_note` | 支付说明 / 备注要求 |
| `vip_price_cents` | VIP 价格（分），默认 200 |
| `svip_price_cents` | SVIP 价格（分），默认 500 |
| `updated_by` | 最近更新管理员 ID |
| `updated_at` | 更新时间 |

收款码图片复用现有头像 / 反馈图片存储目录与 URL 解析逻辑。

### 9.2 接口建议

用户端：

`GET /api/v1/membership/payment`（需登录）

```json
{
  "enabled": true,
  "qrUrl": "/files/payment-qr/xxx.png",
  "note": "转账请备注您的注册手机号",
  "plans": [
    { "tier": "vip", "priceCents": 200, "period": "month" },
    { "tier": "svip", "priceCents": 500, "period": "month" }
  ]
}
```

管理端：

- `PUT /api/v1/admin/membership/payment`：上传 / 更换收款码、更新支付说明；
- `DELETE /api/v1/admin/membership/payment/qr`：移除收款码；
- `GET /api/v1/admin/membership/settings`：查看当前配置与变更记录；
- 身份开通继续复用 `PATCH /api/v1/admin/users/{userId}/role`。

## 10. 安全与合规

1. 所有用户端支付信息接口必须登录后访问；收款码不匿名公开，避免被站外滥用；
2. 仅管理员可上传、更换、移除收款码，接口做 `admin_required` 校验；
3. 上传图片限制格式与大小，禁止执行文件；
4. 收款码变更记录写入审计，日志不记录完整手机号之外的敏感信息；
5. 页面上只展示脱敏手机号示例，不要求用户明文提交手机号以外的隐私信息；
6. 建议管理员定期更换收款码，并在收款说明中写明平台名称，防止误付与仿冒。

## 12. 验收标准

### 12.1 功能验收

- 普通用户在会员中心能看到 VIP `¥2/月`、SVIP `¥5/月` 与「立即开通」；
- 选择套餐后能看到后台配置的收款码与应付金额；
- 支付页明确提示备注手机号、等待人工开通；
- 未配置收款码时，用户端不显示假二维码，套餐按钮禁用并提示；
- 管理员能上传、更换、移除收款码，并能编辑支付说明；
- 收款码与说明保存后，用户端立即生效；
- 管理员在用户身份页搜索手机号并调整为 VIP / SVIP 后，用户端回到前台能刷新出新身份；
- 每次收款码变更与身份调整均有审计记录。

### 12.2 体验验收

- 套餐卡在窄屏（320px）下不换行、不溢出；
- 支付步骤清晰，用户不需要问客服就知道下一步；
- 等待态明确说明人工开通非即时到账；
- 后台收款码预览与移动端展示一致；
- 上传失败、网络失败、未配置等状态均有明确文案。

### 12.3 测试重点

- 四种身份的会员中心展示差异；
- 收款码未配置 / 已配置 / 移除后再次访问；
- 上传非法图片、超大图片；
- 非管理员越权访问上传接口；
- 用户身份调整后前台权限刷新；
- 并发修改收款码时以后一次保存为准并记录审计。

## 13. 上线顺序

1. 后端新增 `membership_settings` 表与支付信息接口，完成管理员上传能力与测试；
2. 后台新增「会员收款」页面（上传、说明、审计）；
3. 用户端会员中心新增套餐卡、扫码支付页与等待态；
4. 用测试账号走通「上传收款码 → 用户扫码 → 管理员手动开通 → 用户刷新身份」全链路；
5. 小范围开放给真实用户，观察付款备注规范率与人工核销耗时。

## 14. 待评审问题

1. 价格是否需要后台可编辑？本期默认只读展示 2 / 5 元，正式支付前再放开；
2. SVIP 是否自动包含 VIP 权益？当前权限模型分别配置，需要产品明确；
3. 收款码共用一张还是按 VIP / SVIP 分两张？本期共用，二期可选；
4. 是否需要「开通码」替代手机号备注？本期先用注册手机号，避免生成码丢失问题；
5. 是否需要在后台记录「收款确认」动作（管理员确认已收到某用户转账）？本期可先用调整原因覆盖；
6. 会员到期时间是否进入本期？建议二期配合正式支付一起做。
