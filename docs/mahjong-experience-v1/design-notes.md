# 麻将记分互动体验概念 V1

基于当前原生微信小程序页面梳理，2026-10-30。交付为视觉探索，不修改业务代码。设计图中的姓名、房间号、日期和分数均为演示数据。

## 视觉方向

沿用现有蓝白卡片与立体插画：钴蓝主操作、白瓷牌面、青绿牌背、局部浅绿桌面。麻将元素参与身份、状态和操作反馈；高频输入区域保持稳定、清晰。根据首页 V2 反馈，麻将主题仅用于麻将入口卡片及麻将内页；公共首页改用通用积分牌与正负分元素，取消大幅麻将主视觉。

另两个可选方向是保留现状只换插画（改动较小，但过程感弱），或全面改为深绿牌桌（氛围强，但偏离当前工具型界面）。本版建议采用局部牌桌方案，供用户评审。

| --- | --- | --- |

| 批量给分 | 保留三位收分者输入与合计；成功后记分棒飞向收分者 | 成功响应后 350ms，失败保留输入，不播放成功效果 |

| 结算结果 | 收牌完成后账单展开，金额与转账建议保持可读 | 同一结算首次进入约 400ms，重进直接展示 |

| 最近牌局 | 已结算记录呈白瓷账签，保留时间筛选、参与者、分页 | 每页卡片短暂错峰入列，总时长不超过 300ms |
| 加载／离线／空数据 | 加载用三张牌依次翻面；离线保留已有比分，提供重连；空记录用未写字的账签 | 加载低频循环；恢复后立即停止 |

## 交互约束

- 这是手动记分工具。不给用户暗示系统能够识别胡牌、计算番型、掷骰决定座位或自动判定赢家。
- 当前座位标记按加入顺序分配，视觉布局不得改变实际身份映射；积分排序与座位位置分别处理。
- 给分区不出现金额；房主在散场结算时设置每分金额，默认 1 元／分。
- 扫码与邀请链接只确认昵称；手动房间码加入仍需房间密码。
- 记分动画支持一次给多人，输入、合计和提交仍是当前批量流程。动画仅表达已确认结果，不延迟数据更新与后续操作。
- 不把记分棒设计成金币，不增加金钱爆炸、自动支付、虚构胜率或战绩成就。转账建议仍是建议。
- 昵称牌、分数和按钮不靠动效传递唯一信息；支持减少动态与低性能设备静态替代。声音、震动若后续加入，默认关闭，由用户选择。
- 图中的动效轨迹为静态示意，交互尚未实现；二维码为视觉占位，不用于真实入桌。

## 建议落地顺序

1. 优先做等人入座、给分成功反馈、分数更新：与实际动作联系最紧密。
2. 再补入口、创建、加入、结算的过渡与插画。
3. 最后统一个人中心、战绩、加载和空状态。
