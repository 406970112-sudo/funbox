跟做菜谱 · 教做菜

搜菜系，找喜欢的菜，看真实图片，按真实步骤炒出来

产品设计 V1 真实数据闭环 · 2026-08-02
STRATEGY

把"看美食"变成"做出来"

V1 解决一件事：用户从菜系或菜名进入，看到真实图片和食材，再按真实步骤完成一道菜。全程不出现编造内容。

真实数据原则

  • 图片、食材、步骤只来自真实数据源
  • 每条数据带来源、抓取时间与许可
  • 缺字段显示"暂无"，禁止 AI 补造
  • AI 只做搜索理解与文案摘要，不生成菜谱

核心闭环

搜索菜系 / 菜名 → 真实结果列表（图片 + 字段） → 详情页（食材 + 步骤 + 来源） → 购物清单勾选备菜 → 跟做模式逐条完成

页面范围

  • 发现、搜索、详情、跟做、购物清单
  • 我的厨房：收藏、做过、历史、偏好
  • 来源弹层、反馈、用户审核、离线缓存
  • 一期一次交付，不分期上线

SCREEN 01

菜系发现

菜系是入口，也是内容组织方式。

设计要点

  • 菜系横滑来自真实数据源，带真实菜谱数量
  • 菜卡展示真实图片、中文名、英文原名
  • 食材数、步骤数由真实字段计算
  • 每张菜卡带数据徽标，可点开查看来源

真实字段

菜系area
图片image.url
食材数ingredients.length
步骤数steps.length

交互说明

  • 输入菜名或食材，按搜索进入结果页
  • 点击菜卡进入详情页
  • 菜系点击后可按该菜系过滤
中文名来自人工映射词表 V1，菜谱正文、图片、食材以真实数据源原文为准。
SCREEN 02

搜索筛选

只返回真实数据池中的结果。

设计要点

  • 搜索在真实数据池执行，不调用 AI 生成结果
  • 筛选字段：菜系、分类、标签，全部来自真实字段
  • 排序含"步骤少""食材少"，由真实字段计算
  • 空态提示真实可尝试词，不填充假菜谱

真实字段

搜索q
菜系area
分类category
来源source

交互说明

  • 筛选只在当前结果池内生效
  • 点击结果卡进入详情页
  • 筛选后可重置
搜索结果数量与列表内容全部来自 08-02 数据快照，未手工增删。
SCREEN 03

菜谱详情

先确认可做性，再决定要不要动手。

设计要点

  • 大图来自真实图片来源，缺图显示占位
  • 食材名称与用量来自菜谱原文
  • 步骤预览展示前两步，完整步骤进入跟做
  • 来源卡片可打开原菜谱与视频

真实字段

食材ingredients[]
步骤steps[]
原菜谱recipeSource
视频videoUrl

交互说明

  • 开始跟做进入全屏步骤模式
  • 购物清单由真实食材自动生成
  • 信息有误可反馈，进入后台审核队列
一期不展示编造难度、时长、价格；缺字段显示"暂无"。
SCREEN 04

跟做模式

按做菜场景设计，手脏也能继续。

设计要点

  • 大字号步骤，每屏只放当前一步
  • 进度条与第 N 步 / 共 M 步明确
  • 上一步、下一步、朗读、退出并保存进度
  • 进入后请求屏幕常亮

真实字段

步骤原文steps[i]
进度session.stepIndex
朗读TTS 复用

交互说明

  • 步骤正文不做改写，仅按原文分段
  • TTS 失败时提示后继续
  • 原文含时间信息时照原文展示
一期不做没有真实来源的精确计时器和难度评分。
SCREEN 05

购物清单

备菜一次看清，少跑一趟。

设计要点

  • 清单由菜谱真实食材字段自动生成
  • 食材与用量一一对应，缺失用量只显示名称
  • 支持勾选已备、复制清单、分享文本
  • 不展示价格、商家与购买链接

真实字段

食材ingredients[].name
用量ingredients[].measure
菜谱dishId

交互说明

  • 勾选状态仅保存在本地会话
  • 复制为纯文本，便于发到任何聊天工具
清单内容与详情页食材完全一致，来源可追溯。
