# FunBox 智能商品推荐产品设计方案 V1

> 版本：V1 草案
> 日期：2026-08-01
> 状态：待评审
> 定位：把"买什么、为什么值得买、去哪买"三个问题，在一次推荐里回答清楚。

## 1. 背景与问题

用户想买手机时，常见的路径是先在搜索框里看参数，再跑去电商平台比价，最后还要自己判断哪一款更适合自己。整个过程信息分散、决策成本高，容易出现这几个问题：

| 现状 | 问题 |
| --- | --- |
| 搜索结果同质化 | 前几名推荐几乎一样，缺少按预算和使用场景的差异化 |
| 参数门槛高 | 芯片、屏幕、电池、影像等参数看不懂，也不知道和自己的需求有什么关系 |
| 推荐理由不透明 | 很多榜单只说"值得买"，不说清楚为什么值得 |
| 价格与链接分散 | 京东、淘宝、拼多多价格不同，用户要分别打开对比 |
| 决策后没有复盘 | 买贵了或买错了，没有地方反馈和沉淀 |

FunBox 已经具备 DeepSeek 能力（翻译、摘要、邮件代理共用 `DEEPSEEK_API_KEY`），可以低成本扩展出一个"智能商品推荐"工具，把需求理解、推荐理由、参考价格和购买链接串起来。

## 2. 对原始想法的补充

原始想法是"用户想买手机，就给推荐列表、理由、价格、购买链接"。在保留这个核心闭环的基础上，补充六点：

1. 先结构化需求，再推荐。用户一句话可以，但系统内部要解析出品类、预算、品牌偏好、使用场景、平台偏好，避免"推荐得热闹但不对路"。
2. 每条推荐必须带"为什么"。理由要落到具体参数或具体场景，例如"6550mAh 大电池，重度使用一天一充""骁龙 8 Elite，游戏高画质稳定 60 帧"。
3. 价格区分为"参考价"与"平台到手价"。参考价来自结构化商品库或联盟接口，展示时带价格快照时间和来源，不承诺实时最低价。
4. 购买链接统一聚合。每款商品给京东、淘宝、拼多多入口；V1 先放可配置链接，V2 接入联盟 API 自动生成。
5. DeepSeek 只负责理解和文案，不负责编造事实。商品参数、价格、链接全部来自结构化数据源；AI 输出需要引用商品库中的字段，未命中字段不生成理由。
6. 增加追问、对比、反馈闭环。用户可以说"再便宜一点""更看重拍照""和另一款比一下"，系统基于同一份数据重新生成推荐。

## 3. 产品目标与原则

### 3.1 产品目标

1. 用户从输入需求到看到推荐列表，目标在 10 秒内（DeepSeek 正常响应前提下）。
2. 推荐结果必须有可解释的理由，且理由可追溯到商品参数或平台价格。
3. 每个推荐商品至少提供一个可跳转的电商链接。
4. 支持同一需求下的一次对比和一次追问，形成轻量决策闭环。

### 3.2 设计原则

- 先事实、后观点：参数和价格来自数据源，观点由 DeepSeek 基于事实生成。
- 少而准：默认返回 3-5 款，不追求列满全部商品。
- 链接透明：标注平台和价格快照时间，不假装"全网最低价"。
- 轻量克制：不引入社区种草、自动下单等重运营能力。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 刚需消费者 | 想买手机/耳机/家电，预算明确 | 一句话输入，快速得到适合的几款和理由 |
| 参数小白 | 看不懂芯片、屏幕、电池差异 | 理由用"续航两天""游戏不卡"等结果语言表达 |
| 比价用户 | 想在不同平台买 | 同一商品聚合京东、淘宝、拼多多入口和参考价 |
| 犹豫用户 | 在两三款之间纠结 | 提供对比表和"为什么选它"的差异说明 |

首期建议只覆盖"手机、平板、耳机、电视、数码配件、小家电"这类标品，参数和价格都相对透明，适合做结构化推荐。

## 5. 产品结构

### 5.1 入口

- 工具注册名：`product-recommendation`
- 工具名称：智能商品推荐
- 分类：生活
- 路由：`/tools/product-recommendation`
- 入口图标建议：`shopping-bag-outline`
- 状态先按 `coming-soon` 注册，上线后切换为 `available`

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 需求输入页 | 品类、预算、品牌、场景、平台偏好，支持自然语言输入 |
| 推荐结果页 | 3-5 张推荐卡，含理由、参考价、平台链接、适合人群 |
| 商品详情页 | 完整参数、推荐理由、各平台价格与链接、购买注意事项 |
| 对比页 | 2-4 款商品并排对比核心参数与价格 |
| 追问结果页 | 在上一轮结果基础上调整预算/偏好，重新生成 |
| 历史记录 | 登录用户查看历史查询与收藏商品 |

## 6. 核心流程

```text
进入工具
  → 输入"想买手机，3000 左右"
  → 前端解析为：品类=手机，预算=2000-3000，偏好=待补充
  → 用户补充品牌/场景/平台偏好（可跳过）
  → 后端从商品库按预算和品类召回候选
  → DeepSeek 基于候选参数生成排序理由与文案
  → 返回推荐列表：名称、理由、参考价、平台链接
  → 用户点击平台链接跳转，或进入详情/对比/追问
```

## 7. 功能设计

### 7.1 需求输入页

- 顶部搜索框支持自然语言，例如"想买手机，预算 3000，主要打游戏"。
- 下方提供快捷标签，让不愿意打字的用户也能点选：品类、预算档、品牌、使用场景、平台偏好。
- 预算使用分段控件，品牌和场景使用多选 chips。
- 平台偏好默认"全部"，支持京东/淘宝/拼多多单选或组合。
- 输入为空时禁用生成按钮；输入过短时给出轻提示。

### 7.2 推荐结果页

每张推荐卡包含：

- 排名与"最推荐/高性价比/谨慎购买"等适配套签
- 商品名称、品牌、核心卖点一句话
- 参考价与价格快照时间
- 3 条推荐理由，每条带一个简短标签（性能/续航/影像/价格等）
- 京东、淘宝、拼多多三个平台入口，价格有差异时分别标注
- "适合谁"一行，帮助用户判断是否匹配

默认返回 3-5 款，按匹配度排序；排序算法由商品库评分 + DeepSeek 对需求理解共同决定。

### 7.3 商品详情页

- 商品主视觉、完整参数表（屏幕、芯片、内存、电池、影像、重量等）
- "为什么值得买"模块：每条理由对应一个参数卡片
- 平台比价模块：京东/淘宝/拼多多当前参考价与跳转按钮
- "购买前注意"：如版本差异、赠品口径、价格波动说明
- 收藏与分享

### 7.4 对比页

- 支持从推荐结果中选择 2-4 款进入对比
- 对比维度：价格、性能、屏幕、续航、影像、重量、适合人群
- 每个维度显示"胜出"标记，并给出简短解释
- 底部提供每款商品各自最便宜的平台入口

### 7.5 追问与调整

用户可以在结果页直接追问：

- "再便宜一点"：预算下限不变，上限下调
- "更看重拍照"：提高影像维度权重
- "不要曲面屏"：作为硬性过滤条件
- "和 XX 比一下"：把指定商品加入对比

追问沿用同一 queryId，方便后端做上下文续聊和历史归因。

### 7.6 历史与反馈

- 登录用户保留最近 20 条查询与收藏商品
- 推荐卡提供"有帮助/没帮助"反馈，用于校准排序
- 商品或价格失效时，用户可以点"报错"，进入后台审核队列

## 8. AI 与数据架构

### 8.1 DeepSeek 复用方式

- 复用后端现有 `DEEPSEEK_API_KEY`，即文字翻译使用的同一个 key。
- 复用 `config.DeepSeekConfig`：`BaseURL`、`Model`、`RequestTimeout` 保持一致，不新增前端 Key。
- 新增 `backend/internal/recommendation/` 模块，通过 Chat Completions 完成两件事：
  1. 将用户自然语言解析为结构化需求
  2. 基于候选商品的结构化数据生成排序理由和推荐文案
- DeepSeek 不可用时降级为规则推荐：按预算、品类、参数权重排序，理由改为"参数匹配"，并提示 AI 文案暂不可用。

### 8.2 商品数据源

| 阶段 | 数据源 | 说明 |
| --- | --- | --- |
| V1 | 结构化商品库（Seed/后台维护） | 每款商品维护参数、参考价、平台链接，首期内置 30-50 款常用机型/品类商品 |
| V2 | 京东联盟、淘宝联盟、拼多多多多进宝 API | 自动搜索、价格、链接与佣金字段 |
| V3 | 价格快照与提醒 | 定期抓取价格，支持降价提醒 |

V1 商品库字段必须包含：`productId`、`name`、`brand`、`category`、`price`、`specs`、`links`、`reviewNote`（可选）、`updatedAt`。

## 9. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/product-recommendation/query` | 提交需求，返回推荐列表；复用现有限流中间件 |
| GET | `/api/v1/product-recommendation/catalog?category=&q=` | 商品库搜索，用于补充候选和详情 |
| GET | `/api/v1/product-recommendation/queries/{queryID}` | 查询单次推荐结果 |
| POST | `/api/v1/product-recommendation/feedback` | 提交有帮助/没帮助/报错反馈 |
| GET | `/api/v1/product-recommendation/history` | 登录用户历史查询与收藏 |
| POST | `/api/v1/product-recommendation/watch` | 收藏商品，V1 可选 |

说明：

- 查询接口不强制登录，用 `withRateLimitedAPIPipeline` 限流；历史与收藏需要登录。
- DeepSeek 未配置时接口仍可返回规则推荐，响应中带 `ai: "fallback"` 标记。
- 所有价格字段带 `priceSource` 与 `updatedAt`，前端不自行声称实时价格。

## 10. 页面与交互设计

- 沿用 FunBox 现有视觉体系：浅蓝背景、白色表面、深色 `#151b3b` 重点、主色 `#4b6bff`。
- 价格与平台用少量强调色区分：京东红、淘宝橙、拼多多红/绿可做平台角标，但页面主体仍保持克制。
- 内容区最大 430px 移动宽度，宽屏居中；圆角不超过 16px，推荐大卡不超过 20px。
- 推荐理由用"标签 + 一句人话"的紧凑行，避免大段 AI 文本。
- 平台链接用图标 + 平台名按钮，点击后在新页面打开电商平台。
- 支持浅色与深色主题；320px、390px、430px 视口下文字不溢出、元素不重叠。

## 11. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| DeepSeek 超时/失败 | 降级为规则推荐，返回 `ai: "fallback"`，文案改为参数匹配说明 |
| 商品库无匹配 | 提示缩小或放宽条件，并提供相近品类 |
| 价格快照过期 | 标记 `stale`，展示"价格可能已变化"，仍可跳转平台 |
| 平台链接失效 | 卡片显示"链接待更新"，用户可点报错 |
| 用户输入过短 | 保留输入并给出一个示例，不生成推荐 |
| 敏感品类 | 药品、处方药、金融产品等不开放推荐 |

## 12. 分期实施

### M1 结构化推荐

- 商品库种子数据 30-50 款
- 需求解析 + 规则排序 + DeepSeek 理由生成
- 推荐结果页、商品详情页、平台链接跳转
- 有帮助/没帮助反馈

### M2 对比与追问

- 对比页、追问续聊、历史记录
- 商品库后台维护页
- 深色主题与收藏

### M3 联盟 API 与实时比价

- 京东联盟、淘宝联盟、多多进宝接入
- 自动搜索、价格刷新、链接生成
- 价格快照与过期标记

## 13. 成功指标

1. 一次推荐生成 p90 耗时不超过 10 秒。
2. 推荐理由可追溯到商品参数或平台价格，不展示无来源结论。
3. 推荐卡片平台链接可点击率 100%。
4. 用户对推荐"有帮助"反馈占比不低于 70%。
5. 从推荐卡跳转电商平台的比例不低于 25%。
6. 追问/对比功能使用率不低于推荐页访问量的 15%。

## 14. 明确不做

- 不承诺"全网最低价"或"绝对最优选择"。
- 不做自动下单、自动比价代购。
- 不引入达人种草、社区评分、虚假销量等不可验证内容。
- 不开放药品、处方药、金融、投资等敏感品类。
- V1 不做会员专属推荐和付费榜单。

## 15. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 联盟 API 资质 | V1 用维护式链接，V2 再申请联盟权限 | 上线周期可控，链接时效性依赖人工维护 |
| 价格波动 | 用价格快照 + 时间戳，不承诺实时 | 用户可能误以为价格错误，需文案引导 |
| 推荐立场 | 所有链接标注平台与来源，不做隐性付费排序 | 降低信任风险 |
| AI 幻觉 | 理由只允许引用商品库字段，未命中字段不生成 | 需要后端做字段级约束 |
| 品类扩展 | 首期只做标品 | 非标品参数不稳定，暂不开放 |
