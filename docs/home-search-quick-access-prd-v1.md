# FunBox 首页搜索直达产品设计方案 V1

> 版本：V1 草案  
> 日期：2026-08-02  
> 状态：待评审  
> 定位：把首页搜索从“过滤后仍需向下滚动”升级为“输入即见、点击即达”，结果完全来自真实工具注册表与真实可玩游戏。

## 1. 背景与问题

当前首页搜索框的职责是“过滤”：输入关键词后，匹配的工具仍排在“全部工具”网格中，位于今日推荐、最近使用之后；匹配的游戏则出现在更下方的“放松一下”板块。用户完成一次搜索，需要经历“输入 → 向下滚动 → 在网格中辨认 → 点击进入”四个动作。

由此产生四个问题：

1. 结果位置与搜索动作割裂：搜索框在顶部，结果却在页面中下部，用户第一眼看不到反馈。
2. 游戏结果可达性更差：“棋”“贪吃蛇”等关键词命中的游戏在最底部，容易被忽略。
3. 搜索反馈不完整：当前页面只有网格内的数量变化，没有“搜到了什么、为什么匹配”的即时解释。
4. 真实数据被网格截断：首页默认只展示 6 个工具，展开/收起按钮进一步增加寻找成本。

## 2. 设计目标与原则

### 2.1 核心目标

让用户输入关键词后，结果面板立即出现在搜索框下方，工具与游戏统一展示；点击任意一行直接进入对应路由，全程不需要滚动首页正文。

### 2.2 设计原则

1. 搜索即达：结果面板紧贴搜索框，一次点击完成跳转。
2. 真实数据：结果只来自真实功能注册表与真实可玩游戏，经过权限、状态、隐藏规则过滤，不出现假数据、mock 结果或硬编码热词。
3. 所见即所得：面板展示的每一项都真实存在且当前用户可访问，点击后路由可达。
4. 不破坏现有结构：全部工具、分类、最近使用、游戏板块在非搜索状态下保持现状；搜索时正文降低干扰。
5. 移动端优先，Web 同步可用：移动端点击直达，Web 端补充键盘操作。

### 2.3 非目标（V1 不做）

- 不做服务端搜索接口，V1 使用前端本地索引。
- 不做 AI 语义搜索、拼音/同义词纠错、模糊匹配。
- 不展示运营造词的“大家都在搜”“热门推荐词”。
- 不改变权限体系、底部导航、工具详情页和游戏详情页。
- 不新增后端接口；不新增静态 mock 数据文件。

## 3. 目标用户与核心场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 回访用户 | 记得工具名或大概功能，想一步进入 | 输入关键词后直接在面板点击进入 |
| 工具探索用户 | 只记得场景词，例如“压缩”“翻译” | 结果面板同时解释匹配来源，降低辨认成本 |
| 游戏用户 | 想快速开一局“五子棋”“象棋” | 游戏与工具混排展示，同样一步直达 |
| 权限受限用户 | 搜索到无权限或未上线能力 | 结果集合与首页可见集合一致，不出现“看得见进不去”的假入口 |

## 4. 信息架构与页面结构

### 4.1 默认首页结构（非搜索态，保持不变）

1. 品牌区：FunBox、副标题、能力计数。
2. 搜索框。
3. 今日推荐。
4. 最近使用。
5. 全部工具（分类 + 网格 + 展开）。
6. 放松一下（游戏横滑）。
7. 会员引导。
8. 底部导航。

### 4.2 搜索态结构（输入关键词后）

1. 品牌区。
2. 搜索框 + 紧跟其下的“搜索结果面板”。
3. 面板下方正文降级为辅助信息：今日推荐与最近使用隐藏，全部工具/游戏保留过滤结果，供“查看全部”承接。
4. 底部导航保持不变。

搜索态不新增页面，不新增 Tab；面板是首页的局部浮层。

## 5. 功能设计

### 5.1 搜索结果面板

#### 展示规则

- 搜索框聚焦且关键词非空时，面板立即出现在搜索框下方，与搜索框左右对齐。
- 面板宽度与搜索框一致，最大高度不超过 360px；最多展示 5 行结果，超出部分收进“查看全部”底栏。
- 面板包含三部分：
  - 结果区：工具与游戏混排，行高固定 56px。
  - 底栏：展示真实统计“N 个工具 · M 款游戏”，右侧为“在全部工具中查看”。
  - 选中态：Web 端键盘选择时行背景加深；移动端通过按压反馈表现。

#### 结果行内容

每行由五部分组成：

1. 图标：工具使用注册表 `icon` 与 `accentColor`，游戏使用游戏 `accentColor` 与玩法图形。
2. 名称：工具 `name` 或游戏 `name`，匹配关键词高亮。
3. 类型/分类：工具展示 `category`，游戏展示 `genre`。
4. 一句话摘要：工具展示 `tagline`，游戏展示 `description` 或 `genre` 摘要，单行省略。
5. 右侧箭头：进入对应 `route`。

#### 底栏“在全部工具中查看”

- 点击后收起面板，自动滚动到正文“全部工具”区块，并自动展开完整结果网格。
- 关键词同步保留在搜索框中，正文过滤结果与面板统计完全一致。
- 搜索结果只有 1-5 条时，底栏仍展示真实数量统计，便于用户确认覆盖范围。

### 5.2 初始态与空输入

- 搜索框聚焦但未输入时，不展示空面板。
- 若本地存在最近使用记录（工具或游戏），聚焦时展示最多 3 条“快速直达”，数据来自真实 `tool-usage` / `recent-usage` 存储；无记录时不展示。
- 清空关键词后立即恢复默认首页，不保留搜索态残留。

### 5.3 点击跳转与数据记录

- 点击工具结果：记录 `tool-usage`，然后 `router.push(tool.route)`。
- 点击游戏结果：记录 `recent-usage`，然后 `router.push(game.route)`。
- 记录失败不影响跳转。
- 从结果页返回首页时，最近使用按现有逻辑刷新。

### 5.4 键盘操作（Web）

- `↑` / `↓`：在面板结果行间移动选中项。
- `Enter`：进入当前选中项路由。
- `Esc`：收起面板，焦点留在搜索框。
- 点击页面其他区域：收起面板。
- 面板保留正确的无障碍语义：输入框 `accessibilityLabel`、结果行 `accessibilityRole="button"`、选中态 `accessibilityState`。

### 5.5 正文联动

- 面板打开时，正文“今日推荐”和“最近使用”自动隐藏，避免与结果面板竞争注意力。
- 正文“全部工具”和“放松一下”继续按同一关键词过滤，作为“查看全部”的承接区域。
- 面板关闭或清空关键词后，正文恢复默认结构。
- 分类筛选不与面板叠加：进入搜索态后分类临时忽略，面板覆盖所有可见工具与游戏；退出搜索态后恢复原分类。

## 6. 搜索数据契约与真实性保障

### 6.1 数据源

搜索索引只由以下真实数据构成：

| 类型 | 数据源 | 过滤条件 |
| --- | --- | --- |
| 工具 | `backend/internal/access/feature_registry.json` 经 `frontend/mocks/app-data.ts` 装载 | `route` 以 `/tools/` 开头；`status === "available"`；`hiddenFromList !== true`；当前角色可见 |
| 游戏 | `frontend/mocks/app-data.ts` 的 `popularGames` | `status === "playable"`；当前角色可见 |

`feature_registry.json` 是功能的唯一事实源，`frontend/mocks/app-data.ts` 只是装载模块，不新增任何造数。

### 6.2 搜索字段

- 工具：`name`、`tagline`、`description`、`badges`、`category`。
- 游戏：`name`、`genre`、`description`、`tag`。
- 匹配方式：大小写不敏感的子串包含，空格按整体关键词处理。

### 6.3 禁止项

- 不出现注册表中不存在的工具或游戏。
- 不出现 `status !== "available"` 的工具与 `status !== "playable"` 的游戏。
- 不出现 `hiddenFromList: true` 的子入口（例如双色球概率参考、双色球历史开奖记录等），保持与首页列表一致的隐藏规则；这些能力仍通过可见的“双色球”统一入口访问。
- 不出现当前用户无权限的项。
- 不展示手工维护的搜索建议词、热词或运营占位。

### 6.4 权限一致性

- 面板结果集合 = 首页“全部工具”可见集合 + “放松一下”可玩游戏集合，复用 `useFeatureAccess` 的 `visibleTools` / `visibleGames`。
- 权限加载中或失败时，不单独构造结果，沿用现有 fallback 角色逻辑。

## 7. 排序规则

结果按以下优先级稳定排序，不做人工置顶：

1. 名称精确等于关键词。
2. 名称以关键词开头。
3. 名称包含关键词。
4. 标签、一句话说明、描述或分类包含关键词。
5. 同一层级内：最近使用/点击次数高者优先；其余按注册表原始顺序。

示例：输入 `AI` 时，“AI 导航”排在“热点速览”“智能翻译”之前，因为它们名称命中；输入 `棋` 时，“中国象棋”“五子棋人机对战”排在名称只部分命中的其他内容之前。

## 8. 视觉与组件规范

- 搜索框沿用现有 `searchShell`：高 42px、圆角 14px、白底、1px 边框。
- 面板：白底、1px 边框、圆角 14px、投影沿用现有 `colors.shadow`；与搜索框间距 6px。
- 结果行：高 56px，图标 34px，圆角 10px；名称 13px 粗体，摘要 11px；类型徽章 10px。
- 匹配关键词高亮：`#f5d76e` 浅黄底或主题 `primarySoft`，保持可读性。
- 底栏：高 40px，上边框 1px，统计文字 11px，右侧入口 12px 主色。
- 主题：浅色/深色均从现有 `appTheme` 取色；不新增一套配色。
- 布局：内容区最大宽度 430px，左右边距 16px；面板与正文统一对齐。

## 9. 状态与异常处理

| 状态 | 行为 |
| --- | --- |
| 关键词无匹配 | 展示空态：图标 + “没有找到与「X」匹配的工具或游戏”；提供“清空关键词”与“在全部工具中查看”两个真实操作，不展示假热词 |
| 快速连续输入 | 本地过滤成本低，使用 `useDeferredValue` 保持输入流畅，不需要网络防抖 |
| 权限尚未就绪 | 不展示结果面板，避免出现无权限假入口 |
| 点击记录失败 | 静默忽略，不影响跳转 |
| 超长关键词 | 面板行名称/摘要单行省略，空态文案完整展示关键词 |
| 面板打开时返回上一页 | 返回首页后搜索态不保留，恢复默认首页 |

## 10. 埋点与验收标准

### 10.1 建议埋点

- `home_search_focus`：搜索框聚焦。
- `home_search_query`：关键词变化（含长度与结果数）。
- `home_search_result_click`：结果点击（含工具/游戏、排名、是否最近使用）。
- `home_search_no_result`：空结果曝光。
- `home_search_view_all`：“在全部工具中查看”点击。

### 10.2 验收标准

- 输入关键词后，面板在搜索框下方直接出现，无需滚动。
- 面板中每一项都来自真实数据源，且与当前权限、状态、隐藏规则一致。
- 点击任意结果行后进入对应真实路由。
- 搜索结果统计“N 个工具 · M 款游戏”与正文过滤结果数量一致。
- Web 端支持键盘上下选择、回车直达、Esc 关闭。
- 清空关键词后首页恢复原状；无结果时展示真实空态。
- 新增单元测试覆盖排序、过滤、数据真实性，现有首页与工具目录测试不回归。

## 11. 技术实现建议

### 11.1 新增模块

- `frontend/lib/home-search.ts`：定义 `SearchEntry`、`searchHomeEntries(tools, games, query, recentUsage)`、`rankHomeEntries`，输出稳定排序。
- `frontend/tests/home-search.test.mjs`：使用真实注册表数据断言：结果 id 全部存在、无隐藏/无权限/无未上线项、排序与高亮位置正确、空态分支正确。

### 11.2 首页改造

- `HomeScreen` 增加 `searchFocused`、`selectedSearchIndex` 状态。
- 搜索结果面板组件复用现有 `ToolTile`/`GameTile` 的视觉元素，但不复用网格布局。
- 面板结果与正文过滤共用同一个 `searchHomeEntries` 结果，保证数量一致。
- 搜索态下隐藏今日推荐与最近使用区块。

### 11.3 不做的事

- 不新增后端接口、不新增数据库表。
- 不引入新依赖。
- 不改动 `feature_registry.json` 的字段结构；如需补充游戏字段，直接增强现有真实数据，而不是另建 mock 数组。

## 12. V2 扩展（暂不做）

- 服务端搜索接口与聚合索引，支持跨设备一致排序。
- 拼音、同义词、英文别名与轻量纠错。
- 基于真实点击埋点的“最近搜索”和个性化排序。
- 将 `hiddenFromList` 子入口纳入搜索，但需展示明确的父子归属关系。
- 运营可配置搜索直达位，内容必须来自真实上架能力。
