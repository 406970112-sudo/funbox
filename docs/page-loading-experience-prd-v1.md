# FunBox 页面加载体验优化产品设计方案 V1

> 版本：V1 草案
> 日期：2026-08-02
> 状态：待评审
> 定位：从首页点击进入功能页时，消灭“白屏/空白等待”，统一页面打开、加载、失败与空数据四种体验；所有内容只来自真实功能、真实接口与真实本地数据，不引入 mock 或假数据。

## 1. 背景与问题

### 1.1 用户反馈

用户从首页点击部分功能页时，会看到接近全白的空页面，且没有加载过渡，体验像是“页面卡死或没打开”。

### 1.2 现象核验

对用户反馈截图做像素分析：全图 99.8% 像素为浅色背景（亮度 192-255），没有任何深色文字块，确认是“只有页面背景、没有内容、没有加载反馈”的空白状态，而不是深色主题或内容截图。

### 1.3 代码排查结论

现有代码中已经存在零散的加载处理，但形态不统一、覆盖不完整，主要有五类根因：

1. 路由转场首帧无统一背景。功能页路由虽然配置了 `slide_from_right` 等转场，但目标页在组件与数据就绪前，屏幕上只有页面背景色；部分页面在转场瞬间没有“页面正在打开”的视觉，用户看到的是一块空白。
2. 通用启动加载页被复用为页面加载态。`ToolDetailScreen` 与 `GameDetailScreen` 在权限状态为 loading 时直接返回 `AppLoadingScreen`，文案是“正在准备 FunBox / 正在加载图标与界面资源”，用户从首页进入功能页时像重新启动 App，且该组件在 Web 首帧也可能先渲染空白。
3. 各功能页加载态不统一。目前热点速览有列表骨架，资源搜索有来源列表骨架，市场雷达有居中转圈，日记本、效率清单是居中转圈，翻译/打牌记分等工具直接渲染工作台；用户看到的反馈完全不同，部分页面在慢网络下仍会出现较长时间的空白区。
4. 真实接口慢、失败与空数据缺少统一反馈。热点速览、市场雷达、资源搜索、免费阅读、朋友圈等依赖真实后端或第三方数据源；接口慢时没有统一进度反馈，失败时部分页面只有小字提示，容易被误认为白屏卡死；空数据场景也没有统一空态。
5. Web 路由懒加载存在白闪。首次进入某个功能页时，路由代码块与页面组件需要加载；在代码块就绪前，页面区域可能保持空白，尤其是首次点击、弱网或缓存被清空时。

### 1.4 问题分级

| 优先级 | 问题 | 影响 |
| --- | --- | --- |
| P0 | 转场/加载首帧出现纯白或接近纯白区域 | 用户认为页面没打开 |
| P0 | 权限加载复用“启动 App”文案 | 语义错误，放大焦虑 |
| P1 | 各页加载态形态不一致 | 缺乏统一心智，反馈不可预期 |
| P1 | 接口失败/空数据反馈弱 | 无法恢复，误判为卡死 |
| P2 | 首次进入路由懒加载白闪 | 首次体验差 |

## 2. 设计目标与原则

### 2.1 核心目标

任何一次从首页进入功能页，从“手指按下”到“真实内容可见”全程都有明确反馈：按压反馈、转场动画、页面骨架、内容淡入；任意时刻都不允许出现纯白空白区域。

### 2.2 设计原则

1. 永不白屏：目标页在数据就绪前必须渲染“页面容器 + 标题 + 骨架或状态”，页面容器始终使用主题背景色，不允许透明或纯白占位。
2. 真实数据：页面内容、标题、数量、来源说明全部来自真实功能注册表、真实接口结果和真实本地存储；任何加载、失败、空态都不允许用 mock 数据或硬编码假内容填补。
3. 状态可预期：每个页面只有五种状态：打开中、加载中、内容、错误、空数据；同一状态在不同页面使用同一套视觉语言。
4. 内容渐进呈现：骨架屏展示真实页面结构，数据就绪后内容淡入，避免内容突变闪烁。
5. 失败可恢复：错误态提供真实错误原因、重试与返回操作；刷新时保留旧内容，不整屏变白。
6. 一期完整交付：本方案所有能力一次完成，不分期、不预留半成品状态。

## 3. 目标用户与核心场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 高频工具用户 | 从首页快速进入打牌记分、热点速览、市场雷达 | 点击后有明确反馈，页面骨架与最终结构一致，数据一到立即可用 |
| 探索型用户 | 首次点击免费阅读、AI 导航、资源搜索 | 即使路由首次加载也能看到页面标题与骨架，不出现白屏 |
| 弱网/接口异常用户 | 热点、市场、资源搜索接口变慢或失败 | 看到统一加载进度与真实失败原因，可重试，不误判为卡死 |
| 空数据用户 | 新用户进入朋友圈、书城、效率清单 | 看到真实空态与可操作动作，不用假内容填充 |
| 无障碍用户 | 开启减少动态效果或系统字体放大 | 保留静态骨架、状态文本与可读性，动画不影响使用 |

## 4. 整体体验模型

每个功能页统一采用五态模型：

```text
首页点击 -> 打开中（转场 + 页面容器） -> 加载中（骨架 + 进度）
                                          |-> 内容（真实数据淡入）
                                          |-> 错误（原因 + 重试 + 返回）
                                          |-> 空数据（真实空态 + 动作）
```

关键规则：

- “打开中”从路由开始切换时出现，时长与转场动画一致（约 220-320ms），期间显示页面标题与背景，禁止白屏。
- “加载中”是主状态，数据未就绪时使用与页面真实结构一致的骨架屏。
- “内容”必须来自真实数据；内容就绪后骨架淡出、内容淡入。
- “错误”和“空数据”都是终态，必须有明确操作，不允许自动用假数据填充。
- 返回首页、重试、刷新都不清空页面容器背景。

## 5. 功能设计

### 5.1 首页点击反馈与路由预取

#### 按压反馈

- 首页工具卡、游戏卡、推荐卡与搜索结果的点击反馈统一为现有 `pressed` 按压态（降透明度 + 轻微缩放），并增加移动端轻触震动（已启用 Haptics 的平台）。
- 点击后立即记录真实使用记录（沿用 `tool-usage` / `recent-usage`），记录失败静默，不影响跳转。

#### 路由预取

- 首页渲染完成后，对可见区域内的功能路由发起轻量预取（Web 使用浏览器 prefetch 或动态 import 预热代码块；原生端预载对应路由组件）。
- 预取只加载真实路由与真实页面模块，不加载任何 mock 数据；预取失败不阻塞点击。
- 用户点击时若路由已预热，转场首帧直接显示页面标题与骨架。

### 5.2 页面容器与转场统一

- 所有功能页（工具、游戏、阅读、社交、个人中心子页）统一在页面容器层设置主题背景色（浅色 `#eef4ff`、深色 `#0f1317`），任何子组件未就绪时都渲染容器背景，杜绝透明/纯白首帧。
- 所有功能页统一使用 `slide_from_right` 转场；进入动画结束后，页面内容已处于“打开中”或“加载中”状态。
- 转场期间底部 Tab 与页面背景保持可见，避免整屏黑/白过渡。

### 5.3 PageLoadingFrame 统一加载框架

新增统一加载框架，由三部分组成：

1. 页面头部：返回按钮 + 真实功能名 + 一句“正在打开/正在加载”的状态说明。
2. 顶部进度条：2px 高度，使用主题 primary 色；仅在加载真实数据时出现，数据就绪后消失。
3. 骨架屏：按页面真实结构生成，禁止使用与最终内容无关的随机占位。

#### 四种骨架模板

| 模板 | 适用页面类型 | 骨架内容 | 真实页面示例 |
| --- | --- | --- | --- |
| 列表类 | 信息流、列表、搜索 | 顶部摘要卡 + 6-8 行“缩略图 + 两行文字”列表 | 热点速览、资源搜索、免费阅读书城、朋友圈 |
| 工作台类 | 表单、工作台、工具 | 顶部标题 + 2-4 个功能卡 + 表单行 | 打牌记分、智能翻译、文字转语音、图片压缩、JSON 工作台、发版邮件助手 |
| 数据面板类 | 行情、图表、数据 | 顶部摘要卡 + 2-3 个指标块 + 图表块 | 市场雷达、双色球、跟做菜谱结果 |
| 沉浸类 | 游戏、阅读器、识别器 | 顶部标题 + 大面积主视觉块 + 底部操作条 | 贪吃蛇、象棋、阅读器、图片压缩预览 |

#### 骨架使用规则

- 页面首次进入且无缓存时显示骨架，最小展示时长 350ms，避免快速接口导致骨架闪一下。
- 骨架结构与真实页面内容区域一一对应，尺寸使用真实布局参数（行高、卡片宽度、间距），不随机变化。
- 页面头部必须显示真实功能名，禁止显示“FunBox 正在启动”等 App 级文案。

### 5.4 内容就绪淡入

- 真实数据就绪后，骨架淡出（150ms）、内容淡入（300ms），两者通过同一 Animated 序列完成，不允许内容区域先变空白再出现内容。
- 淡入期间页面可交互；用户快速点击返回不等待动画完成。
- 数据量较大的页面（热点列表、书城、朋友圈）首次只渲染首屏真实数据，滚动时继续加载，不整页等待全量数据。

### 5.5 错误态与空态

#### 错误态 PageErrorState

错误态由五部分组成：

1. 图标：使用与功能主题色一致的 MaterialCommunityIcons 图标。
2. 标题：固定文案“加载失败”。
3. 原因：展示真实错误信息（接口错误码/超时/权限/来源不可用），不做包装成假成功。
4. 操作：主按钮“重试”，副操作“返回首页”。
5. 保底：如果接口超时，页面显示“接口响应超时，请检查网络后重试”，并保留 8 秒超时兜底。

错误态不允许出现：

- 用缓存中的假数据、示例数据或默认内容假装成功；
- 只显示一条小字提示而无操作；
- 空白页面等待用户手动刷新。

#### 空态 PageEmptyState

空态用于真实空数据场景：

1. 图标 + “暂无内容”标题 + 一句真实说明（如“还没有发布过动态”“书架还没有图书”）。
2. 一个可执行动作（“去发布”“去导入”“去添加”）。
3. 空态数据判断必须来自真实接口或真实本地存储的返回结果，不得通过判断时间、随机数等方式制造空数据。

### 5.6 刷新、重试与缓存

- 下拉刷新或手动刷新时，保留当前真实内容，顶部显示细进度条；刷新失败保留旧内容并在内容区顶部显示可关闭的错误条。
- 重试时从“加载中”骨架开始，不保留失败页半透明叠加。
- 真实接口成功结果支持二级缓存：内存缓存优先，必要时使用 `AsyncStorage` / Web `localStorage`；缓存只保存真实接口结果，并记录 `updatedAt`。
- 二次进入同一功能页：缓存有效期内直接展示真实缓存内容（可见“更新时间”），同时后台刷新；缓存过期或无缓存时显示骨架。
- 涉及账户、支付、实时会话等敏感页面不做内容缓存，只缓存页面模块代码。

### 5.7 无障碍与减少动态效果

- 系统开启“减少动态效果”时：关闭按压缩放、转场位移、骨架闪烁与淡入动画，保留静态骨架、状态文本与背景色。
- 所有状态卡片保留可读对比度与完整文本；加载中状态提供 `accessibilityLiveRegion` 播报“正在加载 XX”。
- 支持系统字体放大；骨架高度按文本行高自适应，不允许文字溢出或覆盖。

## 6. 真实数据保障

1. 页面标题、图标、副标题来自 `backend/internal/access/feature_registry.json`（真实功能注册表）或对应页面的真实配置，不新增文案表。
2. 骨架屏只表达真实结构，不渲染具体内容；内容区展示的每条数据必须来自真实接口或真实本地存储。
3. 热点、市场、资源搜索、阅读、朋友圈、日记、效率清单等数据页面，一律使用现有真实接口；接口失败只能展示错误态，禁止 fallback 到 mock。
4. 缓存层只缓存真实接口响应；缓存命中时页面仍显示真实“更新时间”。
5. 不新增任何 mock 数据文件；`frontend/mocks/app-data.ts` 只保留“加载真实注册表”的角色，不增加新造数据。
6. 验收阶段用真实后端与真实数据源执行全页面检查，截图与像素检测结果作为交付证据。

## 8. 视觉与组件规范

- 颜色全部来自现有 `appTheme`：背景 `background`、表面 `surface`、弱表面 `surfaceMuted`、线条 `line`、主色 `primary`、主色浅底 `primarySoft`、错误沿用现有错误色（如 `#d6455d`）。
- 骨架块使用 `surfaceMuted` 填充、`line` 描边，圆角 8-12px；禁止使用渐变或彩色骨架。
- 顶部进度条高 2px、圆角 1px、使用 `primary`，位于页面头部下方。
- 页面头部沿用现有 `PageHeader`：返回按钮、标题 28px 粗体、副标题 14px；加载时副标题替换为“正在打开/正在加载”状态文案。
- 内容区最大宽度 430px，左右边距 16px，与首页一致；Web 宽屏居中。
- 错误态主按钮使用 `primary` 底白字，返回首页为文字按钮；空态动作按钮使用 `hero` 深底 + `#c9f36a` 图标风格，与现有会员/空态按钮一致。
- 转场统一 `slide_from_right`，时长保持系统默认 320ms 以内；减少动态效果时关闭。

## 9. 状态与异常处理

| 状态/异常 | 行为 |
| --- | --- |
| 路由首次加载 | 页面容器 + 真实标题 + “正在打开”文案，背景为主题色 |
| 接口加载中 | 对应骨架模板 + 顶部进度条 |
| 接口快速返回（<350ms） | 骨架保底展示 350ms，避免闪烁 |
| 接口失败 | 错误态：图标 + “加载失败” + 真实原因 + 重试 + 返回首页 |
| 接口超时（8s） | 错误态提示“接口响应超时”，提供重试 |
| 数据为空 | 空态：真实说明 + 可执行动作 |
| 下拉刷新 | 保留真实内容 + 顶部进度条；失败保留旧内容 + 错误条 |
| 重试 | 从“加载中”骨架重新开始 |
| 二次进入 | 命中真实缓存直接展示内容与更新时间，后台刷新 |
| 减少动态效果 | 关闭动画，保留静态骨架与文本 |
| 权限加载 | 显示目标页面的“正在打开”加载态，不再复用 App 启动文案 |

## 10. 埋点与验收标准

### 10.1 建议埋点

- `page_open`：功能页打开，含路由、来源、首帧耗时。
- `page_first_paint`：首帧内容非空时间。
- `page_content_ready`：真实数据就绪时间。
- `page_load_error`：加载失败，含错误类型与路由。
- `page_blank_detect`：像素检测发现大面积空白时上报（可先本地检测）。

### 10.2 验收标准

1. 以 390x844 视口逐页检查：点击进入后 0ms、120ms、350ms、1s、3s 五个时间点，页面均非空白，浅色页面白色像素占比不高于背景本身的占比。
2. 所有功能页在“无后端”与“慢网络”条件下均显示骨架或错误态，不允许出现纯白屏。
3. 加载/错误/空态文案与真实功能名一致；页面内容全部来自真实数据，截图内不出现 mock 或示例占位。
4. 任意页面均可在 8 秒超时后看到错误态并可重试；重试后进入加载态。
5. 二次进入同一页面展示真实缓存内容与更新时间，后台刷新后内容更新。
6. 浅色、深色、字体放大、减少动态效果四种场景通过视觉检查。
7. 新增单元测试覆盖：页面加载状态机、骨架模板选择、错误/空态判定、缓存真实数据更新时间，现有首页与功能页测试不回归。
8. 新增 Playwright 全页面巡检：逐页点击、截图、像素检测、控制台错误为零。

## 11. 技术实现建议

### 11.1 新增模块

- `frontend/shared/ui/page-loading-frame.tsx`：统一加载框架（头部 + 进度条 + 骨架模板）。
- `frontend/shared/ui/page-loading-skeleton.tsx`：四种骨架模板组件。
- `frontend/shared/ui/page-error-state.tsx` 与 `page-empty-state.tsx`：统一错误态与空态。
- `frontend/shared/ui/use-page-load-state.ts`：页面加载状态机（opening / loading / ready / error / empty）与 8 秒超时、最小展示时长、内容淡入。
- `frontend/lib/real-data-cache.ts`：真实接口结果缓存（内存 + AsyncStorage/Web localStorage），记录 `updatedAt`。
- `frontend/lib/route-prefetch.ts`：首页可见路由预取与预热。

### 11.2 页面改造

- `ToolDetailScreen`、`GameDetailScreen`：权限 loading 改为目标页“正在打开”加载态，移除 `AppLoadingScreen` 复用。
- 数据页：接入 `usePageLoadState`，首次加载使用对应骨架模板，数据就绪淡入。
- 首页：点击反馈 + 路由预取 + 可见区预热。
- 路由层：功能页统一背景色与 `slide_from_right` 转场。

### 11.3 不做的事

- 不新增 mock 数据文件，不修改 `feature_registry.json` 字段结构。
- 不引入新的第三方 UI 库或动画库。
- 不改动真实业务接口与权限体系。
- 不把任何功能拆成二期，全部在本期完成。
