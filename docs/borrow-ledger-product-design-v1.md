# 借还记录 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 定位：FunBox 移动端"临时借还记录"工具，本期一次交付全部核心能力，不拆分二期。

## 1. 产品概述

### 1.1 一句话定位

"借还记录"把"谁借了我什么、什么时候还、要不要提醒"收进一个轻量记录中心，覆盖我借出、我借入、公司领用和代付垫付，所有人员、物品、金额、日期和提醒都来自用户真实录入，提醒卡也由真实记录自动生成。

### 1.2 解决的问题

- 借给同事的充电器、借给朋友的钱、借出去的书，时间一长就忘了是谁、借了多久。
- 借用的会员账号、公司领用的设备，归还状态没有地方记录，容易漏还或不好开口问。
- 朋友或同事帮自己垫付费用后，只靠口头约定，结清状态和金额没有可查证记录。
- 想提醒对方时不知道怎么说，容易显得催得很急；产品需要提供轻松、不施压的提醒文案。
- 已有"物品在哪里"解决的是"东西放在哪"，不能表达"谁在用、什么时候还、有没有结清"。

### 1.3 与 FunBox 现有能力的衔接

- 复用首页工具目录、底部 Tab、主题色、SurfaceCard、PageHeader 等现有视觉与导航组件。
- 复用首页搜索：输入"借还""借出""借入""归还""充电器""书""会员账号""垫付""还钱"等关键词可模糊匹配到本功能。
- 登录后直接选择真实好友，复用现有 `GET /api/v1/friends` 好友数据；未登录或非好友场景支持手动输入真实称呼。
- 复用账号体系、JWT、SQLite、AsyncStorage / Web localStorage 与现有本地优先同步模式。
- 沿用现有真实数据产品原则：首启为空，不预置任何 mock 记录、mock 好友、mock 物品或 mock 提醒。

## 2. 真实数据原则（硬性要求）

1. 首次进入"借还记录"不展示任何预置借还记录、人员、物品、金额、日期或提醒，全部为空态。
2. 人员必须是用户现有真实好友，或用户手动输入的真实姓名/称呼；不允许内置"小明""小红"等示例人员。
3. 物品名称、金额、平台、账号名、备注必须由用户真实录入，不允许自动补全、推算或编造。
4. 会员账号类只记录平台、账号名/昵称和备注，不存储密码、验证码、登录态或其他敏感凭证。
5. 提醒卡只能由用户已保存的真实记录字段生成，不允许凭空生成"几天前""逾期""请归还"等结论。
6. 天数、逾期、金额、统计都由真实时间或真实金额计算，服务端不返回虚假计数。
7. 设计稿中出现的姓名、物品与金额仅用于表达"录入后"界面，正式产品首启为空。

## 3. 目标用户与场景

| 场景 | 用户行为 | 产品应满足 |
| --- | --- | --- |
| 借给同事充电器 | 随手借出，几天后想确认 | 10 秒内记录人员和物品，到期前给轻提醒 |
| 借给朋友钱 | 借出现金，怕忘记金额和日期 | 记录金额、币种、借出日期，可标记已还 |
| 借出去的书 | 书被借走，不记得归还时间 | 记录书名和借出时间，生成轻松提醒卡 |
| 借用会员账号 | 朋友/家人借用自己的会员账号 | 只记录平台和账号名，不保存密码，到期提醒归还 |
| 公司领用设备 | 从公司行政领用笔记本、工牌等 | 记录"我借入"和负责人，标记归还 |
| 代付垫付 | 同事帮自己垫付餐费、打车费 | 记录谁垫付、金额、结清状态，生成致谢/结清提醒 |

## 5. 核心功能设计

### 5.1 记录方向与状态

本期一次交付三种记录方向：

1. 我借出：对方借走了我的物品、钱或会员账号。
2. 我借入：我借用了对方的物品、公司设备或会员账号。
3. 垫付费用：对方帮我垫付了费用，我需要结清。

状态由用户真实操作和真实时间派生，不允许手动造状态：

| 方向 | 进行中 | 已完成 | 逾期 |
| --- | --- | --- | --- |
| 我借出 | 未归还 | 已归还 | 未归还且超过约定归还日期 |
| 我借入 | 未归还 | 已归还 | 未归还且超过约定归还日期 |
| 垫付费用 | 待结清 | 已结清 | 待结清且超过约定结清日期 |

### 5.2 人员选择

- 已登录用户点击"谁"后，优先展示当前账号的真实好友列表，支持按昵称或账号搜索。
- 好友数据来自现有好友接口，不展示非好友、不内置演示账号。
- 未登录或对象不是好友时，支持手动输入真实姓名/称呼，长度 1-20 个字符。
- 公司、物业等非个人对象也可手动输入"公司行政""同事小王"等真实称呼。
- 已保存记录保存人员快照，好友改名或删除好友后不影响历史记录真实性。

### 5.3 标的物与金额

标的物类型：

| 类型 | 必填字段 | 说明 |
| --- | --- | --- |
| 物品 | 物品名称 | 1-60 字，例如"充电器""JavaScript 高级程序设计" |
| 金额 | 金额、币种 | 金额大于 0，默认 CNY，支持用户选择真实币种 |
| 会员账号 | 平台、账号名 | 平台 1-30 字，账号名 1-80 字，不保存密码 |

规则：

- 物品名称、平台、账号名自动去首尾空格，空内容不允许保存。
- 金额最多两位小数，不允许负数；币种为展示字段，不做实时汇率换算。
- 垫付费用和借出/借入金额的"已还/已结清"状态，只由用户点击操作改变。
- 账号类字段只用于提醒和识别，不提供密码保存、复制或自动登录能力。

### 5.4 日期与提醒

#### 日期字段

- 借出/借入/垫付日期：必填，默认今天，不晚于今天。
- 约定归还/结清日期：选填，可晚于今天或早于今天。
- 归还/结清日期：由"标记归还"或"标记已结清"写入真实操作时间。

#### 提醒规则

- 每条记录可单独设置"不提醒 / 提前 1 天 / 提前 3 天 / 提前 7 天 / 到期当天 / 逾期后每天一次"。
- 提醒只在存在约定日期且记录未完成时生成。
- 首页提醒卡只展示用户真实设置过提醒的记录，未设置提醒的记录不出现。
- 系统通知可关可开，默认跟随 App 通知设置；即使关闭通知，功能内提醒卡仍保留。

### 5.5 提醒卡

提醒卡是核心表达层，文案必须由真实记录生成：

```text
我借出 · 物品
你在 12 天前借走了我的《JavaScript高级程序设计》，
方便的话这周带给我吧。
借出时间：2026-07-25 · 已借 12 天 · 约定 2026-08-02 归还
```

```text
垫付费用
谢谢你上次帮我垫付的 120 元，
我这边已经记下，方便时转给你。
垫付时间：2026-07-30 · 已 7 天 · 金额 120 元
```

规则：

- "12 天""7 天"等天数由借出日期与当前日期计算，不写死。
- 已逾期文案使用"方便的话""不着急""随时告诉我"等轻松语气，不出现威胁、催收或情绪化表达。
- 支持"轻松 / 简短 / 正式"三种语气模板；语气只改变措辞结构，不改变事实字段。
- 支持复制提醒卡文本和分享给好友，分享内容只包含用户已录入的真实字段。
- 会员账号记录生成提醒卡时，只出现平台和账号名，不出现任何凭证信息。

### 5.6 搜索、筛选与历史

- 搜索范围：人员姓名、物品名称、平台、账号名、金额、备注。
- 筛选：方向（我借出/我借入/垫付费用）、状态（进行中/已完成/已逾期）、类型（物品/金额/账号）、时间范围。
- 历史按时间倒序分组，已完成记录默认折叠，可展开查看完整快照。
- 最近搜索只来自用户真实搜索词，最多保留 10 条，可清空。
- 清空全部记录需要二次确认，并提示"该操作不可恢复"。

### 5.7 持久化与账号

- 本机为第一数据源：记录写入 AsyncStorage / Web localStorage。
- 未登录用户可完整使用，数据保存在当前设备。
- 登录用户进入时自动从账号拉取并合并到本机，修改后自动同步到账号。
- 同一账号多设备以 `updatedAt` 为准做最后写入覆盖，并在界面提示同步状态。
- 借还记录属于个人隐私数据，不进入公开资料、社交动态或排行榜。

## 7. 交互细节与状态

### 7.1 页面状态

- 加载态：读取本机与账号数据期间显示现有 PageLoadingFrame 工作台样式。
- 空态：无记录时显示空态引导，不出现占位假数据。
- 错误态：同步失败时保留本机真实数据，顶部提示"同步失败，已使用本机数据"，不阻断录入。
- 保存态：保存按钮进入加载态，成功后返回并轻提示"已保存真实记录"。
- 完成态：标记归还/结清后立即更新状态和时间，并轻提示。

### 7.2 关键约束

- 所有可点击区域不小于 40px。
- 人员、金额、日期、提醒控件尺寸固定，内容变化不导致布局跳动。
- 提醒卡文本在手机窄屏下不截断、不遮挡，必要时换行。
- 320px 起所有视口不横向溢出、不重叠。
- 已逾期记录使用视觉标签区分，但提醒卡仍保持轻松语气。

## 8. 数据模型

```text
BorrowKind = "lend_out" | "borrow_in" | "paid_for"
BorrowSubjectType = "item" | "money" | "account"

BorrowCounterparty {
  friendId?: string
  name: string
  avatarUrl?: string
}

BorrowRecord {
  id: string
  userId: string
  kind: BorrowKind
  subjectType: BorrowSubjectType
  title: string
  amount?: number
  currency?: string
  platform?: string
  accountName?: string
  counterparty: BorrowCounterparty
  lentAt: string
  dueAt?: string
  remindRule?: "none" | "before_1d" | "before_3d" | "before_7d" | "on_due" | "daily_overdue"
  returnedAt?: string
  settledAt?: string
  note?: string
  createdAt: number
  updatedAt: number
}

BorrowLedgerState {
  schemaVersion: 1
  records: BorrowRecord[]
  updatedAt: number
}
```

存储 Key：

```text
funbox:borrow-ledger:state:v1
```

状态派生规则：

```text
active = 未归还 / 待结清
overdue = active && dueAt < today
done = returnedAt 或 settledAt 已写入
days = today - lentAt（按本地日期边界计算）
```

## 9. 技术方案

### 9.1 前端

- 新增 `frontend/types/borrow-ledger.ts`，定义方向、类型、人员、记录、状态与提醒元数据。
- 新增 `frontend/lib/borrow-ledger.ts`，负责记录增删改、状态派生、提醒卡生成、搜索与统计。
- 新增 `frontend/lib/borrow-ledger-storage.ts`（Web 与 Native 各一份实现），读写本机真实数据。
- 新增 `frontend/lib/borrow-ledger-api.ts`，负责登录账号同步。
- 新增 `frontend/features/tools/borrow-ledger-screen.tsx`，在 `ToolDetailScreen` 增加路由映射。
- 好友选择复用 `useSocial().friends` 与现有好友搜索模型，不复制好友数据到借还记录。
- 提醒卡文本由真实 `BorrowRecord` 字段生成，不允许拼接任何预置值。

### 9.2 后端

- 新增 `backend/internal/borrowledger` 包，沿用 SQLite 全量状态存储模式。
- 新增接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/borrow-ledger/state` | 拉取当前账号借还记录 |
| PUT | `/api/v1/borrow-ledger/state` | 全量保存借还记录 |
| DELETE | `/api/v1/borrow-ledger/state` | 清空借还记录 |

- 服务端执行与前端一致的方向、类型、人员、金额、日期、长度与状态校验。
- 接口只接受真实用户输入，不提供任何默认记录、默认物品、默认金额或默认提醒。

### 9.3 测试

- 记录管理：三种方向、三种类型、增删改、清空、字段长度与金额边界。
- 状态派生：未归还、已归还、待结清、已结清、逾期、完成后的提醒停止。
- 提醒卡：真实天数计算、语气模板、账号类不出现凭证、逾期不改变事实字段。
- 好友集成：登录好友选择、手动输入、好友改名后历史快照不变化。
- 搜索：新增关键词在首页搜索全部可命中。
- 存储：本地持久化、清空、登录同步、同步失败降级。
- UI：Node 测试覆盖空态、录入态、详情、提醒卡、历史与筛选关键逻辑。
- Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。

## 11. 关键风险与决策

| 风险 | 决策 |
| --- | --- |
| 借还记录容易被理解成记账 App | 只做轻量借还台账，不做余额、利息、分期、账单或资产管理 |
| 提醒卡容易显得催收 | 固定轻松语气模板，只表达事实和可选归还，不出现催促或施压 |
| 会员账号涉及凭证安全 | 不存储密码、验证码、登录态，提醒卡只展示平台和账号名 |
| 好友改名或删除好友 | 记录保存人员快照，历史真实性不随好友数据变化 |
| 金额换算和汇率 | 只展示用户录入的币种和金额，不做实时汇率换算 |
| 多设备同步冲突 | 以 `updatedAt` 做最后写入覆盖，并在 UI 展示同步状态 |
| 已逾期记录被误解 | 逾期由真实日期计算，仅作为状态标签，不改变提醒卡语气 |
