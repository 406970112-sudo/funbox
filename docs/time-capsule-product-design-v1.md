# FunBox 时间胶囊 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 状态：待评审
> 定位：把今天的一句话、照片或语音封存起来，在真实日期或真实目标达成时开启；支持个人与双人共同封存，未到开启时间任何一方都看不到内容。

## 1. 产品概述

### 1.1 一句话定位

"时间胶囊"让用户把真实的一句话、照片或语音封存到未来，在真实日期或真实目标达成时开启；双人胶囊由两位真实好友共同放入内容，封存后双方都只能到期查看。

### 1.2 解决的问题

| 场景 | 现状 | 问题 |
| --- | --- | --- |
| 写给一个月后的自己 | 想给自己留句话，但消息很快被淹没 | 缺少一个会到期自动开启的私密容器 |
| 明年生日 | 想在生日当天看到过去的自己 | 没有真实生日来源和到期开启机制 |
| 恋爱一周年 | 两个人想一起给未来留内容 | 单人聊天记录不是共同封存，内容也不私密 |
| 项目上线那天 | 想在上线日复盘当时的状态 | 没有可关联真实日期的倒计时容器 |
| 减肥目标完成时 | 想达成目标后看到当时的承诺 | 目标数据分散，无法用真实完成事件触发开启 |

### 1.3 与 FunBox 现有能力的衔接

- 复用账号、JWT、SQLite、统一工具注册、主题系统、好友关系、消息中心与 WebSocket 实时通知。
- 日期开启可复用"还有几天"中的真实到期/纪念日记录。
- 目标开启可复用"效率清单"中的真实目标或任务，目标完成时由服务端触发胶囊开启。
- 生日开启需要在个人资料中补充真实生日字段，未填写时该预设不可用。
- 工具入口沿用现有 `feature_registry.json` 与 `frontend/mocks/app-data.ts` 注册方式，工具列表、最近使用、首页推荐位自动生效。

### 1.4 一期全量边界

本方案不设分期，以下能力在同一个版本一次交付：

- 单人胶囊的创建、内容录入、封存、等待、开启与归档。
- 双人胶囊的好友邀请、接受/拒绝、双方内容录入、双方封存与到期开启。
- 日期开启、生日开启、还有几天记录开启、效率清单目标开启。
- 文字、照片、语音三种真实内容类型。
- 封存后内容隐藏、到期自动开启、双方通知。
- 空状态、错误状态、权限校验、真实数据接口与前后端测试。

## 2. 真实数据原则（硬性要求）

1. 首次进入"时间胶囊"为空态，不预置任何胶囊、文字、照片、语音、好友或开启记录。
2. 文字内容只能是用户真实输入；照片和语音只能是用户真实上传或录制，不允许内置素材。
3. 开启时间由服务端基于用户选择的真实日期或真实关联记录计算，客户端不能直接标记"已开启"。
4. 双人胶囊只能选择当前账号的真实好友，双方都必须接受并各自放入真实内容后才能封存。
5. "明年生日"使用个人资料中的真实生日；未填写时不能使用该预设，需先去个人资料填写。
6. "项目上线那天"和"减肥目标完成时"只能关联当前账号真实存在的"还有几天"记录或"效率清单"目标；没有真实记录时引导用户先创建，不自动生成假记录。
7. 设计稿中出现的示例文字、照片、语音、名称仅用于版式演示，不会在运行时写入数据库。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户 60 秒内完成一次"创建胶囊 + 放入内容 + 封存"。
2. 封存后内容立刻从所有列表接口隐藏，到期后自动开放。
3. 双人胶囊在双方都接受并各自放入内容前不能封存。
4. 所有开启时间和开启动作都来自服务端真实状态，不依赖客户端伪造。

### 3.2 设计原则

- 真实优先：内容、好友、日期、目标全部来自真实数据源。
- 封存即隐藏：封存后任何接口都不返回正文与媒体内容。
- 双人共写：双方各自写自己的内容，封存后合为一颗胶囊。
- 到期才开启：时间未到、目标未完成、胶囊未封存时都不能查看内容。
- 轻量克制：不做公开分享、排行榜、AI 代写或虚拟奖励。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 普通用户 | 写给一个月后的自己 | 快速输入一句话、照片或语音并封存 |
| 普通用户 | 明年生日看自己 | 用真实生日预设开启时间 |
| 情侣/好友 | 恋爱一周年共同封存 | 选择真实好友、双方共同放入内容、到期共同查看 |
| 职场用户 | 项目上线那天复盘 | 关联真实"还有几天"记录，到期自动开启 |
| 自我成长用户 | 减肥目标完成时 | 关联真实"效率清单"目标，目标完成后自动开启 |

## 5. 产品结构

### 5.1 入口

- 工具注册名：`time-capsule`
- 工具名称：时间胶囊
- 分类：记录
- 路由：`/tools/time-capsule`
- 入口图标：`clock-fast`，备用 `hourglass`
- 状态：一期发布时注册为 `available`
- 权限：`normal / vip / svip / admin` 均可使用，V1 不做会员权益差异
- 搜索关键词：时间胶囊、写给未来、未来、生日、纪念日、恋爱、一周年、项目上线、减肥、目标完成、语音、照片、封存

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 首页 | 胶囊列表、待开启倒计时、待处理邀请、创建入口 |
| 创建胶囊 | 单人/双人模式、标题、内容块、开启条件 |
| 开启条件页 | 日期预设、生日预设、还有几天记录、效率清单目标 |
| 双人协作页 | 选择真实好友、查看双方放入状态、发送/接受邀请 |
| 封存等待页 | 倒计时、封存信息、成员状态、内容隐藏提示 |
| 开启阅读页 | 展示双方真实内容、文字、照片、语音播放 |
| 通知中心 | 邀请、接受、封存、开启等真实事件通知 |

### 5.3 核心流程

```text
进入时间胶囊
  -> 首次进入：空状态 + 新建胶囊
  -> 选择单人/双人
  -> 单人：填写标题 + 放入文字/照片/语音 + 选择开启条件
  -> 双人：选择真实好友发送邀请
  -> 对方接受后，双方各自放入内容
  -> 双方都有内容且接受邀请后，任一方点击封存
  -> 服务端隐藏内容并开始计时
  -> 到期或关联目标完成时，服务端标记已开启并通知双方
  -> 双方进入开启阅读页查看全部内容
```

## 6. 功能设计

### 6.1 首页

- 顶部展示统计：进行中、待开启、已开启、待处理邀请，全部由服务端按真实记录聚合。
- "我的胶囊"按状态分组：等待开启、已开启、草稿、已归档。
- 等待开启的胶囊展示真实倒计时和成员状态，不展示正文、不展示媒体预览。
- 首页右上角提供"新建胶囊"入口。
- 首次进入为空态，只展示"写一个给自己的胶囊"和"与好友共同创建"两个真实动作，不预置内容。

### 6.2 创建胶囊

#### 基本信息

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 胶囊标题 | 是 | 单行文本，1-40 字，自动去除首尾空格 |
| 胶囊备注 | 否 | 多行文本，最长 200 字 |
| 单人/双人 | 是 | `personal` 或 `joint` |
| 好友 | 双人必填 | 从当前账号真实好友中选择，不能选择自己 |

#### 内容块

| 类型 | 必填规则 | 限制 |
| --- | --- | --- |
| 文字 | 每颗胶囊至少一个内容块 | 单块 1-2000 字，最多 3 块 |
| 照片 | 可选 | JPEG/PNG/WebP，单张最大 5MB，每颗胶囊最多 6 张 |
| 语音 | 可选 | M4A/WAV/MP3，单个最大 20MB，最长 10 分钟，每颗胶囊最多 1 条 |

- 单人胶囊内容块总数为 1-6 条。
- 双人胶囊每位成员内容块总数为 1-6 条，双方都必须至少有一条。
- 封存前可增删改自己的内容块；封存后不可修改。
- 上传失败显示真实错误，不保存半成品，不展示 mock 素材。

#### 开启规则

开启规则分为两类：

1. 日期开启
   - 快捷预设：1 个月后、3 个月后、1 年后。
   - 生日开启：使用当前账号真实生日，由服务端计算下一个生日日期。
   - 自定义日期：用户选择未来日期和时分，服务端校验至少晚于当前时间 1 分钟，最远不超过 10 年。
2. 事件开启
   - 还有几天记录：选择当前账号真实存在的 `days_left_records`，到期日到达时开启。
   - 效率清单目标：选择当前账号真实存在的 `focus_goals` 或 `focus_tasks`，目标完成后开启。

规则：

- 所有快捷预设都由服务端解析成真实 `open_at`，客户端不保存相对时间。
- 生日未填写时，"明年生日"入口不可用并提示去个人资料填写真实生日。
- 关联记录被删除、关联目标已归档或已经完成时，不能继续使用该规则封存。
- 封存后若关联记录被删除，胶囊保持封存状态并在详情页提示"关联记录已失效，请联系创建者重新设置"；个人胶囊可先取消封存再修改，双人胶囊需双方同意取消封存。

### 6.3 双人协作规则

1. 发起方选择真实好友并发送邀请。
2. 好友收到通知后进入邀请详情，只能看到标题、开启规则、发起方，不能看到任何内容。
3. 好友接受后进入共同编辑状态；双方各自只能看到自己的草稿和对方"已放入 N 条内容"的状态。
4. 双方都接受且各自至少有一条内容后，任意一方可以点击"封存"。
5. 封存后内容隐藏，双方都看不到正文和媒体，直到开启时间到达。
6. 封存前任一方可退出共同创建，退出后胶囊回到单方草稿或取消。

### 6.4 封存与权限

- 个人胶囊：保存内容后点击"封存胶囊"，服务端校验内容数量和开启规则后写入 `sealed_at`。
- 双人胶囊：只有双方都接受且都有内容时，封存按钮才可用。
- 封存后内容从所有列表和详情接口隐藏；媒体文件不提供公开 URL，只提供签名访问链接。
- 封存后不可编辑、不可删除，只有到期开启后才能归档。
- 归档已开启的胶囊后，内容仍可在"已开启"列表中回看。

### 6.5 开启与阅读

- 日期开启：服务端在 `open_at` 到达后标记 `opened`，并向所有成员写入开启通知。
- 事件开启：关联目标完成时，由服务端在同一个事务中标记胶囊开启并写入通知。
- 开启阅读页按成员分组展示内容：文字、照片、语音；语音使用真实文件 URL 播放，播放状态只记录当前设备，不写入服务端。
- 已开启状态不可回退，关联目标被撤销完成不会把胶囊重新封存。

### 6.6 通知

时间胶囊复用消息中心和 WebSocket 实时能力，发送以下真实事件：

- 收到共同创建邀请。
- 对方接受了邀请。
- 对方拒绝或退出了共同创建。
- 胶囊已封存。
- 胶囊已到期开启。
- 关联记录失效或关联目标变化需要用户处理。

## 7. 数据模型

```text
time_capsules
  id, creator_id, mode, title, note,
  open_rule, open_at, open_timezone,
  linked_days_left_id, linked_focus_goal_id, linked_focus_task_id,
  status, sealed_at, opened_at, archived_at, created_at, updated_at

time_capsule_members
  id, capsule_id, user_id, role,
  invite_status, invited_at, accepted_at, declined_at, exited_at,
  content_count, created_at, updated_at

time_capsule_contents
  id, capsule_id, user_id, kind,
  text_content, media_id, sort_order, created_at, updated_at

time_capsule_media
  id, capsule_id, user_id, kind, file_name, file_path,
  mime_type, byte_size, width, height, duration_ms, created_at

time_capsule_events
  id, capsule_id, user_id, action,
  created_at

time_capsule_notifications
  id, recipient_id, capsule_id, type,
  read_at, created_at
```

状态：

- 胶囊：`draft / sealed / opened / archived`
- 成员邀请：`pending / accepted / declined / exited`
- 开启规则：`date / birthday / days_left / focus_goal / focus_task`

约束：

- `mode = joint` 时成员必须恰好两人。
- `open_rule = date/birthday` 时必须写入 `open_at`。
- `open_rule = days_left` 时 `open_at` 由关联记录到期日计算。
- `open_rule = focus_goal/focus_task` 时 `open_at` 为空，开启由目标完成事件触发。
- 封存后禁止修改正文与媒体；只有 `opened` 后可以归档。

## 8. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/time-capsule/home` | 首页统计、胶囊列表、待处理邀请 |
| POST | `/api/v1/time-capsules` | 新建草稿，支持单人/双人 |
| GET | `/api/v1/time-capsules/{capsuleID}` | 胶囊摘要；未开启不返回正文与媒体 |
| PATCH | `/api/v1/time-capsules/{capsuleID}` | 修改草稿标题、备注、开启规则 |
| DELETE | `/api/v1/time-capsules/{capsuleID}` | 删除未封存草稿 |
| POST | `/api/v1/time-capsules/{capsuleID}/contents` | 新增内容块 |
| PATCH | `/api/v1/time-capsules/{capsuleID}/contents/{contentID}` | 修改自己的未封存内容块 |
| DELETE | `/api/v1/time-capsules/{capsuleID}/contents/{contentID}` | 删除自己的未封存内容块 |
| POST | `/api/v1/time-capsules/{capsuleID}/media` | 上传照片/语音，返回媒体 ID 与草稿预览签名 URL |
| POST | `/api/v1/time-capsules/{capsuleID}/accept` | 接受双人共同创建邀请 |
| POST | `/api/v1/time-capsules/{capsuleID}/decline` | 拒绝双人共同创建邀请 |
| POST | `/api/v1/time-capsules/{capsuleID}/exit` | 退出未封存双人胶囊 |
| POST | `/api/v1/time-capsules/{capsuleID}/seal` | 封存，服务端校验内容与成员状态 |
| POST | `/api/v1/time-capsules/{capsuleID}/archive` | 归档已开启胶囊 |
| GET | `/api/v1/time-capsule/sources/birthday` | 获取当前账号真实生日 |
| GET | `/api/v1/time-capsule/sources/days-left` | 获取可关联的真实到期/纪念日记录 |
| GET | `/api/v1/time-capsule/sources/focus` | 获取可关联的真实效率清单目标 |
| GET | `/api/v1/time-capsule/notifications` | 时间胶囊通知列表 |
| POST | `/api/v1/time-capsule/notifications/read` | 标记通知已读 |
| GET | `/time-capsule-media/{fileName}?token=` | 签名媒体访问，仅参与成员且在允许状态下可访问 |

说明：

- 所有接口要求 JWT 登录，沿用现有鉴权、限流和 JSON 中间件。
- 新增模块放在 `backend/internal/timecapsule/`，在 `httpapi/server.go` 注册路由。
- 上传媒体使用现有文件存储模式，文件放在 `data/time-capsule-media/`，文件名由服务端生成。
- 媒体访问使用带签名的一次性 URL，未开启状态不返回公开地址。

## 10. 交互与视觉设计

- 沿用 FunBox 视觉体系：浅蓝画布、白色表面、深藏青重点、品牌蓝主色。
- 本工具补充"时间感"语义色：琥珀金 `#e8a33d`、深藏青 `#151b3b`、荧光绿 `#c9f36a`。
- 内容区最大 430px 移动宽度，宽屏居中。
- 首页、创建页、等待页和开启页都把主要操作放在首屏。
- 倒计时、状态标签、成员头像、内容块卡片使用固定尺寸，内容变化不导致布局跳动。
- 图标沿用 Lucide / Material Community Icons，可点区域不小于 40px。
- 支持浅色与深色主题，320px、390px、430px 视口下文本不溢出、元素不重叠。
- 不做教程式大段说明，空状态只给可执行动作。

## 11. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 首次进入 | 空状态 + 新建胶囊，不预置任何数据 |
| 未填写生日但选择生日开启 | 提示先去个人资料填写真实生日 |
| 双人模式没有好友 | 提示先添加好友，提供好友添加入口 |
| 对方拒绝邀请 | 邀请状态变为已拒绝，发起方可选择其他好友或取消 |
| 只有一方放入内容 | 封存按钮禁用，提示双方都需要真实内容 |
| 关联记录已删除 | 胶囊保持封存，提示关联记录失效 |
| 关联目标已完成 | 不能使用该规则封存，提示选择其他开启方式 |
| 上传失败 | 显示真实错误，不保存半成品 |
| 未到开启时间 | 接口不返回正文与媒体，详情页显示倒计时 |
| 已到期但未封存 | 不自动开启，详情页提示"尚未封存，内容不会开放" |
| 媒体签名过期 | 提示刷新访问地址，不展示 mock 占位 |

## 12. 一期交付清单

- 首页、空状态、胶囊列表、统计。
- 单人胶囊创建、内容块增删改、封存、等待、开启、归档。
- 双人胶囊邀请、接受、拒绝、退出、双方内容录入、封存、开启。
- 日期开启、生日开启、还有几天记录开启、效率清单目标开启。
- 文字、照片、语音三种内容类型的真实上传与播放。
- 封存后内容隐藏、签名媒体访问、到期自动开启、双方通知。
- 深浅主题、320/390/430 响应式。
- Go 测试、前端 Node 测试、TypeScript 检查与 lint。

## 13. 明确不做

- 不做预置胶囊、演示内容、mock 好友、mock 照片或 mock 语音。
- 不做 AI 代写、AI 美化、AI 摘要或自动补全内容。
- 不做公开分享、排行榜、朋友圈转发。
- 不做虚拟积分、奖励或会员权益差异。
- 不做"双方必须同时在线才能开启"的面对面解锁。
- 不导入第三方日记、聊天记录或外部时间线数据。

## 14. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 用户忘记关联目标 | 详情页持续显示真实关联状态，开启前可处理 | 需要状态提示 |
| 关联记录被删除 | 胶囊保持封存并提示失效，避免误开 | 需要用户处理 |
| 双人封存后一方想取消 | 封存后不可编辑删除，需双方同意后由创建者取消 | 降低误删风险 |
| 媒体隐私 | 私密存储 + 签名 URL，不提供公开地址 | 需要媒体访问鉴权测试 |
| 服务端时间跨时区 | 开启时间按用户选择时区存储，服务端以 UTC 比较 | 需要时区测试 |

## 15. 验收清单

1. 新用户首次进入没有任何预置胶囊、内容、好友邀请或开启记录。
2. 单人胶囊至少一条真实内容后可以封存，封存后所有接口不返回正文与媒体。
3. 双人胶囊未双方接受或未双方放入内容时不能封存。
4. 日期开启在真实 `open_at` 到达后自动开启，并通知所有成员。
5. 生日开启在没有真实生日时不可用，填写生日后由服务端计算开启时间。
6. 还有几天记录开启在记录到期日到达后自动开启。
7. 效率清单目标开启在目标完成时自动开启，目标撤销完成不会回退已开启状态。
8. 照片和语音上传使用真实文件，媒体访问需要签名且未开启时不可访问。
9. 邀请、接受、封存、开启通知全部来自真实事件。
10. 320px、390px、430px 视口下无文本溢出和元素重叠，深浅主题均可读。

## 16. 附录：真实数据锚点

设计稿中的标题、文字、照片、语音、日期、目标名称和好友昵称均为版式演示，用于表达交互形态，不会在运行时写入数据库。

产品运行时的数据只来自以下真实来源：

1. 用户手动输入的文字和胶囊标题。
2. 用户真实上传的照片或录制的语音。
3. 用户个人资料中的真实生日。
4. 用户真实好友关系。
5. 用户真实创建的"还有几天"记录。
6. 用户真实创建的"效率清单"目标或任务。
7. 服务端记录的创建、邀请、接受、封存、开启、归档时间。
