# FunBox 用户端「身份展示」产品方案

> 文档版本：V1.0  
> 实施状态：Phase 1 已完成，Phase 2 已部分完成  
> 状态：待评审  
> 适用端：Expo 移动端 / 管理后台 Web  
> 目标版本：MVP

## 1. 背景与问题

从当前「我的」页面截图和代码确认：用户头像、昵称、用户名下方没有任何身份标识，账户区也没有会员或身份入口。四种身份 `normal / vip / svip / admin` 在用户端几乎无法感知，管理员也只能通过「管理后台」入口被动判断自己的身份。

这带来四个问题：

1. VIP / SVIP 用户不知道自己拥有特权，会员价值感完全缺失。
2. 管理员身份不直观，后台能力入口容易被当成普通菜单。
3. 社交场景（在线好友、会话列表、聊天页）无法体现任何身份差异。
4. 身份被管理员调整后，用户端没有任何反馈，用户可能继续按旧身份理解产品。

## 2. 产品判断

本期目标是让用户「一眼知道自己的身份」，并能在需要时查看自己的身份权益。基于这个目标，补充并收敛成以下三条原则：

1. **身份是状态，不是装饰。** 所有身份展示必须与实际权限一致；身份变更后要及时刷新，展示不能比权限更快或更慢。
2. **分层表达。** 常驻徽标负责「认出来」，身份卡负责「看得懂」，场景化触点（社交、后台、403 提示）负责「用得上」。
3. **视觉统一。** 用户端与管理后台共用同一套身份令牌（颜色、图标、文案、形态），避免两套色值各自漂移。

语义边界：

- VIP / SVIP 是会员等级，`admin` 是后台角色，两者不是同一层概念。
- 当前 `users.role` 是单选字段，本期先做「一身份一徽标」；后续拆分为 `membership_tier` + `system_role` 后，再支持「管理员 + VIP」并排展示。
- 展示克制：常驻徽标只给 `vip / svip / admin`；`normal` 不常驻展示，只在身份卡和会员中心出现「普通用户」。
- 社交场景默认公开会员等级；管理员身份默认不在社交场景公开，避免权威感影响普通用户交流。

## 3. 身份视觉系统 V1

在现有 `frontend/lib/admin-users.ts` 的 `rolePresentation` 基础上，把身份令牌收敛为前端统一模块，用户端与后台都从这里读取。

| 身份 | 图标 | 文案 | Light 色 | Dark 色 | 徽标形态 | 常驻位置 |
| --- | --- | --- | --- | --- | --- | --- |
| 普通用户 | `account-outline` | 普通用户 | `#7483a2` | `#9eacb9` | 弱化描边 | 仅身份卡 / 会员中心 |
| VIP | `diamond-stone` | VIP | `#e8a33d` | `#f2c14e` | 金色软底 + 描边 | 昵称旁、头像角、身份卡 |
| SVIP | `crown-outline` | SVIP | `#e8667a` | `#ff8ba3` | 玫瑰渐变 + 高光 | 昵称旁、头像角、身份卡 |
| 管理员 | `shield-check-outline` | 管理员 | `#151b3b` | `#c9f36a` | 实心高对比 | 个人页、后台顶栏 |

徽标尺寸：

- 昵称旁徽标：高度 18px，图标 12px，文字 10px。
- 头像角徽章：18px 圆形，只放图标，深色描边隔离背景。
- 身份卡徽标：24px，图标 + 文案。
- 后台顶栏徽章：28px，图标 + 文案，深色模式使用 `#c9f36a`。

实现建议：新建 `frontend/lib/identity.ts` 承载统一令牌；`admin-users.ts` 的 `rolePresentation` 改为引用它，避免两套色值。

## 4. 页面与触点方案

### 4.1 「我的」页面（本期核心）

1. **昵称旁身份徽标**：VIP 显示金色钻石「VIP」，SVIP 显示玫瑰皇冠「SVIP」，管理员显示盾牌「管理员」。普通用户不显示常驻徽标。
2. **头像右下角徽章**：`vip / svip / admin` 显示 18px 圆形小徽章，帮助用户在任何头像出现的位置快速识别自己。
3. **新增「身份权益」卡**：位于头像区下方、账户区上方。

   - VIP：金色卡片，「VIP 会员 · 已生效」，主操作「查看权益」。
   - SVIP：玫瑰色卡片，「SVIP 会员 · 已生效」，主操作「查看权益」。
   - 管理员：深色卡片，「管理员账号」，主操作「进入管理后台」。
   - 普通用户：灰色弱化卡片，「普通用户」，文案引导了解会员权益；本期无支付时不展示价格，只做介绍。

4. 账户区保留现有「管理后台」入口；身份卡出现后，管理后台入口不重复堆叠，改为身份卡内承载。

### 4.2 新增「会员中心」页 `/profile/membership`

1. 身份大卡：徽标 + 身份名 + 一句权益概述 + 到期时间占位（预留 `membership_expires_at`，为空不显示）。
2. 我的权益：根据当前可见功能列表生成，展示「当前身份可用能力」，例如市场雷达、AI 导航等。
3. 等级对比：普通 / VIP / SVIP 三列，标注每类功能开放情况，让用户理解升级差异。
4. 普通用户进入时展示「升级后可解锁」的介绍区；无支付能力前不做付费按钮。
5. 页面每次获得焦点时刷新 `/api/v1/auth/me` 与可见功能列表，保证身份刚被调整时能看到最新状态。

### 4.3 首页与工具页

本期不在工具卡片上加「VIP / SVIP」角标，避免首页噪音。身份相关的功能差异统一收敛到会员中心说明。

后续可选：当功能对当前用户不可见时，在入口卡片显示锁定角标和「升级解锁」文案。

### 4.4 社交与消息

- 在线好友、会话列表、聊天页中，在对方昵称旁显示 VIP / SVIP 徽标。
- 管理员身份默认不对外展示；自己的身份已在「我的」页展示，聊天页不重复显示自己的徽标。
- 二期可选：游戏排行、对局列表、评论等场景复用同一徽标组件。

### 4.5 管理后台

- 管理后台顶栏固定展示「管理员」徽章 + 当前账号名，避免后台页面切换后丢失身份感知。
- 用户身份管理列表继续使用统一身份令牌（此功能已实现，只需切换到 `identity.ts` 数据源）。

### 4.6 身份变更反馈

- 管理员调整身份后，用户端在回到前台、重新进入受限功能或收到 403 时刷新 `/api/v1/auth/me` 与可见功能列表。
- 「我的」页面在身份变化后显示一次性提示，例如「你的身份已更新为 VIP」。
- 403 提示统一为「该功能需要 SVIP 身份」，并带「查看权益」入口。

## 5. 状态与边界

- 未登录：「我的」页不显示任何徽标，身份卡显示「登录后查看身份」。
- 加载中：徽标占位保持固定尺寸，避免布局跳动。
- 深色模式：使用 dark 色令牌；管理员徽章在深色模式使用 `#c9f36a`。
- 昵称过长：徽标固定宽度，昵称省略号截断，不允许挤压或换行导致错位。
- 小屏幕：头像角徽章 16px，昵称旁徽标可隐藏文字只留图标，但仍保留无障碍标签。
- 无障碍：徽标必须带 `accessibilityLabel`，例如「身份：VIP」，不能只依赖颜色区分。
- 管理员同时拥有会员权益：本期数据模型为单选，不处理；拆分模型后并排展示。

## 6. 数据与接口

MVP 不需要后端改动：

- 复用 `GET /api/v1/auth/me` 返回的 `role` 字段。
- 前端 `identity.ts` 负责角色到「颜色 / 图标 / 文案」的统一映射。

二期预留：

- `auth/me` 增加 `identity` 块：`{ role, label, expiresAt }`。
- 用户表预留 `membership_expires_at` 展示位，为空不显示。
- 身份变更通知建议使用轻量方案：前端本地记录最近一次看到的身份，发现变化后展示一次性 banner。

## 7. 埋点建议

| 事件 | 触发时机 | 关键参数 |
| --- | --- | --- |
| `profile_identity_impression` | 我的页展示身份卡 | 当前身份 |
| `identity_badge_tap` | 点击昵称旁徽标或头像角徽章 | 当前身份 |
| `membership_center_open` | 打开会员中心 | 当前身份、来源 |
| `membership_benefit_view` | 查看权益详情 | 功能 ID |

不上传手机号、变更原因等敏感信息。

## 8. 验收标准

### 8.1 功能验收

- `normal / vip / svip / admin` 四种身份在「我的」页展示正确，颜色、图标、文案符合身份令牌。
- 普通用户不出现常驻徽标，身份卡正确引导查看权益。
- 管理员在个人页和管理后台展示徽章，不在社交场景公开。
- 身份被调整后，用户端回到前台能看到新身份，可见功能同步变化。
- 深色模式下四种徽标均可读，管理员徽章使用 dark 色。

### 8.2 体验验收

- 长昵称、小屏幕、加载态下布局不跳动、不重叠。
- 徽标有可访问性标签，不依赖颜色单独传达信息。
- 「我的」页身份卡、账户区、最近使用区层级清楚，不重复堆叠入口。
- 会员中心能说清「我是什么身份、我能用什么、升级差在哪」。

### 8.3 测试重点

- 四种身份在 Light / Dark 下的显示。
- 未登录、加载中、接口失败状态。
- 身份变更后的刷新与一次性提示。
- 社交场景只公开会员等级、不公开管理员。
- 长昵称、小屏、系统字体放大。

## 9. 实施节奏

1. Phase 1（MVP，约 2-3 天）：新建 `identity.ts`，完成「我的」页昵称徽标、头像角徽章、身份权益卡、管理员后台顶栏徽章；后端无改动。
2. Phase 2（约 1 周）：新增会员中心页、社交场景徽标、403 提示、身份变更 banner、到期时间展示。
3. Phase 3（远期）：付费购买 / 续费，`membership_tier` 与 `system_role` 拆分，管理员 + 会员双徽标，工具入口锁定角标。

## 10. 待评审问题

1. VIP 推荐使用金色以强化会员感，但会与后台现有蓝色 VIP 令牌不一致，是否接受同步调整？
2. 社交场景是否默认公开 VIP / SVIP 徽标？管理员是否永久不公开？
3. 本期是否做独立「会员中心」页，还是先只做「我的」页身份卡？
4. 是否需要预留到期时间展示？当前没有会员有效期数据。
5. 普通用户是否展示「升级」引导？在无支付能力前，建议只做权益介绍。
