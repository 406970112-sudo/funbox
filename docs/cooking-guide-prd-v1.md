# FunBox 跟做菜谱（教做菜）产品设计方案 V1

> 版本：V1 草案
> 日期：2026-08-02
> 状态：待评审
> 定位：搜菜系、找喜欢的菜、看真实图片与食材，再按真实步骤一步步炒出来。

## 1. 背景与问题

用户想学做菜时，常见路径是刷短视频、收藏图文教程，最后真正动手的却很少。现有内容有几个断点：

| 现状 | 问题 |
| --- | --- |
| 搜"菜系"得到的是餐厅列表 | 用户想知道"这道菜怎么做"，不是"去哪吃" |
| 教程以视频和长文为主 | 做菜时手脏、锅热，暂停回看很麻烦 |
| 菜谱真假难辨 | AI 生成图、编造步骤、缺食材用量，照着做容易翻车 |
| 食材信息分散 | 不知道要买什么、买多少，经常做到一半发现少料 |
| 收藏后不行动 | 收藏夹越攒越多，没有"今晚就做"的路径 |

FunBox 已有本地美食推荐（解决"吃什么"），缺一个"自己动手做出来"的闭环。跟做菜谱可以补上这个环节，复用现有的账号、TTS、收藏、反馈和后台体系。

## 2. 对原始想法的补充

原始闭环：搜索菜系 → 找到喜欢的菜 → 展示对应图片 → 按流程自己炒出来。

在此基础上补充八点：

1. 菜系既是搜索入口，也是内容组织方式。首页按真实菜系浏览，同时支持菜名、食材、分类混合搜索。
2. 图片和菜谱正文都可溯源。每道菜带图片来源、菜谱来源、抓取时间；图片缺失时显示占位，不生成假图。
3. 详情页突出"可做性"。食材清单、步骤数量、适合人数等只展示真实字段；缺字段显示"暂无"，不编造难度和时长。
4. 跟做模式按做菜场景设计。大字号步骤、上一步/下一步、进度、语音朗读、屏幕常亮，减少停下来擦手。
5. 购物清单从真实食材自动生成。按菜谱字段生成"食材 + 用量"，勾选备菜，不编造价格和商家。
6. 备菜替换只来自数据源或人工审核内容。V1 不做未经审核的 AI 替换建议。
7. 我的厨房沉淀行为。收藏、做过、最近浏览、口味偏好，后续用于排序和提醒，不用于生成内容。
8. 真实数据治理贯穿全流程。字段级 `source`、`fetchedAt`、`license`，禁止 AI 编造菜谱正文、图片、营养、难度和价格。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户 30 秒内从"想吃什么"进入一道可跟做的菜。
2. 每道菜的图片、食材、步骤都能追溯到真实数据源。
3. 跟做过程不丢步：进度、回退、朗读、常亮。
4. 缺数据不造数据：字段缺失有明确提示与来源。

### 3.2 设计原则

- 真实优先：图片、菜谱正文、食材必须来自真实数据源。
- 先事实后体验：AI 只做理解、检索、排序、摘要，不做菜谱生成。
- 可追溯：每条数据带 `source`、`fetchedAt`、`license`。
- 少而准：首屏返回 6-12 道，不为了填满页面展示低质量内容。
- 跟做友好：步骤短句、大字号、防熄屏、可回退、可朗读。
- 一期交付：本方案所有功能在一个版本内一次做完，不设分期。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 厨房新手 | 想学第一道家常菜，怕步骤看不明白 | 按菜系找到菜，图片真实，步骤逐条跟做 |
| 挑食/忌口用户 | 不吃辣、不吃香菜、素食 | 按菜系和真实标签筛选，避免买错料 |
| 家庭用户 | 晚饭要做 2-3 道菜 | 菜谱详情生成购物清单，一次买齐 |
| 海外用户 | 想吃中式菜但本地菜谱不熟 | 中文界面 + 真实英文原菜谱，双语可对照 |
| 收藏党 | 收藏很多教程但没动过手 | 跟做模式降低启动成本，完成后记录"做过" |

## 5. 产品结构

### 5.1 入口

- 工具注册名：`cooking-guide`
- 工具名称：跟做菜谱
- 分类：生活
- 路由：`/tools/cooking-guide`
- 入口图标建议：`chef-hat` 或 `utensils-crossed`
- 状态：一期发布时直接注册为 `available`；如需灰度，先 `coming-soon` 并在同一次发布中切换

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 菜系发现首页 | 搜索、菜系横滑、精选真实菜卡、数据徽标 |
| 搜索结果页 | 真实结果列表、筛选、排序、空态 |
| 菜谱详情页 | 大图、食材、步骤预览、来源、开始跟做 |
| 跟做模式 | 全屏步骤卡片、进度、朗读、回退、防熄屏 |

## 6. 核心流程

```text
进入工具
  → 浏览菜系 / 搜索菜名或食材
  → 结果列表：真实图片 + 真实字段
  → 菜谱详情：食材 + 步骤预览 + 来源
  → 购物清单：勾选备菜
  → 跟做模式：步骤/进度/朗读/回退
  → 完成：收藏、反馈、标记做过
```

## 7. 功能设计

### 7.1 菜系发现首页

- 顶部搜索框支持菜名、英文名、食材、菜系，例如"宫保""chicken""豆腐""中式"。
- 菜系横滑来自真实数据源，展示菜系名称与真实菜谱数量，例如"中式 · 27 道"。
- 精选菜卡包含：真实图片、中文名（人工映射表）、英文原名、菜系、分类、食材数、步骤数。
- 每张菜卡带数据徽标：`TheMealDB · 08-02 快照`。
- 图片加载失败时显示占位和"图片整理中"，不展示无来源图片。

### 7.2 搜索与筛选

- 搜索在服务端或本地真实数据池执行，不调用 AI 生成结果。
- 筛选项：菜系、分类（鸡肉/猪肉/牛肉/素食等）、标签（甜口、主食等），全部来自真实字段。
- 排序：综合、图片优先、步骤少、食材少。后两者由真实字段计算，不虚构难度评分。
- 空态提示："该菜系暂无菜谱，可重置条件"，并提供真实相近菜系入口。

### 7.3 菜谱详情

- 顶部大图来自真实图片来源，带返回、收藏、分享。
- 基本信息：中文名、英文原名、菜系、分类、标签。
- 食材清单：名称 + 用量，来自菜谱原文；缺失用量时只显示名称。
- 步骤预览：展示前 2 步和总步数，完整步骤进入跟做模式。
- 来源卡片：原菜谱链接、YouTube 视频链接、抓取时间；点击可查看原文。
- 操作：开始跟做、加入购物清单、收藏、反馈（有帮助/没帮助/信息有误）。

### 7.4 跟做模式

- 全屏步骤卡片：当前第 N 步 / 共 M 步，进度条明确。
- 操作：上一步、下一步、朗读本步、暂停、退出并保存进度。
- 朗读复用 FunBox 现有 TTS 能力；TTS 失败时仅提示，不影响步骤阅读。
- 保持屏幕常亮，进入模式时请求唤醒锁；不支持的平台提示手动设置。
- 步骤正文以真实数据源为准。一期不显示没有真实来源的精确计时，若原文包含时间则照原文展示。

### 7.5 购物清单

- 从菜谱真实食材字段自动生成"食材 + 用量"。
- 支持勾选已备、全选、复制清单、分享文本。
- 不展示价格、商家、购买链接，避免编造数据。

### 7.6 我的厨房与历史

- 登录用户保存最近浏览、收藏、做过的菜。
- 口味偏好（不吃辣、素食等）只用于排序和筛选，不参与内容生成。
- 跟做完成后可标记"我做出来了"，进入个人记录。

### 7.7 真实数据治理

- 数据源白名单：TheMealDB 开放接口、授权菜谱库、授权出版社/媒体。
- 字段级来源：菜谱正文、图片、食材、步骤分别记录来源与抓取时间。
- 校验任务：定时检查图片可达性、来源链接、字段完整性。
- 失效处理：图片 404 显示占位；链接失效标记 `stale`，不删除菜谱但提示。
- 禁止事项：不生成菜谱正文、图片、营养、难度、价格；不展示无来源内容；AI 文案必须标注。

## 8. 真实数据方案

### 8.1 数据源

一期交付全部数据源接入，不做阶段式上线：

| 数据源 | 说明 |
| --- | --- |
| TheMealDB 开放接口 | 菜系（area）、分类（category）、真实图片、食材与用量、步骤、原菜谱链接、YouTube 视频；无需密钥，允许标注来源使用 |
| 人工整理映射表 | 菜系中文名、菜名中文映射、别名、忌口标签；人工审核并记录来源，随主数据一起发布 |
| 授权中文菜谱库 | 一期接入，补齐八大菜系、克数、难度、时长、份量等结构化字段 |
| 用户贡献 | 用户上传菜谱，人工审核通过后展示，带作者信息与版权声明 |

数据源接入顺序只影响内容覆盖度，不影响功能交付：所有功能模块一期同时上线。

### 8.2 菜谱字段模型

```json
{
  "dishId": "52947",
  "name": "Ma Po Tofu",
  "nameZh": "麻婆豆腐",
  "area": "Chinese",
  "areaZh": "中式",
  "category": "Beef",
  "tags": [],
  "image": {
    "url": "https://www.themealdb.com/images/media/meals/1525874812.jpg",
    "source": "themealdb",
    "credit": "TheMealDB",
    "checkedAt": "2026-08-02T00:00:00+08:00"
  },
  "ingredients": [
    { "name": "Tofu", "measure": "450g" },
    { "name": "Minced Beef", "measure": "100g" }
  ],
  "steps": ["...真实步骤原文..."],
  "recipeSource": "https://www.chinasichuanfood.com/mapo-tofu-recipe/",
  "videoUrl": "https://www.youtube.com/watch?v=IhwPQL9dFYc",
  "license": "themealdb-open",
  "fetchedAt": "2026-08-02T00:00:00+08:00"
}
```

### 8.3 数据管道

1. 定时同步：脚本按菜系拉取 TheMealDB 列表和详情。
2. 校验：检查图片 URL 可达、步骤非空、食材非空、来源 URL 有效。
3. 入库：写入 SQLite 缓存表，保留 `fetchedAt` 与 `source`。
4. 展示：前端只展示已校验字段，缺失字段显示"暂无"。
5. 审计：后台可查无来源数据，目标为 0。

项目内已放一份真实快照：`docs/cooking-guide-assets/themealdb-snapshot.js`，抓取时间为 2026-08-02，字段与 8.2 一致。

### 8.4 AI 边界

允许 AI 做的：

- 理解自然语言搜索，转换为结构化条件。
- 把长步骤按原文分段展示。
- 基于真实字段总结"食材数量、步骤数量、适合新手程度"。
- 界面文案翻译；菜名中文映射只作为人工词表结果展示。

禁止 AI 做的：

- 生成或改写菜谱步骤、食材、用量、图片。
- 编造营养、热量、难度、时长、价格。
- 生成无来源的"正宗""最地道"等断言。

DeepSeek 不可用时，检索降级为规则匹配，并在响应中标注 `ai: "fallback"`。

## 9. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/cooking-guide/areas` | 菜系列表与真实数量 |
| GET | `/api/v1/cooking-guide/dishes?area=&q=&category=&tag=` | 菜谱搜索与筛选 |
| GET | `/api/v1/cooking-guide/dishes/{dishId}` | 菜谱详情 |
| GET | `/api/v1/cooking-guide/dishes/{dishId}/shopping-list` | 购物清单（由食材字段生成） |
| POST | `/api/v1/cooking-guide/sessions` | 创建跟做会话并保存进度 |
| POST | `/api/v1/cooking-guide/feedback` | 有帮助/没帮助/信息有误 |
| GET | `/api/v1/cooking-guide/history` | 最近浏览与做过记录 |
| POST | `/api/v1/cooking-guide/favorites` | 收藏/取消收藏 |

说明：

- 浏览、搜索、详情不强制登录，复用限流中间件。
- 历史、收藏、跟做进度需要登录。
- 所有响应字段带 `source` 与 `fetchedAt`。
- 图片字段带 `checkedAt`，前端据此显示数据新鲜度。

## 10. 页面与交互设计

- 沿用 FunBox 视觉体系：浅蓝画布、深色文字、品牌蓝主色；食物类补充暖橙、珊瑚红、青柠绿。
- 内容区最大 430px 移动宽度，宽屏居中。
- 菜卡图片建议 4:3，加载前显示灰色占位。
- 跟做模式使用深色背景，步骤文字大号高对比，按钮大间距。
- 支持浅色与深色主题；320px、390px、430px 视口下文字不溢出、元素不重叠。
- 搜索输入、筛选、勾选、步骤切换均为原生控件，避免自定义交互控件。

## 11. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 数据源不可用 | 展示缓存数据并标注快照时间；无缓存时展示"数据源维护中" |
| 图片加载失败 | 占位图 + "图片整理中"，不展示无来源图片 |
| 菜系无数据 | 空态 + 重置条件 + 相近真实菜系入口 |
| 搜索无结果 | 空态 + 展示可尝试的真实搜索词 |
| 步骤缺失 | 该步骤显示"原文暂无此步骤"，禁止补写 |
| TTS 失败 | 提示后继续，不影响阅读 |
| 网络断开 | 已浏览菜谱本地缓存可继续跟做 |

## 12. 技术架构建议

- 前端：新增 `frontend/features/tools/cooking-guide-screen.tsx`，复用 `MobileScreen`、`PageHeader`、`SurfaceCard`、主题 Hook。
- 后端：新增 `backend/internal/cookingguide/` 模块，SQLite 缓存菜谱表 + 同步 Job。
- 工具注册：沿用现有工具注册机制，按 `cooking-guide` 注册入口。
- 同步脚本：`scripts/sync-themealdb.ps1` 或 Go Job，定时拉取并校验。
- 本地开发：V1 可直接读取 `docs/cooking-guide-assets/themealdb-snapshot.js` 对应 JSON 作为种子数据，前端代码仍走 API。

## 13. 成功指标

1. 30 秒内找到可跟做菜谱的比例不低于 70%。
2. 真实图片加载成功率不低于 98%。
3. 详情页到跟做模式的转化率不低于 40%。
4. 跟做模式完成率（进入后完成全部步骤）不低于 30%。
5. 数据字段来源覆盖率 100%，无来源内容展示次数为 0。
6. 购物清单使用率不低于跟做用户的 30%。

## 14. 明确不做

- 不做 AI 生成菜谱、步骤、图片、营养、难度、价格。
- 不做外卖、点餐、支付、餐厅点评。
- 不做未经审核的用户菜谱。
- 不做药物、保健品、食疗功效宣称。
- 一期不做没有真实来源的精确计时器和难度评分。

## 15. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| TheMealDB 中文菜系覆盖有限 | 界面双语：中文名（人工词表）+ 英文原名与原文 | 中文体验依赖映射表质量 |
| 菜谱正文为英文 | 展示原文并标注"界面翻译，原文见来源" | 需要翻译质检流程 |
| 版权与使用条款 | 仅使用开放/授权数据，展示来源与许可 | 上线前完成数据源合规确认 |
| 数据质量参差 | 校验任务 + 信息有误反馈 | 需要人工巡检队列 |
| 离线缓存 | 已浏览菜谱本地缓存，一期随主功能一起交付 | 存储与更新策略待定 |
| DeepSeek 接入范围 | 仅用于查询理解与文案摘要 | 需限制 prompt，禁止生成菜谱 |

## 16. 验收清单

- [ ] 每张菜卡有真实图片与 `source`。
- [ ] 详情页食材、步骤与数据源原文一致。
- [ ] 跟做模式可前进、后退、朗读、防熄屏。
- [ ] 购物清单由真实食材字段自动生成。
- [ ] 搜索无结果、图片失败、数据源不可用均有真实状态提示。
- [ ] 全站无 AI 生成的菜谱内容。
- [ ] 320px、390px、430px 视口无文字溢出与元素重叠。
- [ ] 数据快照文件带抓取时间与来源说明。
- [ ] 发现、搜索、详情、跟做、购物清单、我的厨房、用户审核、离线缓存一次性验收通过。
