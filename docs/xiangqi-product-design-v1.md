# 象棋产品设计方案 V1

> 版本：V1 草案  
> 日期：2026-08-01  
> 定位：FunBox 移动端“象棋”小游戏，同时支持人机对战与好友实时对战。

## 1. 产品概述

### 1.1 一句话定位

一款上手快、氛围轻松、又保留专业棋感的象棋小游戏：随时和 AI 练一盘，也能和好友实时来一局，胜负记录、棋谱复盘和好友战绩都会沉淀在 FunBox 账号里。

### 1.2 与 FunBox 现有能力的衔接

仓库里已经具备可直接复用的能力：

- 账号体系、好友关系、WebSocket 实时消息。
- 通用“游戏社交能力层”：对局邀请、接受/拒绝、落子、认输、断线恢复、成绩提交和好友排行榜。
- 五子棋已完成“人机 + 好友”双模式，验证了模式切换、邀请面板、登录引导和实时棋盘刷新。
- 小游戏首页与游戏详情页已经存在，新增象棋可直接挂入。

象棋是本能力层接到的第二个对局类游戏，同时也是第一个“走子型”棋盘游戏（棋子会移动和吃子），因此需要对通用对局模型做一次轻量扩展。

### 1.3 产品目标

1. 让用户进入象棋后 30 秒内能开始一局棋，不设置任何理解门槛。
2. 人机模式覆盖“新手学规则 → 普通娱乐 → 认真对战”三个层次，AI 难度可切换。
3. 好友对战复用好友体系，提供邀请、实时同步、断线恢复、认输和复盘。
4. 对局数据完整可回放，为后续棋谱分享、残局挑战和等级分做准备。

### 1.4 非目标（V1 不做）

- 不做随机匹配陌生人的“快速匹配”，V1 只做好友邀请和房号邀请。
- 不做正式等级分（Elo/中国象棋等级分）、段位、赛季制。
- 不做解说、直播、观战大厅。
- 不做残局题库、开局库教学课程（放到 V2 学习中心）。
- 不做完整的人工智能棋谱分析（仅保留“提示一手”）。

## 2. 目标用户与场景

### 2.1 目标用户

- **休闲入门用户**：会下但很少下，需要一个随时能开始、输了不心疼的对手。
- **好友娱乐用户**：喜欢和朋友在聊天之外找个轻互动，输赢之后还能复盘互损。
- **认真练习用户**：想和更强 AI 对弈，观察棋谱、琢磨失误。

### 2.2 核心场景

| 场景 | 用户行为 | 产品应满足 |
| --- | --- | --- |
| 通勤打发时间 | 打开象棋，选“轻松”，2 分钟下一盘 | 免登录可玩，AI 等待短 |
| 睡前放松 | 和 AI 下到中盘想看看有没有更好走法 | 悔棋、提示一手 |
| 好友聊天 | 在消息里说“来一局”，直接进象棋发起邀请 | 从好友列表发起，实时同步 |
| 约好时间下棋 | 一人创建房间，另一人输房号加入 | 房号 6 位数字，无需先加好友 |
| 下完复盘 | 输赢之后想看看哪一步出了问题 | 棋谱回放、步数列表、局面快照 |

## 3. 核心玩法设计

### 3.1 双模式入口

象棋游戏页顶部使用分段控件：**人机对战 / 好友对战**。

- 未登录用户默认进入人机对战，可完整游玩；点击好友对战时引导登录，不阻断单机体验。
- 已登录用户进入后默认回到上次使用的模式。

### 3.2 棋盘与棋子

- 标准 9 列 × 10 行棋盘，楚河汉界居中，双方各有九宫。
- 红方执帅、仕、相、马、车、炮、兵；黑方执将、士、象、马、车、炮、卒。
- 棋子使用传统汉字刻字风格，红黑两色清晰区分；己方棋子在屏幕下方，对手在上方。
- 采用“选中棋子 → 显示可走点位 → 点击落子”的交互，所有非法点不可点。
- 最后一手和将军状态有视觉标记：被将军时对手方棋盘边缘出现警示色。

### 3.3 规则完整性

V1 必须实现的标准中国象棋规则：

- 车、马、炮、兵（卒）、帅（将）、仕（士）、相（象）的标准走法与吃子规则。
- 九宫限制、象田字不可过河、马腿/炮架、兵过河前只能前进。
- 帅将不能照面；己方行棋后不能使己方帅将处于被将军状态（不能送将）。
- 将军、应将、将死（绝杀）、困毙的判定。
- 和棋判定：双方同意和棋、无子可动（困毙按规则为负，需实现）、自然限着（默认 60 回合无吃子可提议和棋）。

### 3.4 人机对战

#### 难度分级

| 难度 | 名称 | 定位 | 行为特征 | AI 响应目标 |
| --- | --- | --- | --- | --- |
| 轻松 | 新手 | 学规则、熟悉走法 | 只做合法走法，偶尔主动吃子，会有明显失误 | < 0.5s |
| 进阶 | 棋友 | 日常娱乐 | 优先吃子、防守将军，评估车马炮价值 | < 1s |
| 高手 | 高手 | 认真对战 | 多层搜索 + 子力/位置评估，会制造威胁 | < 2s |
| 大师 | 大师（后续） | 挑战极限 | 可选接入 Fairy-Stockfish 等 UCCI 引擎 | 异步等待 |

V1 先做“新手 / 棋友 / 高手”三档，大师作为 V1.1 或 V2 能力。

#### 人机模式功能

- 执红先行，人机模式默认玩家执红；提供“先手/后手/随机”设置。
- 悔棋：回到玩家上一手之前（同时撤回 AI 一手），无次数限制。
- 提示：AI 在当前局面给出 1 个推荐走法，每次提示后进入短暂冷却。
- 重新开始、认输；认输后直接进入结算面板。
- 人机模式走法由客户端计算（规则校验与搜索函数），联网状态不阻断游玩。

### 3.5 好友对战

#### 进入方式

1. **好友邀请**：从在线好友列表发起邀请，对方收到实时通知。
2. **房号加入**：创建房间获得 6 位数字房号，好友输入房号加入；房号 5 分钟内有效。
3. **消息直达**：聊天页“＋”菜单提供“象棋对战”，携带象棋邀请卡片，点击直达房间。

#### 对局流程

```text
发起邀请 → 等待接受（对方可接受/拒绝） → 开始对局
→ 红方先手 → 双方轮流走子 → 将死/困毙/认输/和棋 → 结算
→ 再来一局（交换先后手） / 回看棋谱 / 退出
```

#### 好友模式规则约束

- 必须登录且双方为好友，或通过房号进入同一房间。
- 走法由服务端权威校验，客户端只做交互；同一对局中只有当前行棋方能走子。
- 客户端走子先本地渲染“待确认”状态，服务端返回成功后才确认；网络失败自动重试或提示。
- 支持断线恢复：断线后棋盘保留，顶部显示重连状态；重连成功后拉取服务端最新局面。
- 好友模式不提供悔棋；双方同意和棋可结束对局。
- 认输、将死、困毙都会自动结算并写入战绩。

### 3.6 结算与复盘

- 结算面板展示：胜负结果、行棋方、总步数、耗时、双方头像。
- 提供“再来一局”“分享战绩”“查看棋谱”三个动作。
- 棋谱页支持：步数列表、自动播放/手动前进后退、回到任意一步查看局面。
- 好友模式对局自动保存到“我的棋谱”，人机模式默认保存最近 50 局（可在设置中关闭）。

### 3.7 战绩与好友榜

- 我的象棋页展示：总对局数、胜/负/和、当前连胜、最高连胜。
- 好友榜按周/全部两个周期展示胜场数和胜率，复用现有游戏排行榜能力。
- V1 只统计好友对战；人机成绩不计入排行榜，但保留个人对局记录。

## 4. 视觉与交互设计

### 4.1 视觉原则

- 棋盘以暖木色为主，避免过重科技感；整体页面沿用 FunBox 深蓝、主蓝、青柠辅助色。
- 棋盘是页面绝对主角：移动端占首屏主要区域，HUD 信息压到最薄。
- 棋子字号、盘面比例使用固定尺寸，不随设备宽度缩放，避免棋子重叠。
- 所有可点区域不小于 40px；棋盘交点可点击区域使用“透明扩大热区”保证小屏可点。

### 4.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 象棋首页 | 模式切换、开始对局、最近战绩、好友榜入口 |
| 人机设置 | 难度、先后手、规则说明 |
| 好友大厅 | 在线好友、待处理邀请、当前对局、房号创建/加入 |
| 对局页 | 棋盘、双方信息、回合状态、将军/悔棋/提示/认输 |
| 结算页 | 结果、再来一局、分享、看棋谱 |
| 棋谱页 | 步数列表、播放器、局面回放 |
| 我的象棋 | 战绩统计、棋谱列表、设置 |

## 5. 技术方案

### 5.1 总体架构

```text
Expo 前端
  ├─ 棋盘渲染组件（9×10 交点布局、棋子、可走点、动画）
  ├─ 本地规则引擎（走法合法性、将军/将死判定，人机与本地预览共用）
  ├─ AI 搜索模块（难度分层，纯前端计算）
  └─ 游戏社交适配层（复用 GameSocialProvider，扩展象棋走法载荷）

Go 后端
  ├─ 通用对局/落子/战绩存储（复用 game_matches / game_match_moves）
  ├─ 象棋适配器（服务端权威校验走法、胜负与和棋判定）
  ├─ 房号房间接口（创建/加入/有效期）
  └─ WebSocket 事件（邀请、对局更新、结束、战绩刷新）
```

### 5.2 通用对局模型扩展

现有落子模型 `GameMoveInput{ClientMoveID, Col, Row}` 是五子棋的“放置式”走法。象棋是“走子式”，需要扩展为：

```text
GameMoveInput{
  ClientMoveID,
  FromRow, FromCol,   // 起点
  ToRow,   ToCol      // 终点
}
```

兼容策略：

- `game_match_moves` 表新增 `from_row_index`、`from_col_index` 可空字段；已有行保留 `row_index/col_index` 作为终点。
- 走子类游戏写入 from/to 四坐标，放置类游戏继续只写终点；读取时按游戏类型映射。
- 服务端为象棋新增 `GameAdapter` 接口：`ValidateMove`、`ApplyMove`、`IsFinished`、`LegalMoves`。
- 五子棋继续走原逻辑，不破坏现有测试与对局。

### 5.3 象棋规则引擎选型

实现方式按“先自有规则引擎，后接强引擎”分两步：

- **V1 规则层**：使用成熟的开源中国象棋规则库（如 `xiangqi.js`）或自研纯函数规则引擎，覆盖走法、将军、将死、困毙和自然限着。规则引擎必须是确定性的，并在前后端复用同一套测试向量。
- **V1 高手 AI**：子力价值表（车 900 / 马 400 / 炮 450 / 兵 100 / 士相 200）+ 位置权重 + 快速 alpha-beta 搜索；目标深度 3~4。
- **V1.1 大师 AI**：评估 Fairy-Stockfish（UCCI 协议）的服务端集成方式；若接入成本高，则保持前端深度搜索并提高搜索层数。

### 5.4 接口设计

新增/扩展接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/game-matches` | 创建象棋好友对局（复用） |
| GET | `/api/v1/game-matches` | 对局列表（复用） |
| POST | `/api/v1/game-matches/{id}/moves` | 提交 from/to 走法（扩展） |
| POST | `/api/v1/game-matches/{id}/resign` | 认输（复用） |
| POST | `/api/v1/game-matches/{id}/draw` | 同意和棋（新增） |
| POST | `/api/v1/xiangqi/rooms` | 创建房号房间 |
| POST | `/api/v1/xiangqi/rooms/{code}/join` | 房号加入 |
| GET | `/api/v1/xiangqi/matches/{id}/replay` | 棋谱回放数据 |
| GET | `/api/v1/xiangqi/records` | 我的战绩 |
| GET | `/api/v1/game-leaderboards/xiangqi` | 好友榜（复用） |

实时事件继续复用：

- `game.match.invited`
- `game.match.updated`
- `game.match.finished`
- 新增 `game.match.draw-requested`

事件只做即时刷新信号，完整状态始终以 REST 为准，沿用现有断线重连策略。

### 5.5 数据模型增量

```text
game_matches：复用，game_id='xiangqi'
game_match_moves：新增 from_row_index / from_col_index
xiangqi_rooms：room_code、match_id、owner_id、expires_at
xiangqi_records：user_id、wins、losses、draws、streak、best_streak
（战绩也可直接由对局聚合计算，视查询量决定是否建表）
```

## 6. 里程碑

### M1：可玩版本

- 前端本地规则引擎与棋盘渲染，人机三档难度。
- 悔棋、提示、认输、重新开始。
- 未登录可玩，局部战绩本地存储。

### M2：好友对战

- 通用对局模型扩展 from/to 走法。
- 好友邀请、接受/拒绝、实时走子同步、断线恢复。
- 房号创建/加入、同意和棋。
- 好友排行榜、我的战绩。

### M3：复盘与分享

- 棋谱回放、分享战绩卡片、最近对局列表。
- 象棋规则引擎测试覆盖：走法矩阵、将军/将死/困毙、自然限着。

### V2 候选

- 大师难度接入 Fairy-Stockfish。
- 随机匹配、等级分、赛季。
- 残局题库、开局教学、每日一题。
- 观战、直播推流入口、自定义棋盘皮肤。

## 7. 关键风险与决策

| 风险/决策 | 结论 |
| --- | --- |
| 走法模型破坏五子棋 | 采用可空扩展列 + 适配器分发，双模式互不干扰 |
| AI 强度与响应速度 | 三档使用不同搜索深度和剪枝策略，异步 Web Worker 计算避免卡 UI |
| 好友对局作弊 | 服务端权威校验，前端只做交互；不依赖客户端上报胜负 |
| 断线恢复一致性 | 对局版本号 + 服务端状态快照，重连全量拉取 |
| 规则引擎正确性 | 建立标准走法测试向量表，用棋谱样本做回归 |
| 房号房间 | 5 分钟有效期、单局绑定、加入后自动清除 |

## 8. 验收标准

- 未登录用户可完整进行人机对局；登录后可进入好友对战。
- 服务端只接受当前行棋方的合法 from/to 走法；非法走法、非本方回合均被拒绝。
- 将死、困毙、认输、和棋均可正确结束对局并写入战绩。
- 好友断线重连后局面与服务端一致，不出现重复走子或状态错乱。
- 人机三档难度行为差异可感知，高手档单步响应不超过 2 秒。
- 移动端和桌面视口下棋盘、HUD、结算面板无重叠、无横向溢出。
- Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。

## 9. 待确认问题

1. 房号邀请是否必须在 V1 上线？如果先只做好友邀请，可砍掉房号相关接口。
2. “提示一手”在人机模式免费、每日限量还是付费点？V1 建议免费。
3. 好友模式是否允许中途离开自动判负？建议 V1 采用“断线后 2 分钟未重连自动判负”。
4. 大师难度是否接受服务端排队计算（单步 2~10 秒）？如不接受，V1.1 只做前端深搜。
