# 谁来干 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-05
> 定位：FunBox 移动端"转盘抽人"工具，本期一次交付全部核心能力，不拆分二期。

## 1. 产品概述

### 1.1 一句话定位

"谁来干"是一个圆形转盘抽人工具：用户把真实参与人放进转盘，选择或输入本次任务，转动后由转盘真实随机决定"谁去干"，并把每一次真实结果保留下来。

### 1.2 解决的问题

- 一群人吃饭、聚会、值班、做家务、玩大冒险时，经常靠"剪刀石头布"或口头指定决定谁去，结果不透明、容易扯皮。
- 普通抽奖工具只能抽奖品，不能同时表达"抽中的人去干什么"。
- 临时拼名单很麻烦，抽完一次就忘了是谁，缺少真实记录可追溯。

### 1.3 与 FunBox 现有能力的衔接

- 复用 FunBox 首页工具目录、底部 Tab、主题色、SurfaceCard、PageHeader 等现有视觉与导航组件。
- 复用首页搜索框：输入"大转盘""抽奖""谁来干""抽签"等关键词可以模糊匹配到本功能。
- 复用账号体系与现有本地/后端存储模式：未登录本机可用，登录后名单、任务与历史自动同步到 FunBox 账号。
- 复用现有真实数据产品原则：不预置任何 mock 名单、mock 任务、mock 抽奖记录。

## 2. 目标用户与场景

| 场景 | 用户行为 | 产品应满足 |
| --- | --- | --- |
| 聚餐结账 | 饭局结束，几个人都不想买单 | 快速把在场真人加进转盘，转动后显示谁买单 |
| 家务分工 | 两人及以上轮流洗碗、倒垃圾、遛狗 | 名单可随时加减，任务可写"洗碗/倒垃圾" |
| 办公室值班 | 团队轮流做会议记录、周报汇总 | 支持多人、批量粘贴名单，记录每次真实结果 |
| 聚会游戏 | 抽中的人完成大冒险或喝酒 | 任务自由输入，也可从真实用过的任务里快速选择 |
| 日常决策 | 不知道让谁先讲、谁先发言、谁选座位 | 只抽人，不绑定任务 |

## 3. 真实数据原则（硬性要求）

1. 首次进入"谁来干"不展示任何预置名单、任务或历史记录，全部为空态。
2. 转盘上的每个人必须是用户真实输入的名字或昵称，不允许内置"小明""小红"等示例数据。
3. 任务文案由用户输入或从用户真实使用过的任务中选取，不内置固定话术。
4. 抽签结果由真实随机逻辑产生，并把当次参与人、结果、任务、时间完整落盘。
5. 历史记录只来自用户真实抽过的次数，页面不允许出现未发生过的记录。
6. 设计稿中出现的 A/B/C/D 与任务文案仅用于表达"录入后"界面，正式产品首启为空。

## 5. 核心功能设计

### 5.1 人员管理

#### 人数规则

- 最少 2 人，最多 36 人。
- 人数少于 2 人时，"开始抽"按钮置灰并提示"至少再添加 1 人"。
- 人数达到 36 人时，"添加"入口置灰并提示已达上限。

#### 添加方式

- 单个添加：输入真实姓名或昵称，点击"添加"后立即进入转盘。
- 批量添加：支持一次粘贴多行或多个人名，按换行、逗号、顿号、空格分隔，逐条真实入库。
- 去重：与现有名单完全同名时阻止重复添加，并提示该姓名已存在。
- 去空白：自动去除首尾空格，空内容不添加。
- 长度：姓名 1-12 个字符，超出时提示。

#### 编辑与删除

- 每个人员卡片提供"编辑"和"删除"。
- 删除后转盘实时重排，人数低于 2 人时自动进入不可抽状态。
- 提供"清空名单"二次确认，防止误删真实数据。

### 5.2 圆形转盘

#### 视觉与布局

- 主页主体为圆形转盘，按当前人数均分扇区。
- 每个扇区显示人员姓名，字号随人数自适应，最多 36 人仍保持可读。
- 转盘中心为"开始抽"主按钮，顶部有固定指针。
- 转盘下方显示"当前 N 人参与"，随名单实时变化。

#### 随机与动画

- 点击"开始抽"后，转盘按真实随机目标角度旋转，先加速后减速停止。
- 结果由随机算法在抽奖开始时确定，动画仅用于呈现，不改变结果。
- 停止后指针指向的扇区高亮放大，其他扇区弱化。
- 旋转时长约 2.8-4 秒，支持中途再次点击重抽（当前次完成后）。

#### 状态

- 空态：虚线圆形 + "还没有人，先添加 2 位以上真实姓名"。
- 可抽态：人数 2-36，按钮高亮。
- 旋转态：按钮变为"转动中"，禁止重复点击。
- 结果态：浮层展示中选人与任务。

### 5.3 任务设置

任务设置位于转盘下方，本期一次交付三种模式：

1. 只抽人：不绑定任务，结果只显示"抽中 XXX"。
2. 自定义任务：用户输入本次任务，例如"去洗碗""大冒险""喝一杯"，字数 1-20。
3. 常用任务：自动收集用户真实输入过的任务，按最近使用排序，最多保留 8 条；选择后直接使用。

规则：

- 任务只作用于当次抽签，抽完后记录在历史中。
- 历史里允许"无任务"记录，不与有任务记录混淆。
- 常用任务不包含任何预置内容，只来自用户真实历史。

### 5.4 结果展示

- 抽中结果以浮层呈现：顶部显示"本次结果"，中间是人物头像占位与姓名，下方显示任务文案。
- 提供"再抽一次"：使用同一份名单与任务再次抽取。
- 提供"完成"：关闭浮层，结果已自动写入历史。
- 未绑定任务时，结果只强调姓名；绑定任务时，姓名与任务同屏展示。

### 5.5 历史记录

#### 记录内容

每一条真实记录包含：

- 抽签时间
- 当次参与人快照（完整名单）
- 中选人
- 任务文案（可为空）
- 抽签模式

#### 展示

- 历史页按日期分组，同一天内按时间倒序。
- 每条记录显示中选人、任务、参与人数，点击可展开完整参与人快照。
- 顶部统计今日次数与累计次数，均来自真实记录。

#### 管理

- 支持单条删除与清空历史（二次确认）。
- 名单被删除后，历史中的参与人快照不随名单变化，保证历史真实可追溯。

### 5.6 持久化与账号

- 本机为第一数据源：名单、任务、历史写入 AsyncStorage / Web localStorage。
- 未登录用户可完整使用本功能，数据保存在当前设备。
- 登录用户进入时自动从账号拉取并合并到本机，修改后自动同步到账号。
- 同一账号多设备以最后修改时间为准。

### 6.2 模糊匹配

- 现有首页搜索会对 `name / tagline / description / category / badges` 做包含匹配。
- 为保证"大转盘""抽奖"等词稳定命中，本期为工具条目新增 `keywords` 字段，并让搜索匹配算法同时检索该字段。
- 关键词集合：

```text
大转盘、转盘、抽奖、抽签、随机抽人、随机选人、抽人、选人、谁来干、谁去、抽中谁
```

- 命中后搜索结果高亮关键词，点击直达 `/tools/who-does-it`。
- 新增测试用例覆盖："大转盘""抽奖""抽签""选人""谁来干" 全部能搜到，且不返回无关工具。

## 7. 交互细节与状态

### 7.1 页面状态

- 加载态：读取本地与账号数据期间显示现有 PageLoadingFrame 工作台样式。
- 空态：无人员时显示空转盘引导，不出现占位假数据。
- 错误态：同步失败时保留本机数据，顶部提示"同步失败，已使用本机数据"，不阻断抽奖。
- 操作反馈：添加、删除、开始抽、任务保存均有轻提示；旋转结束配合触感反馈。

### 7.2 关键约束

- 所有可点击区域不小于 40px。
- 转盘扇区文字不溢出、不重叠；36 人时字号最小为 10px。
- 姓名与任务文字在手机窄屏不截断、不遮挡，必要时换行。
- 转盘区域尺寸稳定，名单增删只改变扇区文字与数量，不改变整体布局。

## 8. 数据模型

```text
WhoDoesItParticipant {
  id: string
  name: string
  createdAt: number
}

WhoDoesItTaskMode = "person-only" | "custom" | "recent"

WhoDoesItSettings {
  taskMode: WhoDoesItTaskMode
  customTask?: string
  selectedRecentTaskId?: string
}

WhoDoesItRecord {
  id: string
  createdAt: number
  participantNames: string[]
  winnerName: string
  taskText?: string
  taskMode: WhoDoesItTaskMode
  participantCount: number
}

WhoDoesItState {
  participants: WhoDoesItParticipant[]
  settings: WhoDoesItSettings
  records: WhoDoesItRecord[]
  updatedAt: number
}
```

存储 Key：

```text
funbox:who-does-it:participants
funbox:who-does-it:settings
funbox:who-does-it:records
```

## 9. 技术方案

### 9.1 前端

- 新增 `frontend/features/tools/who-does-it-screen.tsx`，在 `ToolDetailScreen` 增加路由映射。
- 转盘使用 `react-native-svg` 绘制均分扇区；旋转动画使用 `Animated` 驱动，不依赖网络。
- 随机逻辑独立为 `frontend/lib/who-does-it.ts`，抽签时先确定结果再计算动画目标角度。
- 本地存储独立为 `frontend/lib/who-does-it-storage.ts`（Web 与 Native 各一份实现）。
- 任务常用列表从历史记录中聚合真实 `taskText` 生成。

### 9.2 后端

- 复用 Go 后端与 JWT 认证，新增：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/who-does-it/state` | 拉取当前账号名单、设置与历史 |
| PUT | `/api/v1/who-does-it/state` | 全量保存名单、设置与历史 |
| GET | `/api/v1/who-does-it/records` | 历史记录列表 |
| DELETE | `/api/v1/who-does-it/records` | 清空历史 |

- 接口只接受真实用户输入，服务端做长度、人数上限与字符白名单校验。

### 9.3 测试

- 转盘引擎：2 人、36 人边界，随机结果必为名单内成员，动画不改变结果。
- 名单管理：批量解析、去重、空内容、超长、人数边界。
- 搜索：新增关键词在首页搜索全部可命中。
- 存储：增删人员、抽签、清空历史后持久化状态正确。
- UI：Node 测试覆盖空态、可抽态、结果态与历史展示关键逻辑。

## 10. 一期验收标准

1. 首次进入为空态，不出现任何预置名单、任务或历史。
2. 支持 2-36 人添加、批量粘贴、去重、编辑、删除、清空，人数规则正确。
3. 转盘按人数均分，点击开始后真实随机抽中名单内成员，动画结束后高亮结果。
4. 支持只抽人、自定义任务、常用任务三种模式，任务可完整进入历史。
5. 每次抽签真实写入历史，历史按日期分组，可查看参与人快照，可清空。
6. 首页搜索"大转盘""抽奖""抽签""选人""谁来干"均可命中并直达。
7. 未登录可完整使用；登录后名单、任务、历史与账号同步。
8. 转盘文字、按钮、结果浮层在 320px 起所有视口不重叠、不溢出。
9. Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。

## 11. 关键风险与决策

| 风险 | 决策 |
| --- | --- |
| 抽奖公平性受质疑 | 抽奖开始瞬间使用真实随机数锁定结果，动画只做呈现，结果可追溯 |
| 多人转盘文字拥挤 | 人数上限 36，扇区字号随人数自适应，并在实现阶段做视觉回归 |
| 历史与当前名单不一致 | 历史保存参与人快照，名单后续变化不影响历史真实性 |
| 搜索词覆盖不全 | 为工具增加 keywords 字段并纳入现有模糊匹配，新增关键词测试 |
| 账号同步冲突 | 以 updatedAt 为准做最后写入覆盖，并在 UI 提示同步状态 |

- 前后端测试、类型检查与 lint。
