# 我的尺寸库 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 定位：FunBox 移动端"家庭尺寸记录"工具，本期一次交付全部核心能力，不拆分二期。

## 1. 产品概述

### 1.1 一句话定位

"我的尺寸库"把家人身体尺寸、衣物鞋饰尺码和家居空间尺寸集中管理，在网购、装修、代买和软装时一键查看、复制和核对，所有内容都是用户真实录入的数据。

### 1.2 解决的问题

- 网购衣服、鞋、戒指时，尺寸散落在聊天记录、订单备注或记忆里，临时找不到。
- 帮家人买东西时，不清楚对方身高、体重、腰围、鞋码、衣服尺码和戒指号。
- 装修或买书桌、窗帘时，房间、桌面、窗户和落地高度分散，容易买错。
- 家庭数据没有统一入口，换设备后无法继续使用，缺少可同步的真实记录。

### 1.3 与 FunBox 现有能力的衔接

- 复用首页工具目录、底部 Tab、主题色、SurfaceCard、PageHeader 等现有视觉与导航组件。
- 复用首页搜索框：输入"尺寸库""身高""体重""鞋码""腰围""戒指""房间""书桌""窗帘""装修""代买"等关键词可模糊匹配到本功能。
- 复用账号体系与现有本地/后端存储模式：未登录本机可用，登录后尺寸库自动同步到 FunBox 账号。
- 沿用现有真实数据产品原则：不预置任何 mock 成员、mock 尺寸、mock 空间，首次进入为空态。

## 2. 真实数据原则（硬性要求）

1. 首次进入"我的尺寸库"不展示任何预置成员、尺寸、房间、书桌或窗帘数据，全部为空态。
2. 每个成员必须是用户真实录入的姓名或称呼，不允许内置"小明""小红"等示例数据。
3. 每个尺寸值必须是用户真实测量或确认后的输入，不允许根据身高体重自动推算衣服尺码、鞋码或戒指号。
4. 房间、书桌、窗帘必须是用户真实录入的空间与尺寸，不做示例户型、示例家具或示例窗帘。
5. 购买核对只展示用户已录入的真实尺寸，未填写项显示"未填写"，不生成任何估算值。
6. 设计稿中出现的姓名、尺寸与空间名称仅用于表达"录入后"界面，正式产品首启为空。

## 3. 目标用户与场景

| 场景 | 用户行为 | 产品应满足 |
| --- | --- | --- |
| 自己网购 | 买衣服、鞋或戒指时想确认尺码 | 快速查看本人真实尺寸，并复制成一条购物核对文本 |
| 帮家人代买 | 给妈妈买衣服、给孩子买鞋 | 选择家人档案，只展示该类商品需要的尺寸 |
| 购买戒指 | 不确定圈号，需要戒指内径与常买圈号 | 记录戒指圈号与内径，购物时同时展示 |
| 装修量房 | 记录房间长宽高，后续买家具参考 | 按房间保存真实尺寸，并关联书桌、窗帘 |
| 买书桌 | 需要桌面长宽高与放置房间 | 查看书桌尺寸和关联房间，不混淆其他数据 |
| 买窗帘 | 需要窗户宽高、轨道长、落地高度 | 按窗帘档案保存真实测量值，购买时直接核对 |
| 家庭成员维护 | 家人更换手机或登录不同设备 | 登录后自动同步，同一账号多设备以最后修改时间为准 |

## 5. 核心功能设计

### 5.1 档案管理

#### 档案类型

1. 家人：记录真实姓名或称呼，可填写身体尺寸、衣物鞋饰与戒指尺寸。
2. 房间：记录真实房间名称与长宽高，可关联书桌和窗帘。
3. 书桌：记录桌面长宽高，可关联放置房间。
4. 窗帘：记录窗户宽高、窗帘宽高、轨道长与落地高度，可关联房间。

#### 数量与命名规则

- 家人最多 30 位，房间最多 30 个，书桌与窗帘合计最多 60 个。
- 家人称呼 1-12 个字符，房间/书桌/窗帘名称 1-20 个字符。
- 同一类型内不允许重名；不同类型可重名，例如"客厅"房间与"客厅"窗帘。
- 名称自动去除首尾空格，空内容不允许保存。
- 删除档案前弹二次确认，并说明该档案关联的尺寸会一并删除。
- "清空尺寸库"需要输入二次确认，防止误删真实数据。

### 5.2 尺寸录入

#### 家人尺寸字段

| 分组 | 字段 | 默认单位 | 说明 |
| --- | --- | --- | --- |
| 身体尺寸 | 身高 | cm | 真实测量值 |
| 身体尺寸 | 体重 | kg | 真实称量值 |
| 身体尺寸 | 胸围 | cm | 可选 |
| 身体尺寸 | 腰围 | cm | 可选 |
| 身体尺寸 | 臀围 | cm | 可选 |
| 身体尺寸 | 肩宽 | cm | 可选 |
| 身体尺寸 | 臂长 | cm | 可选 |
| 身体尺寸 | 裤内长 | cm | 可选 |
| 衣物鞋饰 | 衣服尺码 | 文本 | 例如 M、170/88A，用户自己确认 |
| 衣物鞋饰 | 鞋码 | 文本 | 例如 38、240，用户自己确认 |
| 衣物鞋饰 | 脚长 | cm | 可选 |
| 衣物鞋饰 | 戒指圈号 | 文本 | 例如 12 号、US 6 |
| 衣物鞋饰 | 戒指内径 | mm | 可选 |
| 自定义 | 其他尺寸 | 名称+数值+单位 | 每个档案最多 10 条 |

#### 空间尺寸字段

| 档案类型 | 字段 | 默认单位 | 说明 |
| --- | --- | --- | --- |
| 房间 | 长 / 宽 / 高 | cm | 真实测量值 |
| 房间 | 面积 | 自动 | 由真实长宽计算并标注"由长宽计算" |
| 书桌 | 长 / 宽 / 高 | cm | 真实测量值 |
| 窗帘 | 窗户宽 / 窗户高 | cm | 真实测量值 |
| 窗帘 | 窗帘宽 / 窗帘高 | cm | 真实测量值 |
| 窗帘 | 轨道长 | cm | 可选 |
| 窗帘 | 落地高度 | cm | 可选 |

#### 校验规则

- 数值字段允许小数一位，禁止空数值保存到主字段。
- 身高 30-250 cm，体重 2-300 kg，身体围度 20-200 cm。
- 房间长宽高 10-10000 cm，书桌长宽高 10-1000 cm，窗帘尺寸 10-1000 cm，戒指内径 8-30 mm。
- 文本字段 1-40 个字符，备注 1-60 个字符。
- 单位只允许 cm、m、mm、kg；不提供内置换算表，展示时保留用户录入时的单位。
- 所有主字段未填写时显示"未填写"，不允许自动填充。

### 5.3 购买核对

购买核对是尺寸库的核心使用场景，本期一次交付以下六种场景：

1. 买衣服：展示身高、体重、胸围、腰围、臀围、肩宽、臂长、衣服尺码与备注。
2. 买鞋：展示鞋码、脚长与备注。
3. 买戒指：展示戒指圈号、戒指内径与备注。
4. 买书桌：展示书桌长宽高、关联房间与备注。
5. 买窗帘：展示窗户宽高、窗帘宽高、轨道长、落地高度与备注。
6. 房间软装：展示房间长宽高、面积、关联书桌与窗帘。

规则：

- 选择购买场景后，目标档案中不相关字段不展示。
- 相关字段未填写时显示"未填写"，不允许用其他字段推算。
- 提供"复制全部尺寸"，复制内容来自用户真实录入值，格式如下：

```text
妈妈 · 买衣服
身高 158cm
体重 62kg
胸围 88cm
腰围 78cm
臀围 94cm
衣服尺码 L
备注 肩宽偏窄
最后更新 2026-08-06 09:12
```

- 复制成功后轻提示"已复制真实尺寸"，不写入商品平台，不做跳转。

### 5.4 空间与关联

- 房间详情页显示长宽高与"由长宽计算"的面积，并列出关联书桌和窗帘。
- 书桌详情页显示长宽高、放置房间和备注。
- 窗帘详情页显示窗户、窗帘、轨道、落地高度和备注。
- 删除房间时，已关联的书桌/窗帘保留档案但清空关联房间，避免误删真实数据。
- 面积只在用户真实填写长和宽后显示，不预置任何示例值。

### 5.6 持久化与账号

- 本机为第一数据源：档案与尺寸写入 AsyncStorage / Web localStorage。
- 未登录用户可完整使用，数据保存在当前设备。
- 登录用户进入时自动从账号拉取并合并到本机，修改后自动同步到账号。
- 同一账号多设备以 `updatedAt` 为准做最后写入覆盖，并在界面提示同步状态。
- 尺寸库属于隐私数据，不出现在公开资料、社交动态或排行榜中。

## 6. 交互细节与状态

### 6.1 页面状态

- 加载态：读取本地与账号数据期间显示现有 PageLoadingFrame 工作台样式。
- 空态：无任何档案时显示空态引导，不出现占位假数据。
- 错误态：同步失败时保留本机数据，顶部提示"同步失败，已使用本机数据"，不阻断录入。
- 保存态：保存按钮进入加载态，成功后返回并轻提示。
- 删除态：删除前二次确认，删除后立即更新列表。

### 6.2 关键约束

- 所有可点击区域不小于 40px。
- 输入框、单位选择、备注等控件尺寸固定，内容变化不导致布局跳动。
- 尺寸值使用等宽数字特性，编辑后长度变化不影响同行对齐。
- 家人、房间、书桌、窗帘在手机窄屏下不截断、不遮挡，必要时换行。
- 320px 起所有视口不横向溢出、不重叠。

## 7. 数据模型

```text

SizeMeasurement {

SizeLibraryState {
```

## 8. 技术方案

### 8.1 前端

- 新增 `frontend/types/size-library.ts`，定义档案、尺寸、状态与维度元数据。
- 新增 `frontend/lib/size-library.ts`，负责档案增删改、尺寸校验、购买核对卡生成与复制文本。
- 新增 `frontend/lib/size-library-storage.ts`（Web 与 Native 各一份实现），读写本机真实数据。
- 新增 `frontend/lib/size-library-api.ts`，负责登录账号同步。
- 新增 `frontend/features/tools/size-library-screen.tsx`，在 `ToolDetailScreen` 增加路由映射。
- 购买核对文本由真实 `measurements` 生成，不允许拼接任何预置值。

### 8.2 后端

- 新增 `backend/internal/sizelibrary` 包，沿用 SQLite 全量状态存储模式。
- 新增接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/size-library/state` | 拉取当前账号尺寸库 |
| PUT | `/api/v1/size-library/state` | 全量保存尺寸库 |
| DELETE | `/api/v1/size-library/state` | 清空尺寸库 |

- 服务端执行与前端一致的档案数量、名称长度、维度 key、单位与数值范围校验。
- 接口只接受真实用户输入，不提供任何默认档案、默认尺寸或估算逻辑。

### 8.3 测试

- 档案管理：家人/房间/书桌/窗帘增删改、重名、数量边界、删除确认。
- 尺寸校验：数值范围、单位白名单、文本长度、未填写态、自定义尺寸。
- 购买核对：六种场景只展示相关字段，缺失字段显示"未填写"，复制文本与真实数据一致。
- 搜索：新增关键词在首页搜索全部可命中。
- 存储：本地持久化、清空、登录同步、同步失败降级。
- UI：Node 测试覆盖空态、录入态、档案详情、购买核对与空间关联关键逻辑。
- Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。

## 10. 关键风险与决策

| 风险 | 决策 |
| --- | --- |
| 尺寸缺失导致误买 | 相关字段未填写时显示"未填写"，不做任何估算 |
| 尺码推算不准确 | 衣服尺码、鞋码、戒指号全部由用户确认后录入 |
| 家庭数据隐私 | 本地优先，仅同步到本人账号，不进入公开场景 |
| 尺寸会随时间变化 | 每条尺寸记录更新时间，详情页展示最后更新 |
| 房间与家具关联复杂 | 只做单层关联：房间关联书桌和窗帘，删除房间不清空家具档案 |
| 数据迁移 | 状态模型带 `schemaVersion`，后续升级可做兼容解析 |
