# FunBox 股票交易提醒 产品设计方案 V1

> 版本：V1 草案
> 日期：2026-08-03
> 状态：待评审
> 定位：用户输入股票代码或名称，系统基于近 3 个月真实日线行情与当日真实分时数据，由 DeepSeek-V4-Flash 生成今日买卖点信号规则，后台实时监听分时波动，当前价格与指标满足条件时给出精确买卖点，并通过 Server酱 推送到微信，在 FunBox 站内消息中心留痕。
> 交付原则：一期全量交付，不分期、不降级为演示数据。

## 1. 背景与问题

1. 行情工具停留在“看盘”阶段：FunBox 已有市场雷达能看到板块强弱，但用户无法对单只股票设置可执行的买卖点提醒。
2. 静态参考区间不够用：单纯给“1410-1430”这类大致区间，无法应对盘中分时波动，用户仍不知道当下这一分钟是不是买点。
3. AI 建议不可验证：泛泛的“近期强势、可以关注”无法落到具体价格与触发时刻，用户不知道何时买、何时卖、何时止损。
4. 缺少提醒渠道：用户不会一直停留在 App 内，需要在分时信号触发时主动收到微信推送。
5. 数据可信度风险：任何用假数据或演示数据包装出来的“买卖点”都会直接伤害用户信任，必须全部使用真实上游行情，并且把数据来源、计算口径和时效展示清楚。

## 2. 产品目标

1. 从“输入代码/名称”到“看到可执行的买卖点信号规则”，3 秒内完成标的解析，10 秒内完成首次 AI 分析。
2. 每个标的给出精确的分时触发价、信号条件、止损触发价、观察有效期和理由要点，不再只是大致参考区间。
3. 交易时段内实时监听分时价、分时均线、量能变化与盘口特征，信号满足后立即判定，触发后同时写入站内消息中心并通过 Server酱 推送微信。
4. 所有行情数字保留来源、更新时间和计算口径；上游不可用时明确报错，绝不回退到演示数据。
5. 复用 FunBox 现有账号体系、后端限流、DeepSeek 配置和视觉体系，一期一次交付完成。

## 3. 目标用户与场景

| 用户 | 核心场景 | 产品要满足 |
| --- | --- | --- |
| 有自选股的散户 | 盯着一只股票不知道什么时候买/卖 | 快速给出分时触发价与信号条件 |
| 上班族 | 盘中无法一直盯盘 | 分时信号触发后微信收到提醒 |
| 已使用市场雷达的用户 | 从板块切到个股 | 单个标的独立分析、独立管理提醒 |
| 新手用户 | 不理解技术指标 | 用一句话说明触发依据，不堆术语 |

## 4. 一期全量范围

本次一次性交付，不设分期：

- 自选列表：添加/删除/暂停/开启提醒，展示最新分时价、分时均线、涨跌幅与信号状态。
- 标的解析：支持 A 股（沪深京）、港股、美股，按代码或名称搜索真实标的。
- AI 买卖点分析：90 个交易日真实日 K + 当日真实分时快照 + 结构化技术特征，由 DeepSeek-V4-Flash 生成今日信号规则。
- 分时实时监听：交易时段后台高频拉取真实分时价与分时序列，按信号规则实时判定当前是否为合适买点/卖点。
- 双通道提醒：站内消息中心 + Server酱 微信推送。
- 消息中心：提醒历史、未读状态、跳转详情。
- Server酱 设置：SendKey 绑定/更换/测试推送/额度展示，支持 SCT 与 SC3。
- 状态覆盖：加载中、解析失败、数据不足、上游不可用、分析过期、推送失败、已触发等状态一次做全。

## 5. 核心流程

```text
输入代码/名称
  → 东方财富真实标的口径解析（失败则明确提示，不出演示结果）
  → 拉取近 90 个交易日复权日 K 线 + 当日真实分时序列 + 最新真实行情
  → 后端计算日线与分时结构化特征（均线/RSI/MACD/BOLL/支撑压力/分时均价/量比/涨速等）
  → DeepSeek-V4-Flash 基于特征 JSON 生成今日买卖点信号规则（精确触发价 + 信号条件，后端校验）
  → 加入自选并开启实时监听（默认有效期 5 个交易日）
  → 交易时段后台每 10 秒检查最新分时价，分钟级校验分时均线与量能信号
  → 分时信号触发 → 站内消息 + Server酱 微信推送（含精确触发时刻与价格）
  → 用户点击消息进入个股详情查看触发依据
```

兜底路径：
- 标的无法解析：提示“未找到匹配标的，试试 600519 / 贵州茅台 / NVDA”。
- 90 日 K 线或当日分时数据不足：提示“历史/分时数据不足，无法生成买卖点”，不降级分析。
- 上游行情不可用：展示可重试错误，保留最近一次成功快照并标注 stale，stale 数据不触发提醒。
- 盘中休市或停牌：展示“休市/停牌，暂停分时监听”，恢复后自动继续。
- Server酱 未绑定或推送失败：站内消息仍然保留，设置页给出失败原因。

## 6. 功能设计

### 6.1 自选首页

- 顶部输入框：占位文案“输入股票代码或名称，如 600519 / 贵州茅台”。
- 主按钮“AI 分析并开启分时提醒”：解析成功、日线与分时数据全部就绪后加入自选并开始监听。
- 自选列表行字段：股票名称、代码/市场、最新分时价、分时均线、涨跌幅、信号状态、迷你分时走势、提醒开关。
- 当前状态五态：
  - 分时监听中：尚未满足任何信号条件。
  - 买入信号触发：分时价与指标满足买入条件，消息已推送。
  - 卖出信号触发：分时价与指标满足卖出条件，消息已推送。
  - 止损信号触发：分时价跌破止损触发价。
  - 信号待确认：接近触发阈值但未完全满足（如价格接近但量能不足）。
- 空态：引导添加第一只股票，展示 3 个热门示例但点击后仍走真实分析。

### 6.2 标的解析与搜索

- 输入支持：6 位数字代码、带市场后缀代码（600519.SH / 00700.HK / NVDA）、中文名称、英文名称。
- 解析接口返回真实候选列表，用户可确认或选择；命中唯一标的时直接进入分析。
- 市场映射：沪市 `1.`、深市/北交所 `0.`、港股 `116.`、美股 `105/106/107.`，具体以东方财富 suggest 接口联调结果为准。
- 解析失败不做模糊“编造”，只提示用户换一种写法。

### 6.3 AI 买卖点方案与分时信号规则

后端先计算结构化特征，再交给 DeepSeek-V4-Flash：

| 特征 | 口径 |
| --- | --- |
| 价格序列 | 近 90 个交易日复权日 K 线（OHLCV） |
| 均线 | MA5 / MA10 / MA20 / MA60 |
| 动量 | RSI14、MACD（DIF/DEA/柱） |
| 波动 | BOLL 上轨/中轨/下轨、近 20 日振幅 |
| 支撑压力 | 近 60 日阶段高低点、近期平台上下沿 |
| 量能 | 最新量比、近 5/20 日均量 |
| 区间表现 | 近 20/60/90 日涨跌幅、最大回撤 |
| 分时价格 | 当日分时序列：最新价、分时均价、日内高低点 |
| 分时均线 | 当前价与分时均价的位置关系、上穿/下穿状态 |
| 分时量能 | 分钟量、量比、放量/缩量状态、5 分钟涨速 |
| 盘口参考 | 买卖五档委比、内外盘（真实公开数据可用时） |

DeepSeek 输出 JSON 必须包含“今日信号规则”，每条规则都是可执行的分时判定条件：

```json
{
  "buySignal": {
    "triggerPrice": 1450.0,
    "conditions": ["分时价站稳 triggerPrice 上方", "分时价位于分时均价上方", "量比 >= 1.2"],
    "referenceZone": { "low": 1440.0, "high": 1458.0 }
  },
  "sellSignal": {
    "triggerPrice": 1458.6,
    "conditions": ["分时价放量突破 triggerPrice", "5 分钟涨速 >= 0.8%"],
    "referenceZone": { "low": 1458.6, "high": 1510.0 }
  },
  "stopLoss": { "triggerPrice": 1440.0, "condition": "分时价跌破 triggerPrice" },
  "validTradingDays": 5,
  "reasons": ["现价贴近 MA20 且 BOLL 下轨附近", "RSI14 处于 32 低位区间", "分时量能不足，等待放量确认"],
  "summary": "今日以分时均价为强弱分界，回踩站稳 1450 放量确认买入，放量突破 1458.60 触发卖出观察"
}
```

防幻觉规则：
- 所有理由只能引用后端传入的真实特征字段，不能编造新闻、业绩、政策。
- 后端校验每个触发价与条件：必须落在真实日线与分时数据可解释范围内，且满足 `止损触发价 < 买入触发价 ≤ 卖出触发价`；不合法则重试一次，仍不合法则返回明确错误。
- 信号规则只在每个交易日开盘前或用户点击“重新分析”时生成，盘中判定由后端确定性引擎执行，不依赖 LLM 逐笔响应。
- 页面展示模型标识（DeepSeek-V4-Flash）与数据截止时间。

### 6.4 分时实时监听与触发规则

- 监控任务只读真实分时行情、只做确定性信号判定，不调用 LLM，保证触发判定可复现、可测试。
- 交易时段轮询间隔默认 10 秒；A 股默认 09:30-11:30、13:00-15:00（周一到周五），港股/美股按各自交易所时段；休市/停牌自动暂停。
- 分时数据源：东方财富真实分时序列接口（`trends2/get`，含每分钟价格与分时均价），每次拉取当日完整分时并增量更新，绝不本地生成演示分时。
- 触发判定：
  - 买入：分时价满足 `triggerPrice` 与条件组合（如站稳关键价 + 位于分时均价上方 + 量比达标）。
  - 卖出：分时价满足卖出触发价与放量/涨速条件。
  - 止损：分时价跌破 `stopLoss.triggerPrice`，无需量能确认。
- 信号强度分级：满足全部条件为“确认信号”，只满足价格条件为“观察信号”，观察信号不推送、只在列表与详情展示。
- 去重：同一标的同一信号规则下同一方向每个交易日最多推送 1 条；分时价回落超过 0.3% 后再次满足才可重新触发。
- 有效期：默认 5 个交易日，到期后状态变为“分析已过期”，提示一键重新分析，不自动删除自选。
- 行情新鲜度：触发判定只使用不超过 15 秒的最新分时快照；行情更新超时则跳过本轮并记录健康状态，绝不使用过期价格触发。

### 6.5 提醒消息中心

- 消息字段：标的名称/代码、信号方向（买入/卖出/止损）、精确触发时刻（HH:MM:SS）、触发时最新分时价、分时均价、信号条件摘要、是否已推送 Server酱、是否已读。
- 消息可点击跳转到对应个股详情。
- 未读红点在工具页与底部导航消息入口展示；进入后自动标记已读。
- 站内消息与 Server酱 独立存储推送状态，推送失败不影响站内留痕。

### 6.6 Server酱 设置

- SendKey 支持 SCT（sct.ftqq.com）与 SC3（sc3.ft07.com），由官方 serverchan-sdk 自动识别。
- 提供“测试推送”按钮，发送一条带当前页面标题的测试消息，展示接口返回 code/message。
- 展示当日已用/免费额度（Turbo 免费版每日 5 条），并提示“超出免费额度后仍可收到站内提醒”。
- SendKey 只允许写入、不允许回显完整值，前端只显示脱敏 Key（如 `sct****NoMR`）。
- 推送失败时消息中心保留记录，并在设置页展示最近一次失败原因。

### 6.7 个股详情

- 实时监听头：实时状态（监听中/休市/数据缺失）、最近一次分时刷新时间、最新分时价与分时均价。
- 分时图：当日真实分时价格线 + 分时均价线 + 买入/卖出/止损触发价标记 + 已触发信号点。
- 90 日 K 线：可切换 MA5/10/20/60，作为分时判定的历史背景。
- 今日信号规则卡：三列展示买入触发价、卖出触发价、止损触发价及各自的信号条件，而不是大致区间。
- 分时信号时间线：当天每次“观察信号/确认信号”发生的时刻、价格与依据，可追溯。
- 触发依据：3-5 条结构化理由，每条可对应到具体日线或分时指标值。
- 操作区：开启/暂停提醒、重新分析、删除自选。
- 数据卡：来源（东方财富）、行情延迟说明、分析模型、数据截止时间、免责声明。

### 6.8 错误与边界状态

- 加载中：骨架屏 + “正在拉取真实行情”。
- 解析失败：明确提示，不出示任何猜测结果。
- 数据不足：少于 60 个有效交易日，或当日分时数据不可用/不足时，拒绝生成买卖点。
- 分时数据缺失：分时接口连续拉取失败时展示“分时数据缺失”，停止信号判定并保留站内错误状态。
- 盘中休市/停牌：暂停监听，恢复交易后自动继续。
- 上游不可用：可重试错误页；已有成功快照时展示 stale 快照但禁用触发提醒。
- 分析过期：状态置灰，提供“重新分析”。
- Server酱 未绑定：绑定引导，站内提醒不受影响。
- 自选超上限：每用户默认 10 只，提示移除后添加。

## 7. 数据真实性与安全

### 7.1 真实数据来源

- 沿用市场雷达同源的东方财富公开接口，全部由 FunBox Go 后端发起，前端不直连第三方。
- 标的解析：东方财富 suggest 搜索接口。
- 最新行情：优先实时行情接口，失败回退延迟行情接口并明确标注“延迟行情”。
- 历史 K 线：近 90 个交易日复权日 K 线（`klt=101`、`fqt=1`）。
- 分时数据：当日真实分时序列接口（`trends2/get`，含每分钟价格与分时均价）；盘口五档与分笔成交仅在真实公开数据可用时使用。
- 所有上游 URL、缓存与超时均为后端配置，不在客户端 bundle 暴露任何行情密钥。

### 7.2 禁止假数据原则

- 生产环境不存在 mock 数据回退路径：无可用真实快照时返回可重试错误。
- 测试 fixture 只进入测试编译，绝不进入生产回退分支。
- stale 快照只能用于展示并标注，不能用于生成新分析或触发提醒。
- 任何“买卖点”“触发价”都必须能追溯到真实 K 线与真实分时价格计算。

### 7.3 LLM 幻觉防护

- 模型只接收结构化真实特征，不接收自由文本行情描述。
- 输出必须为 JSON 且通过 schema 与数值范围双重校验。
- 理由生成约束为“只引用给定指标”，并对“业绩、新闻、政策、内幕”等词做输出过滤。

### 7.4 免责声明

- 所有页面固定展示：仅供信息参考，不构成投资建议。
- 买卖点为模型基于历史与分时行情生成的信号规则，不承诺收益，不提供自动交易。

### 7.5 密钥与隐私

- Server酱 SendKey 仅在服务端保存，落库前加密，日志中脱敏，API 只返回掩码。
- 自选与提醒事件与用户 ID 绑定，接口全部走现有 JWT 鉴权。
- 不采集用户的券商、持仓、交易记录；本功能不接入真实下单。

## 9. 技术方案

### 9.1 后端模块

新增 `backend/internal/stockalert`：

| 子模块 | 职责 |
| --- | --- |
| `provider` | 东方财富 suggest / 实时行情 / 延迟行情 / 90 日 K 线 / 当日分时序列抓取与解析 |
| `indicator` | 日线 MA/RSI/MACD/BOLL/支撑压力/量比 + 分时均价/量比/涨速/委比等特征计算 |
| `analysis` | DeepSeek-V4-Flash 调用、JSON schema 与数值范围校验，输出今日信号规则 |
| `monitor` | 交易时段 10 秒级分时轮询、信号引擎判定、去重、推送与事件落库 |
| `store` | 自选、分析、提醒事件、Server酱 设置持久化 |

新增数据表（SQLite）：

```text
stock_watch_items   user_id, symbol, name, market, enabled, reminder_types, analysis_id, valid_until, created_at
stock_analyses      id, watch_item_id, model, data_end_date, buy_trigger, buy_conditions_json, sell_trigger, sell_conditions_json, stop_loss_trigger, reasons_json, feature_snapshot_json, created_at
stock_alert_events  id, user_id, watch_item_id, direction, signal_strength, trigger_time, trigger_price, intraday_avg_price, signal_conditions_json, pushed_status, pushed_message, read_at, created_at
stock_alert_settings user_id, sendkey_encrypted, reminder_enabled, updated_at
```

### 9.2 接口设计（草案）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/stock-alert/search?q=` | 真实标的口径解析 |
| POST | `/api/v1/stock-alert/watch` | 添加自选并触发首次分析 |
| GET | `/api/v1/stock-alert/watch` | 自选列表 + 最新分时价/分时均价 + 信号状态 |
| GET | `/api/v1/stock-alert/watch/{symbol}` | 个股详情 + 分析 + 近期事件 |
| PATCH | `/api/v1/stock-alert/watch/{symbol}` | 暂停/开启、提醒类型、有效期 |

### 9.3 DeepSeek 复用与模型

## 10. 非功能需求

- 性能：自选列表 P95 < 800ms；分时刷新接口 P95 < 500ms；AI 分析允许异步，首次分析期间显示进度状态。
- 限流：沿用现有后端限流配置，分析接口单独限频。
- 弱网：列表/详情支持本地缓存，缓存内容仅用于展示并标注时间。
- 主题：支持 FunBox 浅色/深色主题。
- 布局：320px / 390px / 430px 三档宽度无溢出、无重叠，数字使用等宽排版避免刷新跳动。
- 可观测：监控任务记录每次轮询健康度，上游持续失败时生成可排查日志。

## 11. 验收标准

1. 输入真实代码/名称可解析出真实标的，解析失败不出现演示结果。
2. 分析结果必须基于近 90 日真实 K 线，页面展示数据截止时间、来源和模型标识。
3. 分时触发判定只使用真实分时快照（新鲜度 ≤ 15 秒），stale 数据不会触发提醒。
4. 买卖点必须是精确触发价与信号条件，能给出触发时刻与当时分时均价，而不是大致区间。
5. 触发后站内消息与 Server酱 推送均可用，Server酱 失败不影响站内消息。
6. 同一方向每个交易日去重，分时回落再触发逻辑有测试覆盖。
7. 每用户自选上限、分析日限、Server酱 免费额度约束生效。
8. 上游不可用、K 线不足、分时数据缺失、休市停牌、解析失败、分析过期、Key 未绑定等状态全部有明确 UI。
9. 生产代码不包含任何 mock 回退路径；测试 fixture 只用于测试。
10. Go 测试、TypeScript、lint、前端相关测试、全量既有测试通过。
11. 桌面与移动视口浏览器 QA 通过：无空白、无控制台错误、无元素重叠、无文字溢出。

## 12. 明确不做

- 不提供毫秒级实时成交保证，分时行情以东方财富公开数据为准并标注刷新时间与延迟。
- 不提供自动下单、券商接入、持仓同步。
- 不承诺收益，不生成收益预测。
- 不编造新闻、业绩、政策等非行情理由。
- 不做社交分享、社区跟单、付费订阅。

## 13. 设计说明（对应设计稿）

- 三屏主链路：自选列表 → 分时实时监听详情 → 提醒消息与 Server酱 设置。
- 首页只做一件事：输入标的并开启分时提醒；其余全部由系统推进。
- 详情页信息分层：实时监听状态 → 分时图与触发价标记 → 今日信号规则 → 分时信号时间线 → 操作与数据卡。
- 提醒消息突出“方向、触发价、触发时间、推送状态”，让用户一眼判断发生了什么。
- 全量状态覆盖放在设计稿底部，表示一期包含全部异常与边界状态，不是分阶段补做。
- 视觉直接复用 FunBox 现有体系：浅蓝背景、白色表面、深藏青重点、主蓝操作、青柠强调、细分隔线，圆角不超过 8px，图标使用 Material Community Icons。
