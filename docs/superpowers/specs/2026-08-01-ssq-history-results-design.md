# 双色球历史开奖记录查询设计

## 设计结论

在双色球二级功能选择页的深色说明区后新增独立的“历史开奖记录”卡片，置于概率参考与两个实验室入口之前。入口采用与现有卡片相同的尺寸、圆角、排版和按钮结构，使用绿色作为事实查询语义色，避免与粉色概率参考、蓝色 V2、橙色 V1 混淆。

点击后进入 `/tools/double-color-ball-history`。页面复用现有 `GET /api/v1/lottery/ssq/history` 数据，不新增上游请求和依赖；MVP 明确展示实际覆盖期数，不承诺全部历史。

## 页面结构

1. 顶部栏：返回按钮、标题“历史开奖记录”、占位右侧槽位。
2. 数据概览：最新期号、已加载期数、官方来源、同步时间；缓存数据展示黄色提示。
3. 查询区：完整期号、开始日期、结束日期、查询、重置。
4. 快捷范围：近 30 期、近 100 期、近 400 期，默认近 30 期。
5. 结果列表：期号、日期、6 个红球、1 个蓝球，按期号倒序；100/400 期范围按 30 条继续加载。
6. 详情态：点击列表项后原页切换到详情，展示期号、日期、号码、来源、同步时间；返回恢复查询条件和列表位置。
7. 底部说明：开奖结果仅为官方历史事实，开奖为独立随机事件。

## 逻辑边界

- 期号仅接受数字，按完整期号精确匹配。
- 日期必须为 `YYYY-MM-DD`，开始日期不得晚于结束日期。
- 红球按升序和两位数展示，蓝球单独分隔并带“蓝球”可访问语义。
- 过滤顺序为：快捷范围截取 -> 期号精确过滤 -> 日期范围过滤 -> 分页展示。
- 上游失败且无页面数据时展示可重试错误态；接口返回 `stale=true` 时保留数据并明确提示。

## 技术边界

- 新建 `frontend/lib/double-color-ball-history.ts`，承载纯函数查询、日期校验和分页逻辑。
- 新建 `frontend/features/tools/double-color-ball-history-screen.tsx`，承载页面状态和渲染。
- 修改 `frontend/features/tools/double-color-ball-hub-screen.tsx` 新增入口。
- 修改 `frontend/features/tools/tool-detail-screen.tsx` 注册页面组件。
- 修改 `backend/internal/access/feature_registry.json` 增加隐藏工具路由，使统一权限和路由解析继续工作。
- 不修改后端开奖服务，不新增 npm 依赖，不触碰当前工作区的其他未提交改动。

## 测试策略

- 纯函数使用 Node 内置测试框架按 TDD 覆盖：范围截取、精确期号、日期区间、非法日期、分页和号码格式。
- 运行现有双色球测试、前端 lint、TypeScript 检查和 Expo Web 导出构建。
- 启动本地 Expo Web，只使用 Codex 内置 Browser 验证桌面与移动视口：入口可见、路由跳转、页面非空、筛选、详情/返回、控制台健康和截图证据。
