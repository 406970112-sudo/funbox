# 小程序交互优化

用户已批准上一轮提出的八点，并要求 UI 与现有风格一致。此文件将已批准方案具体化。

## 目标和范围
1. 首页在验证当前身份和服务端状态后，展示继续当前牌局。游客原身份可恢复，账号身份不跨账号泄露；失效或结束房间不再作为进行中展示，暂时断网保留缓存并允许重试。
2. 排行榜随分数排序，给分输入按座位/加入时间稳定排序；提供常用 +1/+5/+10 快捷给分和清空，展示本人扣分、各收分者加分预览，按钮显示合计。
3. 麻将、通用记分由房主在记录里撤销普通批次。复用服务端 reverse 接口、确认权限和版本；展示原记录已撤销和独立的冲正记录，不允许重复撤销或对冲正记录撤销。
4. 等待页明确实际人数、开始后本局成员固定；麻将不足四人需明确确认。通用房间也明确当前人数。
5. 提交失败在给分/结算操作附近可见，草稿保留；区分实时通道恢复（轮询正常）与真正断网；真正断网暂停写入，恢复后先同步再操作，防重复提交。
6. 麻将、通用、炸金花结算优先显示本人应付/应收具体清单、提供复制完整结算清单；麻将和通用提供按本局设置再开一局的入口，预填房间名、本人昵称和玩法，不携带密码或直接创建。原每分金额仍结算时设置。
7. 等待房间提供房主取消；活动中完全没有账目时提供结束且无需结算；有历史账目必须正常结算，哪怕当前净分为零。返回首页只导航，不改变房间状态。
8. 表情包列表使用追加式加载更多，保留列表和浏览位置，失败后原内容仍可使用；列表独立收藏按钮、长按菜单（预览/收藏或取消/分享图片）。无搜索结果时一键沿用关键词联网搜图。复用详情页的下载/分享和收藏能力，不复制大段逻辑。

## 视觉和实现约束
沿用 #f5f7fa 背景、#2d5bff 主色、白色圆角卡片、淡蓝辅助按钮、现有插画和安全区布局；不增加依赖或新视觉体系。保持原生 WXML/WXSS/JS 和现有 Go 后端。账目以服务端为准，命令仍使用版本控制和操作 ID，不做本地假记分，不绕过权限，不自动重试账目写入。完整保留游客模式、账号绑定和现有炸金花规则。

## 方案选择
采用渐进式优化现有页面、复用已有逆向记分和取消接口。独立重构整套页面会扩大回归范围；完全只改文案无法解决返回、纠错、断网和连续浏览问题。用户已选择按八点实施且保持现有风格。

## 验收
Node 全套小程序测试、Go 全套测试；重点覆盖失效身份、跨账号、旧版本冲突、重复撤销、有历史但净分为零、断网恢复、加载更多失败和重复项、收藏失败恢复。使用本机微信开发者工具编译和模拟器检查主页面；不在生产创建或更改真实牌局。
