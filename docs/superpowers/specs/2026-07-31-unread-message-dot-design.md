# 未读消息红点设计

## 目标

当用户存在未读聊天消息时，在底部导航的“消息”图标右上角显示红点。红点只表示聊天消息，不包含好友申请；只有所有未读会话都被打开并成功标记为已读后，红点才消失。

## 现有能力

- 后端会话接口已经返回每个会话的 `unreadCount`。
- `SocialProvider` 在登录后加载会话，并在 WebSocket 收到实时事件时刷新会话数据。
- 聊天页已经调用会话已读接口。
- 消息列表已经根据 `unreadCount` 显示逐会话未读数量。

因此本功能不新增后端接口，也不维护独立的未读状态。

## 前端设计

新增一个纯函数，汇总所有会话的未读消息数。底部 Tab 布局从 `SocialProvider` 获取会话列表，并根据汇总结果决定是否渲染红点。

“消息”图标使用固定尺寸容器。红点绝对定位在图标右上角，直径约 8 像素，使用高对比红色和浅色描边，不参与布局计算，避免出现或消失时导致导航栏位移。界面只显示红点，不显示数字；聚合数量可用于无障碍标签和测试。

## 状态流转

1. 初次登录或刷新时，会话接口返回 `unreadCount`，底部导航据此显示红点。
2. 收到 `message.created` 实时事件时，现有 WebSocket 流程刷新会话列表，红点在任何页面都能更新。
3. 用户打开具体会话后，通过 `SocialProvider.markRead` 调用现有已读接口。
4. 已读接口成功后，仅把该会话的本地 `unreadCount` 置零，使红点立即重算。
5. 若仍有其他未读会话，红点继续显示；全部为零时红点消失。
6. 若已读接口失败，本地状态不清零，红点继续显示，避免误报已读。

## 范围

- 包含底部“消息”入口红点、未读聚合逻辑、聊天页已读状态接入和相关测试。
- 不包含好友申请红点、数字角标、系统通知、推送通知或后端数据结构变更。

## 验证

- 单元测试覆盖无会话、全部已读、单个未读、多个未读和异常计数归一化。
- 运行前端 lint 与新增测试。
- 使用内置浏览器在桌面和手机宽度下验证：未读时出现红点、读取部分会话后保留、全部读取后消失、实时新消息后重新出现，并检查图标与文字不重叠。
