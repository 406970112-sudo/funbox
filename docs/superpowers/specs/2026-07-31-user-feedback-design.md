# 问题反馈功能设计

## 目标

为已登录用户在“我的”栏目新增“问题反馈”入口。用户可以填写问题描述并上传图片；管理员可以在管理后台查看所有反馈、用户信息、提交时间、完整描述和图片。用户端与移动端后台沿用 FunBox 现有视觉语言，桌面端后台使用宽屏铺开布局。

本期管理员后台仅提供只读查看，不包含回复、删除、处理状态或通知能力。

## 用户体验

### 用户入口

- 仅已登录用户可在“我的 > 账户”操作列表中看到“问题反馈”。
- 入口使用现有 `AccountAction` 的图标、颜色、间距和点击反馈。
- 点击后进入 `/profile/feedback`；匿名访问该路由时跳转到登录页。

### 反馈提交页

- 顶部使用现有个人资料页面的返回按钮和居中标题结构。
- 描述为必填多行输入框，去除首尾空白后限制为 10 至 1000 个字符。
- 图片为可选，允许 JPG、PNG、WebP，最多 3 张，单张最大 5 MB。
- 使用系统图片选择器并支持一次多选；已选图片以缩略图展示，每张图片均可移除。
- 提交按钮在内容无效、正在提交或图片超限时不可用。
- 提交期间显示加载状态并防止重复提交。
- 成功后清空表单，显示明确的成功结果和返回“我的”按钮。
- 图片选择权限被拒绝、文件类型或大小不合法、网络失败、登录失效时显示可恢复的中文错误提示。

## 管理后台

### 后台入口

- 管理员在“我的”中点击“管理后台”进入 `/admin`，不再直接进入权限页面。
- 后台首页提供“入口权限”和“问题反馈”两个入口，并复用现有深色概览区、主色、图标和卡片样式。
- `/admin`、`/admin/permissions` 和 `/admin/feedback` 均在前端校验管理员身份；非管理员回到“我的”。后端接口仍执行最终权限校验。

### 问题反馈列表

- 默认按提交时间倒序展示。
- 列表项显示用户昵称、账号、提交时间、描述摘要和图片数量。
- 无数据、首次加载、加载失败与重新加载均有独立状态。
- 本期数据量预期较小，接口采用 `limit` 和 `offset` 分页，页面提供“加载更多”，默认每页 30 条。

### 响应式布局

- 移动端宽度小于 768 px：使用现有 430 px 内容上限、单列反馈卡片和触控友好的间距；点击卡片后在同一路由中切换到详情视图，返回后保留列表数据。
- 桌面端宽度不小于 768 px：内容区域最大宽度 1440 px，左侧为可滚动反馈列表，右侧为固定详情面板；默认选中第一条反馈，点击列表项即时更新右侧。
- 桌面端图片使用自适应网格铺开展示；移动端使用单列或双列缩略图。点击图片打开全屏预览，支持关闭。
- 两种布局共享同一份数据状态和详情组件，只改变排列方式，避免行为分叉。

## 数据与存储

### SQLite

新增独立 `feedback` 业务模块并复用当前 SQLite 数据库。

`feedback_submissions`：

- `id`：随机字符串主键。
- `user_id`：提交用户 ID，外键关联 `users`。
- `description`：清理后的问题描述。
- `created_at`：UTC Unix 时间戳。

`feedback_images`：

- `id`：随机字符串主键。
- `feedback_id`：关联反馈 ID，删除反馈时级联删除元数据。
- `stored_name`：服务器生成的不可猜测文件名。
- `content_type`：校验后的 MIME 类型。
- `size_bytes`：文件大小。
- `sort_order`：用户选择顺序。

数据库迁移使用现有模块的幂等建表方式，并为 `feedback_submissions.created_at` 和 `feedback_images.feedback_id` 建索引。

### 图片文件

- 图片写入 `STORAGE_FEEDBACK_DIR`，默认 `data/feedback-images`。
- 生产部署把该目录映射到现有共享持久化根目录，确保发布切换后文件不丢失。
- 配置项 `STORAGE_MAX_FEEDBACK_IMAGE_BYTES` 默认 5242880，`STORAGE_MAX_FEEDBACK_IMAGES` 默认 3。
- 服务端根据实际文件头识别 JPEG、PNG、WebP，不信任客户端文件名或 MIME。
- 文件名由反馈 ID、图片 ID 和受控扩展名组成，禁止使用用户提供路径。
- 创建失败时删除本次已写入的文件并回滚数据库事务，避免孤立文件或半条反馈。

## API 设计

### 提交反馈

`POST /api/v1/feedback`

- 必须携带 Bearer Token。
- 使用 `multipart/form-data`。
- `description` 为单个文本字段；`images` 为可重复文件字段。
- 服务端再次校验描述长度、图片数量、单图大小、总请求大小和真实图片类型。
- 成功返回 `201`、反馈 ID 和创建时间，不回传私有图片地址。

### 管理员读取

`GET /api/v1/admin/feedback?limit=30&offset=0`

- 必须是管理员。
- 返回分页反馈、用户公开信息和图片元数据，不返回磁盘路径。

`GET /api/v1/admin/feedback/{feedbackID}/images/{imageID}`

- 必须是管理员。
- 校验图片确实属于指定反馈后再读取文件。
- 返回正确 `Content-Type`、内容长度和私有缓存策略。
- 前端图片请求携带管理员 Bearer Token，不提供公开静态目录。

## 前端模块

- `types/feedback.ts`：反馈、图片、提交资源和分页响应类型。
- `lib/feedback-api.ts`：跨 Web/Native 组装 multipart、提交反馈、读取管理员列表和生成受保护图片请求。
- `features/feedback/feedback-submit-screen.tsx`：用户表单、选择器、校验和提交结果。
- `features/feedback/admin-feedback-screen.tsx`：共享状态、分页、桌面双栏与移动详情切换。
- `features/feedback/admin-home-screen.tsx`：管理后台首页。
- Expo Router 路由文件仅负责挂载对应屏幕。

业务校验和响应式决策尽量提取为无 UI 的纯函数，便于 Node 测试；页面组件保留渲染与交互职责。

## 安全与错误处理

- 用户提交和管理员查询分别使用现有 `withAuth`、`withAdmin` 与 API 流水线。
- 上传请求设置独立的总大小上限，避免通用 JSON 请求上限误伤，也避免未受限 multipart 消耗内存或磁盘。
- 所有数据库错误、文件系统错误和校验错误映射为稳定错误码；客户端统一映射为中文提示。
- 不在日志、API 或前端状态中暴露真实磁盘路径。
- 图片接口拒绝不匹配的反馈 ID、图片 ID、越权用户和不存在文件。

## 测试与验收

### 后端测试

- 幂等迁移、创建反馈、图片顺序和按时间倒序分页。
- 未登录提交返回 401，普通用户访问管理员接口返回 403。
- 描述过短、过长、空白，图片过多、过大、伪造类型均被拒绝。
- 多图片成功持久化；中途失败时数据库与文件均回滚。
- 管理员可读取图片；普通用户、错误归属和未知 ID 不可读取。

### 前端测试

- 描述规范化、长度校验、图片数量和文件大小校验。
- Web 与 Native multipart 字段名称及顺序一致。
- 断点规则在 768 px 两侧分别选择移动和桌面布局。
- 分页合并不重复，加载失败可重试。

### 运行验证

- 运行 Go 全量测试和前端 lint、TypeScript 检查及新增 Node 测试。
- 启动本地前后端，使用真实登录用户提交文字与多张图片。
- 使用管理员账号在桌面宽屏和移动窄屏查看同一条反馈，确认描述、用户、时间和所有图片一致。
- 检查无溢出、遮挡、空白图片、控制台错误和失败网络请求。
