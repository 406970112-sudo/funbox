# 双色球概率参考功能设计

日期：2026-07-31  
状态：设计已确认，等待规格复核

## 1. 产品目标

在 FunBox 的“工具”栏目增加“双色球概率参考”。用户可以查看官方历史开奖的统计结构，并生成五组可解释、低重合的下一期参考号码。

产品必须始终说明：双色球开奖是随机事件，每个合法单式组合的一等奖理论概率相同。历史频次、遗漏和结构匹配度只描述数据与生成规则，不代表未来中奖概率提高。

首版成功标准：

- 用户在 30 秒内理解最近历史数据的冷热和常见结构。
- 每组参考号码都能查看区间、奇偶、和值和冷热构成依据。
- 五组参考号码之间保持较低重复，扩大号码覆盖，而不是反复推荐相同数字。
- 页面不出现“必中、稳赚、提高中奖率、AI 胜率”等误导表达。

## 2. 范围

首版包含：

- 中国福彩网官方历史开奖同步；界面最多分析最近 300 期，后端额外读取 100 期供走步回测。
- 近 30、100、300 期三个统计窗口。
- 红球与蓝球频次、遗漏、冷热分层。
- 红球三区比例、奇偶比例、和值区间和连号特征。
- 每期五组参考号码的生成、刷新和本地保存。
- 每组号码的结构匹配度与生成依据。
- 无未来数据泄漏的历史回测分布。
- 加载、刷新、数据过期、上游失败和无数据状态。

首版不包含：

- 购票、支付、追号、奖金计算和彩票店导流。
- 用户自定义“投注策略”、付费荐号或会员胜率承诺。
- 推送提醒、社区晒单、排行榜或收益统计。
- 用大模型生成号码或解释结果。

## 3. 用户流程

1. 用户从“工具”进入“双色球概率参考”。
2. 页面读取最近一次可用历史快照，默认展示近 100 期分析。
3. 用户可切换近 30、100、300 期，查看冷热与常见结构。
4. 用户点击“查看下期参考组合”，进入五组号码视图。
5. 用户选择某组号码，查看该组的三区、奇偶、和值、冷热构成和与最近一期重号数。
6. 用户可以“换一批组合”，生成同一数据窗口下的新批次；也可以保存当前批次。
7. 页面始终保留“仅供娱乐与概率研究参考”的责任提示。

## 4. 信息架构与界面

### 4.1 概率分析总览

顶部展示：

- 最新历史期号、开奖日期和数据更新时间。
- “下一期参考”状态，不把推算期号作为官方信息。
- 红球热区、蓝球关注和结构匹配度概览。
- 一等奖理论概率：`1 / (C(33, 6) × 16) = 1 / 17,721,088`。

主体展示：

- 30 / 100 / 300 期分段控制。
- 01-33 红球热力矩阵；蓝球用单独的 01-16 排名展示。
- 三区、奇偶、和值和连号的历史分布摘要。
- “查看下期参考组合”主按钮。

结构匹配度是 0-100 的规则贴合分数，衡量一组号码与所选历史窗口常见结构的接近程度。界面必须在分数附近注明“不是中奖概率”。

### 4.2 下期参考组合

页面展示五组组合，每组包含六个不重复红球和一个蓝球。每组有一个中性标签，例如“均衡型”“分散型”“冷热混合”，标签只描述生成策略。

用户选中组合后展示：

- 三区分布。
- 奇偶比例。
- 红球和值。
- 热号、中性号、冷号构成。
- 与最近一期红球重号数。
- 与同批其他组合的最大重合数。

回测区展示所有历史回测样本中，单组参考号码红球命中 `0-1`、`2-3`、`4+` 的分布。回测旁明确标注“仅描述模型行为，不代表未来表现”。

## 5. 数据来源与服务边界

官方来源：

- 游戏规则与责任提示来源：中国福利彩票发行管理中心网站 `https://www.cwl.gov.cn/`。
- 历史开奖接口：`https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice?name=ssq&issueCount=400`。
- 2026-07-31 已验证该接口返回 400 期，字段包含 `code`、`date`、`red`、`blue`。最新 300 期用于当前分析，更早 100 期只用于无未来数据泄漏的回测。

后端新增 `lottery` 模块，通过可替换的上游客户端读取官方数据。前端不直接请求中国福彩网，避免浏览器跨域、上游格式变化和来源校验逻辑散落在客户端。

后端公开接口：

```http
GET /api/v1/lottery/ssq/history
```

响应结构：

```json
{
  "source": "cwl",
  "sourceUrl": "https://www.cwl.gov.cn/",
  "fetchedAt": "2026-07-31T12:00:00Z",
  "stale": false,
  "analysisWindowMax": 300,
  "draws": [
    {
      "issue": "2026087",
      "date": "2026-07-30",
      "red": [4, 6, 10, 18, 23, 31],
      "blue": 11
    }
  ]
}
```

后端规则：

- 请求超时默认 10 秒，缓存有效期默认 15 分钟。
- 缓存保存最近 400 期。前端当前分析只读取最新 300 期，额外历史不可进入热度或结构统计。
- 每期开奖必须有六个 1-33 的不重复红球和一个 1-16 的蓝球。
- 无效记录跳过；有效记录少于 360 期时返回 `502 lottery_source_invalid`，因为 300 期窗口至少需要 60 个额外目标期完成约定回测。
- 上游失败且存在过期缓存时返回缓存并设置 `stale: true`；没有缓存时返回 `502 lottery_source_unavailable`。
- 响应中的数据按期号从新到旧排序，并去除重复期号。

## 6. 分析口径

所有分析逻辑放在前端纯函数模块中，输入为已验证的开奖数组和窗口大小，输出不可变分析结果。

### 6.1 频次与遗漏

- 红球频次：窗口内每个 01-33 出现次数。
- 蓝球频次：窗口内每个 01-16 出现次数。
- 遗漏：从最新一期向前查找号码最近一次出现的位置；最新一期出现为 0。
- 从频次与遗漏的标准化值生成历史活跃度，仅用于排序展示。
- 活跃度前 25% 为“热”，后 25% 为“冷”，其余为“中性”。

### 6.2 结构统计

- 三区：01-11、12-22、23-33。
- 奇偶：六个红球中的奇数和偶数数量。
- 和值：六个红球之和。
- 连号：相邻红球差为 1 的配对数量。
- 重号：与最新一期红球交集数量。

和值参考区间使用历史窗口的第 20 至第 80 百分位。三区、奇偶和连号参考使用窗口内出现次数最多的前三种模式。

## 7. 参考组合生成

生成器不宣称预测开奖。它的职责是从全部合法组合中筛选出符合所选历史结构、且五组之间重复较少的参考集合。

生成规则：

1. 使用 `窗口 + 最新期号 + 批次序号` 作为确定性随机种子。
2. 红球候选权重由活跃度和均匀基线组成，任何号码都保留非零权重。
3. 每组选择六个不重复红球并升序排列，再选择一个蓝球。
4. 仅接受满足以下约束的组合：
   - 三区模式属于历史常见前三种。
   - 奇数个数为 2、3 或 4。
   - 和值位于历史第 20 至第 80 百分位。
   - 最多包含一组连号。
   - 与最近一期红球重号不超过 2 个。
5. 同批任意两组红球重合不超过 2 个；蓝球优先不重复。
6. 最多尝试 5,000 次。若约束无法凑满五组，按“蓝球不重复、组间重合、连号、和值”的顺序逐级放宽，并在结果中记录实际放宽项。

结构匹配度由以下项目组成：三区 30 分、奇偶 20 分、和值 20 分、冷热混合 15 分、低重合 15 分。分数只用于排序和解释，不参与中奖概率文案。

“换一批组合”只增加批次序号，并保存用户主动选择的最新批次。重新进入同一期时，默认恢复已保存批次；没有保存时恢复批次 0 的确定性结果。

## 8. 历史回测

回测必须使用走步验证，禁止使用目标期开奖之后的数据：

1. 对每个目标期开奖，只使用其之前的 N 期开奖作为分析窗口。
2. 按相同生成规则生成五组参考号码。
3. 将每一组与目标期比较，记录红球命中数和蓝球是否命中。
4. 展示全部“目标期 × 五组”的红球命中分布。

为控制首屏计算量，近 30 期窗口回测 30 个目标期，近 100 与 300 期窗口最多回测最近 60 个目标期。计算在用户进入参考组合页时执行，并显示短暂加载状态。

## 9. 状态与错误处理

- 首次加载：骨架屏，不显示示例开奖号。
- 加载成功：显示官方来源、最新期号、开奖日期和拉取时间。
- 手动刷新：保留旧页面内容，按钮进入加载态；成功后替换。
- 过期缓存：显示“官方数据暂时不可用，当前为缓存快照”和快照时间。
- 上游不可用且无缓存：展示明确错误和重试按钮，不生成参考号码。
- 数据不足：禁用不可用窗口，仅允许当前有效窗口。
- 保存失败：组合仍可使用，按钮恢复并提示“保存失败，请重试”。
- 生成器放宽约束：在对应组合的依据区显示“为凑满五组已放宽某项”，不得静默隐藏。

## 10. 本地保存

只保存当前期、当前窗口、批次序号和五组组合，不保存完整历史开奖。

- Web 使用 `localStorage`。
- 原生端使用现有 `expo-secure-store`。
- 键名为 `funbox.ssq.saved-batch.v1`。
- 年龄和责任提示不做“已读后永久隐藏”。

## 11. 代码结构

后端：

- `backend/internal/lottery/service.go`：官方数据客户端、校验、排序和缓存。
- `backend/internal/lottery/service_test.go`：上游解析、缓存、失败回退和无效数据测试。
- `backend/internal/httpapi/lottery_handlers.go`：历史快照响应与错误映射。
- `backend/internal/httpapi/lottery_handlers_test.go`：接口状态码与响应结构测试。
- `backend/internal/config/config.go`：增加 `LotteryConfig`，支持来源 URL、超时和缓存周期。

前端：

- `frontend/types/double-color-ball.ts`：开奖、分析、组合和回测类型。
- `frontend/lib/double-color-ball-api.ts`：后端请求和错误映射。
- `frontend/lib/double-color-ball.ts`：统计、生成器、评分和回测纯函数。
- `frontend/lib/double-color-ball-storage.ts`、`.web.ts`、`.native.ts`：保存批次。
- `frontend/features/tools/double-color-ball-screen.tsx`：页面状态和总览/组合视图。
- `frontend/features/tools/double-color-ball-components.tsx`：号码球、热力矩阵、结构条和组合卡片。
- `frontend/tests/double-color-ball.test.mjs`：纯函数、注册表和关键文案测试。
- `frontend/features/tools/tool-detail-screen.tsx`：新增工具分发。
- `backend/internal/access/feature_registry.json`：注册 `double-color-ball` 工具，对所有现有角色开放。

## 12. 测试策略

后端测试：

- 正确解析官方 JSON 和日期字段。
- 拒绝红球重复、越界、数量错误和蓝球越界。
- 去重并按期号排序。
- 缓存命中时不重复请求上游。
- 上游失败时返回过期缓存；无缓存时映射为 502。
- 接口始终返回最多 400 期，并声明界面允许的最大分析窗口为 300。

前端纯函数测试：

- 频次总和等于 `期数 × 6`，蓝球频次总和等于期数。
- 遗漏值、三区、奇偶、和值和连号计算正确。
- 同一随机种子生成相同结果，不同批次能生成不同结果。
- 每组红球唯一、升序且合法，蓝球合法。
- 五组之间的重合和结构约束符合规则，或明确记录放宽项。
- 结构匹配度始终在 0-100。
- 回测只读取目标期之前的数据。
- 工具注册表、路由和责任文案存在。

界面验证：

- Web 端桌面窄屏 430px、iPhone 尺寸和 Android 常见尺寸无横向溢出。
- 明暗主题中文字、红球和蓝球对比度可读。
- 加载、错误、过期缓存、保存成功和保存失败状态可操作。
- 页面中不出现“必中、稳赚、提高中奖率、AI 胜率”。

## 13. 交付验收

- 工具列表可进入新功能，普通用户、VIP、SVIP 和管理员均可访问。
- 后端能获取最多 400 期官方历史开奖；界面仅分析最近 300 期，并显示来源和更新时间。
- 三个统计窗口均能稳定切换。
- 能生成、解释、刷新和保存五组合法参考组合。
- 回测无未来数据泄漏，结果由测试覆盖。
- 上游失败时不会用示例数据冒充官方开奖。
- 前后端测试、前端 lint 和 Web 构建通过。
