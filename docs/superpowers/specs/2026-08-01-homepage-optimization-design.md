# FunBox 首页布局优化产品设计

## 1. 文档信息

- 文档状态：已确认
- 产品方向：效率优先，兼顾功能发现
- 适用范围：FunBox 移动端首页及最大宽度为 430px 的 Web 首页
- 设计原则：保留现有品牌语言，以信息架构、内容密度和交互效率优化为主

## 2. 背景与问题

当前首页已经具备品牌区、精选轮播、工具网格、游戏区和固定底部导航，基础结构完整，但仍存在以下问题：

1. 精选轮播优先级过高，高频用户需要越过大卡片才能进入常用工具。
2. 三列工具卡片同时承载图标、标题、说明和跳转箭头，说明文字普遍被截断。
3. 轮播下一张卡片露出过多，正文被裁切，容易被理解为布局溢出。
4. 顶部装饰、区块间距和卡片高度共同占用较多首屏空间。
5. 固定底部导航可能遮挡最后一排内容，页面缺少明确的底部安全距离。
6. “常用工具”和“精选功能”的数据职责不够清晰，存在推荐与个性化入口混用的问题。

## 3. 产品目标

### 3.1 核心目标

让用户进入首页后，优先看到并以一次点击打开高频工具，同时保留精选推荐和轻游戏带来的功能发现能力。

### 3.2 体验目标

- 在主流手机首屏内完整展示品牌区和六个常用工具。
- 用户不需要阅读说明文字即可识别并进入常用工具。
- 精选轮播明确表达“可以横向浏览”，但不出现被硬裁切的正文。
- 常用工具和精选功能不重复，提升首页有效信息量。
- 最后一张内容卡片能够完整滚动到底部导航上方。

### 3.3 非目标

本次不包含以下能力：

- 新增搜索、收藏或自定义排序功能；
- 新增服务端推荐系统或用户画像；
- 重做品牌标识、主题色和底部导航结构；
- 改造工具详情页、工具列表页或游戏详情页；
- 新增埋点平台或数据分析后台。

## 4. 用户与核心场景

### 4.1 主要用户

- 回访用户：已经使用过部分工具，希望快速再次打开。
- 新用户：首次进入 FunBox，需要理解产品能力并找到可用入口。
- 轻度探索用户：完成效率任务后，希望浏览其他工具或进入小游戏。

### 4.2 核心路径

1. 用户打开首页。
2. 首页读取当前有权限且状态为可用的工具。
3. 首页根据本地使用记录生成六个常用工具；无有效记录时使用默认顺序。
4. 用户可直接点击常用工具，或继续浏览精选功能与游戏。
5. 工具进入成功后继续沿用现有使用记录逻辑，为下次首页排序提供依据。

## 5. 信息架构

首页从上到下按以下顺序展示：

1. 紧凑品牌区
2. 常用工具
3. 精选功能
4. 放松一下
5. 固定底部导航

首页继续使用单列纵向滚动结构，内容区域最大宽度保持 430px，左右统一留出 16px。

## 6. 页面设计

### 6.1 品牌区

- 高度控制在约 48px，顶部留白不超过 16px。
- 左侧保留品牌图标、`FunBox` 和“工具与游戏，随手即用”。
- 右侧显示当前用户可访问的可用工具数量，例如“11 个工具”。
- 右上背景线条仅作为弱装饰，范围不得延伸到常用工具区域。
- 品牌区不新增搜索框、通知入口或运营按钮。

### 6.2 常用工具

#### 展示结构

- 区块标题为“常用工具”。
- 辅助说明为“高频能力，一步直达”。
- 右侧提供“全部”文字与右箭头，点击进入现有工具列表页。
- 工具采用三列两行布局，目标数量为六个。
- 默认字号下单张卡片高度为 92-104px，圆角不超过 16px。
- 卡片只保留图标和工具名称，不显示说明文字和右上跳转箭头。
- 整张卡片为点击区域，并保留按压反馈。
- 默认字号下工具名称最多两行；当前可见工具的完整名称不得被省略。

#### 排序规则

常用工具只从当前用户有权限、`status = available` 且未被隐藏的工具中选择。排序顺序如下：

1. 已使用工具按累计点击次数降序排列；
2. 点击次数相同时，最近使用时间更近的工具优先；
3. 使用记录不足六个时，按默认工具列表补位；
4. 默认列表仍不足时，按功能注册表中的可用工具顺序补位。

默认工具列表为：

1. 免费阅读
2. 打牌记分
3. 热点速览
4. AI 导航
5. 市场雷达
6. 双色球

无权限、已下线、隐藏入口和即将上线的工具不得占据常用工具位置。可用工具少于六个时按实际数量展示，不渲染空白占位卡片。

### 6.3 精选功能

#### 内容职责

精选功能用于帮助用户发现常用工具之外的能力，不再承担“常用工具”排序职责。

- 精选候选优先顺序为：文字转语音、图片压缩、二维码生成器、智能翻译。
- 已出现在常用工具区的工具从精选候选中排除。
- 排除后不足四项时，从其余可用且未隐藏的工具中按注册顺序补位。
- 精选区最多展示四项，与常用工具区不得出现重复入口。
- 没有可展示项时隐藏整个精选区。

#### 轮播布局

- 区块标题为“精选功能”，右侧显示当前页和总页数，例如 `01 / 04`。
- 主卡片高度为 168-176px。
- 下一张卡片仅露出约 16px，不显示任何被裁切的正文或按钮。
- 卡片内保留工具类型、两行主标题、最多两行说明和一个圆形进入按钮。
- 卡片背景色、插画和文案继续使用现有工具配置；缺少专属配置时使用工具主题色、图标、名称和说明作为安全回退。
- 分页圆点紧邻卡片底部，当前项与非当前项需要具有清晰的颜色和尺寸差异。

#### 轮播交互

- 支持左右滑动和点击分页圆点切换。
- 自动轮播继续使用现有往返顺序，不从末项突然跳回首项。
- 用户手动滑动或点击分页后，本轮自动切换计时重新开始。
- 应用进入后台或页面失去焦点时暂停自动轮播。
- 系统开启“减少动态效果”时关闭自动轮播，保留手动切换。
- 只有一项时隐藏分页和自动轮播；两项及以上才启用轮播交互。

### 6.4 放松一下

- 区块标题为“放松一下”，辅助说明为“四款小游戏，随时开一局”。
- 仅展示 `status = playable` 的游戏，最多四项。
- 游戏卡采用横向滑动列表，卡片宽度约为内容区宽度的 28%-30%，首屏展示约 3.2 张。
- 卡片保留玩法图形、游戏名称和一行弱化分类信息。
- 图形区域尺寸固定，标题或按压状态不得造成卡片宽高变化。
- 可玩游戏为空时隐藏整个区块。

### 6.5 底部导航与页面滚动

- 保持现有“首页、工具、消息、我的”四项导航及选中态。
- 首页内容底部内边距必须等于固定导航实际高度、系统底部安全区和额外 16px 间距之和。
- 最后一张游戏卡片必须能够完整滚动到导航栏上方。
- 页面不显示纵向滚动条，但需保持原生滚动和回弹行为。

## 7. 视觉规范

- 保留现有浅蓝背景、白色表面、深绿精选卡和蓝色主色。
- 内容区左右边距统一为 16px，区块间距为 24-28px。
- 标题、辅助说明和内容之间形成稳定的 4px、12-16px 层级关系。
- 页面区块不增加外层卡片，避免卡片嵌套。
- 工具卡片使用不超过 16px 的圆角；精选大卡可保留更明显但不超过现有视觉体系的圆角。
- 保持浅色和深色主题可用，颜色必须来自现有主题或工具配置，不新增单独主题系统。

## 8. 状态与异常处理

### 8.1 使用记录

- 本地使用记录缺失、格式错误或读取失败时，按默认列表展示，不显示错误提示。
- 首页重新获得焦点时刷新使用记录，使刚使用过的工具能够进入新的排序。
- 排序变化不播放大幅重排动画，避免用户返回首页时产生位置错觉。

### 8.2 权限与可用性

- 首页只渲染当前权限范围内的工具。
- 工具权限或状态变化后，在下一次首页渲染时自动移除对应入口并补位。
- 被 `hiddenFromList` 标记的内部子工具不得单独出现在首页。

### 8.3 内容不足

- 常用工具不足六项时按实际数量展示，最后一行左对齐。
- 精选功能为零项时隐藏区块；一项时展示静态卡片。
- 可玩游戏为零项时隐藏“放松一下”。
- 隐藏区块后，前后区块间不得遗留额外空白。

## 9. 无障碍与适配

- 所有卡片使用按钮语义，并提供“打开 + 工具名/游戏名”的可访问标签。
- 点击区域不小于 44x44px。
- 正文与背景满足移动端可读对比度，信息不能只依赖颜色表达。
- 支持系统字体放大；超出默认字号范围时允许工具卡片增高，文字不得覆盖其他元素。
- 支持 320-430px 内容宽度；宽屏 Web 继续居中显示，不拉伸卡片布局。
- 系统减少动态效果设置必须影响自动轮播行为。

## 10. 产品成功标准

本次没有新增埋点系统，首版以可验证的体验标准作为上线判断：

1. 在 390x844 视口下，品牌区和六个常用工具完整可见，精选功能标题或卡片顶部进入首屏。
2. 任一常用工具均可通过一次点击进入。
3. 常用工具区和精选功能区不存在重复工具。
4. 三列工具卡片中不再出现无意义的省略说明文字。
5. 轮播下一张卡片正文、按钮和图标不会被截断展示。
6. 在 320px、390px 和 430px 宽度下不存在文字或卡片重叠。
7. 浅色和深色主题均可读，减少动态效果开启后不自动轮播。
8. 页面最后一张卡片可以完整滚动到底部导航上方。

后续若接入产品埋点，可追加观察“首页进入工具的平均耗时”“常用工具点击占比”和“精选功能点击率”，但不作为本次交付阻塞项。

## 11. 验收清单

- [ ] 首页模块顺序为品牌区、常用工具、精选功能、放松一下。
- [ ] 常用工具按使用频率、最近使用和默认列表稳定排序。
- [ ] 新用户默认展示六个指定工具。
- [ ] 常用工具和精选功能无重复。
- [ ] 工具卡片只显示图标和完整名称，无重复跳转箭头。
- [ ] “全部”正确进入现有工具列表页。
- [ ] 精选轮播在零项、一项和多项状态下行为正确。
- [ ] 自动轮播遵循往返顺序，并响应后台状态和减少动态效果设置。
- [ ] 游戏区只显示最多四个可玩游戏，并支持横向浏览。
- [ ] 固定底部导航不遮挡页面内容。
- [ ] 320px、390px、430px 和桌面居中布局通过视觉检查。
- [ ] 浅色、深色和字体放大场景通过视觉检查。

## 12. 实施边界

本设计应优先复用现有首页组件、主题、工具注册表、权限过滤、使用记录存储和精选轮播能力。实现时允许拆分首页内部展示组件和纯排序函数，但不应修改工具业务逻辑、引入新的服务端接口或进行与首页无关的重构。
