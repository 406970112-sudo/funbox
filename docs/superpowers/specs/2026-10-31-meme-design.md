# FunBox 表情包功能设计 V1

状态：用户于 2026-10-31 批准实施；补充约束为首页不加“我的藏图”入口。代码实现与本地验证完成，用户已要求合入并推送 main；运行方式见 `docs/meme-design-v1/implementation.md`。

用户目标：把第一个项目 ChineseBQB 接入现有 FunBox，支持全量图库、分类搜索和热门排行，同时给出小程序设计图。本文将“分类锁有”理解为“分类、搜索”。本方案已获批准，首页藏图快捷入口按用户最新要求取消；收藏保留在表情包模块内。

## 1. 调研结果

### 上游实际提供什么

ChineseBQB 是素材库、静态网站和生成工具的组合。适合消费其公开数据，不需要把上游整套网页或代码嵌进小程序。

- 分类目录：https://zhaoolee.com/ChineseBQB/catalog/index.json
- 完整图片索引：https://zhaoolee.com/ChineseBQB/catalog/search.json
- 相对路径基址：https://zhaoolee.com/ChineseBQB/
- README 明确提到开放图片与标注数据，可用于开发微信小程序。

本次实际请求索引得到的快照（上游更新后会变化）：

| 项目 | 实测值 | 对设计的影响 |
| --- | --- | --- |
| 原生分类 | 115 个 | 全部保留，可以另外添加运营分组 |
| 图片索引记录 | 5,887 条 | 包含跨分类重复素材，不能直接当作去重后的图片数 |
| 按 `src` 去重 | 5,756 个资源 | 主图库去重，分类关系多对多保留 |
| `animated=true` 索引记录 | 1,282 条 | 作为初始动图字段，入库时按实际文件校验；不能单凭 GIF 后缀判断有无动画 |
| 去重资源声明原图体积合计 | 539,647,902 字节，约 515 MiB | 不含缩略图、数据库、备份；无须放进小程序包 |
| 完整索引响应体积 | 3,322,392 字节，约 3.17 MiB | 放到后端处理，小程序分页请求 |
| 最大声明单图 | 12,001,225 字节，约 11.45 MiB | 大图按需加载，分享和下载前提示体积并提供重试 |

分类字段包括 `slug/title/count/cover/url/bytes/download`；图片字段包括 `id/name/path/label/src/thumb/width/height/animated/bytes/category/categoryTitle/folder`。原图有 JPG、GIF、PNG、WebP，缩略图示例为 WebP。`src` 指向内容哈希命名的媒体文件，已经提供 `thumb`，通常不用重新生成整库缩略图。

本次 1,439 条记录的 `label` 不含中文（包含编号、英文等），许多标签只是分类名加序号。上游不提供可靠的逐图语义描述、逐图流行日期、浏览量、收藏量、每日热榜或更新 SLA。新同步到本地不等于当天诞生的网络热梗。

### 现有 FunBox

- 小程序：`miniprogram/`，原生 JS/WXML/WXSS；目前首页是麻将、炸金花、通用记分，底部“首页 / 我的”。全局主色 `#2d5bff`、背景 `#f5f7fa`，白色圆角卡片。
- 请求：`miniprogram/utils/request.js` 统一请求和 Bearer Token；生产 API 为 `https://www.xwhub.cn/api/v1`。
- 后端：`backend/`，Go 1.22、net/http、SQLite，现有 JWT 用户、反馈、功能权限注册表可复用。
- Web：`frontend/`，已有工具目录、搜索与工具使用记录，后续增加 `/tools/memes`，与小程序复用 API 和收藏。
- 目前小程序并没有完整复用 Web 工具中心；需新增明确入口，不能只在 Web 注册一个工具就认为小程序自动可见。

## 2. 接入方式比较与建议

| 方式 | 优点 | 代价 / 限制 |
| --- | --- | --- |
| A. 小程序直读上游索引和图片 | 验证最快 | 首次索引大、依赖外部域名和网络、统计和下架难统一；不建议作为正式方案 |
| B. Go 缓存索引，图片按需经受限代理缓存 | 复用现有后端、初始资源少 | 首次访问受上游影响，需要严格限制源地址与缓存大小 |
| C. Go 同步索引，图片镜像到自有静态域名 | 国内访问、稳定性、微信下载域名和下架控制更可控 | 需要初次同步约 515 MiB 原图及缩略图，承担存储与带宽 |

**建议正式采用 C，按 B 的模式先完成联调，再补齐镜像。** 不新增 Node 服务、不把全库打包进小程序。镜像可以先用现有服务器共享持久目录加 Nginx，流量增大后再迁移对象存储/CDN。上传和镜像读取策略应在确认素材使用范围后定稿；README 的开放使用说明不能替代所有第三方图片的权利说明。本次没有确认覆盖全部代码、第三方图片和商业再分发的统一授权，保留来源、单图下架与反馈渠道。

数据链路：

```text
ChineseBQB 分类目录 / 图片索引 / 缩略图 / 原图
       ↓ 后端定时同步、校验、按资源去重、保存快照
FunBox SQLite 元数据 + 持久媒体目录
       ↓ Go API 分页搜索 / 收藏 / 行为聚合 / 日榜快照
原生小程序                         Web 工具页
       └──────── 自有 HTTPS 图片域名 ────────┘
```

建议每天北京时间 04:00 检查一次索引；使用响应校验信息或文件摘要判断变化。同步走临时快照：两份索引完整、分类关系有效才发布；网络错误或少量下载失败保持上一份可用数据，不清空图库。不凭一次异常空响应批量删除。

资源以内容哈希为规范 ID，保存上游 ID、版本和分类映射；上游更名时收藏不丢失。相同图跨分类共用媒体资源，但仍可在每个原生分类中找到。源撤回先标记不可见，人工确认后归档；本地屏蔽状态不得被下次同步覆盖。同步任务记录成功数、失败数、总条数、摘要和最后成功时间，可重试且幂等。

## 3. 可实现的功能边界

| 功能 | 第一期建议 | 实现说明 |
| --- | --- | --- |
| 全部图库与全部原生分类 | 支持 | 覆盖上游所有记录和分类，默认展示可发布且媒体可用的内容；重复图去重、保留全部分类关系 |
| 分类搜索、名称搜索 | 支持 | 匹配分类名、文件标签、人工别名；支持分类与静图/动图组合筛选 |
| 按“开心、下班、无语”搜图 | 部分支持 | 只有已有标签覆盖的图片能搜到；后续补 OCR、人工标签和语义索引，不能承诺第一期任意语义都准确 |
| 静图、动图预览 | 支持 | 列表加载静态缩略图，详情才加载原始动图；保留原图比例 |
| 收藏、最近浏览 | 支持 | 游客本机收藏和浏览记录；登录后可同步账号收藏，登录合并时去重 |
| 分享单图 / 分类页面 | 支持 | 分享小程序详情卡片，好友打开同一图片或分类 |
| 分享图片 | 支持，按客户端能力显示 | 下载为临时文件后调用 `wx.showShareImageMenu`；能力检测，失败提供预览或保存入口 |
| 保存相册 | 支持，按格式和授权处理 | `wx.downloadFile` 后用 `wx.saveImageToPhotosAlbum`；拒绝授权时保留当前图、提供设置入口和重试 |
| 今日 / 本周 / 总榜、历史日榜 | 支持 | FunBox 站内统计，自上线开始积累；上游没有现成日榜 |
| 全网 / 微信聊天真实使用热榜 | 无数据来源 | 不以站内浏览数据冒充全网排名，无法获得微信聊天使用次数 |
| 一键装入微信表情面板、整包自动安装 | 不列入承诺 | 本次未查到适用于该场景的通用公开能力；分享图片与添加微信表情不是同一件事 |
| 表情包改字、制作、批量 ZIP | 后续可做 | 另需模板、画布、字体和导出设计；上游网站有制作入口，不代表小程序已具备对应能力 |

**微信能力核验说明：** 微信文档站本次无法正常读取，已直接查看微信官方 `wechat-miniprogram/api-typings` 的 API 定义。确认 `showShareImageMenu`（基础库 2.14.3 起）、预览及本地文件保存接口存在。其定义不能证明每种图片格式在每个客户端都完整支持。GIF/动画 WebP 的分享、收藏到微信表情与相册保留动画效果，需 iOS/Android 真机验收；不默认把 GIF 转静图，不把打开分享菜单计为实际发送成功。

“全量支持”指同步和检索覆盖全部素材；小程序对外展示仍应过滤不可用资源与不适合发布的内容，并在运营数据中显示导入数、可用数、重复数、待处理数。目录中“人物、影视”等原生分类与“动物、情绪”等运营分组分开存储，不伪装成上游原有分类。

## 4. 页面与交互

### 项目入口

小程序首页在三个现有记分入口后新增独立“表情包”卡片，副标题“分类搜图 · 热门排行”；现有“选择牌局”区块保持牌局语义，新增“发现更多”区块承载该入口。底部仍为“首页 / 我的”。个人页增加“我的藏图”。Web 工具中心新增“表情包”项与 `/tools/memes` 页面。表情包模块内使用“全部 / 分类 / 榜单 / 藏图”页内导航，不与全局 tabBar 混淆。

首页补充设计见 `docs/meme-design-v1/meme-home-entry.png`，展示同一首页的首屏与下滑状态。新卡片采用浅紫色、右侧叠放猫/熊猫/鸭子表情贴纸插画，整卡可点击。保留当前卡片尺寸时，表情包入口通常位于首屏以下，需要上滑才能完整看到；这是本版布局的可见性取舍。**首页不增加“我的藏图”快捷链接；设计图中该链接已被用户明确取消。** 进入图库后返回，应恢复首页原滚动位置。

### 全部图库

顶部返回、标题、微信胶囊；搜索框固定可达。模块导航下提供“全部 / 静图 / 动图”及默认排序，三列方形缩略图，图片使用 contain，不裁掉梗图文字；动图角标 GIF，点图进入详情。

每页建议 36 项，cursor 分页；仅视口附近懒加载，控制保留节点，避免持续追加无限 DOM。返回时恢复搜索条件、筛选和滚动位置。骨架屏、加载失败重试、缺图占位、到底提示均需覆盖。

### 分类与搜索

115 个原生分类全部能访问，支持搜索分类名和查看全部列表。可增加“动物萌宠 / 影视动漫 / 人物表情 / 日常场景”运营分组，逐项维护映射，不依赖臆测自动归类。分类卡片显示封面、清洗后的中文名和当前可见数量，原名在来源详情可查。

全局搜索提交后展示结果页：顶部关键词、结果数（区分加载状态）、分类筛选与动图筛选；用分类/标签匹配给出可解释结果。无结果时显示“没有找到，换个词试试”和分类入口，不返回随机图冒充匹配。历史搜索在本地，支持清除；云端热搜需要达到数据量后才显示。

### 热门榜

展示“FunBox 站内热门”，今日、本周（北京时间自然周周一至当前）、总榜。日榜支持日期选择和历史回看，今日为动态榜，历史为已封榜快照。说明入口展示计算依据和更新时间。

建议第一期评分：`热度 = 有效详情浏览 × 1 + 收藏新增 × 3 + 保存成功 × 5`。不是曝光次数；不计取消收藏为新增长，不记录“实际转发成功”这类无法证实的事件。

- 账号或匿名安装标识按“图片 + 日期 + 行为”去重；仅用户真实打开详情才记浏览。保存只在成功回调后上报，带事件 ID 防重；客户端事件始终属于近似统计，服务端限频并过滤异常，不作为奖励或金钱依据。
- 收藏每个主体每图每天最多记一次正向事件，反复取消再收藏不涨分。上报服务校验图片可见状态、事件类型与时间；日期由服务端按 Asia/Shanghai 归桶，匿名标识只做本产品统计。
- 无有效行为的图片不伪造分数；单图至少 3 个独立主体产生有效行为才参与热榜；当天符合条件图片少于 10 张时显示“精选推荐，热度积累中”，不标 01/02 排名。
- 每 10 分钟刷新今日/本周缓存；次日 00:10 冻结前一日快照并保存算法版本，延迟事件按服务端接收时间进入新一天，保持旧榜不变。总榜从本站上线累计，不伪造更早历史。
- 榜单在返回时再次过滤已屏蔽素材。历史榜保留当日序号，移除下架项并显示“部分内容已下架”；不足项不补伪数据。

### 单图详情与藏图

详情：大图预览、清洗后的名称、分类、真实格式和体积、来源、收藏、分享页面、“分享图片”“保存到相册”、同类推荐。编号型标题以“分类名 · 序号”展示，不能凭空生成语义标题。

大图失败保留缩略图和重试；正在下载禁用重复点击并显示进度；后台切换回来不重复触发分享。保存/分享失败不清空图或收藏。客户端不支持的格式给出“预览原图 / 分享页面”，如提供静态预览另标明，不能声称已保存原动图。

藏图：默认收藏，次级“最近浏览”；游客清楚标识“仅保存在本机”，登录后合并本地收藏到账号，成功才清理待同步记录；已下架收藏显示不可用占位，允许移除。

## 5. 技术落点

新增 Go 业务模块 `backend/internal/meme/`，HTTP handler 接在现有 httpapi，复用数据库、日志、限流和用户身份。建议数据模型：

| 表 | 主要职责 |
| --- | --- |
| meme_sources / meme_sync_runs | 来源、同步摘要、版本、完成状态 |
| meme_images | 规范资源 ID、源路径、缩略图、格式、尺寸、大小、首次导入时间、可见状态 |
| meme_categories / meme_image_categories | 原生分类与多对多映射，另存上游条目 ID 和标签 |
| meme_tags / meme_image_tags / meme_category_groups | 人工别名、情绪标签和运营分组 |
| meme_favorites | 用户收藏，user_id + image_id 唯一 |
| meme_daily_events | 每日去重事件和限期保留明细；主体使用服务端散列值 |
| meme_daily_stats / meme_rank_snapshots | 分日聚合、分数、历史位置与算法版本 |

读取 API 建议：

```text
GET    /api/v1/memes/categories?q=&group=
GET    /api/v1/memes?q=&category=&animated=&sort=&cursor=&limit=36
GET    /api/v1/memes/{id}
GET    /api/v1/memes/rankings?period=day|week|all&date=YYYY-MM-DD
GET    /api/v1/memes/ranking-dates?cursor=
GET    /api/v1/memes/favorites?cursor=                 [登录]
PUT    /api/v1/memes/{id}/favorite                    [登录，幂等]
DELETE /api/v1/memes/{id}/favorite                    [登录，幂等]
POST   /api/v1/memes/events                          [校验、去重、限频]
```

榜单响应包含 `mode=ranking|curated`、`dataSince`、`updatedAt`、`algorithmVersion`、`isFinal`；图片响应区分原生标签和运营标题。按可见资源聚合数量，分页按稳定顺序和快照版本返回，避免同步期间跨页漏项或重复。搜索先做 SQLite 元数据匹配，数据量增长再引入全文或语义检索，不提前添加向量服务。

鉴权：建议公开浏览/搜索/榜单，账号收藏走现有 JWT；需在现有 `backend/internal/access/feature_registry.json` 登记 `memes`、路由 `/tools/memes` 并明确初始角色，避免新功能默认只管理员可见。公开只读 API 的权限与入口可见性须同步定义，不能沿用登录中间件误挡游客。管理员同步、标签维护、屏蔽等走现有管理权限。

小程序建议新建 `packages/meme/` 分包（图库、分类、搜索、榜单、详情、藏图），在 `app.json` 注册分包，在首页/个人页增加入口。Web 在现有工具目录和路由体系中注册。图片仅走自有静态域名，并配置 request/downloadFile 合法域名；不把完整索引或原图作为小程序资源。

媒体目录放部署 release 之外的共享持久位置，避免更新时丢失。只同步已知上游索引中的 HTTPS 路径，不接受任意 URL 代理；限制域名、重定向、文件大小与 MIME，下载失败保留旧版本。静态分发必须能执行下架/缓存失效，避免只隐藏列表但旧图片链接长期公开可读。单图长缓存以资源内容版本命名，撤回时删除/禁止访问并清理 CDN。

## 6. 实施顺序与验收目标

以下前三阶段已完成，第四项保留为后续增强；实际实现与验证见实施说明。

1. 数据基础：读取全部分类和索引、资源去重、多分类映射、缩略图/原图镜像、分页 API、来源与下架管理。先验证真实客户端可读取自有域名。
2. 小程序第一版：首页入口、全图库、分类/名称搜索、静动筛选、预览、收藏、图片/页面分享和相册保存；同步交付 Web 工具页，复用后端。
3. 站内榜单：事件采集、去重与冷启动精选、今日/本周/总榜、历史日榜；没有真实数据时明确展示推荐状态。
4. 后续增强：OCR/情绪标签、语义搜索、表情改字、批量导出、更丰富榜单来源。

验收覆盖：导入快照计数与来源一致且可解释重复数；全部 115 个分类可检索；未提供语义标签的图片不承诺语义命中；首次同步失败不影响既有服务；上下游删除和屏蔽正确传播；游客浏览与登录收藏互不阻塞；反复收藏和保存不刷榜；封榜按北京时间且可回看；iOS/Android 真机验证 JPG/PNG/GIF/WebP 预览、相册权限拒绝、取消分享、原图过大、弱网重试和低版本能力降级；发布时包体不含图库。
