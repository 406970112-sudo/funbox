# FunBox 首页与工具页合并产品设计方案 V1

> 版本：V1 草案
> 日期：2026-08-01
> 状态：待评审
> 定位：将首页与工具页合并为统一的发现页，以搜索、推荐、最近使用、全部工具和游戏板块构成一个入口。

## 1. 背景与问题

当前首页已包含品牌区、常用工具、精选轮播和游戏区，工具 Tab 又承载一份完整的工具列表，两个页面职责重叠，用户的注意力被拆散。

新工具页设计具备搜索、分类筛选、最近使用和今日推荐能力，信息效率更高，但如果把它整页叠加到首页，游戏板块会被推到很下面，娱乐发现和放松场景被弱化。

因此本方案将两者合并为一个统一发现页，并约束工具的默认展示密度，保证游戏板块仍然可见、可及。

## 2. 产品目标

### 2.1 核心目标

让用户进入首页后，可以用一次搜索或分类找到工具，通过最近使用一步复用，通过推荐位发现新能力，同时保留游戏板块的娱乐可达性。

### 2.2 体验目标

- 默认只展示两行工具，游戏板块在默认状态下明显提前。
- 高频用户不需要进入第二个 Tab 即可完成绝大多数工具访问。
- 搜索、分类筛选、最近使用形成完整的“找工具”闭环。
- 保留首页的功能发现与轻游戏入口，不牺牲娱乐场景。

### 2.3 非目标

- 不新增服务端个性化推荐或用户画像。
- 不改造工具详情页和游戏详情页。
- 不新增后端接口，V1 使用现有本地使用记录数据。
- 不重做品牌标识、主题色和基础组件体系。
- 不引入完整运营后台，推荐位先以前端配置预留。

## 3. 用户与核心场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 回访用户 | 打开首页，想再次使用某个工具 | 最近使用直接呈现，一步进入 |
| 新用户 | 首次进入，想了解有哪些能力 | 搜索、分类和推荐位帮助发现 |
| 探索用户 | 完成效率任务后想放松 | 工具只占两行，游戏板块紧跟其后 |
| 会员用户 | 查看会员权益与专属能力 | 轻量会员引导，不打断浏览 |

## 4. 信息架构

### 4.1 页面结构

合并后的首页从上到下依次为：

1. 品牌区
2. 搜索
3. 今日推荐
4. 最近使用
5. 全部工具（默认两行，可展开）
6. 放松一下（游戏板块）
7. 会员中心（轻量引导）
8. 底部导航

页面继续使用单列纵向滚动，内容区域最大宽度保持 430px，左右统一留出 16px。

### 4.2 Tab 结构

- 原结构：首页 / 工具 / 消息 / 我的
- 新结构：首页 / 消息 / 我的

独立“工具”Tab 移除，首页成为统一发现页。`/tools` 路由和现有工具列表页保留，用于深链、会员入口和后续扩展，但不占用底部导航。

## 5. 页面设计

### 5.1 品牌区

- 左侧保留品牌图标、`FunBox` 和“工具与游戏，随手即用”。
- 右侧展示能力计数，例如“15 个工具 · 5 款游戏”，数字按当前权限动态计算。
- 品牌区不新增通知、设置等运营入口。

### 5.2 搜索

- 全页搜索框，覆盖工具名称、一句话说明和场景关键词。
- 输入时实时过滤工具网格，并与当前分类筛选叠加生效。
- 搜索框高度固定为 42px，圆角不超过 14px。
- 无结果时展示空态，并提供清除搜索的入口。

### 5.3 今日推荐

- 运营推荐位，默认展示“免费阅读”。
- 卡片包含推荐标签、工具名称、一句话说明和 CTA。
- V1 固定单卡，结构上预留后续扩展为轮播。
- 卡片整卡可点击，进入对应工具路由。

### 5.4 最近使用

- 复用现有本地 `tool-usage` 存储，展示最近 4 个工具。
- 每项包含工具图标、名称和相对时间。
- 无使用记录时隐藏整个区块，不渲染空白占位。
- 点击“查看全部”进入展开后的全部工具列表。

### 5.5 全部工具

#### 默认展示

- 默认只展示两行，即三列网格中的 6 个工具。
- 排序规则：最近使用优先，其余按注册表中的可用工具顺序补位。
- 卡片只保留图标、工具名称和轻量徽章，不展示长说明。

#### 展开与收起

- 可用工具超过 6 个时，网格下方显示“展开全部 N 个”按钮。
- 点击后展开完整列表，按钮变为“收起工具”。
- 展开状态下再次点击可收起，工具网格和游戏板块位置即时回弹。

#### 分类筛选

- 分类：全部 / AI / 效率 / 阅读 / 数据 / 音频 / 生活 / 行情 / 直播 / 多媒体。
- 当前分类匹配工具少于或等于 6 个时全部展示，不显示展开按钮。
- 分类和搜索叠加过滤，任意一项为空即显示空态。

### 5.6 游戏板块

- 标题为“放松一下”，辅助说明为“5 款可玩小游戏，随时开一局”。
- 只展示 `status = playable` 的游戏，最多 5 个。
- 游戏卡采用横向滑动列表，首屏可见约 3 张。
- 卡片包含玩法图形、游戏名称和类型信息。
- 可玩游戏为空时隐藏整个区块。

### 5.7 会员中心

- 轻量引导条，包含锁形图标、一句权益文案和“查看权益”入口。
- 建议对未登录或普通角色展示，已登录且无会员差异时不展示。
- 点击进入现有会员页，不引入弹窗和强打断。

### 5.8 底部导航

- 保留“首页、消息、我的”三项，首页为默认选中态。
- 页面底部内边距等于固定导航高度、系统底部安全区和额外 16px 间距之和。
- 最后一张游戏卡片必须能完整滚动到导航栏上方。

## 6. 交互设计

- 搜索和分类叠加过滤；清除搜索词后恢复当前分类结果。
- 展开和收起工具网格即时切换，不播放大幅重排动画。
- 推荐位、最近使用、工具卡片和游戏卡片均为整卡点击区域。
- 工具点击后进入现有路由；返回首页时刷新最近使用记录。
- 搜索、分类、展开按钮使用原生控件语义，保留键盘可操作性。

## 7. 数据与个性化

### 7.1 最近使用

- 读取本地 `tool-usage` 存储，按最近使用时间降序取前 4 个。
- 数据缺失或读取失败时隐藏最近使用区块，不展示错误提示。

### 7.2 工具排序

- V1：最近使用优先，其余按注册表顺序补位。
- V2：可增加累计点击次数、使用时长等权重，形成稳定个性化排序。

### 7.3 权限与可用性

- 只展示当前角色可见、`status = available` 且未被隐藏的工具。
- 权限或状态变化后，下次渲染自动移除对应入口并补位。

### 7.4 推荐位

- V1 使用前端静态配置，默认免费阅读。
- V2 可接入服务端运营配置，支持按用户角色和活动动态下发。

## 8. 视觉规范

- 沿用现有浅蓝背景、白色表面、主色 `#4b6bff`、强调色 `#ff6b8f` 和深绿推荐卡。
- 内容区左右边距统一为 16px，区块间距为 24-28px。
- 工具卡片圆角不超过 16px，推荐大卡不超过 20px。
- 页面区块为全宽分段，不新增卡片嵌套。
- 浅色和深色主题均可使用，颜色必须来自现有主题或工具配置。

## 9. 状态与异常处理

- 最近使用数据缺失：隐藏区块。
- 可用工具少于 6 个：按实际数量展示，最后一行左对齐。
- 分类无结果：展示空态和清除筛选入口。
- 搜索无结果：展示空态并保留搜索词，提供清除按钮。
- 游戏为空：隐藏“放松一下”，前后区块不遗留额外空白。
- 权限变化：下次渲染自动移除无权限工具。

## 10. 无障碍与适配

- 所有卡片使用按钮语义，并提供“打开 + 工具名/游戏名”的可访问标签。
- 点击区域不小于 44x44px。
- 支持 320-430px 内容宽度，文字不溢出、元素不重叠。
- 浅色和深色主题均可读，状态信息不能只依赖颜色表达。
- 系统开启“减少动态效果”时，展开收起不做动画，只即时切换。

## 11. 成功标准

1. 在 390x844 视口下，搜索、推荐位、最近使用和两行工具完整可见。
2. 游戏板块顶部在默认工具两行状态下进入首屏或只需一次轻滚。
3. 搜索、分类、最近使用可以组合工作。
4. 展开全部后能访问所有工具，收起后游戏板块位置回弹。
5. 320px、390px、430px 宽度下无文字或卡片重叠。
6. 浅色和深色主题均可读。

## 12. 里程碑

| 阶段 | 范围 | 验收信号 |
| --- | --- | --- |
| M1 页面合并 | 移除独立工具 Tab，新增搜索、分类、最近使用、两行工具和展开收起 | 游戏板块可见性提升，找工具闭环可用 |
| M2 个性化 | 最近使用排序、常用工具补位、返回首页刷新记录 | 回访用户一步到达常用工具 |
| M3 运营化 | 推荐位配置、工具状态标记、会员引导策略 | 运营可独立调整推荐内容 |

## 13. 实施边界

- 优先复用现有首页组件、工具注册表、权限过滤、`tool-usage` 存储和游戏卡片能力。
- 改动集中在 `frontend/features/home`、`frontend/features/tools`、`frontend/app/(tabs)/_layout.tsx`。
- 不新增服务端接口，不修改工具业务逻辑。
- `/tools` 路由与 `ToolsScreen` 保留，作为展开态和深链场景的承接。

## 14. 验收清单

- [ ] 底部 Tab 为首页、消息、我的，无独立工具 Tab。
- [ ] 搜索能按名称与关键词过滤工具。
- [ ] 分类筛选正确，少于或等于 6 个时不显示展开按钮。
- [ ] 默认展示 6 个工具，展开后展示全部，可收起。
- [ ] 最近使用只显示最近 4 个，无记录时隐藏。
- [ ] 游戏板块只显示可玩游戏，支持横向滑动。
- [ ] 游戏板块位置相比原方案明显提前。
- [ ] 权限过滤正确，隐藏工具不出现。
- [ ] 320px、390px、430px 布局无溢出。
- [ ] 浅色和深色主题可用。

## 15. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 移除工具 Tab 后入口变深 | 用搜索、分类、展开和“我的”页入口覆盖 | 首页需要足够强的搜索和分类体验 |
| 首页内容仍然偏长 | 默认两行工具 + 展开收起控制 | 高频场景高效，完整浏览需要一次展开 |
| 游戏是否应排在工具之前 | V1 建议工具在前、游戏紧随其后 | 兼顾效率主场景与娱乐可达性 |
| 会员引导展示条件 | 仅对未登录或普通角色展示 | 避免打扰已满足权益的用户 |
