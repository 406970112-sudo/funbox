# 会员中心「权益对比」折叠展示产品设计方案

## 1. 结论

在会员中心的「权益对比」区域，只展示普通、VIP、SVIP 三个会员身份之间确实存在权限差异的入口。差异项超过 5 项时，默认展示前 5 项，其余项目进入折叠区；用户点击「展开更多 · N 项」后显示全部差异，再次点击「收起差异项」恢复默认状态。

本功能一次性完成并上线，不拆分为多期。线上展示的功能名称、角色权限、排序和总数全部来自后端权限库，不在前端写入示例权限，不使用 mock、seed 或接口失败兜底数据。

## 2. 用户问题与目标

### 用户问题

- 会员功能数量较多，首次进入页面时需要滚动很久才能找到核心差异。
- 现有对比表同时展示「全员可用」和「会员专属」入口，信息密度高但决策价值低。
- 权限配置由后台管理，前端如果写死角色会出现展示与实际权限不一致。

### 产品目标

- 首屏在 5 行内回答「会员等级差在哪」。
- 保留完整查看能力，不丢失任何差异项。
- 权限调整后，用户重新进入会员中心即可看到最新结果。
- 接口异常时宁可明确提示未加载，也不展示过期或虚构内容。

## 3. 范围

### 本次交付

- 会员中心「权益对比」差异筛选、默认折叠、展开/收起。
- 真实接口加载态、空态、失败重试态。
- 普通、VIP、SVIP 三列的勾选/未开放标记。
- 折叠按钮剩余数量、无障碍标签和展开状态。
- 页面聚焦时刷新用户身份与权限矩阵。
- 产品设计画板与验收说明。

### 不做

- 不新增会员等级、价格、支付流程或权限管理后台。
- 不在工具卡片上增加会员角标。
- 不把管理员专属入口当作会员权益展示。
- 不为了让画板出现更多行而修改线上权限配置。

## 4. 数据与权限规则

### 唯一数据源

客户端调用：

```text
GET /api/v1/membership/features
Authorization: Bearer <access token>
```

响应结构：

```json
{
  "features": [
    { "id": "market-radar", "name": "市场雷达", "roles": ["vip", "svip"] }
  ]
}
```

后端从启用中的 `features`、`feature_role_permissions` 表读取数据，保持后台 `sort_order`。前端只负责筛选与呈现；不读取 `initialRoles` 作为运行时权限，不从 `mocks/app-data` 回填矩阵。

### 对比项筛选

1. 从响应中取 `normal / vip / svip` 三个角色的可见性。
2. 三列布尔值完全相同时隐藏该入口。
3. 三列中至少一列不同则保留。
4. 三列均不可见的管理员专属入口不进入对比表。
5. 角色顺序固定为普通、VIP、SVIP，入口顺序沿用后端权限库。

### 计数规则

- 标题右侧显示 `差异项总数`，折叠前后不变化。
- 折叠按钮显示未展示数量：`展开更多 · {总数 - 5} 项`。
- 总数小于等于 5 时不显示按钮。
- 接口为空时显示空态，不显示 0 行表头。

## 5. 页面结构

```text
会员中心
├─ 身份大卡（沿用现有会员色）
├─ 开通会员 / 已拥有全部权益
├─ 我的权益（现有五项折叠保持不变）
└─ 权益对比
   ├─ 标题 + 差异项总数
   ├─ 普通 / VIP / SVIP 表头
   ├─ 前 5 项差异功能
   ├─ 展开更多 / 收起差异项（仅总数 > 5）
   └─ 规则说明
```

表格第一列为功能名称，后三列为角色权限。勾选使用绿色圆形勾，未开放使用灰色减号圆形图标；信息不依赖颜色单独表达。

## 6. 交互细节

### 默认态

- 页面每次重新获得焦点时重新拉取矩阵，折叠状态重置为收起。
- 首次加载期间保留表格区域高度，显示「正在同步最新权限配置」。
- 超过 5 项时只渲染前 5 行，按钮位于第 5 行之后，避免把更多内容藏在不可发现的滚动区域。

### 展开态

- 点击整块按钮区域均可触发，不要求点击文字本身。
- 文案变为「收起差异项」，右侧箭头向上。
- 展开后保留当前滚动位置，不自动跳到页面底部。
- 收起后回到前 5 行，按钮文案重新显示剩余数量。

### 异常态

- 加载失败时清空当前矩阵，不沿用上一次结果。
- 展示「权限服务暂时不可用，未展示缓存或示例数据」与「重试」按钮。
- 重试成功后进入默认收起态；连续失败不弹 Toast，避免打断用户浏览。
- 接口返回空数组时展示「当前没有需要对比的会员功能」。

## 7. 视觉规范

- 沿用会员中心现有浅蓝页面底、白色面板、18px 圆角和 FunBox 顶部品牌标记。
- 会员身份色不改变：VIP 使用金色，SVIP 使用玫瑰色，普通使用中性蓝灰。
- 对比表采用紧凑行高（约 42px），首列左对齐，角色列居中，保持手机端可扫描。
- 展开按钮使用现有主色描边与上下箭头，不新增胶囊或渐变装饰。
- 小屏幕下功能名单行截断，完整名称通过无障碍 label 保留；表格不横向溢出。

## 8. 状态与边界

| 场景 | 页面行为 |
| --- | --- |
| 0 项差异 | 空态，不显示表头与展开按钮 |
| 1-5 项差异 | 显示全部，不显示展开按钮 |
| 6 项及以上 | 默认显示 5 项与剩余数，支持展开/收起 |
| 权限服务加载中 | 显示同步状态，不显示旧数据 |
| 权限服务失败 | 显示错误说明与重试，不显示 mock |
| 管理员账号 | 只按普通/VIP/SVIP 三列计算；管理员专属能力过滤 |
| 角色刚被调整 | 页面重新聚焦时刷新身份与矩阵 |
| 深色模式 | 使用现有 dark 主题 token，图标和文字保持对比度 |

## 9. 埋点与指标

本次沿用现有会员中心事件命名，仅增加展开行为：

| 事件 | 触发时机 | 参数 |
| --- | --- | --- |
| `membership_compare_impression` | 对比区成功展示 | `role`, `diffCount`, `collapsed` |
| `membership_compare_expand` | 点击展开更多 | `role`, `diffCount`, `visibleCount` |
| `membership_compare_collapse` | 点击收起 | `role`, `diffCount` |
| `membership_compare_retry` | 点击重试 | `role` |

关注指标：展开率、展开后到达支付入口的点击率、权限接口失败率、空态占比。埋点不上传手机号、功能内容以外的个人信息。

## 10. 一次性交付验收

- [ ] 接口返回 6 项差异时，初始只显示 5 项，按钮显示「展开更多 · 1 项」。
- [ ] 接口返回 12 项差异时，初始只显示 5 项，展开后显示 12 项，收起后恢复 5 项。
- [ ] 三个角色权限完全一致的入口不会出现在对比表。
- [ ] 仅管理员可见的入口不会出现在对比表。
- [ ] 标题总数与实际差异项数量一致，折叠前后不变。
- [ ] 权限接口失败时不展示 `initialRoles`、缓存或手写示例。
- [ ] 页面重新聚焦后重新请求身份与矩阵，配置变更可见。
- [ ] Light / Dark、小屏、系统字体放大、无障碍读屏均无重叠或横向溢出。

## 11. 设计图说明

`membership-benefit-comparison-design-v1.html` 是可点击画板，左侧为收起态，右侧为展开态，底部为数据链路与异常态说明。画板中的功能名称复用仓库现有入口注册表，仅用于呈现布局；运行时权限单元格不写死，必须由 `/api/v1/membership/features` 注入。当前本地权限库若无差异项，真实页面会按方案展示空态。
