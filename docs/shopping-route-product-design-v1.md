# FunBox 购物路线 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 状态：待评审
> 定位：把用户真实购物清单按常去超市的真实区域顺序，一键变成一条不用来回走的路线；所有商品、区域、顺序与归位关系都可溯源，不预置假数据。

## 1. 背景与问题

用户去超市前已经想好要买什么，但清单通常按“想到什么写什么”排列，到了超市要反复跨区。常见问题：

| 现状 | 问题 |
| --- | --- |
| 购物清单按书写顺序排列 | 蔬菜、牛奶、洗衣液混在一起，反复跨区 |
| 每家超市区域位置不同 | 同一商品在不同门店不一定在同一区域 |
| 区域顺序只靠记忆 | 换一家店或隔一段时间去，又要重新想 |
| 自动排序常见方案依赖假数据 | 内置区域表与商品映射可能不符合真实门店，误导用户 |
| 路线生成只给“顺序” | 没有说明来源，用户无法判断是否可信 |

FunBox 已有账号、SQLite、工具注册、首页搜索、主题系统和“跟做菜谱”的真实购物清单，可以复用这些能力，不需要引入新的外部服务。

## 2. 对原始想法的补充

原始想法是：用户建立购物清单后，按“蔬菜区、冷藏区、日用品区”自动排序，并保存常去超市的区域顺序，以后自动排列。

在此基础上补充十一点：

1. 购物清单完全来自用户真实创建，或从“跟做菜谱”的真实食材清单导入，首次进入不预置任何商品。
2. 常去超市由用户真实创建，至少包含名称；地址、坐标和区域顺序由用户填写或确认。
3. 区域名称不内置为每家店的事实。系统提供“标准区域类型”用于匹配，但每个门店的区域名称必须来自用户录入或门店官方数据。
4. 商品归区采用“已核实映射库 + 用户确认”双来源。已核实映射带 `source`、`reviewedAt`；没有来源的商品进入“未归位”，绝不自动猜测。
5. 条码商品通过 Open Food Facts 官方公开接口取真实名称、品牌、图片和分类字段；接口不可用时只保留用户输入，不补造元数据。
6. “自动排序”是确定性规则：有门店区域顺序和已归位商品才生成路线；未归位商品单独展示，不混入路线。
7. 路线只承诺“按真实区域顺序一次走完”，不显示无来源的距离、步行时间和“最短路径”；只有当门店提供真实区域邻接图时，才计算避免折返的路线。
8. 用户确认一次商品归区后，映射只保存在当前账号；后续同一商品在其他门店可复用“标准区域类型”，再按目标门店区域翻译。
9. 支持购物中逐项打勾，已完成商品不改变路线顺序，路线进度与清单同步。
10. 历史记录、导出、清空、删除都只操作真实数据，不做演示记录。
11. 本方案所有页面、接口、规则、导入、归位和历史功能在一个版本内一次做完，不设二期。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户建立清单并确认常去超市后，30 秒内得到一条可执行的区域顺序路线。
2. 每个商品、区域、顺序和归位关系都能追溯到用户确认或已核实来源。
3. 未归位商品不会被隐藏，也不会被错误塞进某个区域。
4. 换一家超市时，已保存的商品归位类型仍可复用，但门店区域顺序以该店真实配置为准。
5. 一期完整交付：清单、超市、区域、路线、购物中、历史全部一次上线。

### 3.2 设计原则

- 真实优先：无来源不排序、不补数据、不显示距离和时间。
- 用户决策：区域顺序和商品归位由用户确认，系统只给带来源的建议。
- 可解释：每个自动归位项显示来源与更新时间，用户可一键改为自己的选择。
- 克制自动：不做位置轨迹推断，不根据常去超市猜用户当前在哪家店。
- 一期全量：不把“手动确认”“历史”“导入”放到二期。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 家庭采购用户 | 一周买蔬菜、牛奶、日用品 | 建立真实清单，按常去超市区域顺序一次走完 |
| 跟做菜谱用户 | 菜谱详情生成备菜清单 | 一键把真实食材导入购物路线，不重复录入 |
| 固定超市用户 | 每周去同一家店 | 保存该店区域顺序，以后自动排列 |
| 新超市用户 | 第一次去某家店 | 先录入或确认区域顺序，系统不猜测 |
| 习惯扫码的用户 | 想确认商品真实名称和分类 | 条码查询 Open Food Facts，失败时使用用户输入 |
| 购物中用户 | 边买边核对 | 路线置顶，逐项打勾，已完成不重排 |

### 5.3 核心流程

```text
进入购物路线
  -> 建立真实购物清单（手动添加 / 从菜谱购物清单导入）
  -> 选择或创建常去超市并确认区域顺序
  -> 已归位商品按标准区域类型翻译到该店区域
  -> 未归位商品进入“未归位确认”
  -> 一键生成路线：入口 -> 区域 1 -> 区域 2 -> ... -> 收银台
  -> 购物中逐项打勾，路线顺序不重排
  -> 完成写入真实历史记录
```

## 6. 功能设计

### 6.1 购物路线首页

- 顶部展示当前清单名称、商品数量、已归位数量和路线状态。
- 常去超市选择器只展示用户真实创建的超市；未创建时显示空态引导。
- 路线卡分为四种状态：
  - 可生成：清单有商品、超市有区域顺序、已归位数量大于 0，主按钮“一键生成路线”。
  - 需补超市：没有常去超市，按钮引导创建。
  - 需确认区域：超市存在但区域顺序为空，按钮引导录入。
  - 需归位：存在未归位商品，按钮引导先处理未归位。
- 路线卡只展示真实来源摘要，例如“3 个区域 · 8 项已归位 · 2 项未归位”。
- 不展示“预计步行时间”“节省 X 分钟”等无来源数据。

### 6.2 购物清单

- 支持手动添加：名称、数量、单位、备注、可选条码。
- 支持从“跟做菜谱”的购物清单导入：导入内容为菜谱真实食材字段，按商品名去重合并数量。
- 条码输入后调用 Open Food Facts API：
  - 命中时展示真实商品名、品牌、分类和图片，并标记 `source=openfoodfacts`、`fetchedAt`。
  - 未命中或接口失败时只保留用户输入，不自动填充。
- 每个商品行显示来源标识：用户录入、菜谱导入、条码查询。
- 支持编辑、删除、清空清单；清空需二次确认。

### 6.3 常去超市与区域顺序

- 创建超市字段：名称、地址、可选坐标、备注。
- 区域列表由用户添加，名称 1-12 个字符，同一超市不允许重名。
- 每个区域可选择标准区域类型：蔬菜水果、冷藏冷冻、肉禽蛋、粮油调味、日用品、个护清洁、零食饮料、烘焙、其他。
- 区域顺序通过“上移/下移”或拖拽保存，保存后记录 `updatedAt`。
- 入口和收银台为可选配置，配置后路线首尾明确；未配置时从第一个区域开始。
- 如果门店提供官方区域表或平面图，可通过管理员审核后的 `storeLayoutSource` 导入；导入数据仍需要用户确认后生效。
- 同一超市被删除前要求二次确认，并提示关联的用户商品归位映射不受影响。

### 6.4 未归位确认

- 未归位商品按清单顺序展示，不排序、不猜测。
- 系统建议来自“已核实映射库”，显示来源和更新时间；用户点击“使用建议”后才写入映射。
- 用户也可以手动选择该商品在当前超市的区域，或选择“通用区域类型”。
- 用户确认后生成一条 `user mapping`，包含商品归一化名、区域、来源、确认时间。
- 未归位商品在路线结果中显示为“未归位 N 项”，不参与路线排序。

### 6.5 路线生成

生成规则：

```text
1. 输入 = 当前清单全部商品 + 选定超市
2. 已归位商品 = 商品有 user mapping 或 verified mapping，且能翻译到该店区域
3. 未归位商品 = 无法翻译的商品，独立分组
4. 区域顺序 = 该店用户确认的区域顺序
5. 路线顺序 = 入口(可选) + 按区域顺序出现的区域 + 收银台(可选)
6. 同一区域内商品按清单原始顺序排列
7. 如果门店提供真实区域邻接图，则在同一组区域顺序内选择不折返的遍历方向；否则不计算方向
```

- 每次生成写入一条路线记录，包含清单快照、门店区域顺序快照和归位快照。
- 路线结果页展示“区域顺序路线”，每个区域一个分组，区域内列出商品和数量。
- 路线完整性 = 已归位商品数 / 清单商品总数，未归位商品单独提示。
- 不展示“预计时间”“距离”“最短路径”，除非门店提供真实邻接图和距离数据。

### 6.6 购物进行中

- 顶部固定路线进度：已买 / 共需买。
- 按区域顺序展示商品，点击商品行可打勾；已完成商品进入“已购买”分组。
- 打勾状态写入本地和账号，退出后恢复。
- 已完成商品不改变路线顺序，防止页面跳动。
- 支持“清空已购买”回到未完成状态；清空需二次确认。

### 6.7 历史记录

- 只记录用户真实生成的路线和真实完成的购物会话。
- 每条记录包含清单快照、超市、区域顺序、完成时间、完成项数。
- 支持导出 CSV/JSON，数据来自当前账号真实记录。
- 无记录时显示真实空状态，不预置演示记录。

## 7. 真实数据方案

### 7.1 数据来源

| 数据 | 来源 | 展示规则 |
| --- | --- | --- |
| 购物清单商品 | 用户创建或菜谱购物清单导入 | 首次进入为空；菜谱导入来自真实食材字段 |
| 商品条码元数据 | Open Food Facts API | 命中才展示名称、品牌、分类和图片，带 `source` 与 `fetchedAt` |
| 常去超市 | 用户创建 | 名称、地址为真实输入，不做演示超市 |
| 区域顺序 | 用户确认或门店官方数据导入 | 保存 `source=user` 或 `source=official` 与 `updatedAt` |
| 商品归位映射 | 已核实映射库 + 用户确认 | 带 `source`、`reviewedAt` 或 `confirmedAt` |
| 路线记录 | 系统按真实输入生成 | 只保存清单与区域顺序快照 |
| 历史记录 | 用户真实完成 | 服务端真实时间 |

### 7.2 已核实映射库

已核实映射库是仓库内版本化 JSON，不是运行时 mock：

```json
{
  "productKey": "tomato",
  "names": ["西红柿", "番茄"],
  "zoneType": "produce",
  "source": "openfoodfacts-category",
  "sourceRef": "en:vegetables",
  "reviewedAt": "2026-08-06T00:00:00+08:00"
}
```

规则：

- 只有带 `source` 和 `reviewedAt` 的条目才允许作为系统建议。
- 用户确认后的映射比系统建议优先。
- 商品名先做归一化匹配；匹配不到时进入未归位。
- 映射库缺失时功能不降级为猜，而是引导用户确认。

### 7.3 无 mock 保障

- 生产环境无种子商品、无演示超市、无演示区域、无演示路线。
- Open Food Facts 不可用时，不返回假名称、假分类或假图片。
- 门店没有官方区域数据时，不把通用区域表当作该店事实。
- 未归位商品不会被自动分配区域。
- 不展示无法追溯到来源的“预计时间”“距离”“最短路径”。
- 测试数据与生产数据物理隔离。

## 9. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 首次进入且无清单 | 真实空态，只提供“建立清单”和“添加超市” |
| 无常去超市 | 不生成路线，引导创建超市 |
| 超市无区域顺序 | 不生成路线，引导录入区域 |
| 存在未归位商品 | 路线可生成但标为不完整，未归位商品独立展示 |
| Open Food Facts 不可用 | 只保留用户输入，不显示伪造元数据 |
| 门店官方区域数据不可用 | 只使用用户确认的区域顺序 |
| 路线生成失败 | 保留原清单，显示错误态，不生成假路线 |
| 购物中断 | 已打勾状态保存，下次进入继续 |
| 删除超市或清单 | 二次确认；商品归位映射保留 |

## 11. 视觉与交互

- 沿用 FunBox 现有浅蓝画布、白色表面、深色文字、品牌蓝主色体系。
- 本功能主色为绿色 `#1d9c7c`，路线使用蓝绿渐变，未归位使用琥珀色。
- 内容区最大宽度 430px，宽屏居中；320px、390px、430px 视口内不允许文字溢出或元素重叠。
- 区域顺序使用上移/下移和拖拽，按钮尺寸不小于 40px。
- 路线区域分组使用稳定高度，商品数量变化不引起布局跳动。
- 所有来源标签使用统一格式：来源名 + 更新时间。

## 12. 一期验收标准

1. 首次进入没有任何预置商品、超市、区域、路线或历史记录。
2. 购物清单只来自用户创建或菜谱真实食材导入。
3. 条码查询只展示 Open Food Facts 真实返回字段，失败时不补造。
4. 未归位商品不会被自动分配区域，也不会被隐藏。
5. 区域顺序只来自用户确认或门店官方数据导入。
6. 自动排序必须使用该店真实区域顺序，不使用通用假区域表。
7. 路线结果不展示无来源的距离、步行时间和“最短路径”。
8. 购物中逐项打勾，退出后状态可恢复。
9. 历史与导出只包含真实记录。
10. 320px、390px、430px 视口无文字溢出和元素重叠。
11. Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。

## 13. 明确不做

- 不做 AI 生成购物清单、商品名、区域名或归位关系。
- 不做基于位置的自动判断“用户正在哪家超市”。
- 不展示无来源的价格、库存、距离、步行时间和最短路径。
- 不自动创建用户未确认的超市、区域或商品。
- 不做共享清单、家庭协作、好友排行。
- 不做分期实施；所有功能一次交付。

## 14. 风险与决策

| 风险 | 决策 |
| --- | --- |
| 用户希望“开箱即用” | 提供菜谱导入与已核实映射建议，但必须先由用户确认 |
| 每家超市区域不同 | 区域名称和顺序按门店保存，通用区域类型只做翻译 |
| 自动排序可能误导 | 未归位商品独立展示，路线完整性明确标注 |
| Open Food Facts 中文覆盖有限 | 条码查询失败时保留用户输入，不影响正常使用 |
| 用户担心系统猜位置 | 不做定位推断，路线始终由用户选择超市生成 |
| 历史误删 | 删除与清空均二次确认，导出可作为备份 |

## 15. 成功指标

1. 已确认常去超市的用户，首次生成路线时间不超过 30 秒。
2. 用户完成一次路线生成到完成购物，中位时间不高于未使用路线用户。
3. 已核实映射库命中率逐步提升，未归位商品占比在 3 次使用后不高于 20%。
4. 所有商品、区域、顺序字段来源覆盖率达到 100%。
5. 路线页面中无来源距离/时间展示次数为 0。
