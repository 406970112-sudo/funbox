# FunBox 出门检查清单 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 状态：待评审
> 定位：出门前一键确认的“真清单”。物品、场景、完成记录全部来自用户真实创建与确认；天气按真实公开数据自动补充已有物品，不做预置演示、不补造缺失值。

## 1. 背景与问题

出门前遗漏物品通常发生在“赶时间、换场景、天气变化”三个时刻，现有做法大多依赖记忆或纸质便签，缺少一个可确认、可回看、可被真实天气提醒的闭环。

| 现状 | 问题 |
| --- | --- |
| 靠脑子记 | 换场景时容易漏带工牌、门禁卡、充电器等 |
| 固定清单纸 | 无法随天气变化，下雨仍忘伞 |
| 只列物品 | 门窗、燃气等离家安全检查没有确认入口 |
| 场景切换麻烦 | 上班、旅行、运动需要临时增减物品 |
| 完成没有反馈 | 检查完没有可回看的真实记录 |

FunBox 已有账号、JWT、SQLite、工具注册、主题系统和通知能力，可以复用一个完整的前后端基础设施，不需要引入新服务。

## 2. 对原始想法的补充

原始想法是：出门前确认手机、钥匙、钱包、耳机、充电宝、工牌、雨伞、门窗、燃气，并按上班、旅行、运动切换清单，下雨自动加伞。

在此基础上补充十二点：

1. 物品、场景、完成记录全部来自用户真实操作，首次进入没有任何预置物品、预置场景记录或演示完成数据。
2. “一键确认”不等于无脑全选。首页逐项可勾选，底部一键“确认全部已带”，只有全部确认后才生成“今日出门检查完成，没有遗漏。”
3. 场景是用户可管理的真实配置，提供版本化模板供用户主动选择，模板被选择后才写入用户数据。
4. 自动切换只依据用户配置的“星期 + 时间”，不做位置推断、不做 AI 猜测；未配置时保持用户上次手动选择的场景。
5. 天气联动由真实天气源触发，只把用户已经创建的物品加入“天气补充”；用户没有创建雨伞时，只提示“是否添加雨伞”，不自动生成假物品。
6. 每件物品可绑定一个或多个天气规则，规则版本化，条件、阈值、数据来源均可解释。
7. 天气失败时天气卡片显示“暂未获取”，隐藏依赖该数据的规则，不补造降雨概率或体感温度。
8. 通知权限显示系统真实授权状态；未授权时不提示“已通知”。
9. 历史与统计只来自真实完成记录，空状态就是真实空状态。
10. 未登录可本地使用，登录后同步到账号；完成记录带服务端真实时间。
11. 本方案所有页面、接口、规则、通知、测试在一个版本内一次做完，不设二期。
12. 开发与测试使用测试库和契约测试，生产环境无种子数据、无 mock 兜底、无演示账号。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户在 30 秒内完成一次“场景切换 + 逐项确认 + 一键完成”。
2. 首页每个真实数据字段都能追溯到用户创建、系统时间或公开天气源。
3. 天气异常、权限未开启、无完成记录时页面仍然真实可用，但绝不编造。
4. 换场景不再重新整理清单，模板、自定义和定时切换一次做完整。

### 3.2 设计原则

- 真实优先：物品、场景、完成、统计缺则隐藏，不为了填满页面而补数据。
- 用户决策：模板只提供内容建议，选择权永远在用户。
- 可解释：天气补充项展示触发规则和真实天气依据。
- 克制自动：自动切换只按用户配置执行，不做“聪明”猜测。
- 一期全量：核心页面、规则、接口、通知和测试一次交付。
- 隐私克制：不保存精确轨迹，不根据位置自动推断出门场景。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 上班族 | 每天早晨赶时间出门 | 30 秒内确认手机、钥匙、工牌，自动带天气补充 |
| 出差/旅行用户 | 打包换场景，物品差异大 | 切换旅行模式，模板创建身份证、充电器、药品、换洗衣物 |
| 运动爱好者 | 下班或周末去健身 | 一键切换运动模式，确认水杯、毛巾、耳机、门禁卡 |
| 家庭用户 | 出门后担心门窗燃气 | 离家安全组强制确认，完成记录可回看 |
| 天气敏感用户 | 下雨、暴晒、高温天出门 | 真实天气触发雨伞、防晒霜、水杯等已有物品 |

| 页面 | 说明 |
| --- | --- |
| 一键检查首页 | 真实天气、当前场景、常备物品、场景物品、天气补充、离家安全、一键确认 |
| 完成反馈 | “今日出门检查完成，没有遗漏。”以及真实时间、确认项数和场景 |

### 5.3 核心流程

```text
进入出门检查清单
  -> 首页显示当前场景 + 真实天气
  -> 天气规则命中且用户已有对应物品 -> 加入“天气补充”
  -> 用户逐项确认或“确认全部已带”
  -> 全部确认后生成完成反馈并写入真实记录
  -> 有定时配置 -> 按真实星期和时间自动切换场景并提醒
  -> 历史页只展示真实完成记录
```

## 6. 功能设计

### 6.1 一键检查首页

- 顶部显示真实日期、时间、城市和天气摘要：当前温度、体感温度、降雨概率、AQI。
- 天气摘要来自公开天气接口，并标注来源与抓取时间。
- 场景切换使用分段控件：上班 / 旅行 / 运动 / 自定义。
- 清单按组展示：
  - 常备清单：手机、钥匙、钱包、耳机、充电宝等用户自己创建的物品。
  - 场景物品：当前场景额外加入的工牌、身份证、水杯等。
  - 天气补充：由天气规则触发，只在用户已有对应物品时出现。
  - 离家安全：门窗关闭、燃气关闭等安全确认项。
- 每个检查项可单独点击确认，已确认项有稳定选中态。
- 底部主按钮为“确认全部已带”，点击后如果存在未确认项，按钮提示剩余数量；全部确认后进入完成反馈。
- 无物品时不显示“空模板占位”，显示“先把常用物品加进清单”并提供场景模板入口。

### 6.2 完成反馈

- 成功页主文案固定为“今日出门检查完成，没有遗漏。”
- 下方展示真实信息：完成日期、完成时间、场景名称、确认项数、天气补充项数。
- 完成记录写入服务端，时间为服务端当前时间。
- 提供“返回首页”和“查看今日记录”两个操作。
- 若用户在完成后 5 分钟内撤销，可删除本次记录并回到检查首页；撤销写入事件流。

### 6.3 场景与模板

- 模板库包含上班、旅行、运动三套版本化模板：
  - 上班模式：手机、钥匙、工牌、耳机。
  - 旅行模式：身份证、充电器、药品、换洗衣物。
  - 运动模式：水杯、毛巾、耳机、门禁卡。
- 模板不是自动写入；用户点击“使用此模板”后，系统才创建真实物品和场景。
- 用户可编辑场景名称、图标、排序和物品。
- 自定义物品支持名称、图标、类别（物品 / 安全确认项）和天气规则。
- 同一个物品可被多个场景引用，删除场景不会删除物品。

### 6.4 天气联动

- 天气数据源为 Open-Meteo Forecast 和 Open-Meteo Air Quality，无密钥，按用户保存的城市坐标查询。
- 天气规则表版本化，V1 提供：

| 规则 ID | 触发条件 | 自动加入对象 | 数据来源 |
| --- | --- | --- | --- |
| `rain-umbrella` | 未来 12 小时最高降雨概率 >= 40% 或当前有雨 | 用户已有“雨伞” | Open-Meteo Forecast |
| `uv-protect` | 当日最大 UV >= 6 | 用户已有“防晒霜” | Open-Meteo Forecast |
| `heat-water` | 当日最高温 >= 32°C | 用户已有“水杯” | Open-Meteo Forecast |
| `air-mask` | 当前 EAQI > 100 | 用户已有“口罩” | Open-Meteo Air Quality |

- 规则命中时，对应物品以“天气补充”组展示，并显示“降雨概率 52%”等真实依据。
- 用户没有对应物品时，天气卡片显示“今日降雨概率 52%，是否添加雨伞？”点击后创建真实物品，不自动插入。
- 天气数据不可用时，天气卡片显示“暂未获取”，天气补充组不出现。
- 支持手动刷新，刷新结果写入当日真实缓存并标注 `cachedAt`。

### 6.5 提醒与自动切换

- 用户可为场景配置“星期 + 时间”，例如周一至周五 08:20 切到上班模式。
- 到配置时间后，应用切换当前场景；如通知权限已开启，发送本地提醒。
- 自动切换依据系统真实星期和时间；没有配置时不改变用户当前场景。
- 通知权限页显示系统真实状态：已开启 / 未开启 / 待授权。
- 未授权时只显示应用内状态，不显示“已通知”。

### 6.6 历史记录

- 历史列表只包含用户真实完成的检查记录。
- 每条记录包含完成时间、场景、确认项数、天气补充项数和天气摘要快照。
- 统计字段全部来自真实记录：今日完成、本周完成、连续出门天数。
- 无记录时显示真实空状态，不预置任何演示记录。
- 支持单条删除、导出 CSV/JSON 和清空全部数据（需二次确认）。

## 7. 真实数据方案

### 7.1 数据来源

| 数据 | 来源 | 展示规则 |
| --- | --- | --- |
| 物品与场景 | 用户创建或用户主动选择模板 | 只展示用户真实创建内容 |
| 完成记录 | 用户全部确认后写入 | 带服务端真实时间 |
| 天气 | Open-Meteo Forecast | 展示温度、体感、降雨概率、UV，带 `source` 与 `fetchedAt` |
| 空气质量 | Open-Meteo Air Quality | 展示 EAQI、PM2.5 等，带 `source` 与 `fetchedAt` |
| 城市与坐标 | 用户手动选择或系统定位 | 只保存城市名、时区与近似坐标 |
| 定时切换 | 用户配置 | 按系统真实星期和时间执行 |
| 通知状态 | 系统通知权限 | 未授权显示“未开启” |
| 服务端时间 | `serverNow` | 完成、缓存和提醒判断均以服务端时间为准 |

### 7.2 计算规则

```text
未来 12 小时最高降雨概率 = max(precipitation_probability[now, now+12h])
当日最大 UV = uv_index_max
当日最高温 = temperature_2m_max
天气自动加入 = 物品存在 且 物品绑定规则 且 规则条件成立
完成反馈 = 全部检查项已确认 -> "今日出门检查完成，没有遗漏。"
```

### 7.3 无 mock 保障

- 不预置种子物品、种子完成记录或演示统计。
- 不自动创建用户未拥有的天气物品。
- 不用 AI 编造天气、体感温度或提醒状态。
- 数据源失败时不回退到示例数据，只展示真实空状态或已有缓存。
- 开发测试数据与生产数据物理隔离，禁止把测试库写入生产环境。

## 9. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 首次进入且无物品 | 真实空状态 + “从模板创建”入口，不预置物品 |
| 天气数据获取中 | 天气区显示加载状态，其他清单正常使用 |
| 单个天气源失败 | 隐藏依赖该源的数据和规则，不补造 |
| 全部天气源失败且有当日缓存 | 展示缓存并标注 `cachedAt` |
| 全部天气源失败且无缓存 | 天气区显示“暂未获取”和重试按钮 |
| 用户未创建雨伞但天气需要 | 提示“是否添加雨伞”，不自动创建 |
| 通知权限未开启 | 显示系统真实状态，不提示“已通知” |
| 定时配置未设置 | 不切换场景，保持用户手动选择 |
| 用户未全部确认 | 不能生成“没有遗漏”文案，只显示确认进度 |

## 11. 视觉与交互

- 沿用 FunBox 现有浅蓝画布、白色卡片、深色文字、品牌蓝主色体系。
- 本功能主色为 `#4b6bff`，完成态使用绿色 `#1db991`，天气提示使用琥珀色 `#f1a33b`，安全提示使用珊瑚色 `#ff5d6c`。
- 内容区最大宽度 430px，宽屏居中；320px、390px、430px 视口内不允许文字溢出或元素重叠。
- 检查项使用稳定尺寸的圆形选中态，避免动态数字改变布局。
- 天气补充项必须显示触发规则，不单独展示无来源数值。
- 深色主题沿用现有 `appTheme.dark`，颜色映射表不改变，只在渲染层适配。

## 12. 一期验收标准

1. 首次进入没有任何物品、场景记录、完成记录或演示统计。
2. 用户从模板创建场景后，物品和场景才出现在清单中。
3. 天气数据来自 Open-Meteo 真实接口，首页每个天气值可查看来源和抓取时间。
4. 降雨概率 >= 40% 且用户已有雨伞时，雨伞自动进入“天气补充”并展示依据。
5. 用户没有雨伞时只出现添加建议，不自动创建假物品。
6. 全部确认后才出现“今日出门检查完成，没有遗漏。”
7. 定时自动切换只按用户配置执行；未配置时保持不变。
8. 通知权限未开启时显示真实状态，不提示“已通知”。
9. 历史统计只统计真实完成记录，删除后不再出现在任何接口中。
10. 320px、390px、430px 视口无文字溢出和元素重叠。
11. Go 测试、前端 Node 测试、TypeScript 检查与 lint 全部通过。

## 13. 明确不做

- 不做基于位置的自动出门判断或轨迹记录。
- 不用 AI 推断“你现在要去哪里”或自动增减物品。
- 不自动创建用户未拥有的物品，不补造天气值。
- 不做共享清单、家庭协作、好友排行。
- 不做一键“假装全部已带”而绕过安全确认的永久跳过。
- 不做分期实施；所有页面、规则、接口和通知一次交付。

## 14. 风险与决策

| 风险 | 决策 |
| --- | --- |
| 用户把“一键确认”当成无脑全选 | 首页保留逐项确认，主按钮显示剩余未确认数量 |
| 天气源偶尔不可用 | 字段级降级 + 当日缓存 + 明确状态 |
| 模板可能不符合个人习惯 | 模板需用户主动选择，支持全部自定义 |
| 自动切换造成意外 | 只按用户配置的星期和时间执行，不猜测 |
| 通知权限被系统关闭 | 显示真实授权状态，应用内照常可用 |
| 完成记录被误操作 | 5 分钟撤销窗口 + 二次确认删除 |

## 15. 成功指标

1. 一次检查从进入首页到完成的中位时间不超过 30 秒。
2. 天气数据字段来源覆盖率 100%，无来源字段展示次数为 0。
3. 天气规则触发时，“天气补充”项必须包含可解释依据。
4. 用户完成检查后，历史记录写入成功率不低于 99%。
5. 无 mock 校验：生产环境种子数据、演示记录和模拟统计数量为 0。

## 16. 附录：设计稿数据说明

设计稿中出现的天气数值来自 2026-08-06 上海 Open-Meteo Forecast 与 Open-Meteo Air Quality 真实公开接口。清单物品、场景、完成记录仅用于展示交互位置；正式产品首次进入为空状态，所有数据来自用户真实创建、选择与确认。
