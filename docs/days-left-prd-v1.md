# FunBox 还有几天（个人期限管理器）产品设计方案 V1

> 版本：V1 草案  
> 日期：2026-08-04  
> 状态：待评审  
> 定位：一个只管理“什么时候到期”的个人期限管理器，把所有真实到期信息收进一个可查、可提醒、可续期、可追溯的中心。

## 1. 背景与问题

证件、续费、物品保质期、数字资产和纪念日分散在钱包、邮箱、日历、App 会员中心和纸箱包装上，用户经常在“已经过期”之后才想起来。

| 场景 | 现状 | 问题 |
| --- | --- | --- |
| 身份证、驾驶证、护照 | 证件实体上的到期日，想起来才翻 | 到期前没有主动提醒，换证排队后才发现 |
| 房租、保险、会员 | 扣款通知和续费邮件散落各处 | 不知道该提前多久准备，续费后没有记录 |
| 药品、食品、化妆品 | 开封后保质期经常被忽略 | 只知道保质期，不知道开封后还有多久 |
| 域名、服务器、SSL 证书 | 注册商、云厂商、证书面板各管各的 | 到期日分散，证书过期导致服务不可用 |
| 汽车保养和年检 | 里程、日期、提醒混在备忘录里 | 保养周期和年检截止容易记混 |
| 生日、纪念日 | 日历只显示当天 | 不知道提前几天准备，错过才知道 |

FunBox 已有账号、JWT、SQLite、工具注册、主题系统和“最近使用”能力，新增该工具可以沿用同一套基础设施，不需要引入新服务。

## 2. 对原始想法的补充

原始想法是“管理什么时候到期”。在此基础上补充十点：

1. 到期类型分四类：固定到期、开封有效期、周期续费、纪念日。不同类型的计算和后续动作不同。
2. 风险分级与提前量：证件提前 90 天、财务合同提前 30 天、生活物品提前 7 天、数字资产提前 30 天、车辆提前 30 天、纪念日提前 3 天，均可按单条记录覆盖。
3. 真实数据优先：记录只能来自用户真实录入、真实照片、真实扫描确认或真实公开接口校验，不做种子数据、演示数据、mock 数据和 AI 编造。
4. 续期闭环：续费、更新、处理后保留历史，可以撤销，可以追溯上一次和下一次到期时间。
5. 分类模板与自定义分类：内置证件、财务合同、生活物品、数字资产、车辆、纪念日六类，允许自定义名称、图标、颜色和提醒提前量。
6. 提醒分层：App 内提醒、移动端系统通知、Web 站内提醒；提醒时间由真实到期日和提前量计算，不手动编造。
7. 日历与统计：未来 30/90 天、已逾期、已处理、处理率、月度日历和续期历史都基于真实记录计算。
8. 证据存档：证件、包装、账单可以拍照存档，照片只作真实证据，不参与日期生成。
9. 隐私优先：记录仅属于当前用户，接口全部走 JWT 鉴权；敏感证件信息不对外展示、不上传公共空间。
10. 备份导出：支持把用户自己的真实数据导出为 CSV/JSON，不做跨用户分享。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户 30 秒内完成一次“新增到期记录”或“查看今天要处理什么”。
2. 每条记录都能说清到期类型、剩余天数、来源和证据。
3. 到期前能按风险提前量收到提醒，续期后能保留真实历史。
4. 产品运行时没有任何假数据、mock 数据或 AI 编造的到期日期。

### 3.2 设计原则

- 真实优先：日期、状态、统计只来自真实来源，缺字段显示“暂无”，不补造。
- 风险可判：用“已逾期 / 7 天内 / 30 天内 / 90 天内”四档表达紧迫程度。
- 一屏可查：首页直接给出今日到期、即将到期和快捷添加。
- 一期全量：本方案所有功能在同一个版本内一次做完，不设分期。
- 可追溯：每条记录带 `source`、`createdAt`、`verifiedAt` 和可选证据。
- 隐私克制：只做个人管理，不做公共分享、排行、团队协作。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 职场用户 | 身份证、驾驶证、护照到期，续期手续复杂 | 提前 90 天提醒，保存真实换证日期 |
| 租客/家庭用户 | 房租、保险、会员扣款日期分散 | 周期续费自动生成下一次到期 |
| 家庭采购用户 | 药品、食品、化妆品开封后不知道何时过期 | 开封日期 + 有效期自动计算到期日 |
| 站长/开发者 | 域名、服务器、SSL 证书到期影响线上服务 | 真实证书校验 + 提前提醒 |
| 车主 | 保养周期和年检日期容易记混 | 分类记录保养和年检，分别提醒 |
| 亲密关系用户 | 生日、纪念日需要提前准备 | 纪念日提前提醒，当天标记完成 |

## 5. 产品结构

### 5.1 入口

- 工具注册名：`days-left`
- 工具名称：还有几天
- 分类：生活
- 路由：`/tools/days-left`
- 入口图标建议：`calendar-clock-outline`（Material Community Icons）
- 状态：一期发布时直接注册为 `available`；如需占位，先 `coming-soon` 并在同一次发布中切换
- 权限：`normal / vip / svip / admin` 均可使用，V1 不做会员权益差异

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 首页“还有几天” | 日期、今日摘要、风险分桶、今日到期、即将到期、快捷添加 |
| 记录列表 | 分类/状态筛选、搜索、排序、批量标记、导出 |
| 新增/编辑 | 名称、分类、到期类型、到期日期、提醒、备注、证据照片 |
| 详情/续期 | 真实来源、校验状态、续期/完成、历史记录、撤销 |
| 分类管理 | 内置分类模板、自定义分类、图标/颜色/提醒提前量 |
| 提醒中心 | 待提醒、已提醒、提醒渠道、应用内通知 |
| 统计与日历 | 未来 30/90 天、已逾期、处理率、月度日历、续期历史 |

以上页面均为一期交付范围。

### 5.3 核心流程

```text
进入还有几天
  -> 首页：今日到期 / 即将到期 / 风险分桶
  -> 新增记录：名称 + 分类 + 到期类型 + 日期 + 提醒
  -> 可选：拍照存档 / 真实来源校验
  -> 保存后进入记录列表与统计
  -> 到期前：提醒中心触发提醒
  -> 处理后：续期或完成，生成历史，可撤销
```

## 6. 功能设计

### 6.1 首页“还有几天”

- 顶部显示本地日期与“今日摘要”，例如“今天没有到期”“未来 90 天有 1 项”。
- 风险分桶四格：已逾期、7 天内、30 天内、90 天内，数字来自真实记录。
- “今日到期”区域：今天到期和已逾期记录，按风险最高优先。
- “即将到期”区域：未来 30 天、未来 90 天分组展示。
- 快捷动作：添加到期记录、拍照/扫一扫、查看提醒。
- 首次使用为空状态：只有引导和分类模板，不预置任何到期记录。

### 6.2 记录列表

- 筛选：分类、状态（全部/待处理/已处理/已续期）、风险分桶。
- 搜索：名称、备注、来源关键字。
- 排序：到期日升序、剩余天数、风险等级、最近添加。
- 批量操作：批量标记已处理、批量导出。
- 记录卡片：名称、分类、到期日期、剩余天数、风险等级、来源徽标。
- 空结果：显示“没有符合条件的真实记录”，提供清空筛选和新增入口。

### 6.3 新增/编辑

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 名称 | 是 | 单行文本，最长 60 字 |
| 分类 | 是 | 从分类列表选择，默认最近使用分类 |
| 到期类型 | 是 | 固定到期 / 开封有效期 / 周期续费 / 纪念日 |
| 到期日期 | 条件必填 | 固定到期与周期续费填写；开封有效期由开封日期 + 有效期计算；纪念日填写当天日期 |
| 开封日期 | 条件必填 | 开封有效期类型使用 |
| 有效期 | 条件必填 | 开封有效期类型使用，单位天/月/年 |
| 续费周期 | 条件必填 | 周期续费类型使用，日/周/月/年 |
| 提前提醒 | 是 | 3/7/14/30/60/90 天，也可自定义 |
| 备注 | 否 | 多行文本，最长 500 字 |
| 证据照片 | 否 | 拍照或相册上传真实照片，最多 5 张 |
| 来源 | 系统记录 | 手动录入 / 照片 / 扫描确认 / 接口校验 / 文件导入 |

开封有效期计算规则：`到期日期 = 开封日期 + 有效期`；修改开封日期或有效期后重新计算，不覆盖用户手动修正的到期日期。

周期续费规则：首次录入到期日后，续期时按周期自动生成下一次到期日；续期日期以用户确认的真实日期为准，不允许应用凭空推算未确认日期。

### 6.4 详情/续期

- 展示名称、分类、类型、到期日期、剩余天数、状态、来源、校验时间、证据照片。
- “标记已续期”：填写真实新到期日期，可修改续费周期，生成历史记录。
- “标记已完成”：用于纪念日和一次性事项，当天处理后进入已完成。
- “编辑/删除”：删除需二次确认，历史统计不受删除影响。
- 撤销：最近一次续期或完成可撤销，恢复旧状态。
- 历史：每次动作保留 `previousExpiryDate -> newExpiryDate`、动作、时间、备注和证据。

### 6.5 分类管理

内置分类模板：

| 分类 | 默认图标 | 默认提醒 | 默认类型 |
| --- | --- | --- | --- |
| 证件 | `id-card` | 90 天 | 固定到期 |
| 财务合同 | `credit-card` | 30 天 | 周期续费 |
| 生活物品 | `package` | 7 天 | 开封有效期 |
| 数字资产 | `server` | 30 天 | 周期续费 |
| 车辆 | `car` | 30 天 | 固定到期 |
| 纪念日 | `cake` | 3 天 | 纪念日 |

- 内置分类不可删除，可修改图标和默认提醒提前量。
- 自定义分类：名称、图标、颜色、默认提醒、默认类型。
- 分类本身是产品结构，不包含任何到期数据。

### 6.6 提醒中心

- 待提醒：未来 3/7/30/90 天内的真实记录，按日期排序。
- 已提醒：已发送的提醒，保留真实时间。
- 渠道：移动端系统通知、App 内提醒、Web 站内提醒。
- 提醒时间 = 到期日期 - 提前量，由服务端计算并排程。
- 用户修改记录后，撤销旧提醒并重新排程。
- 拒绝通知权限时只保留 App 内提醒，不反复打扰。

### 6.7 统计与日历

- 未来 30/90 天数量、已逾期数量、已处理数量、处理率。
- 月度日历：展示真实到期日期，无记录日期不展示任何点。
- 续期历史：按时间倒序展示每次续期动作。
- 导出：CSV/JSON 导出用户自己的真实数据，导出文件带导出时间。

### 6.8 真实数据机制

| 来源 | 说明 | 校验要求 |
| --- | --- | --- |
| 手动录入 | 用户从真实证件、账单、包装上录入 | 用户确认后保存 |
| 照片 | 拍照/相册上传真实证据 | 照片只存档，不生成日期 |
| 扫描确认 | 对真实照片 OCR 后由用户逐项确认 | 未确认字段不提交 |
| 接口校验 | SSL 证书、域名注册信息等真实公开来源 | 记录 `verifiedAt`，不一致时高亮 |
| 文件导入 | CSV/JSON 导入用户自己的备份 | 校验字段后入库，拒绝空值和越界 |

禁止事项：

- 不生成任何种子记录、演示记录、mock 数据或“示例到期”。
- 不由 AI 推断、编造或补全到期日期。
- 不自动把未确认的 OCR 结果写入数据库。
- 不在没有真实来源时展示“已核验”“官方”“准确”等断言。
- 不在 API 或存储中返回虚假统计。

## 7. 数据模型

```text
days_left_categories
  id, user_id, name, icon, color, reminder_lead_days,
  default_record_type, is_system, sort_order, archived_at,
  created_at, updated_at

days_left_records
  id, user_id, category_id, name, record_type,
  start_date, expiry_date, validity_days,
  cycle_unit, cycle_interval, reminder_lead_days,
  note, status, risk_level, source,
  evidence_url, verified, verified_at,
  last_renewed_at, archived_at, created_at, updated_at

days_left_evidence
  id, record_id, user_id, file_url, kind, taken_at, created_at

days_left_events
  id, record_id, user_id, action,
  previous_expiry_date, new_expiry_date,
  note, evidence_url, created_at

days_left_reminders
  id, record_id, user_id, remind_at, channel,
  status, sent_at, created_at
```

时间规则：

- API 使用 `YYYY-MM-DD` 日期字符串，由客户端按用户本地时区生成。
- 剩余天数以本地日期边界计算：`ceil((expiry_date - today) / 86400000)`。
- 已逾期 = `expiry_date < today`；今日到期 = `expiry_date === today`。
- 服务端不自行转换时区，V1 不覆盖跨时区旅行场景。

## 8. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/days-left/summary?date=YYYY-MM-DD` | 首页摘要与风险分桶 |
| GET | `/api/v1/days-left/records?category=&status=&q=&sort=` | 记录列表与搜索 |
| POST | `/api/v1/days-left/records` | 新增记录 |
| GET | `/api/v1/days-left/records/{id}` | 记录详情 |
| PATCH | `/api/v1/days-left/records/{id}` | 编辑记录 |
| DELETE | `/api/v1/days-left/records/{id}` | 删除记录 |
| POST | `/api/v1/days-left/records/{id}/renew` | 续期并生成历史 |
| POST | `/api/v1/days-left/records/{id}/complete` | 标记已完成 |
| POST | `/api/v1/days-left/records/{id}/undo` | 撤销最近动作 |
| POST | `/api/v1/days-left/records/{id}/evidence` | 上传真实证据照片 |
| GET | `/api/v1/days-left/categories` | 分类列表 |
| POST | `/api/v1/days-left/categories` | 新建自定义分类 |
| PATCH | `/api/v1/days-left/categories/{id}` | 修改分类 |
| DELETE | `/api/v1/days-left/categories/{id}` | 删除自定义分类 |
| GET | `/api/v1/days-left/calendar?month=YYYY-MM` | 月度日历 |
| GET | `/api/v1/days-left/stats?range=week\|month\|year` | 统计汇总 |
| GET | `/api/v1/days-left/reminders` | 提醒列表 |
| POST | `/api/v1/days-left/reminders/{id}/dismiss` | 关闭提醒 |
| POST | `/api/v1/days-left/import` | 真实文件导入 |
| GET | `/api/v1/days-left/export?format=csv\|json` | 导出用户自己的数据 |
| GET | `/api/v1/days-left/verify/ssl?host=` | SSL 证书真实到期校验 |

说明：

- 所有接口要求登录，沿用现有 JWT 鉴权与限流中间件。
- 新增模块放在 `backend/internal/daysleft/`，在 `httpapi/server.go` 注册路由。
- 响应中每条记录带 `source`、`createdAt`、`verifiedAt`。
- SSL 校验只返回真实 TLS 握手结果，不生成或修改日期。

## 9. 页面与交互设计

- 沿用 FunBox 视觉体系：浅蓝画布、白色表面、深藏青重点、品牌蓝主色；本工具补充到期语义色：逾期珊瑚红、紧急琥珀、安全绿色。
- 内容区最大 430px 移动宽度，宽屏居中。
- 到期类型、风险分桶、提醒提前量使用分段控件或步进器；日期使用原生选择器；拍照/相册使用图标按钮。
- 图标沿用 Material Community Icons；移动端按钮可点区域不小于 40px。
- 支持浅色与深色主题；320px、390px、430px 视口下文本不溢出、元素不重叠。
- 不做教程式大段说明文字，空状态只给可执行动作。

## 10. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 首次进入，无记录 | 空状态 + 添加入口 + 分类模板，不预置数据 |
| 接口不可用 | 展示已缓存的真实数据并标注更新时间，不展示 mock |
| SSL 校验不一致 | 琥珀色提示“实时校验不一致”，不自动改日期 |
| OCR 未确认 | 字段保持草稿，用户确认后才保存 |
| 照片上传失败 | 保留表单内容，提示重试 |
| 删除记录 | 二次确认，历史统计不受影响 |
| 撤销续期 | 恢复旧状态，生成撤销历史 |
| 导出失败 | 保留页面状态并提示重试 |

## 11. 一期交付清单

本方案不设分期，以下内容在同一版本一次交付：

- 首页摘要、风险分桶、今日到期、即将到期。
- 记录 CRUD、搜索、筛选、排序、批量标记。
- 固定到期、开封有效期、周期续费、纪念日四类记录。
- 内置分类、自定义分类、分类级提醒提前量。
- 详情、续期、完成、撤销、历史。
- 真实照片证据上传。
- SSL 证书真实校验。
- 提醒中心、移动端系统通知、Web 站内提醒。
- 统计、月度日历、续期历史。
- CSV/JSON 导入导出。
- 浅色/深色主题与 320/390/430 响应式。
- 单元测试覆盖计算、校验、权限与接口。

## 12. 明确不做

- 不做 AI 生成或补全到期日期、保质期、续费日期。
- 不做种子数据、演示数据、mock 数据。
- 不做公共日历分享、团队协作、排行榜。
- 不做购物、支付、保险理赔、医疗建议。
- 不做跨设备之外的第三方推送通道；V1 提醒渠道限定 App 内、系统通知和 Web 站内。
- 不做证件真伪识别和国家证件库联网核验。

## 13. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 域名到期数据源不稳定 | 优先用户录入 + 真实文件/注册商截图证据；有公开源时再接入 | 数据源覆盖度不同，但都不造数 |
| OCR 识别率 | 所有字段必须人工确认后才保存 | 录入成本略高，但保证真实 |
| 证件数据敏感 | 全部走登录鉴权，详情不对外暴露 | 需要隐私评审 |
| 系统通知权限 | 拒绝后降级为 App 内提醒 | 提醒覆盖面下降 |
| 时间区跨时区 | V1 以本地日期为准 | 不覆盖旅行跨时区场景 |

## 14. 验收清单

- 首次进入没有预置到期记录，首页为空状态。
- 新增四类记录后，首页摘要、列表、统计与日历数字一致。
- 剩余天数计算、已逾期、今日到期、周期续期计算正确。
- 续期/完成/撤销生成真实历史，可回看。
- SSL 校验返回真实证书到期时间，不一致时有提示。
- 修改记录后提醒重新排程，旧提醒撤销。
- 导出文件只包含当前用户真实数据。
- 320px、390px、430px 视口无文本溢出和元素重叠。
- 深色/浅色主题下页面可读。
- 接口全部有 JWT 鉴权，未登录返回 401。
