# FunBox 拖延任务粉碎机 产品设计方案 V1

> 版本：V1 一期全量
> 日期：2026-08-06
> 状态：待评审
> 定位：把大任务拆成 3 分钟起步的微步骤，每完成一步按真实记录结算经验值，让拖延者在“只做第一步”里开始行动。

## 1. 背景与问题

拖延通常不是“不想完成大任务”，而是大任务在脑子里太大，开始成本太高，完成反馈又太远。

| 场景 | 现状 | 问题 |
| --- | --- | --- |
| 整理房间 | 一想到“收拾整个房间”就迟迟不动 | 任务边界模糊，不知道第一步该做什么 |
| 写周报 | 打开文档后停留在空白页 | 没有可执行的小动作，启动成本高 |
| 复习功课 | 计划“复习整章”但一直拖着 | 目标太大，完成感离得太远 |
| 准备旅行 | 事项散落在多个清单里 | 不知道哪件先做，容易持续往后推 |

FunBox 已有账号、JWT、SQLite、统一工具注册、主题系统和“最近使用”能力，新增该工具可以直接沿用同一套基础设施。

## 2. 对原始想法的补充

原始想法是“把大任务拆成很小步骤，每完成一步获得经验值”。在此基础上补充十点：

1. 微步骤：一个目标拆成 2 到 20 步，每一步只描述一个可立即执行的动作。
2. 预计时间：每步由用户填写 1 到 120 分钟，目标总时长由服务端按步骤求和，不手动编造。
3. 只做第一步：首页直接给出当前建议的第一步，但不强制用户按顺序完成。
4. 真实执行：每步可以“开始”并记录实际用时，也可以不开始直接完成；实际用时只来自服务端时间，不来自客户端猜测。
5. 经验值账本：每步经验值由服务端按已保存的预计分钟数计算，并写入可追溯的 XP 账本。
6. 等级与统计：等级、进度、连续天数、图表全部由真实账本和真实目标记录聚合，不写静态数字。
7. 撤销闭环：撤销某一步或撤销目标完成后，账本同步产生负向记录，总经验值即时冲正。
8. AI 建议拆解：可选功能，只根据用户自己输入的目标文字生成建议；建议必须先由用户确认和编辑，确认后才保存。
9. 真实数据红线：运行时没有任何种子任务、演示记录、mock 数据和 AI 编造的已完成记录。
10. 一期全量：本方案所有功能在同一个版本一次交付，不设分期、不设“后续版本补做”。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户 30 秒内完成一次“创建目标 + 拆解第一步”或“完成当前第一步”。
2. 每一步都能说清做什么、预计多久、完成后获得多少经验值。
3. 经验值只来自真实完成事件，任何页面都可见来源、时间和撤销记录。
4. 用户首次进入时页面是空状态，没有任何预置任务。

### 3.2 设计原则

- 真实优先：任务、步骤、时间、经验值都来自用户真实录入和真实执行。
- 可追溯：每一步完成、撤销和目标完成奖励都写入账本，可以回看。
- 小步推进：默认展示“现在只做这一步”，降低启动成本。
- 一屏可执行：首页、执行页和账本页都把主要操作放在首屏。
- 轻量克制：不做团队协作、公开排行榜和复杂项目管理。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 学生 | 复习、写论文、准备考试前容易拖延 | 把整章复习拆成可逐项完成的小步 |
| 职场用户 | 周报、方案、整理资料迟迟不开始 | 首页直接给出第一步，完成有反馈 |
| 家庭用户 | 整理房间、收纳、大扫除 | 用 3 到 10 分钟小动作推进 |
| 自由职业者 | 项目多但推进慢 | 看到经验值账本和真实完成记录 |

### 5.1 入口

- 工具注册名：`procrastination-crusher`
- 工具名称：拖延任务粉碎机
- 分类：效率
- 路由：`/tools/procrastination-crusher`
- 入口图标建议：`shredder`，备用 `bomb`
- 状态：一期发布时直接注册为 `available`
- 权限：`normal / vip / svip / admin` 均可使用，V1 不做会员权益差异
- 搜索关键词：拖延、任务拆解、微步骤、经验值、目标、第一步

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 首页“继续推进” | 当前目标、当前第一步、进行中目标、最近经验记录 |
| 拆解大任务 | 新建目标、步骤编辑、预计时间、目标总时长与预计经验值 |
| 目标执行页 | 步骤列表、开始/完成、实际用时、撤销、目标完成奖励 |
| 经验账本 | XP 账本、等级进度、统计卡片、最近 7 天图表、筛选 |
| 空状态 | 无目标时展示添加入口，不预置任何数据 |

以上页面均为一期交付范围。

### 5.3 核心流程

```text
进入拖延任务粉碎机
  -> 首次进入：空状态 + 新建目标
  -> 拆解大任务：目标标题 + 2 到 20 个微步骤 + 每步预计分钟数
  -> 可选：AI 建议拆解，用户确认和编辑后保存
  -> 保存后进入目标执行页
  -> 开始/完成当前步骤
  -> 服务端写入完成记录与 XP 账本
  -> 全部完成后目标自动完成，发放目标完成奖励
  -> 经验账本与统计实时更新
```

## 6. 功能设计

### 6.1 首页“继续推进”

- 顶部显示当前等级、总经验值、今日获得经验值。
- “现在只做这一步”：展示当前目标的第一个未完成步骤，包含标题、预计时间、可获得经验值和“开始/完成”按钮。
- “进行中目标”：展示所有未完成目标，包含步骤进度、预计剩余时间和预计可获得经验值。
- “最近经验”：展示最近的真实 XP 账本记录，包含步骤标题、目标名、时间和经验值。
- 快捷动作：新建目标、进入经验账本。
- 无目标时：显示空状态和“新建一个要粉碎的目标”按钮，不显示示例任务。

### 6.2 拆解大任务

#### 目标字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 目标标题 | 是 | 单行文本，最长 60 字 |
| 目标备注 | 否 | 多行文本，最长 500 字 |
| 截止日期 | 否 | 可选，仅用于排序和展示，不参与经验值计算 |
| 微步骤 | 是 | 2 到 20 条，每步标题最长 60 字 |

#### 步骤字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 步骤标题 | 是 | 单行文本，最长 60 字，只描述一个动作 |
| 预计分钟数 | 是 | 整数，1 到 120 |
| 步骤备注 | 否 | 单行文本，最长 200 字 |

- 预计总时长 = 所有未完成步骤预计分钟数之和，由服务端计算。
- 预计可获得经验值 = 所有步骤经验值之和 + 目标完成奖励，由服务端计算。
- 步骤支持新增、删除、上移、下移；删除已完成步骤会先要求确认，并保留账本记录。
- AI 建议拆解：输入目标标题后可选调用现有 DeepSeek 能力，返回候选步骤；用户必须逐条确认和编辑，点击“保存拆解”后才写入数据库。AI 接口失败时显示错误，不返回任何 mock 建议。

### 6.3 目标执行页

- 顶部展示目标标题、总步骤进度、预计剩余时间和已完成经验值。
- 步骤列表按顺序展示，每个步骤包含：
  - 步骤标题
  - 预计分钟数
  - 预计经验值
  - 状态：待开始 / 进行中 / 已完成
  - 实际用时（仅在有开始记录时展示）
  - “开始”“完成”“撤销”操作
- 当前建议步骤高亮，用户仍可完成其他步骤。
- “开始”记录服务端开始时间；“完成”记录服务端完成时间；未开始直接完成时实际用时为空。
- 全部步骤完成后，目标自动变为已完成，并写入目标完成奖励记录。
- 撤销某一步时，如果目标因此从已完成变为未完成，目标完成奖励同步冲正。

### 6.4 经验账本与统计

- 账本：按时间倒序展示所有 XP 事件，包括步骤完成、步骤撤销、目标完成奖励、目标奖励冲正。
- 筛选：按目标、按日期、按事件类型。
- 统计卡片：已完成步骤数、今日经验值、本周经验值、当前连续完成任务天数、已粉碎目标数。
- 最近 7 天图表：按真实完成日期聚合，无记录日期不显示柱体。
- 等级进度：等级由总经验值计算，展示当前等级和下一等级所需经验值。

### 6.5 经验值规则

```text
单步经验值 = 5 + 预计分钟数，封顶 30
目标完成奖励 = 20
目标预计经验值 = 所有步骤经验值之和 + 20
总经验值 = 所有 XP 账本事件求和
等级 = floor(总经验值 / 50) + 1
下一等级所需 = 50 - (总经验值 % 50)
```

示例：

| 步骤 | 预计分钟数 | 单步经验值 |
| --- | --- | --- |
| 只把桌上的垃圾扔掉 | 3 | 8 |
| 桌面物品放回原位 | 5 | 10 |
| 脏衣服放进洗衣机 | 4 | 9 |
| 擦一遍桌面 | 6 | 11 |
| 扫地并拖地 | 12 | 17 |

以上五个步骤全部完成后，步骤经验值共 55，目标完成奖励 20，目标总经验值 75。

### 6.6 真实数据机制

- 目标、步骤、完成事件、XP 账本全部写入 SQLite，接口全部要求 JWT 登录。
- 服务端拒绝重复完成同一未撤销步骤。
- 客户端提交的“已完成”不能直接改变 XP；XP 必须由服务端按已保存的预计分钟数计算。
- 编辑已完成步骤的预计分钟数只影响后续重新完成，不影响已经写入账本的历史经验值。
- 接口失败时展示已缓存的真实数据并标注更新时间，不展示 mock 数据。
- 首次进入、清空筛选、空目标列表都只展示空状态，不生成演示任务。

## 7. 数据模型

```text
procrastination_goals
  id, user_id, title, note, deadline, status,
  completed_at, archived_at, created_at, updated_at

procrastination_steps
  id, goal_id, user_id, title, estimated_minutes, note,
  sort_order, status, started_at, completed_at, xp_earned,
  created_at, updated_at

procrastination_events
  id, user_id, goal_id, step_id, event_type,
  xp_delta, event_date, created_at
```

事件类型：

```text
step_completed        步骤完成，正数经验值
step_undone           步骤撤销，负数经验值
goal_completed        目标完成奖励，正数经验值
goal_completed_undo   目标奖励冲正，负数经验值
```

- 目标状态：`active / completed / archived`。
- 步骤状态：`pending / started / completed`。
- `estimated_minutes` 只接受 1 到 120 的整数。
- `xp_earned` 在步骤完成时由服务端计算并写回。
- 总经验值始终通过 `procrastination_events` 聚合，不依赖客户端缓存。

## 8. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/procrastination/home?date=YYYY-MM-DD` | 首页汇总：当前目标、当前步骤、进行中目标、最近账本 |
| GET | `/api/v1/procrastination/goals?status=` | 目标列表，支持 active / completed / archived |
| POST | `/api/v1/procrastination/goals` | 新建目标与微步骤 |
| GET | `/api/v1/procrastination/goals/{goalID}` | 目标详情与步骤列表 |
| PATCH | `/api/v1/procrastination/goals/{goalID}` | 编辑目标 |
| DELETE | `/api/v1/procrastination/goals/{goalID}` | 归档目标 |
| POST | `/api/v1/procrastination/goals/{goalID}/steps` | 新增步骤 |
| PATCH | `/api/v1/procrastination/goals/{goalID}/steps/{stepID}` | 编辑步骤 |
| DELETE | `/api/v1/procrastination/goals/{goalID}/steps/{stepID}` | 删除步骤 |
| POST | `/api/v1/procrastination/steps/{stepID}/start` | 开始步骤，记录服务端开始时间 |
| POST | `/api/v1/procrastination/steps/{stepID}/complete` | 完成步骤，写入 XP 账本 |
| POST | `/api/v1/procrastination/steps/{stepID}/undo` | 撤销步骤，写入负向账本 |
| GET | `/api/v1/procrastination/ledger?from=&to=&goalID=` | 经验值账本 |
| GET | `/api/v1/procrastination/stats?range=week\|month\|all` | 统计汇总 |
| POST | `/api/v1/procrastination/suggest` | AI 建议拆解，只返回建议，不写库 |

说明：

- 所有接口要求登录，沿用现有 JWT 鉴权与限流中间件。
- 新增模块放在 `backend/internal/procrastinator/`，在 `httpapi/server.go` 注册路由。
- 完成和撤销在同一个事务中更新步骤状态、目标状态与 XP 账本。
- `suggest` 接口只返回候选文本，保存动作仍走正常目标创建接口。

## 9. 权限与入口

- 在现有功能注册表新增 `procrastination-crusher`，上线时直接设为 `available`。
- `initialRoles` 保持 `normal / vip / svip / admin`，V1 不做会员权益差异。
- 未登录用户从工具入口进入时引导登录，登录后回到拖延任务粉碎机。
- 前端按现有模式新增 `features/tools/procrastination-crusher-screen.tsx`，工具列表、最近使用、首页推荐位自动生效。

## 10. 交互与视觉设计

- 沿用 FunBox 视觉体系：浅蓝画布、白色表面、深藏青重点、品牌蓝主色。
- 本工具补充“行动感”语义色：珊瑚红 `#ff6b8f`、荧光绿 `#c9f36a`、深藏青 `#151b3b`。
- 内容区最大 430px 移动宽度，宽屏居中。
- 步骤时间使用步进器或数字输入；开始/完成/撤销使用图标按钮。
- 步骤卡片固定最小高度，按钮与圆形状态控件不随文字变化发生位移。
- 图标沿用 Lucide / Material Community Icons，可点区域不小于 40px。
- 支持浅色与深色主题，320px、390px、430px 视口下文本不溢出、元素不重叠。
- 不做教程式大段说明，空状态只给可执行动作。

## 11. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 首次进入，无目标 | 空状态 + 新建目标，不预置数据 |
| 重复完成同一步骤 | 服务端返回冲突，客户端提示“这一步已完成” |
| 撤销已完成步骤 | 写入负向账本，总经验值即时更新 |
| 目标奖励冲正 | 撤销步骤导致目标不再完成时，同步冲正目标奖励 |
| AI 建议接口失败 | 显示真实错误，不展示 mock 建议 |
| 接口不可用 | 展示已缓存的真实数据并标注更新时间 |
| 删除已完成步骤 | 二次确认，账本历史保留 |
| 输入预计分钟数越界 | 表单校验并提示 1 到 120 分钟 |

本方案不设分期，以下内容在同一版本一次交付：

- 目标与微步骤 CRUD，2 到 20 步，预计分钟数校验。
- 开始、完成、撤销、目标完成奖励。
- AI 建议拆解，人工确认后保存。
- XP 账本、等级进度、统计卡片、最近 7 天图表。
- 目标归档、空状态、真实数据缓存与错误状态。
- 浅色/深色主题，320/390/430 响应式。
- 单元测试覆盖 XP 计算、完成/撤销事务、权限与接口。

## 13. 明确不做

- 不做种子任务、演示任务、mock 数据或 AI 编造的已完成记录。
- 不做团队协作、共享目标、公开排行榜。
- 不做番茄钟提醒和白噪音等专注计时器。
- 不做经验值商城、会员权益兑换或现金奖励。
- 不导入第三方任务平台数据。

## 14. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 预计时间是否准确 | 由用户填写，仅作为经验值计算依据；实际用时单独记录 | 经验值不承诺等于真实投入 |
| AI 建议质量不稳定 | 建议只作为草稿，必须人工确认 | 录入成本略高，但保证真实 |
| 用户重复完成 | 服务端状态校验 + 账本事务 | 需要完整接口测试 |
| 跨时区 | V1 以客户端本地日期为事件日期 | 不覆盖跨时区旅行场景 |
| 缓存与实时一致性 | 接口失败展示缓存真实数据并标注时间 | 页面可能显示稍旧数据 |

## 15. 验收清单

- 新用户首次进入没有任何预置目标或步骤。
- 新建目标后，目标总时长、预计经验值与步骤字段一致。
- 完成步骤后，XP 账本新增一条正数记录，总经验值同步增加。
- 撤销步骤后，XP 账本新增一条负数记录，总经验值同步减少。
- 目标最后一步完成后，自动发放目标完成奖励。
- 撤销最后一步导致目标不再完成时，目标奖励同步冲正。
- 同一步骤不能重复领取经验值。
- AI 建议不确认不落库；接口失败时不显示 mock。
- 320px、390px、430px 视口下无文本溢出和元素重叠。
- 深浅主题均可读，接口全部有 JWT 鉴权。

## 16. 附录：真实数据锚点

设计稿中的目标“整理房间”、步骤、时间和经验值均为版式演示，用于说明交互形态，不会在运行时写入数据库。

产品运行时的数据只来自三类真实来源：

1. 用户手动创建的目标和步骤。
2. 用户点击开始/完成产生的服务端时间。
3. 用户确认后保存的 AI 建议拆解结果。
