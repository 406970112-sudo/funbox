# FunBox 识花草（植物识别）产品设计方案 V1

> 版本：V1 完整版
> 日期：2026-08-02
> 状态：待评审
> 定位：拍一张植物的照片，快速知道它是什么、属于什么科属、常见用途与食用提示，所有内容来自真实数据源，一期一次性交付。

## 1. 背景与问题

用户在路边、公园、山里或阳台遇到不认识的花草时，常见做法是拍照发朋友圈、问朋友、用关键词搜索，得到的答案常常模糊或互相矛盾：

| 现状 | 问题 |
| --- | --- |
| 搜索引擎结果以网页为主 | 需要逐个点开，不知道哪条可信 |
| 拍照问人 | 等待久、答案无依据，容易把相似植物认错 |
| 通用 AI 问答 | 可能给出“看起来像 XX”的猜测，缺少物种资料与来源 |
| 食用/毒性信息分散 | 用户关心“能不能吃”，但没有可靠入口，容易误判 |

FunBox 已经有一批效率与生活工具，缺一个“看见即知道”的自然入口。植物识别正好补上这个场景：相机或相册拿到照片，服务端用真实识别服务给出候选物种，再用权威分类库和百科资料聚合出完整介绍。

## 2. 对原始想法的补充

原始想法是：用户扫一扫或上传照片，识别植物，告诉用户“这是什么”，并补充功能、科属、能不能吃等常见描述。在此基础上补充八点：

1. 双入口缺一不可。既支持相机取景拍摄，也支持从相册选择已有照片；两者走同一条识别链路，不拆成两套体验。
2. “是什么”要给出候选列表和置信度，不只给一个答案。相似物种允许并列展示，用户可在候选中切换，降低误认。
3. 信息分六层呈现：中文名、学名、分类（科/属/目/纲）、常见描述、分布与观察、食用/毒性提示。每层字段缺失时显示“暂无”，不编造。
4. “能不能吃”不做简单是非判断。只展示来自真实词条的可引用原文片段；资料缺失时明确提示“暂无可靠食用资料，请勿采食”，并始终附带免责声明。
5. 识别、分类、描述、图片全部来自真实数据源：PlantNet 识别、GBIF 分类、iNaturalist 图片与观察、维基百科/Wikimedia 描述与图片。每个字段带 `source` 和 `fetchedAt`。
6. 识别历史属于完整闭环。识别完成后自动留痕，支持按时间浏览、删除、重新进入详情。
7. 纠错反馈必须存在。识别错误、信息有误、图片问题三类反馈进入后台审校队列，数据只增不改，由运营核对。
8. 一期一次做完。不设“二期再补识别质量、三期再补历史”的拆解；本文所有功能模块在同一个版本上线。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户从打开工具到看到主结果不超过 60 秒（含拍照与识别等待）。
2. 每条展示内容都能追溯到真实数据源与抓取时间。
3. 高置信度结果可直接查看完整资料；低置信度结果明确提示并给出纠错入口。
4. 涉及食用、药用的内容必须有来源引用和免责提示，不输出无依据判断。

### 3.2 设计原则

- 真实优先：识别结果、分类、描述、图片来自真实数据源，任何字段缺失都显示“暂无”，禁止 mock 填充。
- 少而准：主结果只给 1 个最佳候选，候选列表最多 5 个，不堆砌低分结果。
- 可追溯：每个数据块标注来源与抓取时间，点击可查看来源详情。
- 安全兜底：食用/毒性信息缺省为“请勿采食”，提示语放在详情页固定位置。
- 一期交付：所有功能模块在本版本一次性完成，不做分期上线。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 好奇型用户 | 路边看到好看的花草，想知道名字 | 拍照/选图，60 秒内得到候选物种和资料 |
| 家庭用户 | 阳台植物、小区绿化、野菜疑惑 | 查看科属、养护或食用提示，并看到明确免责 |
| 户外爱好者 | 徒步、露营遇到野生植物 | 识别历史形成个人记录，离线失败有明确提示 |
| 亲子用户 | 孩子问“这是什么” | 详情页给出可读性好的中文描述和真实图片 |
| 纠错型用户 | 发现识别结果不对 | 一键反馈，后台可审校，不假装正确 |

## 5. 产品结构

### 5.1 入口

- 工具注册名：`plant-identifier`
- 工具名称：识花草
- 分类：生活
- 路由：`/tools/plant-identifier`
- 入口图标建议：`sprout-outline`（MaterialCommunityIcons），首页轮播可用 `leaf` 主题
- 强调色建议：`#24b36b`（绿色），与 FunBox 主蓝区分且贴合植物主题
- 状态：一期发布时直接注册为 `available`
- 首页“今日推荐”轮播可配置为识花草卡片，配置复用现有轮播机制

### 5.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 识别首页 | 相机/相册双入口、最近识别、常见植物示例、数据源徽标 |
| 相机识别页 | 全屏取景、拍摄、相册入口、闪光灯/翻转、拍摄后分析态 |

以上页面均为一期交付范围。

## 6. 核心流程

```text
进入识花草
  → 相机拍摄 / 相册选择
  → 服务端调用 PlantNet 识别（图片仅用于本次识别）
  → 返回候选列表：物种 + score + GBIF key
  → 聚合 GBIF 分类、Wikipedia 描述、iNaturalist 图片与观察
  → 结果页展示主结果与候选
  → 详情页展示六层信息与食用提示
  → 识别记录进入历史；可收藏、分享、纠错
```

## 7. 功能设计

### 7.1 识别首页

- 顶部为识花草品牌区，右侧提供“历史”和“数据来源”入口。
- Hero 区固定展示一张真实植物照片，主标题“拍一张，认识眼前的植物”，副标题说明“识别、分类、描述均来自真实数据源”。
- 主操作两个按钮：`扫一扫识别`（相机图标）与 `从相册选择`（图片图标），两者都进入同一识别链路。
- Hero 下方展示数据源徽标：PlantNet / GBIF / iNaturalist / Wikipedia，带 `真实数据` 标签。
- “最近识别”横向展示最近 4 条真实记录，未登录或没有记录时隐藏该区块，不显示空白占位。
- “常见植物”网格展示 4-6 个真实物种（如向日葵、银杏、蒲公英、蔷薇属），图片来自 Wikimedia/iNaturalist 并标注来源，点击直接进入对应详情页。
- 页面底部固定免责说明：识别结果仅供参考，请勿据此采食或药用。

### 7.2 相机识别页

- 全屏相机取景，顶部保留返回与提示条“把叶片和花放进取景框，尽量拍清晰”。
- 取景框为固定比例矩形，四角高亮，不做夸张动效；系统开启“减少动态效果”时不播放扫描线动画。
- 底部控制条：相册缩略图（进入相册）、主快门、闪光灯开关、前后摄像头切换，点击区域不小于 44px。
- 相机权限被拒绝时显示引导页：说明用途、提供“去设置”按钮；用户返回后重试。
- 拍摄完成后进入分析态：显示刚拍的照片、加载动画和“正在识别”文案，并标注 `PlantNet` 数据源；超时或失败有明确提示与重试按钮。
- 照片只上传用于识别，服务端不做长期留存，隐私说明写入数据来源页。

### 7.3 识别结果页

- 顶部展示用户照片，右上角可关闭回到首页。
- 状态行：识别完成 + 最佳匹配置信度；置信度低于 0.6 时显示“置信度较低，请换角度重拍或从候选中确认”。
- 主结果卡：中文名、学名、科/属、主图，按钮“查看完整资料”。
- 候选列表最多 5 个，展示名称、学名、score，按 score 降序；点击候选卡可替换主结果。
- 操作区：重新拍摄、从相册重选；反馈区：`识别结果不对？点此纠错`。
- 数据条：`PlantNet · score 0.92 · 2026-08-02 快照`，用户可点击进入数据来源页。

### 7.4 物种详情页

- 顶部大图来自 Wikimedia/iNaturalist 真实图片，带来源角标；操作包括返回、收藏、分享。
- 名称区：中文名 + 学名，常见别名用 chips 展示（来自词条，缺失时不显示）。
- 分类区：科、属、目、纲，来自 GBIF 真实分类字段，缺失时显示“暂无”。
- 食用/毒性提示区：
  - 有可引用原文时展示词条摘录，标注 `来源：Wikipedia · 快照时间`；
  - 无可靠资料时展示固定文案“暂无可信食用资料，请勿采食”；
  - 所有情况都附免责声明：识别结果与食用信息仅供参考，请以权威来源为准。
- 描述区：维基百科词条摘要前 2-3 句，完整摘要提供“查看原文”链接。
- 分布与观察区：显示真实分布描述（来自词条）和 iNaturalist 观察数快照。
- 数据来源卡：PlantNet（识别）、GBIF（分类）、Wikipedia（描述）、iNaturalist（图片/观察），每项显示来源与更新时间。
- 底部操作：收藏、分享、纠错。

### 7.5 识别历史页

- 登录用户保存最近 50 条识别记录；未登录时提示登录后同步历史，本地仍保留当次结果可回看。
- 列表项：缩略图、中文名/学名、识别时间、置信度，点击进入详情。
- 支持单条删除与全部清空，删除后不再恢复。
- 空态：图标 + “还没有识别记录，拍一棵植物试试”，并提供“去识别”按钮。

### 7.6 数据来源与隐私

- 逐条列出数据源：PlantNet（识别 API）、GBIF（分类学）、iNaturalist（图片与观察）、Wikipedia/Wikimedia（描述与图片）。
- 每条来源说明用途、是否需密钥、更新方式与最近校验时间。
- 隐私说明：照片仅用于本次识别，服务端不长期保存原图；如需缓存缩略图会在 24 小时内清理并说明。

## 8. 真实数据方案

### 8.1 数据源

一期交付全部数据源接入，不做阶段性上线：

| 数据源 | 用途 | 接入方式 |
| --- | --- | --- |
| PlantNet API | 植物图像识别 | 在 my.plantnet.org 注册并生成 API key；服务端 POST `/api/v1/identify?project=all`，multipart 上传图片并返回物种、score、GBIF key；key 只放在 Go 服务端，不进入客户端 |
| GBIF Species API | 分类学：科/属/目/纲、学名、常用名 | `species/match` 与 `species/{key}`，公共 API，无密钥可调用，服务端做缓存 |
| iNaturalist API | 真实植物照片、观察统计、常用名 | `/v1/taxa` 公共只读接口，无需密钥；图片带作者署名与许可协议 |
| Wikipedia / Wikimedia | 中文描述、别名、安全相关原文、图片 | MediaWiki API `action=query&prop=extracts|pageimages`；服务端缓存词条摘要与缩略图 URL |
| 人工审校警示表 | 高风险/有毒常见植物的补充提示 | 上线前由运营依据权威来源（维基百科分类、植物志、权威机构词条）核对并维护，每条带来源 URL 与审核时间；只做“警示”，不做“可食”判断 |

### 8.3 数据管道

1. 识别：前端上传图片，服务端调用 PlantNet，返回候选物种与 GBIF key。
2. 分类：服务端用 GBIF key 查询分类字段，写入 SQLite 缓存并记录 `fetchedAt`。
3. 描述：服务端用学名/中文名查询 Wikipedia 摘要与图片，写入缓存。
4. 图片：优先使用 Wikimedia 条目图，其次使用 iNaturalist 默认照片；保留作者与许可。
5. 安全：先查人工审校警示表，再尝试从词条原文提取可引用片段；都不满足时返回 `state: "unknown"`。
6. 校验：缓存记录带 `source`、`fetchedAt`，超过 7 天自动刷新；图片 URL 失效时显示“图片整理中”，不展示无来源图片。

### 8.4 AI 边界

允许做的：
- 把真实字段翻译为界面中文（学名、科属名保留原文）。
- 根据 score 阈值调整结果页文案（置信度低时提示重拍）。
- 对词条原文做截取展示，保留原文链接。

禁止做的：
- 用 AI 生成识别结论、物种描述、别名、分类或观察数据。
- 用 AI 判断“能不能吃”“有没有毒”。
- 用 AI 补全缺失字段；缺失一律显示“暂无”。

## 9. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/plant-id/identify` | multipart 上传图片（可选 organ 参数），返回候选列表与主结果 |
| GET | `/api/v1/plant-id/species/{gbifKey}` | 聚合分类、描述、图片、观察、安全信息 |
| GET | `/api/v1/plant-id/common-plants` | 常见植物示例（真实数据快照） |
| POST | `/api/v1/plant-id/feedback` | 识别错误 / 信息有误 / 图片问题反馈 |
| GET | `/api/v1/plant-id/history` | 登录用户识别历史，分页 |
| DELETE | `/api/v1/plant-id/history/{id}` | 删除单条历史 |
| DELETE | `/api/v1/plant-id/history` | 清空历史 |
| GET | `/api/v1/plant-id/sources` | 数据源状态与最近校验时间 |

说明：
- 识别接口不强制登录，用现有限流中间件控制频率，避免 PlantNet 配额被单个用户耗尽。
- 历史、收藏、反馈需要登录，复用现有账号体系。
- 所有响应字段带 `source` 与 `fetchedAt`；前端不自行声明实时数据。
- PlantNet API key 只配置在服务端环境变量 `PLANTNET_API_KEY`，客户端不可见。

## 10. 页面与交互设计

- 沿用 FunBox 视觉体系：浅蓝画布 `#EEF4FF`、白色表面、深色文字 `#18233D`、品牌蓝 `#4B6BFF`；植物功能补充绿色 `#24B36B` 与嫩绿 `#C9F36A`，强调色 `#FF6B8F` 仅用于警示与纠错。
- 内容区最大 430px，宽屏居中；卡片圆角不超过 16px，大图卡不超过 20px。
- 图片建议 4:3 或 1:1，加载前显示灰色占位；图片缺失时显示“图片整理中”。
- 所有图标按钮带 tooltip/无障碍标签；按钮点击区域不小于 44x44px。
- 支持浅色与深色主题；320px、390px、430px 宽度下文字不溢出、元素不重叠。
- 相机页使用深色背景，取景框高对比；详情页保持浅色内容风格，食用提示用绿色边框卡，与常规卡片区分。

## 11. 状态与异常处理

| 场景 | 处理 |
| --- | --- |
| 相机权限被拒绝 | 引导页 + “去设置”；返回后重试 |
| 相册权限被拒绝 | 提示手动选择，提供权限引导 |
| 识别服务超时/失败 | 显示“识别服务暂时不可用”，提供重试；不展示占位物种 |
| 置信度低于 0.6 | 主结果旁明确提示“置信度较低”，引导重拍或从候选确认 |
| 候选为空 | 提示“未识别到植物，请换一张叶片/花朵清晰的照片” |
| 词条或分类缺失 | 对应字段显示“暂无”，其余字段正常展示 |
| 图片 404 | 显示“图片整理中”占位，不影响文字资料 |
| 网络断开 | 已缓存的历史与详情可查看，识别入口提示联网 |
| 用户反馈 | 进入后台审校队列，前端显示“已收到，感谢反馈” |

## 12. 技术架构建议

- 前端：新增 `frontend/features/tools/plant-identifier/`，复用 `MobileScreen`、`PageHeader`、`SurfaceCard`、主题 Hook；新增路由 `/tools/plant-identifier`，在 `feature_registry.json` 注册工具。
- 后端：新增 `backend/internal/plantid/` 模块，负责 PlantNet 调用、GBIF/Wikipedia/iNaturalist 聚合、SQLite 缓存、历史与反馈接口。
- 配置：`PLANTNET_API_KEY`、`PLANTNET_PROJECT`（默认 `all`）、缓存 TTL、限流参数写入 `backend/.env.example`。
- 图片：服务端识别后不保存原图，仅缓存缩略图（如需）并定期清理；历史记录保存缩略图引用。
- 测试：单元测试覆盖字段缺失、低置信度、数据源超时；接口测试覆盖识别与历史流程。

## 13. 成功指标

1. 打开工具到看到主结果的时长中位数不超过 60 秒。
2. 真实字段覆盖率：分类字段 ≥ 95%，描述字段 ≥ 80%，图片来源覆盖率 100%。
3. 主结果正确率（人工抽样 Top1）不低于 70%，Top5 不低于 85%。
4. 无来源内容展示次数为 0；安全信息缺失时 100% 展示“请勿采食”提示。
5. 详情页进入率不低于识别完成用户的 45%。
6. 纠错反馈在 24 小时内可被运营查看。

## 14. 明确不做

- 不做基于本地模型或自训练模型的识别，避免结果无法溯源。
- 不做 AI 生成物种描述、图片、别名或食用/药用判断。
- 不做社区鉴定、专家问答、活体植物购买。
- 不做植物养护指导、施肥浇水提醒（可作为后续独立功能，不在本期）。
- 不做“能否食用”的确定性结论，只展示可引用的真实资料或“暂无”。
- 不做离线识别模型，离线时仅可查看已缓存资料。

## 15. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| PlantNet 免费配额有限 | 服务端限流 + 缓存识别结果；超出时明确提示稍后再试 | 高峰期可用性 |
| 中文植物名覆盖率 | 中文名优先取自词条与 iNaturalist 常用名，缺失时显示学名 | 部分稀有植物体验下降 |
| 食用/毒性信息责任 | 只展示可引用原文与警示，不输出判断，上线前完成人工审校表核对 | 需要运营投入 |
| 图片版权 | 仅使用 Wikimedia/iNaturalist 明确许可图片并保留署名 | 设计稿与线上均需标注 |
| 词条更新时间 | 缓存 TTL 7 天，详情页展示快照时间 | 用户需要理解数据非实时 |
