# FunBox DNF手游活动助手 产品设计方案 V1

> 版本：V1 评审稿
> 日期：2026-08-04
> 状态：待评审
> 定位：真实活动聚合 → 状态筛选 → 活动详情 → 关注与分享的完整闭环，数据全部来自《地下城与勇士：起源》官方网站。
> 交付原则：一期全量交付；全部使用真实活动数据；无 mock、无演示数据回退；视觉沿用 FunBox 现有设计体系。

## 1. 背景与问题

1. DNF 手游的活动分散在游戏内活动中心、官网活动中心、官网新闻中心、DNF 助手等多个渠道，玩家往往只知道“有活动”，却不知道哪些还在生效、哪些已经过期。
2. 活动具有强时效性：登录领奖、限时礼包、召回好友等活动错过就结束，玩家需要一眼看到“今天还能做什么”。
3. 第三方攻略站的活动汇总存在更新不及时、标题搬运错误、奖励描述夸张等问题，无法作为可信来源。
4. 现有 FunBox 工具集中在行情、阅读、AI、生活工具，缺少面向 DNF 手游玩家群体的活动聚合能力。
5. 数据可信度风险：任何用假活动、假时间、假奖励包装出来的“活动助手”都会直接伤害用户信任，必须全部使用官方真实数据，并明确展示来源与更新时间。

## 2. 产品目标

1. 聚合《地下城与勇士：起源》官方网站活动中心真实活动，一期覆盖“进行中 / 未开始 / 已结束 / 时间待官方确认”四种真实状态。
2. 用户进入后 1 秒内看到当前进行中的活动数量与活动列表，活动名称、起止时间、配图、跳转链接全部来自官网，不本地造数据。
3. 支持活动详情、活动日历、我的关注、分享链接与分享海报，形成从“看到活动”到“参与活动 / 分享活动”的闭环。
4. 所有活动数字保留来源、抓取时间和计算口径；上游不可用时明确报错，绝不回退到 mock 或演示数据。
5. 复用 FunBox 现有账号体系、后端限流、真实数据缓存体系和视觉体系，一期一次交付完成。

## 3. 目标用户与场景

| 用户 | 核心场景 | 产品要满足 |
| --- | --- | --- |
| DNF 手游活跃玩家 | 想快速知道今天还有哪些活动能参加 | 进入即展示进行中活动、剩余天数、官方入口 |
| 回流/新玩家 | 刚回归，不确定哪些活动过期 | 按状态筛选，已结束活动明确标注，不误导 |
| 公会/好友小队长 | 想拉朋友一起参与限时活动 | 一键复制官方链接、生成分享海报、微信小程序内分享 |
| 有计划的玩家 | 想知道未来一周有哪些活动 | 活动日历按真实起止日期标记，支持关注提醒 |
| 谨慎用户 | 担心活动信息不可信 | 每个活动都显示官方来源、更新时间、官方跳转入口 |

## 4. 核心原则

### 4.1 真实数据原则

- 活动列表只使用 `mdnf.qq.com` 官网活动中心 JSON 数据，失败即明确报错，不展示猜测结果。
- 活动标题、开始日期、结束日期、跳转链接、活动配图全部来自官网字段，前端不做语义改写。
- 活动状态由后端按官网开始/结束日期与服务器当天确定性计算，不依赖前端本地时间。
- 官网未标注开始或结束时间的活动归入“时间待官方确认”，展示官网链接与原文，不猜测时间。
- 活动详情页的官方简介只提取官网活动页的 `description` 原文，不生成 AI 摘要，避免幻觉。
- 测试 fixture 只进入测试编译，绝不进入生产回退分支。

### 4.2 一期全量原则

本次一次性交付，不设分期。活动总览、状态筛选、活动详情、活动日历、我的关注、分享海报/链接、数据来源与全部异常状态在同一版本内完成。

### 4.3 风格一致原则

视觉沿用 FunBox 现有体系：浅蓝背景、白色表面、深藏青 `#151b3b` 重点、主蓝 `#4b6bff` 操作、青柠 `#c9f36a` 强调，圆角不超过 8px，图标沿用 Material Community Icons，支持浅色与深色主题。

## 5. 主流程

```text
进入活动助手
  → 后端读取官网活动中心真实数据（JSON）
  → 服务端按真实日期计算状态：进行中 / 未开始 / 已结束 / 时间待官方确认
  → 展示总览：进行中 3 · 已结束 57 · 时间待确认 3（真实统计）
  → 用户按状态/搜索/日历筛选
  → 查看活动详情：官方标题、真实时间、官方简介、官方入口
  → 关注活动或生成分享：复制官方链接 / 生成分享海报 / 微信分享
```

兜底路径：

| 异常 | 行为 |
| --- | --- |
| 官网数据源不可用 | 展示可重试错误，不展示任何 mock 活动 |
| 单条活动缺少开始/结束时间 | 归入“时间待官方确认”，展示官网原文，不猜测 |
| 活动配图加载失败 | 使用标题卡片占位，不替换为其他活动图片 |
| 活动详情页抓取失败 | 详情页只展示列表已有真实字段，简介区显示“官方详情以官网为准” |
| 未开始活动为空 | 展示真实空态“当前官网暂无未开始活动”，不填充示例数据 |
| 关注列表为空 | 展示“从活动详情添加第一个关注”引导 |

## 6. 功能范围（一期全量）

### 6.1 活动总览

- 顶部展示真实统计：进行中数量、全部数量、已结束数量、时间待确认数量。
- “进行中”优先展示最近结束的活动，突出剩余天数（如“剩余 7 天”），天数由真实结束日期计算。
- “即将结束”区展示结束日期最近的前 3 条进行中活动。
- 总览底部展示数据来源行：`地下城与勇士：起源 官方网站`、最近同步时间、stale 标记。

### 6.2 活动列表与筛选

- 状态分段控件：进行中 / 未开始 / 已结束 / 时间待确认 / 全部。
- 搜索：按活动标题模糊搜索，只搜索后端返回的真实标题，不本地造词。
- 排序：默认按结束日期倒序（离结束越近越靠前），可切换按开始日期、按官网更新时间。
- 活动行：官方配图、真实标题、起止日期、状态标签、分享按钮、关注按钮。
- 分页：后端分页，默认每页 20 条，滚动加载。
- 空态：当前状态没有活动时展示真实空态；未开始为空时明确文案“当前官网暂无未开始活动”。

### 6.3 活动详情

- 官方配图、真实标题、状态标签、起止日期、剩余天数。
- 官方简介：从官网活动页 `description` 提取原文；未抓取到时显示“官方详情以官网活动页为准”。
- 主操作：“打开官方活动页”（跳转官网链接）、“分享活动”。
- 数据卡：来源（地下城与勇士：起源 官方网站）、官网链接、最近同步时间、状态计算口径。
- 底部“相关活动”：同一月份、同一状态的其他真实活动，点击进入对应详情。

### 6.4 活动日历

- 月历视图，按真实开始/结束日期在日期格内标记活动圆点或短标签。
- 点击日期展示该日仍在生效的真实活动列表。
- 跨月/跨年活动（如官网持续活动）在日历上连续标记。
- 今天默认高亮；无活动日期不展示占位内容。

### 6.5 我的关注

- 关注列表本地持久化：Web 使用 `localStorage`，原生使用 `AsyncStorage`/`SecureStore`，微信小程序使用 `wx.setStorageSync`。
- 关注卡片展示真实标题、状态、剩余天数、是否已结束。
- 状态变化提示：关注的活动从“未开始/进行中”变为“进行中/已结束”时，进入页面顶部展示真实状态变更摘要。
- 支持取消关注、清空关注；关注数量上限 30 条。
- 一期不做账号云端同步，结构上预留服务端接口。

### 6.6 活动分享

- 分享链接：复制官网活动页真实 URL，附带真实标题与来源文本。
- 分享海报：使用官方活动配图 + 真实标题 + 真实起止时间 + “地下城与勇士：起源 官方活动” + 指向官网链接的二维码，一次生成，可保存到相册。
- 微信小程序：复用现有 WebView 客户端，通过 `wx.miniProgram.postMessage` 触发小程序分享，分享卡片标题、摘要、封面均来自真实活动数据。
- 海报中的二维码指向官网活动页，不生成站内伪链接。

### 6.7 数据来源与状态覆盖

- 页面固定展示来源与更新时间；stale 快照只展示并标注，不参与“剩余天数”等强时效计算。
- 加载中：骨架屏 + “正在同步官网活动”。
- 数据缺失：展示可重试错误页，不展示猜测活动。
- 时间缺失：明确“时间待官方确认”，不进入日历强标记。
- 图片缺失：标题卡片占位，不串用其他活动图片。

## 7. 数据真实性与安全

### 7.1 数据来源

主数据源为《地下城与勇士：起源》官方网站活动中心数据，由 FunBox Go 后端发起抓取，前端不直连第三方：

```text
GET https://mdnf.qq.com/zlkdatasys/web202405_data/events_data.json
```

该 JSON 是官网首页“活动中心”模块实际加载的数据文件，包含真实活动列表。当前抓取快照（2026-08-04）共 63 条活动。

辅助增强源为各活动官方专题页（如 `act2.hdnf.qq.com/a20260625luckystar/index.html`），后端抓取页面 `description` 作为官方简介，不解析、不生成额外内容。

### 7.2 字段映射

| 官网 JSON 字段 | 产品字段 | 说明 |
| --- | --- | --- |
| `hdm_3953` | 活动标题 | 直接展示，不改写 |
| `hdrlks_8746` | 开始日期 | 可能缺失 |
| `hdrljs_4715` | 结束日期 | 可能缺失 |
| `hdrlmd_9188` | 移动端跳转链接 | 优先使用 |
| `hdrlpc_3198` | PC 跳转链接 | 移动端缺失时兜底 |
| `hdrlmd_6170` | 移动端配图 | 海报与列表封面 |
| `hdrlpc_2742` | PC 配图 | 移动端缺失时兜底 |

### 7.3 状态判定

- 判定基准：服务器当天日期（Asia/Shanghai），不使用客户端时间。
- 进行中：`开始日期 <= 今天 <= 结束日期`。
- 未开始：`今天 < 开始日期`。
- 已结束：`结束日期 < 今天`。
- 时间待官方确认：开始或结束日期任一缺失。
- 剩余天数：`结束日期 - 今天`，只对“进行中”活动展示。
- 官网字段格式为 `YYYY-MM-DD`；解析失败按“时间待官方确认”处理。

### 7.4 禁止假数据原则

- 生产环境不存在 mock 数据回退路径：官网数据源不可用时返回可重试错误。
- 测试 fixture 只进入测试编译，绝不进入生产回退分支。
- stale 快照只能展示并标注，不能用于计算“剩余天数”或生成新状态。
- 任何活动标题、时间、链接、图片都必须能追溯到官网 JSON 原始字段。

### 7.5 详情增强

- 官方简介只使用官网活动页 `description` 元数据原文，最长截断展示并标注“官方简介”。
- 不调用 LLM 生成活动摘要、奖励解读、参与攻略。
- 抓取失败时详情页保留列表真实字段，简介区显示“官方详情以官网活动页为准”。

### 7.6 分享真实性

- 分享链接必须是官网活动页真实 URL，禁止拼接站内伪造链接。
- 海报上的二维码由真实 URL 生成，二维码渲染失败时禁止出图，展示重试。
- 分享文案模板固定为：真实标题 + 真实起止时间 + “地下城与勇士：起源 官方活动”，不追加奖励描述。

- 工具名称：DNF手游活动助手
- 分类：游戏

## 9. 技术方案

### 9.1 后端模块

新增 `backend/internal/dnfactivity`：

| 子模块 | 职责 |
| --- | --- |
| `provider` | 官网活动中心 JSON 抓取、GBK/UTF-8 兼容解析、活动详情页 description 提取 |
| `store` | 活动快照、用户关注持久化 |
| `sync` | 定时同步任务：抓取、归一化、状态计算、增量落库 |
| `handler` | 总览、列表、详情、日历、关注、分享文案接口 |

### 9.2 数据模型

```text
dnf_activities             id, source_id, title, start_date, end_date, mobile_url, pc_url, mobile_image, pc_image, source_checked_at, created_at, updated_at
dnf_activity_snapshots     id, fetched_at, raw_json, activity_count, status, error
dnf_activity_favorites     user_id, activity_id, status, status_changed_at, created_at
```

### 9.3 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/dnf-activity/overview` | 总览：真实统计、进行中、即将结束、来源与同步时间 |
| GET | `/api/v1/dnf-activity/activities` | 活动列表：状态、搜索、排序、分页 |
| GET | `/api/v1/dnf-activity/activities/{id}` | 活动详情：真实字段 + 官方简介 + 状态 |
| GET | `/api/v1/dnf-activity/calendar?month=` | 月历：该月每一天生效的活动 ID |
| GET/POST/DELETE | `/api/v1/dnf-activity/favorites` | 关注列表与增删 |
| GET | `/api/v1/dnf-activity/share/{id}` | 分享文案与海报素材（真实标题/时间/URL） |

### 9.4 前端

- 新增 `frontend/features/tools/dnf-mobile-activity-screen.tsx` 及 `lib/dnf-activity-api.ts`、`lib/dnf-activity-model.ts`。
- 在 `tool-detail-screen.tsx` 注册路由，在 `feature_registry.json` 注册工具。
- 活动列表与详情使用现有真实数据缓存体系缓存最近成功快照，缓存只用于展示并标注 stale。
- 分享海报用 `qrcode` 生成真实 URL 二维码，`expo-sharing` 保存/分享；微信小程序 WebView 通过 `wx.miniProgram.postMessage` 桥接分享。
- 关注存储按平台复用现有本地存储模式。

## 11. 非功能需求

- 性能：总览 P95 < 800ms；活动列表 P95 < 800ms；详情 P95 < 800ms。
- 缓存：服务端快照 TTL 30 分钟；前端缓存最近成功快照并标注时间。
- 弱网：列表/详情可展示 stale 快照，但不参与剩余天数计算。
- 主题：支持 FunBox 浅色/深色主题。
- 布局：320px / 390px / 430px 三档宽度无溢出、无重叠。
- 可观测：同步任务记录抓取成功/失败/条数/解析跳过，持续失败时生成可排查日志。
- 安全：不采集 QQ/游戏账号；不接入游戏内领取与授权；活动页跳转全部为官方域名。

## 12. 验收标准

1. 总览统计与活动列表全部来自官网 JSON，字段一一对应，无 mock 回退。
2. 进行中/未开始/已结束/时间待确认四种状态判定与官网日期一致，缺失时间不猜测。
3. 活动详情展示官方简介原文与官方入口，抓取失败时有明确兜底文案。
4. 活动日历按真实起止日期标记，跨月活动连续，无占位内容。
5. 关注列表本地持久化，状态变更提示真实反映官网日期变化。
6. 分享链接指向官网真实 URL，海报二维码可扫出同一官网链接。
7. 上游不可用、时间缺失、图片缺失、列表为空、关注为空等状态全部有明确 UI。
8. 生产代码不包含任何 mock 回退路径；测试 fixture 只用于测试。

## 14. 设计说明

- 六屏主链路：活动总览 → 活动列表/筛选 → 活动详情 → 活动日历 → 我的关注 → 分享面板。
- 总览突出“真实统计 + 进行中活动”，让用户一眼知道今天还能做什么。
- 列表突出“状态标签 + 官方时间”，避免已结束活动误导用户。
- 详情突出“官方来源 + 官方入口”，让用户明确可追溯。
- 日历与关注服务有计划的玩家，分享服务组队与传播场景。
- 全量状态覆盖放在设计稿底部，表示一期包含全部异常与边界状态。
- 视觉直接复用 FunBox 现有体系：浅蓝背景、白色表面、深藏青重点、主蓝操作、青柠强调、细分隔线，圆角不超过 8px，图标使用 Material Community Icons。
