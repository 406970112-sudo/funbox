# FunBox 股票交易提醒 产品设计方案 V2

> 版本：V2 评审稿
> 日期：2026-08-04
> 状态：待评审
> 定位：真实标的搜索 → 搜索结果确认 → 加入自选 → 从自选标的配置分时提醒 → 交易时段真实分时监听 → 触发后站内消息 + Server酱 双通道提醒。
> 交付原则：一期全量交付；全部使用真实行情；无 mock、无演示数据回退；视觉沿用 FunBox 现有设计体系。

## 1. 与 V1 的差异

1. 搜索行为从“输入后直接分析”改为“输入后先展示真实搜索结果，用户确认后再加入自选”。
2. 自选成为提醒的载体：用户从自选标的中选择股票，再配置分时提醒，而不是搜索后一步直达分析。
3. 提醒从单一 AI 买卖点扩展为可配置的分时提醒：价格、涨跌幅、分时均线、量能、AI 信号五类规则，可组合、可编辑、可暂停。
4. 一期一次性交付，不设分期，不降级为演示数据。

## 2. 背景与问题

1. 行情工具仍停留在“看盘”阶段：用户知道代码或名称，但缺少“搜索 → 确认 → 自选 → 提醒”的完整闭环。
2. 直接输入后马上分析会给用户造成误解：用户可能本想看候选结果，却被直接拉入分析流程；同名或跨市场标的也容易选错。
3. 已有买卖点提醒是系统给定规则，用户不能按自己的价位、涨跌幅或分时均线配置提醒，灵活性不足。
4. 用户不会一直停留在 App 内，提醒需要覆盖站内消息与微信等外部渠道。
5. 数据可信度风险：任何用假数据或演示数据包装出来的“提醒”都会直接伤害用户信任，必须全部使用真实上游行情，并明确展示来源、更新时间和计算口径。

## 3. 产品目标

1. 搜索真实标的后 500ms 内展示候选结果，候选结果必须来自东方财富 suggest 真实接口，不本地造词。
2. 用户确认标的加入自选；自选列表展示真实最新价、涨跌幅、分时均价和提醒状态。
3. 从自选选择标的，配置至少五类分时提醒，支持开启、暂停、编辑、删除。
4. 交易时段后台基于真实分时序列确定性监听；触发后站内消息 + Server酱 微信推送，带精确触发时刻与价格。
5. 所有行情数字保留来源、更新时间和计算口径；上游不可用时明确报错，绝不回退到 mock 或演示数据。
6. 复用 FunBox 现有账号体系、后端限流、DeepSeek 配置和视觉体系，一期一次交付完成。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品要满足 |
| --- | --- | --- |
| 有自选股的散户 | 想先确认候选标的，再把它放进自选池 | 搜索先出结果，用户确认后加入自选 |
| 上班族 | 盘中无法一直盯盘 | 从自选选择股票，按自己的价位或指标设置分时提醒 |
| 已使用市场雷达的用户 | 从板块切到个股 | 个股真实行情、自选管理、分时提醒一体化 |
| 新手用户 | 不理解技术指标 | 用“突破 1330.00”这类直观条件表达，不堆术语 |
| 谨慎用户 | 担心行情不可信 | 每个数字都能看到来源、更新时间、延迟/收盘状态 |

## 5. 核心原则

### 5.1 真实数据原则

- 标的解析只使用东方财富 suggest 真实接口，失败即明确报错，不出猜测结果。
- 最新行情优先东方财富实时接口，失败回退延迟行情并标注“延迟行情”，腾讯行情仅作为同源真实行情兜底。
- 分时图、分时均价、量比、涨速等全部来自真实分时序列，不本地生成演示分时。
- stale 快照只能展示并标注，不能用于生成新分析或触发提醒。
- 测试 fixture 只进入测试编译，绝不进入生产回退分支。

### 5.2 一期全量原则

本次一次性交付，不设分期。搜索、搜索结果、自选、提醒配置、实时监听、消息中心、Server酱 设置、全量状态覆盖在同一版本内完成。

### 5.3 风格一致原则

视觉沿用 FunBox 现有体系：浅蓝背景、白色表面、深藏青 `#151b3b` 重点、主蓝 `#4b6bff` 操作、青柠 `#c9f36a` 强调、涨红跌绿，圆角不超过 8px，图标沿用 Material Community Icons。

## 6. 主流程

```text
输入代码/名称
  → 东方财富 suggest 真实标的口径解析
  → 展示真实搜索结果（名称/代码/市场/类型/最新价/涨跌幅）
  → 用户确认标的 → 加入自选
  → 从自选选择股票 → 配置分时提醒（价格/涨跌幅/分时均线/量能/AI信号）
  → 交易时段后台基于真实分时序列确定性监听
  → 条件满足 → 站内消息 + Server酱 微信推送
  → 用户点击消息进入个股详情查看触发依据
```

兜底路径：

| 异常 | 行为 |
| --- | --- |
| 搜索无结果 | 明确提示“未找到匹配标的，试试 600519 / 贵州茅台 / NVDA” |
| 上游不可用 | 展示可重试错误，不展示任何 mock 结果 |
| 历史或分时数据不足 | 提示“历史/分时数据不足，无法生成提醒”，不降级分析 |
| 盘中休市或停牌 | 显示“休市/停牌，暂停分时监听”，恢复后自动继续 |
| 提醒重复 | 同一提醒规则同一方向每个交易日最多触发 1 次，去重后可重新设置 |
| Server酱 未绑定 | 站内提醒仍生效，设置页给出绑定引导 |

## 7. 功能范围（一期全量）

### 7.1 真实标的搜索

- 输入支持：6 位数字代码、带市场后缀代码（600519.SH / 00700.HK / NVDA）、中文名称、英文名称。
- 后端统一调用东方财富 suggest 接口，过滤出可加入自选的股票类型；指数、板块、期货、权证只展示不加入。
- 搜索防抖：输入停止 300ms 后发起请求；请求中显示轻量 loading；请求失败保留错误提示。
- 市场映射沿用现有实现：沪市 `1.`、深市/北交所 `0.`、港股 `116.`、美股 `105/106/107.`，具体以 suggest 联调结果为准。
- 搜索结果行展示：名称、代码、市场标签、类型标签、最新真实价、涨跌幅、加入自选按钮；已在自选的标的显示“已在自选”状态。
- 热门示例只作为搜索入口文案，点击后仍走真实搜索与分析，不内置假数据。

### 7.2 自选标的

- 自选列表展示：股票名称、代码/市场、最新真实价、涨跌幅、分时均价、提醒状态、迷你分时走势、提醒开关。
- 支持添加、删除、暂停/开启提醒、排序（按添加时间/涨跌幅/代码）、搜索自选内标的。
- 每用户默认 10 只自选；达到上限后明确提示移除后添加。
- 空态：展示搜索入口和“从搜索结果加入第一只股票”的引导。
- 自选数据与用户 ID 绑定，服务端持久化，不随刷新丢失。

### 7.3 分时提醒配置

从自选选择股票后进入提醒配置页，支持：

| 提醒类型 | 可选条件 | 说明 |
| --- | --- | --- |
| 价格提醒 | 分时价向上突破 / 向下跌破目标价 | 目标价支持手输与步进，范围校验在真实日线高低点内 |
| 涨跌幅提醒 | 当日涨跌幅达到 / 跌破阈值 | 阈值支持百分比步进，如 +1.5%、-2% |
| 分时均线提醒 | 上穿 / 下穿分时均价 | 基于真实分时均价序列判定 |
| 量能提醒 | 量比达到 / 5 分钟涨速达到 | 量比与涨速由真实分时成交计算 |
| AI 信号提醒 | 买入 / 卖出 / 止损信号触发 | 复用 deepseek-v4-flash 生成的今日信号规则 |

每条提醒包含：

- 生效标的：从自选选择。
- 规则条件：类型、比较方向、阈值。
- 生效时间：默认 A 股 09:30-11:30、13:00-15:00，可配置；港股/美股按各自交易所时段。
- 有效期：默认 5 个交易日，可配置。
- 提醒渠道：站内消息必开，Server酱 微信可开关。
- 状态：开启、暂停、已到期、数据缺失。

### 7.4 分时实时监听

- 监控任务只读真实分时行情，只做确定性信号判定，不调用 LLM，保证触发判定可复现、可测试。
- 交易时段轮询间隔默认 10 秒；A 股默认 09:30-11:30、13:00-15:00（周一到周五），港股/美股按各自交易所时段；休市/停牌自动暂停。
- 分时数据源：东方财富真实分时序列接口（`trends2/get`，含每分钟价格与分时均价），每次拉取当日完整分时并增量更新，绝不本地生成演示分时。
- 触发判定：
  - 价格：最新真实分时价满足阈值与比较方向。
  - 涨跌幅：最新价相对昨收的涨跌幅满足阈值。
  - 分时均线：最新分时价与最新分时均价发生上穿/下穿。
  - 量能：最新量比或 5 分钟涨速满足阈值。
  - AI 信号：后端信号引擎按今日信号规则判定。
- 行情新鲜度：触发判定只使用不超过 15 秒的最新分时快照；行情更新超时则跳过本轮并记录健康状态，绝不使用过期价格触发。
- 去重：同一提醒规则同一方向每个交易日最多推送 1 条；分时价回落超过 0.3% 后再次满足才可重新触发。
- 监控健康状态：每次轮询记录成功/失败/跳过，持续失败时生成可排查日志并在页面展示状态。

### 7.5 个股详情

- 实时监听头：实时状态（监听中/休市/已收盘/数据缺失）、最近一次分时刷新时间、最新分时价与分时均价。
- 分时图：当日真实分时价格线 + 分时均价线 + 已设置提醒阈值标记 + 已触发提醒点。
- 提醒规则卡：展示当前标的全部已配置提醒，支持编辑、暂停、删除。
- 分时提醒时间线：当天每次“条件接近/已触发”的时刻、价格与依据，可追溯。
- 数据卡：来源（东方财富）、行情延迟说明、分析模型、数据截止时间、免责声明。

### 7.6 提醒消息中心

- 消息字段：标的名称/代码、提醒类型、精确触发时刻（HH:MM:SS）、触发时最新分时价、分时均价、规则摘要、是否已推送 Server酱、是否已读。
- 消息可点击跳转到对应个股详情。
- 未读红点在工具页与底部导航消息入口展示；进入后自动标记已读。
- 站内消息与 Server酱 独立存储推送状态，推送失败不影响站内留痕。

### 7.7 Server酱 设置

- SendKey 支持 SCT（sct.ftqq.com）与 SC3（sc3.ft07.com），由官方 serverchan-sdk 自动识别。
- 提供“测试推送”按钮，发送一条带当前页面标题的测试消息，展示接口返回 code/message。
- 展示当日已用/免费额度，并提示“超出免费额度后仍可收到站内提醒”。
- SendKey 只允许写入、不允许回显完整值，前端只显示脱敏 Key。
- 推送失败时消息中心保留记录，并在设置页展示最近一次失败原因。

### 7.8 状态与边界

- 加载中：骨架屏 + “正在拉取真实行情”。
- 搜索失败：明确提示，不出示任何猜测结果。
- 数据不足：少于 60 个有效交易日，或当日分时数据不可用/不足时，拒绝生成提醒。
- 分时数据缺失：分时接口连续拉取失败时展示“分时数据缺失”，停止信号判定并保留站内错误状态。
- 盘中休市/停牌：暂停监听，恢复交易后自动继续。
- 上游不可用：可重试错误页；已有成功快照时展示 stale 快照但禁用触发提醒。
- 提醒到期：状态置灰，提示重新设置，不自动删除自选。
- Server酱 未绑定：绑定引导，站内提醒不受影响。
- 自选超上限：每用户默认 10 只，提示移除后添加。

## 8. 数据真实性与安全

### 8.1 真实数据来源

- 沿用市场雷达同源的东方财富公开接口，全部由 FunBox Go 后端发起，前端不直连第三方。
- 标的解析：东方财富 suggest 搜索接口。
- 最新行情：优先实时行情接口，失败回退延迟行情接口并明确标注“延迟行情”。
- 历史 K 线：近 90 个交易日复权日 K 线（`klt=101`、`fqt=1`）。
- 分时数据：当日真实分时序列接口（`trends2/get`，含每分钟价格与分时均价）；盘口五档与分笔成交仅在真实公开数据可用时使用。
- 所有上游 URL、缓存与超时均为后端配置，不在客户端 bundle 暴露任何行情密钥。

### 8.2 禁止假数据原则

- 生产环境不存在 mock 数据回退路径：无可用真实快照时返回可重试错误。
- 测试 fixture 只进入测试编译，绝不进入生产回退分支。
- stale 快照只能用于展示并标注，不能用于生成新分析或触发提醒。
- 任何“触发价”“涨跌幅”“量比”都必须能追溯到真实 K 线与真实分时价格计算。

### 8.3 LLM 幻觉防护

- 模型只接收结构化真实特征，不接收自由文本行情描述。
- 输出必须为 JSON 且通过 schema 与数值范围双重校验。
- 理由生成约束为“只引用给定指标”，并对“业绩、新闻、政策、内幕”等词做输出过滤。

### 8.4 免责声明

- 所有页面固定展示：仅供信息参考，不构成投资建议。
- 提醒为基于真实行情生成的信号规则，不承诺收益，不提供自动交易。

### 8.5 密钥与隐私

- Server酱 SendKey 仅在服务端保存，落库前加密，日志中脱敏，API 只返回掩码。
- 自选与提醒事件与用户 ID 绑定，接口全部走现有 JWT 鉴权。
- 不采集用户的券商、持仓、交易记录；本功能不接入真实下单。

## 10. 技术方案

### 10.1 后端模块

在现有 `backend/internal/stockalert` 基础上扩展：

| 子模块 | 职责 |
| --- | --- |
| `provider` | 东方财富 suggest / 实时行情 / 延迟行情 / 90 日 K 线 / 当日分时序列抓取与解析，腾讯行情兜底 |
| `indicator` | 日线 MA/RSI/MACD/BOLL/支撑压力/量比 + 分时均价/量比/涨速/委比等特征计算 |
| `analysis` | DeepSeek-V4-Flash 调用、JSON schema 与数值范围校验，输出今日信号规则 |
| `reminder` | 提醒规则 CRUD、交易时段 10 秒级分时轮询、确定性触发判定、去重、推送与事件落库 |
| `store` | 自选、分析、提醒规则、提醒事件、Server酱 设置持久化 |

### 10.2 数据模型

```text
stock_watch_items      user_id, symbol, name, market, enabled, analysis_id, valid_until, created_at

stock_alert_settings   user_id, sendkey_encrypted, reminder_enabled, updated_at
```

| 方法 | 路径 | 说明 |

| GET | `/api/v1/stock-alert/search?q=` | 真实标的搜索，返回候选列表（含最新价与涨跌幅） |
| POST | `/api/v1/stock-alert/watch` | 按 symbol/secId 加入自选，不做隐式猜测 |
| GET | `/api/v1/stock-alert/watch` | 自选列表 + 最新分时价/分时均价 + 提醒状态 |
| GET | `/api/v1/stock-alert/watch/{symbol}` | 个股详情 + 分析 + 提醒规则 |
| PATCH | `/api/v1/stock-alert/watch/{symbol}` | 暂停/开启提醒、有效期 |
| DELETE | `/api/v1/stock-alert/watch/{symbol}` | 删除自选 |
| GET/POST/PATCH/DELETE | `/api/v1/stock-alert/reminders` | 提醒规则 CRUD |
| POST | `/api/v1/stock-alert/watch/{symbol}/reanalyze` | 重新分析 AI 信号 |
| GET | `/api/v1/stock-alert/watch/{symbol}/intraday` | 当日真实分时序列与提醒时间线 |
| GET | `/api/v1/stock-alert/events` | 消息中心分页 |
| POST | `/api/v1/stock-alert/events/read` | 标记已读 |
| GET/PUT | `/api/v1/stock-alert/settings` | Server酱 设置 |
| POST | `/api/v1/stock-alert/settings/test-push` | 测试推送 |

### 10.4 DeepSeek 复用与模型

- 复用现有 `DEEPSEEK_API_KEY` 与 `config.DeepSeekConfig`。
- 新增 `DEEPSEEK_STOCK_MODEL`，默认 `deepseek-v4-flash`。
- 模型职责调整为“开盘前/重新分析时生成今日 AI 信号规则”，盘中实时判定由后端信号引擎完成。
- 沿用现有 JSON `response_format` 与错误提取模式，超时沿用 120s 配置。

### 10.5 Server酱 集成

- 使用官方 `github.com/easychen/serverchan-sdk-golang`，按 Key 前缀自动选择 SCT 或 SC3。
- 推送参数：`title`、`desp`（Markdown）、`short`（卡片摘要）、`tags`。

## 11. 页面与交互设计（对应设计图）

设计图文件：`docs/stock-trade-alert-product-design-v2.html`、`docs/stock-trade-alert-product-design-v2.png`，另附单屏手机图。

### 11.1 搜索真实标的

- 顶部搜索框 + 搜索按钮；输入后展示真实候选列表。
- 候选行：名称、代码、市场标签、类型标签、最新真实价、涨跌幅、加入自选按钮。
- 已在自选的标的显示“已在自选”，点击后进入自选列表。
- 权证、指数、板块等非股票类型展示但禁用加入，并在行内标注类型。

### 11.2 自选标的

- 顶部搜索入口 + 自选统计（`n/10`）+ 提醒状态摘要。
- 自选行：名称/代码/市场、最新价、涨跌幅、分时均价、提醒开关、设置提醒入口、迷你走势。
- 行点击进入个股详情；“设置提醒”进入分时提醒配置。

### 11.3 分时提醒配置

- 顶部展示当前选择的标的与真实行情摘要。
- 提醒类型分段控件：价格 / 涨跌幅 / 分时均线 / 量能 / AI 信号。
- 条件编辑区：比较方向、阈值、步进；阈值范围校验基于真实日线高低点。
- 生效设置：交易时段、有效交易日、提醒渠道。
- 底部实时预览：当前真实分时状态、今日是否已触发、下一交易日生效提示。

### 11.4 个股分时详情

- 顶部真实行情头：最新价、涨跌幅、今开、分时均价、最高、最低、实时状态。
- 当日真实分时图：价格线 + 分时均价线 + 提醒阈值标记 + 已触发点。
- 提醒规则卡：当前标的所有已配置提醒，可编辑/暂停/删除。
- 分时提醒时间线：真实触发记录；无触发时展示真实空态。

### 11.5 提醒与设置

- 消息中心：今日触发汇总、未读状态、站内/微信推送状态、跳转详情。
- Server酱 设置：SendKey 掩码、测试推送、每日免费额度、失败原因。

## 12. 非功能需求

- 性能：搜索结果 P95 < 800ms；自选列表 P95 < 800ms；分时刷新接口 P95 < 500ms；AI 分析允许异步，首次分析期间显示进度状态。
- 限流：沿用现有后端限流配置，搜索与提醒接口单独限频。
- 弱网：列表/详情支持本地缓存，缓存内容仅用于展示并标注时间。
- 主题：支持 FunBox 浅色/深色主题。
- 布局：320px / 390px / 430px 三档宽度无溢出、无重叠，数字使用等宽排版避免刷新跳动。
- 可观测：监控任务记录每次轮询健康度，上游持续失败时生成可排查日志。

## 13. 验收标准

1. 输入真实代码/名称能解析出真实标的，搜索失败不出现演示结果。
2. 搜索结果先展示，用户确认后加入自选；自选列表服务端持久化。
3. 从自选选择股票可配置五类分时提醒，提醒规则可编辑、暂停、删除。
4. 提醒触发判定只使用真实分时快照（新鲜度 ≤ 15 秒），stale 数据不触发提醒。
5. 触发后站内消息与 Server酱 推送均可用，Server酱 失败不影响站内消息。
6. 同一提醒规则同一方向每个交易日去重，分时回落后再次满足才可重新触发。
7. 每用户自选上限、分析日限、Server酱 免费额度约束生效。
8. 上游不可用、K 线不足、分时数据缺失、休市停牌、解析失败、提醒到期、Key 未绑定等状态全部有明确 UI。
9. 生产代码不包含任何 mock 回退路径；测试 fixture 只用于测试。
10. Go 测试、TypeScript、lint、前端相关测试、全量既有测试通过。
11. 桌面与移动视口浏览器 QA 通过：无空白、无控制台错误、无元素重叠、无文字溢出。

## 14. 明确不做

- 不提供毫秒级实时成交保证，分时行情以东方财富公开数据为准并标注刷新时间与延迟。
- 不提供自动下单、券商接入、持仓同步。
- 不承诺收益，不生成收益预测。
- 不编造新闻、业绩、政策等非行情理由。
- 不做社交分享、社区跟单、付费订阅。
- 不在本期提供用户自定义公式提醒；五类规则 + AI 信号覆盖一期。

## 15. 设计说明

- 三屏主链路：搜索结果 → 自选列表 → 分时提醒配置；个股详情与消息中心作为完整闭环。
- 搜索结果突出“真实来源 + 可加入自选”，让用户明确知道下一步。
- 自选列表突出“提醒状态 + 设置入口”，让用户一眼看出哪些标的正在监听。
- 分时提醒配置突出“当前真实行情 + 条件预览”，避免用户凭猜配置。
- 全量状态覆盖放在设计稿底部，表示一期包含全部异常与边界状态。
- 视觉直接复用 FunBox 现有体系：浅蓝背景、白色表面、深藏青重点、主蓝操作、青柠强调、细分隔线，圆角不超过 8px，图标使用 Material Community Icons。
