## 人性化交互补充（本轮设计者提出）

- 轮到本人：顶部“轮到你了”横幅、本人座位蓝色描边和“行动中”文字、底部本人动作区同时变化。切入本人回合只做一次约 240ms 的轻放大与两次有限强调，之后保持静态高亮；后台不持续震动。首次前台收到新回合可轻震一次，声音默认关，均可关闭。
- 轮到别人：全桌顶部一直显示当前行动者名字、座位和下一位；本人操作区显示等待，不出现可提交的跟注按钮。不能只靠颜色区分，也不自动强制滚动打断阅读账本。
- 等待较久：允许手动“提醒一次”，实际产品应限制频率；不倒计时罚分、不自动弃牌、不替人操作。断线与暂未行动分开显示。
- 高频跟注一键提交：按钮上同时显示积分及折算金额；提交后立即变为“同步中”并禁用，成功以服务端确认后更新，不额外弹一次确认。加注选档时明确展示闷／看投入；弃牌显示不退已投入的确认层。
- 比牌分两步：跟注前可返回；跟注成功后保持“已跟注，待选择对手／录入结果”，刷新重连恢复同一流程。结果选项未选时禁用确认，同大小有明确判负说明。对手离线时不冒充自动裁定。
- 喜钱先现场亮牌、房主登记，登记改变后重新核对；没有喜钱也需要明确确认本场无喜钱，防止直接跳过导致漏记。本人申报不能直接扣别人分。
- 场末先完成胜负和喜钱入账，再出现“开始下一场”；名单有变化时主按钮提示重新核对，不悄悄把新玩家算进上一场。房主离场需有人接受转让，普通离场显示其累计与未结清状态。
- 金额变化：数字立即反映确认值，约 280ms 的短暂数字过渡及“+X分”反馈可辅助理解。奖池插画按实际人民币金额增加有限的蓝／珊瑚色筹码数量和层数，不设置虚假的筹码填满目标，不因人数或每分金额混淆。
- 奖池视觉档位仅用于装饰，不参与规则：低于 ¥50 为 2–3 枚；¥50–199 为 4–5 枚；¥200–499 为 6–7 枚；¥500 以上最多 8 枚。跨档时一次轻弹，普通加分只做局部短反馈；不持续旋转、闪烁或全屏撒币。不用金币、彩金、大奖等误导视觉。
- 比牌、加退人员和规则修改的确认信息优先于动效；动效不遮挡金额、按钮和座位。减少动态／低性能时直接显示最终数值与静态插画；屏幕阅读器只在确认结果后播报一次，不逐动画帧播报。
- 离线时保留最近确认的积分，明显显示“网络中断，操作已暂停”；输入草稿保留，恢复后先同步，不将本地草稿当作已入账。不弹连续重复错误对话框。
- 错记通过独立更正流程保留前后记录、操作者和原因；不提供会悄悄抹掉已确认历史的撤销。进行中本场由房主取消时需显示影响并完整撤销本场投入及未提交喜钱。

## 既定规则不变

房间内多场、每场多圈；房主设置每分金额，整桌统一；闷1看2；比牌人数门槛满足才出现、先跟一次再选人、同大小主动者输、败者出局、从发起者下一座位继续。封顶前不限圈，基准封顶后完整三圈强制开牌，若仅余一人则提前结束。喜钱与本场胜负无关，包含已出局参与者，独立于奖池。场间加退只影响下一场；离场不清账；真正散场才按整桌总账结算。

## 实施时需确认的边界

目前服务端人数上限为8；设计包含12人容量示例，落地需要明确并同步扩展房间限制。相同牌型的最终实体牌裁定仍由现场完成，小程序不自动识别。每分金额和关键规则应留存版本快照。提示设置的声音／震动必须遵循微信能力与设备权限，不承诺后台持续提醒。

## 设计演示核对

- 浏览器实际验证：88分／¥44.00，跟注10分同步中禁用按钮，确认后98分／¥49.00，行动者切到阿杰。
- 奖池¥800时筹码视觉最多8枚；关闭奖池动效后不再显示筹码；减少动态可独立开启。
- 网络中断状态保留分数并隐藏可提交操作。
- 在320px浏览器视口实际检查，演示根容器与手机内容无横向溢出；8人座位保持3列，提醒与操作区完整可用。
