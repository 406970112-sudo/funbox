# UI 状态与提示规范

这些是基于已确认玩法补充的交互默认值，供本轮设计评审；不是新增自动判牌、托管或付款功能。

| 状态 | 本人看到什么 | 全桌看到什么 | 操作与恢复 |
| --- | --- | --- | --- |
| 本人新回合 | “轮到你了，小林”、座位高亮、可操作区；最多一次轻震 | “轮到小林 · 1号位”，提示下一位 | 确认的新回合 ID 仅提醒一次，前台恢复旧回合不反复播放 |
| 他人行动 | “等待阿杰行动”，自己的跟注不可提交 | 当前行动者、座位号持续显示 | 提醒一次，实际实现需有冷却；不自动弃牌 |
| 阅读账本时轮到本人 | 非阻断提示“轮到你了，返回本场” | 正常显示行动者 | 由本人点返回，不抢滚动位置、不关闭正在核对的详情 |
| 跟注提交中 | 原按钮位置显示“同步中”且禁用 | 保留上一份已确认状态 | 一次幂等命令；失败恢复按钮；冲突明确告知本次是否入账 |
| 加注选档 | 显示新的基准、本人倍率、实际投入与折算金额 | 未确认前不改变全桌基准 | 只展示高于当前基准且不超过封顶的档位 |
| 看牌 | “已看 · 2倍”，应跟分立即重新计算 | 玩家已看状态同步 | 不收费、不追补、不结束回合，不能再改回闷牌 |
| 弃牌确认 | “已投入X分保留，退出本场行动，仍参与本场喜钱” | 确认后出局并保留座位 | 确认前可返回，确认后不提供静默恢复 |
| 比牌未跟注 | 跟注金额和RMB，尚不显示可选对手 | 保持当前行动者 | 此时可取消；仅在人数门槛满足时可进入 |
| 比牌已跟注 | 明确已入池；选人、结果确认，不能再次扣费 | 正在比牌的发起者与状态 | 重连恢复；除当前结果流程外不展示可竞争的跟注操作 |
| 比牌结果 | 明确双方、输者及下一位；同大强调主动方输 | 出局状态和行动权更新 | 本次结果只应用一次；仅余一人直接结束 |
| 达到基准封顶 | “封顶后第1/3圈”，加注不可用 | 同步圈数及尚未行动人数 | 触顶动作不占这三圈；看牌不消耗圈数，比牌待结果不提前消耗 |
| 第3圈完成 | “3圈已满，强制开牌” | 停止投入、等待现场结果 | 不叠加新的比牌费；现场核对后选择在局赢家 |
| 喜钱登记 | 房主选择玩家和豹子／顺金，列出每人应给及收取总额 | 非房主只读，可现场提出异议 | 改任何登记则重新核对；无喜钱也明确确认；一次入账 |
| 场末入账 | 本场得分与整桌累计分开，含喜钱 | 相同的已确认账单 | 主按钮开始下一场；至少2人、无待处理账目才可开场 |
| 场间名单变化 | 显示新入座／离场的人数和名字 | 全桌可见变动提示 | 房主核对下场名单，冻结快照；不改上场和历史账目 |
| 房主转让 | 原房主选择接任者；对方接受后显示成功 | 公示新房主 | 未接受不提前取消原房主权限；断线不自动转让 |
| 玩家离场 | 累计积分及金额、未结清状态、历史保留说明 | 该人移至已离场区域 | 不占下场座位；仍进最终整桌结算；回来恢复同一身份 |
| 网络中断 | 顶部横幅“网络中断，操作已暂停” | 其他人可见离线，不认为弃牌 | 保留输入草稿与确认值；重连先同步再提交；不自动代操作 |
| 身份／版本冲突 | “名单或回合已变化，请核对” | 当前正确服务端状态 | 不盲目重放过期命令；有已入账回执就恢复结果，不能扣第二次 |
| 散场确认 | 全部曾参与者、含离场者、固定每分金额与最终净额 | 确认后整桌只读 | 取消保持继续玩；确认停止新场，仅展示转账建议 |

## 回合提示优先级

网络或身份阻断 > 已跟注待完成比牌 > 强制开牌 > 喜钱／场末核对 > 本人回合提醒 > 普通动作流水。高优先级状态下隐藏不适用操作，不叠一屏提示层。顶部持续信息与一次性提示分开：静态高亮常驻，一次性动画和震动有次数上限。

声效默认关；震动由用户开关且受设备能力限制。减少动态时去掉轻弹、数字过渡和筹码进入，只保留精确数值、文字状态和静态描边。按钮不能因数字变化改位置，长昵称、较大金额和12人布局不能覆盖操作区。

## 仍由现场确定的内容

实体牌型与比牌结果不由小程序自动识别。封顶强制开牌如有并列最大，不擅自套用“主动比牌者输”，因为此时没有主动方；暂停提交，让房主按桌上事前约定现场核对再录入最终结果。当前单一赢家模型不伪装支持平分奖池；如需要平分，应单独补充账单拆分流程。

## 本轮交互演示的边界

演示展示回合切换、座位高亮、跟注提交中的防连点、同步后的金额变化、奖池视觉档位、看牌提示、加注／弃牌确认、离线与减少动态设置。右侧按钮只用于切换设计状态，数据不会写入真实房间。封顶后三圈完整状态机与比牌完整交互仍可通过前一版原型查看；不把演示按钮当作正式小程序中的控制项。
