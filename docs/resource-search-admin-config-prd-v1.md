# FunBox 资源搜索站点管理 产品设计方案 V1

> 版本：V1 草案
> 日期：2026-08-02
> 状态：待评审
> 定位：把资源搜索的站点清单、接入方式、可用状态与默认选择全部交给管理员在后台配置，用户端与搜索服务实时读取，一期一次性完整交付。

## 1. 背景与问题

当前 FunBox 的资源搜索已经具备“输入一次关键词、多站并发搜索、结果聚合、来源状态查看、原站直达”的基本闭环，但存在以下问题：

1. 搜索站点写死在客户端。`frontend/lib/resource-search.ts` 中硬编码 6 个站点，新增、下线、改名、改地址都要发版。
2. 前端清单与后端能力双份维护。后端 `resourcesearch` 目前只有“老二搜索”实现了真实聚合 provider，其余站点按固定文案返回“需原站验证 / 不可用”，前端仍把它们展示为可选站点，容易给用户“点了有结果”的错觉。
3. 站点可用性不可运营。站点是否超时、是否支持站内聚合、是否需要浏览器验证，都只能靠代码里写死的状态表达，无法及时发现和调整。
4. 存在非真实数据。客户端预置 `INITIAL_HISTORY = ['流浪地球 2', 'Figma 插件']` 这类假历史，不符合“所见即真实”的原则。
5. 无法审计与统计。谁改了什么站点、哪个站点真实搜索效果如何，均无记录。

## 2. 产品目标与原则

### 2.1 一句话定位

管理员在管理后台维护资源搜索站点，用户端实时使用真实配置与真实结果。

### 2.2 产品目标

1. 管理员可以新增、编辑、停用、删除、排序、设置默认勾选搜索站点，无需改代码发版。
2. 站点支持两种真实接入方式：站内聚合（服务端解析真实结果）与原站直达（生成真实搜索链接跳转）。
3. 后台提供真实健康检测与试搜验证，站点状态、延迟、失败原因均可被管理员看到。
4. 用户端不再硬编码站点与假历史，所有来源、状态、结果都来自服务端真实数据。
5. 后台操作有审计，搜索运行有真实统计，不做假数字。
6. 本次方案不设分期，以下所有能力在同一期交付。

### 2.3 设计原则

- 配置即事实：站点清单、分类、排序、默认勾选、接入方式全部以数据库为准。
- 真实数据：健康检测、试搜、搜索结果、运行统计全部来自真实网络请求与真实日志；任何环境不得引入 mock 数据、占位结果或预置假历史。
- 一期完整：后台配置、健康检测、试搜、审计、统计、移动端动态读取、搜索闭环一次性交付。
- 风格一致：沿用现有 FunBox 管理后台框架、移动端页面结构与视觉体系，不引入新设计语言。

## 3. 一期范围与非目标

### 3.1 一期完整交付

1. 后台“资源搜索”管理模块：站点列表、新建/编辑、启停、删除、排序、默认勾选、分类。
2. 接入模式与适配器注册：聚合模式、直达模式、受限站点仅原站可达。
3. 真实健康检测：单站检测、全部检测、检测历史与原因。
4. 真实试搜验证：保存前用真实请求验证站点与搜索模板。
5. 操作审计：后台所有站点变更留痕。
6. 运行概览：按站点展示真实搜索次数、成功/失败/超时次数、平均耗时、聚合结果数与 Top 关键词。
7. 用户端改造：来源列表来自 API、默认勾选来自配置、历史仅记录真实搜索、来源状态实时展示。
8. 数据迁移：现有 6 个真实站点迁移为后台配置行，首个健康状态由真实检测产生。

### 3.2 非目标（一期不做）

- 不做用户自定义搜索站点。
- 不做手写正则/选择器级别的抓取规则配置；适配器由服务端代码注册，后台只能选择已注册的真实适配器。
- 不做需要登录态或破解验证码的第三方站点抓取。
- 不做内容全文索引、资源入库或版权内容存储。
- 不做会员差异配额；站点配置对所有有权限用户统一生效。
- 不做站点级用户特批；站点属于运营配置，不进入入口权限的角色/用户特批体系。

## 4. 目标用户与场景

### 4.1 管理员

- 场景 A：新增一个真实可用的聚合搜索站点，配置名称、地址、搜索模板，试搜通过后上线。
- 场景 B：某个站点持续超时，查看真实健康检测结果并停用，避免用户继续点击失败来源。
- 场景 C：调整站点排序和默认勾选，让优质站点排在前面，配置保存后用户端立即生效。
- 场景 D：查看最近 7 天各站点真实搜索量、成功率与平均耗时，决定是否下线低质量来源。

### 4.2 普通用户

- 用户打开资源搜索，看到的是管理员当前生效的真实站点。
- 用户搜索时，聚合站点返回真实解析结果，直达站点打开真实搜索链接，不可用站点展示真实失败原因。
- 用户最近搜索只来自本人真实操作，删除假历史。

## 6. 功能设计

### 6.1 后台站点管理

#### 站点列表

- 顶部工具栏：站点名称/域名搜索、分类筛选、状态筛选、启用状态筛选、“立即检测全部”、“新建站点”。
- 列表字段：站点（Logo、名称、简介、域名）、分类、接入模式、默认勾选、排序、健康状态（状态 + 延迟 + 最近检测时间）、启用状态、操作（编辑、试搜、检测、启停、删除）。
- 列表支持按排序值升序排列；排序值相同按更新时间倒序。
- 删除采用二次确认；有真实搜索记录的站点只允许停用，不允许物理删除，避免统计断链。

#### 新建/编辑站点

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 名称 | 是 | 1-20 字，站点展示名 |
| 简介 | 否 | 最多 60 字，用户端来源副标题 |
| 分类 | 是 | 网盘 / 影视 / 文档 / 软件 / 综合，单选 |
| 首页地址 | 是 | 必须是公开 HTTPS 地址，真实可达 |
| 搜索地址模板 | 否 | HTTPS 模板，只允许 `{keyword}` 占位；未配置时仅支持原站直达 |
| 接入模式 | 是 | 聚合 / 直达，单选 |
| 聚合适配器 | 条件必填 | 仅聚合模式需要；从服务端已注册适配器中选择 |
| Logo 类型 | 是 | 文字 / 图片 |
| 文字 Logo | 条件必填 | 最多 2 个字符，背景色 + 文字色 |
| 图片 Logo | 条件必填 | PNG/WebP，最长边不超过 256px，512KB 以内 |
| 默认勾选 | 否 | 用户端首次进入时默认选中；默认开启 |
| 启用状态 | 否 | 停用后用户端不可见，搜索结果不请求该站 |
| 排序 | 是 | 0-999 整数，越小越靠前 |
| 每源最大结果数 | 否 | 聚合模式 1-50，默认 20 |
| 请求超时 | 否 | 1-30 秒，默认 12 秒 |
| 缓存时间 | 否 | 0-60 分钟，默认 2 分钟 |

规则：

- 新增站点必须先通过真实健康检测；聚合模式还必须通过一次真实试搜（可不要求一定有结果，但必须返回真实成功/空结果/失败原因）。
- 编辑首页地址、搜索模板或接入模式时，保存前自动触发一次真实检测与试搜。
- 名称、域名不能与已启用站点重复；域名按主域名归一化去重。

#### 接入模式与适配器

后台不提供自由写抓取规则的能力，适配器在服务端以代码形式注册，后台只选择“已注册适配器”：

| 适配器 | 模式 | 一期能力 | 真实数据来源 |
| --- | --- | --- | --- |
| `laoer_sse` | 聚合 | 真实请求老二搜索 SSE 接口，解析标题、大小、网盘类型；结果可二次解析真实目标链接 | laoer.motewan.com 公开接口 |
| `direct_link` | 直达 | 校验搜索模板，用 `{keyword}` 生成真实搜索链接，用户端点击打开原站 | 管理员配置的真实 HTTPS 模板 |
| `homepage_only` | 直达 | 未配置搜索模板时，只打开真实首页 | 首页真实检测 |

新增适配器属于后端代码扩展，不在本期开放给管理员手工配置。

### 6.2 真实健康检测

- 检测内容：请求站点首页地址，跟随最多 5 次重定向，验证最终 URL 为公开 HTTPS。
- 检测结果：成功（HTTP 2xx）、超时、失败、受限（如被安全验证拦截）、不可用（如需要登录态）。
- 记录字段：检测时间、HTTP 状态、延迟、最终 URL、消息、触发方式（手动/自动/保存前）。
- 支持单站“立即检测”与列表页“检测全部”。
- 启用站点每 6 小时自动检测一次，状态进入列表与用户端来源状态。
- 检测必须真实发起网络请求，任何环境不允许返回预置状态。

### 6.3 真实试搜验证

- 管理员在站点编辑抽屉输入真实关键词（必填，1-100 字），点击“试搜验证”。
- 聚合模式：调用真实适配器，展示真实结果标题、大小、网盘类型、数量与耗时；失败展示真实错误消息。
- 直达模式：用真实搜索模板生成链接，展示最终 URL 并允许管理员打开核对；无模板时提示“仅支持原站直达”。
- 试搜结果不写入用户侧结果缓存；同一站点 60 秒内限 1 次试搜，防止刷接口。
- 试搜界面不提供手工编辑返回数据的能力。

### 6.4 运行概览与操作审计

#### 运行概览

- 时间范围：最近 7 天 / 30 天。
- 指标：站点搜索次数、成功次数、失败/超时次数、平均耗时、聚合结果总数。
- Top 关键词：按真实搜索日志聚合，去重后展示 Top 10，不展示用户身份。
- 无日志时展示真实空状态“暂无搜索记录”，不填充假数字。

#### 操作审计

- 记录：操作时间、操作人、动作（新建/编辑/启停/删除/检测/试搜）、对象、变更摘要、结果。
- 变更摘要记录关键字段前后值；检测与试搜只记录触发人、关键词与结果，不保存第三方返回的敏感内容。
- 审计列表支持按操作人、动作、时间筛选；移动端后台至少可查看最近 100 条。

### 6.5 用户端动态来源

1. 删除前端硬编码站点数组与假历史；来源列表改为请求 `GET /api/v1/resource-search/sources`。
2. 来源按分类分组展示；分类顺序按后台配置顺序；组内按排序值排列。
3. 首次进入默认勾选后台配置的默认站点；用户调整后的选择保存在本地，不影响全局配置。
4. 来源行展示真实能力标识：聚合（返回站内结果）/ 直达（打开原站）/ 维护中（不可选）。
5. 停用站点不出现在用户端；无可用站点时展示真实空状态与“请联系管理员”文案，不展示占位来源。
6. 最近搜索只记录用户真实搜索；首次进入无历史时展示“还没有搜索记录”。
7. 搜索结果中聚合来源展示真实解析结果；直达来源展示“去原站搜索”，打开真实搜索链接。

### 6.6 搜索流程

```text
进入资源搜索
  → 加载真实站点配置
  → 用户输入关键词，选择站点
  → 并行请求所选聚合站点，直达站点生成真实链接
  → 聚合来源返回真实结果，直达来源进入结果页“原站搜索”卡片
  → 用户点击结果 → 有目标链接直接打开；需解析的来源经后端真实解析后打开
  → 来源失败/超时/受限 → 展示真实原因与“查看原站”操作
```

## 7. 数据模型

```text
resource_search_sources
  id, name, description, category, homepage_url, search_url_template,
  mode(aggregate|direct), adapter_key, logo_type, logo_text,
  logo_background, logo_color, logo_image_path, default_selected,
  enabled, sort_order, max_results, timeout_ms, cache_ttl_ms,
  created_by, updated_by, created_at, updated_at

resource_search_health_checks
  id, source_id, checked_at, status, http_status, latency_ms,
  final_url, message, trigger(manual|auto|save)

resource_search_test_runs
  id, source_id, operator_id, query, status, count,
  duration_ms, message, created_at

resource_search_audit_logs
  id, operator_id, operator_name, action, source_id,
  before_json, after_json, result, message, created_at

resource_search_usage_logs
  id, source_id, keyword, status, result_count, duration_ms,
  user_id, created_at
  （索引：source_id + created_at；keyword 仅用于后台统计）
```

存储要求：

- 沿用现有 SQLite + 迁移方式；生产库与开发库结构一致。
- 健康检测保留最近 50 条/站；运行日志保留 30 天；审计日志保留 180 天。
- 删除站点为逻辑删除（`deleted_at`），统计与审计不丢。

## 8. 接口设计

### 8.1 用户端

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/resource-search/sources` | 返回启用站点配置：名称、Logo、分类、排序、默认勾选、接入模式、健康状态 |
| GET | `/api/v1/resource-search/search?q=&source=` | 单站真实搜索；后台读取配置与适配器 |
| POST | `/api/v1/resource-search/results/{resultID}/resolve` | 真实解析结果目标链接 |

### 8.2 管理后台

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/admin/resource-search/sources` | 站点列表，支持名称/域名/分类/状态筛选 |
| POST | `/api/v1/admin/resource-search/sources` | 新建站点，自动执行检测与试搜 |
| PATCH | `/api/v1/admin/resource-search/sources/{id}` | 编辑站点 |
| DELETE | `/api/v1/admin/resource-search/sources/{id}` | 逻辑删除；有使用记录时需先停用 |
| POST | `/api/v1/admin/resource-search/sources/{id}/health-check` | 单站真实健康检测 |
| POST | `/api/v1/admin/resource-search/health-checks` | 全部启用站点检测 |
| POST | `/api/v1/admin/resource-search/sources/{id}/test-search` | 真实试搜 |
| GET | `/api/v1/admin/resource-search/audit-logs?limit=&offset=&action=&operator=` | 操作审计 |
| GET | `/api/v1/admin/resource-search/stats?days=7|30` | 运行概览 |

所有后台接口要求管理员角色与 JWT；用户端搜索接口沿用现有限流。

## 9. 权限、安全与合规

1. 后台模块仅 admin 角色可访问，沿用 `AdminShell` 与现有 JWT 校验。
2. SSRF 防护：健康检测、试搜、搜索请求只允许公开 HTTPS 主机；域名解析后拒绝私网、回环、链路本地地址；最多 5 次重定向；限制响应体大小。
3. 搜索模板校验：只允许 `{keyword}` 占位符，生成链接后再次校验协议与主机；拒绝模板拼接注入。
4. Logo 上传：校验真实文件类型、大小与像素，文件落盘路径不可被路径穿越。
5. 限流：用户搜索按来源限流；后台试搜 60 秒/站/次；健康检测“全部”10 分钟内限 3 次。
6. 隐私：运行日志不对外展示用户身份；关键词仅用于后台统计，30 天后删除。
7. 合规：本站只做第三方站点导航与公开接口聚合，不缓存资源内容，不做绕过登录、验证码或付费限制的行为。

## 10. 视觉与交互

- 管理后台：沿用现有深色侧栏、内容区卡片/表格、加载/空/错误状态；新增页面使用同一套顶栏与面包屑。
- 用户端：沿用现有资源搜索页的深色 Hero、来源列表、进度卡片、结果详情；新增内容仅替换数据来源与能力标识。
- 状态色：正常/成功使用绿色，超时/失败使用珊瑚色，受限使用琥珀色，不可用使用灰色；与现有来源状态一致。
- Logo 优先使用现有文字 Logo 样式；图片 Logo 按正方形裁切展示。
- 移动端 320px/390px/430px 与桌面端 1440px 均不允许文本溢出与元素重叠。

## 11. 验收标准

1. 管理员可完成站点新增、编辑、启停、排序、默认勾选、删除全流程，操作后用户端刷新即生效，无需发版。
2. 健康检测与试搜均为真实网络请求；断网、超时、反爬、404 等状态与真实结果一致，无 mock。
3. 用户端不再包含硬编码站点数组与假历史；来源数量、名称、分类、默认勾选来自后台配置。
4. 聚合模式返回真实解析结果；直达模式生成真实搜索链接；解析失败展示真实错误与“查看原站”。
5. 后台运行概览在无数据时展示空状态，有数据时数字与真实日志一致。
6. 审计日志完整记录站点变更；敏感内容不落库。
7. 现有搜索历史、分类筛选、来源排序、结果详情、复制提取码等既有能力回归通过。
8. 浅色/深色主题、移动端与桌面端布局无溢出；视觉与现有后台、现有资源搜索页一致。
9. 生产环境初始化迁移将现有 6 个真实站点写入配置，首个健康状态来自真实检测，不预置任何假状态。

## 12. 一期交付清单（一次性完成，不设分期）

- 后端：站点配置表、健康检测表、试搜表、审计表、运行日志表；配置存储与迁移。
- 后端：适配器注册与接入模式；`laoer_sse`、`direct_link`、`homepage_only` 三个真实适配器。
- 后端：用户端 sources/search/resolve 接口改造为读取配置。
- 后端：后台 sources/health-check/test-search/audit-logs/stats 接口与权限。
- 前端：移除硬编码站点与假历史；来源、默认勾选、状态改为 API 驱动；直达来源入口。
- 前端：新增后台“资源搜索”模块（列表、编辑、检测、试搜、概览、审计），接入 AdminShell。
- 运维：生产迁移数据脚本；启用站点每 6 小时自动检测任务；日志清理任务。
- 测试：接口单测、健康检测与试搜真实网络用例、移动端与桌面端视觉回归、无 mock 检查。

## 13. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 第三方站点接口随时变化 | 适配器由代码维护，健康检测与试搜可快速暴露变化 | 聚合站点数量短期可能减少，但真实 |
| 部分站点仅支持原站直达 | 用直达模式保留入口，不假装有站内结果 | 用户体验更诚实，运营可引导调整 |
| 移动端后台底部导航已满 7 项 | 本期不加第 8 项，移动端从后台首页卡片进入 | 移动端管理入口深一层，桌面端无影响 |
| 自动检测频率 | 启用站点 6 小时一次，改动保存时即时检测 | 状态最多滞后 6 小时 |
| 是否允许有搜索记录的站点删除 | 只允许停用，避免统计与审计断链 | 数据更完整，后台操作略受限 |
