# FunBox 效率清单产品设计方案 V1

> 版本：V1 草案  
> 日期：2026-08-01  
> 状态：待评审  
> 定位：FunBox“效率清单”工具，承载任务编排、每日目标与持续打卡三类轻量效率能力。

## 1. 产品概述

### 1.1 一句话定位

一个打开即用的个人效率工作台：把零散事项放进清单，把当天最重要的 1-3 件事立为每日目标，把想坚持的小习惯做成打卡，并在“今日页”一站式完成查看、打勾和记录。

### 1.2 与 FunBox 现有能力的衔接

- 功能注册表已预留 `focus-plan` 入口：名称“效率清单”、分类“效率”、路由 `/tools/focus-plan`、状态 `coming-soon`，本方案可直接承接该占位。
- 账号体系、JWT、功能角色与权限控制已存在，清单数据可安全落到服务端并跨设备同步。
- 前端已有统一工具页、主题系统、图标体系和“最近使用”能力，新工具挂入成本低。
- 后端为 Go + SQLite，新功能沿用 `internal` 分层与 `httpapi` 路由注册方式，不需要引入新服务。

### 1.3 产品目标

1. 用户从进入效率清单到完成一次“新增任务 / 打勾 / 打卡”不超过 30 秒。
2. 今日页聚合任务、每日目标与习惯打卡，让用户一眼看清“今天要做什么、做了多少、坚持了多久”。
3. 清单数据登录后保存在服务端，换设备或重装不丢失。
4. 保持轻量克制：只做个人效率闭环，不引入团队协作和复杂项目管理。

### 1.4 非目标（V1 不做）

- 不做团队清单、共享清单、评论与协作。
- 不做看板、四象限、甘特图等完整 GTD/项目管理方法论（放入 V2 候选）。
- 不做番茄钟、白噪音等专注计时能力（放入 V2 候选）。
- 不做服务端推送提醒；V1 只做移动端本地通知与 Web 端应用内提醒。
- 不做补卡、未来日期打卡；习惯只允许记录当天。
- 不做任务导入导出；结构上为后续预留即可。

## 2. 目标用户与场景

### 2.1 目标用户

- **日常任务型用户**：上班族、学生，事情多且容易漏，需要快速记录和按期完成。
- **轻度自律用户**：想坚持阅读、喝水、运动、早睡等小习惯，但不需要重工具。
- **效率工具尝鲜用户**：被复杂清单工具劝退，希望 FunBox 里有一个轻量但完整的闭环。

### 2.2 核心场景

| 场景 | 用户行为 | 产品应满足 |
| --- | --- | --- |
| 早上规划 | 打开效率清单，看昨晚排好的今日任务和目标 | 今日页首屏直接呈现，无需二次点击 |
| 临时接事 | 同事/老师交代一件事，随手记下 | 30 秒新建任务，标题优先，细节可后补 |
| 完成一件事 | 做完后打勾 | 打勾即完成并同步统计，有明确视觉反馈 |
| 坚持习惯 | 每晚固定提醒喝水、阅读、运动 | 习惯提醒 + 一键打卡 + 连续天数 |
| 周末回顾 | 想知道这周完成率和坚持情况 | 统计页展示完成率、目标达成、打卡热力图 |

## 3. 产品结构

### 3.1 信息架构

效率清单内部使用四个一级视图，移动端单列滚动：

1. 今日：每日目标、今日任务、习惯打卡状态。
2. 清单：全部任务清单、清单管理、任务编排。
3. 习惯：习惯列表、频率与提醒设置、月历热力图。
4. 统计：周/月完成率、目标达成、打卡连续与累计。

### 3.2 页面清单

| 页面 | 说明 |
| --- | --- |
| 今日页 | 日期头部、每日目标、今日清单、打卡区、快捷新建入口 |
| 清单页 | 清单切换、任务列表、优先级/日期排序、搜索、拖动排序 |
| 任务新建/编辑 | 标题必填，清单、优先级、日期时间、重复、子任务、备注可选 |
| 目标编辑 | 从任务引用或自定义一句，最多 3 条，按天设置 |
| 习惯页 | 习惯列表、新建/编辑习惯、当日打卡、月历热力图 |
| 统计页 | 周/月切换，任务完成率、目标达成数、打卡连续天数与累计 |

### 3.3 核心流程

```text
进入效率清单
  → 今日页（登录后可读写）
  → 新建任务：标题 → 可选清单/日期/优先级 → 保存
  → 完成：今日页或清单页打勾 → 任务归档 → 统计更新
  → 每日目标：从今日任务中挑 1-3 条，或自定义一句
  → 习惯打卡：当天一键打卡 → 连续天数与热力图更新
```

## 4. 功能设计

### 4.1 今日页

- 顶部展示日期、星期与一句轻量的进度摘要，如“今日完成 2/5”。
- 每日目标区：展示当天 1-3 条目标，未设置时提供“设为今日目标”入口。
- 今日清单：默认展示“今天到期 + 未完成且已逾期”的任务，按优先级排序；完成项折叠到“今日已完成”。
- 打卡区：展示当天待打卡和已打卡习惯，右侧显示连续天数。
- 固定快捷动作：新建任务、设置明日目标，避免进入多级页面。

### 4.2 清单与任务编排

#### 清单

- 新建清单时输入名称、选择颜色，不限制数量。
- 内置默认清单“收集箱”，新任务未选清单时落入收集箱。
- 清单支持重命名、排序、归档；归档清单内的未完成任务回到“全部”视图但不删除。

#### 任务字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 标题 | 是 | 单行文本，最长 100 字 |
| 清单 | 否 | 默认收集箱 |
| 优先级 | 否 | 高 / 中 / 低，默认中 |
| 日期 | 否 | 可选，无日期视为“随时” |
| 时间 | 否 | 有日期时可设置，用于本地提醒 |
| 重复 | 否 | 不重复 / 每天 / 每周 / 每月 |
| 子任务 | 否 | 最多 20 条，全部完成时主任务才视为完成 |
| 备注 | 否 | 多行文本，最长 1000 字 |

#### 重复任务

- 完成一次重复任务后，自动生成下一次到期实例；历史完成记录保留。
- 重复规则在创建后仍可修改，只影响之后生成的新实例。
- V1 支持每天 / 每周固定星期 / 每月固定日期；复杂规则（隔天、自定义周期）放 V2。

#### 完成与归档

- 任务完成后立即归档到“已完成”，可撤销完成。
- 过期未完成任务显示“逾期”标记，不自动删除。
- 删除任务需要二次确认；删除不影响历史统计。

### 4.3 每日目标

- 每天最多 3 条目标，分为“引用任务”和“自定义目标”两种。
- 引用任务：从今日清单选择任务，完成目标任务即同步完成；任务本身不受影响。
- 自定义目标：一句话目标，独立打勾，不与任务耦合。
- 目标按天生效：今天的目标次日自动清空，可提前为明日设置。
- 今日页未设置目标时展示空态引导，但不做强提醒，保持轻负担。

### 4.4 习惯打卡

- 新建习惯：名称、图标、颜色、频率（每天 / 每周指定星期）、提醒时间。
- 打卡：当天可打卡一次，同一习惯当天可取消后重新打卡。
- 不允许补打昨天或更早，不允许打未来日期。
- 连续天数 = 从最近一次有记录的日期开始，往前连续有记录的天数；中断后重新计算。
- 习惯支持暂停（不删除历史记录）与归档。

### 4.5 统计与回顾

- 支持“本周 / 本月”切换：任务完成数、完成率、目标达成数、打卡完成率。
- 打卡热力图：按月展示每日打卡次数，颜色深浅表示当日完成数量。
- 连续纪录：展示当前最长连续打卡天数与累计打卡次数。
- 统计只做事实呈现，不展示排名、不生成压力型文案。

### 4.6 提醒

- 有到期时间的任务和设置了提醒时间的习惯，在移动端通过本地通知提醒。
- 首次使用时申请通知权限，拒绝后仅保留应用内提醒，不反复打扰。
- Web 端不做浏览器推送，打开页面时展示到期任务角标与今日摘要。
- 修改或删除任务/习惯时同步撤销旧的本地通知并重新排期。

## 5. 交互与视觉设计

- 沿用 FunBox 视觉体系：浅蓝背景、白色表面、深色 `#151b3b` 重点区、主色 `#4b6bff`，本工具强调色使用注册表预留的 `#7e5bef`。
- 内容容器保持最大 430px 移动宽度，宽屏居中；页面区域使用全宽分段和细分隔线，不新增嵌套卡片。
- 圆角不超过 8px；图标沿用 Material Community Icons，入口图标为 `clipboard-check-outline`。
- 任务打勾、习惯打卡使用圆形状态控件，可点击区域不小于 40px，控件尺寸固定不随内容变化。
- 优先级、频率、周/月切换使用分段控件或下拉菜单；日期与时间使用原生选择器。
- 支持浅色与深色主题，文本在 320px、390px、430px 视口内不溢出。

## 6. 数据模型

### 6.1 表结构

```text
focus_lists
  id, user_id, name, color, sort_order, archived_at, created_at, updated_at

focus_tasks
  id, user_id, list_id, title, note, priority, due_date, due_time,
  repeat_rule, parent_task_id, status, completed_at, sort_order,
  created_at, updated_at

focus_task_completions
  id, task_id, occurrence_date, completed_at
  （重复任务每次完成的归档记录）

focus_goals
  id, user_id, goal_date, title, source_task_id, sort_order, completed_at

focus_habits
  id, user_id, name, icon, color, frequency, reminder_time,
  sort_order, archived_at, created_at, updated_at

focus_habit_records
  id, habit_id, record_date, created_at
```

### 6.2 时间与日期规则

- API 使用 `YYYY-MM-DD` 日期字符串，由前端按用户本地时区生成；服务端原样存储，V1 不做跨时区旅行场景。
- 任务到期日、目标日期、打卡日期均以本地日期为边界；跨天发生在客户端 00:00。
- 统计口径以本地日期分组，服务端不自行转换时区。

### 6.3 统计口径

- 任务完成率 = 已完成任务数 /（已完成 + 未完成且未删除任务数），按日期或周期过滤。
- 目标达成数 = 目标已完成条数，按 `goal_date` 聚合。
- 打卡完成率 = 当月有记录天数 / 当月应打卡天数，按习惯频率计算。
- 连续天数以 `focus_habit_records` 中距离今天最近的连续日期串计算。

## 7. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/focus/today?date=YYYY-MM-DD` | 今日聚合：目标、任务、打卡状态 |
| GET | `/api/v1/focus/lists` | 我的清单列表 |
| POST | `/api/v1/focus/lists` | 新建清单 |
| PATCH | `/api/v1/focus/lists/{id}` | 重命名/颜色/归档 |
| DELETE | `/api/v1/focus/lists/{id}` | 删除清单 |
| GET | `/api/v1/focus/tasks?listID=&status=&date=&q=` | 任务列表与搜索 |
| POST | `/api/v1/focus/tasks` | 新建任务 |
| PATCH | `/api/v1/focus/tasks/{id}` | 编辑、完成/撤销完成、归档 |
| DELETE | `/api/v1/focus/tasks/{id}` | 删除任务 |
| GET | `/api/v1/focus/goals?date=YYYY-MM-DD` | 查询某日目标 |
| POST | `/api/v1/focus/goals` | 设置目标（引用任务或自定义） |
| PATCH | `/api/v1/focus/goals/{id}` | 完成/撤销、修改 |
| GET | `/api/v1/focus/habits` | 习惯列表 |
| POST | `/api/v1/focus/habits` | 新建习惯 |
| PATCH | `/api/v1/focus/habits/{id}` | 编辑、暂停、归档 |
| POST | `/api/v1/focus/habits/{id}/records` | 当天打卡 |
| DELETE | `/api/v1/focus/habits/{id}/records/{recordID}` | 取消当天打卡 |
| GET | `/api/v1/focus/stats?range=week\|month` | 统计汇总 |
| GET | `/api/v1/focus/calendar?month=YYYY-MM` | 打卡月历热力图数据 |

说明：

- 所有接口要求登录，沿用现有 JWT 鉴权与限流中间件。
- 新增模块在 `backend/internal/focus/` 下实现，并在 `httpapi/server.go` 注册路由。
- 列表接口默认返回最近 90 天的任务，历史数据按月份分页查询。
- 本地通知由客户端根据任务时间和习惯提醒时间自行排期，服务端不维护推送令牌。

## 8. 权限与入口

- 功能继续挂在现有注册表 `focus-plan` 上，上线后把 `status` 从 `coming-soon` 改为 `available`。
- `initialRoles` 保持 `normal / vip / svip / admin`，V1 不做会员权益差异。
- 未登录用户从工具入口进入时引导登录，登录后回到效率清单今日页。
- 前端按现有模式新增 `features/focus/` 目录，工具列表、最近使用、首页推荐位自动生效。

## 9. 里程碑

| 阶段 | 范围 | 验收信号 |
| --- | --- | --- |
| M1 可用清单 | 登录、清单与任务 CRUD、今日页、完成/撤销、搜索 | 30 秒完成一次新增与打勾，数据跨设备可用 |
| M2 目标与打卡 | 每日目标、习惯打卡、月历热力图、统计页 | 目标当日生效，打卡次日不补、连续天数正确 |
| M3 提醒与重复 | 本地通知、重复任务、拖动排序、任务归档 | 到期提醒按时触发，重复任务自动生成下一实例 |

## 10. 验收清单

- 工具入口展示“效率清单”，状态由规划页切换为可用页，所有角色可见。
- 新建任务后可在今日页与清单页看到，刷新与重登后不丢失。
- 完成/撤销完成即时生效，统计数字同步变化。
- 每日目标最多 3 条，次日自动清空；引用任务完成时目标同步完成。
- 习惯每天只能打卡一次，取消后可重打，不能补打历史日期。
- 打卡热力图与统计口径在周/月切换下正确。
- 设置提醒时间后，移动端获得通知权限并按时收到本地通知。
- 深色/浅色主题、320px/390px/430px 视口下无文本溢出与元素重叠。
- 后端接口均有鉴权与基础限流，新增表结构与现有 SQLite 迁移方式一致。

## 11. 风险与开放问题

| 问题 | 当前建议 | 影响 |
| --- | --- | --- |
| 是否支持未登录本地试用 | V1 登录后使用，服务端存储 | 数据安全简单，但入口摩擦高于本地工具 |
| 是否允许补卡 | V1 不允许，保持打卡真实 | 习惯页规则简单，放弃部分宽容场景 |
| 时区与跨日 | V1 以客户端本地日期为准 | 不覆盖旅行跨时区场景 |
| 通知能力 | V1 本地通知，Web 应用内提醒 | 无法跨设备提醒，推送能力后置 |
| 会员权益 | V1 全角色可用 | 后续若做权益需重新定义配额，例如清单数量 |

## 12. V2 候选方向

- 番茄钟专注模式，与任务时长和统计打通。
- 看板/四象限视图与更完整的重复规则。
- 服务端推送提醒、多端通知状态同步。
- 数据导入导出、年度回顾报告。
- 团队/家庭共享清单与轻量协作。
