# FunBox 冲动消费冷静器 产品设计方案 V1

> 版本：V1 完整版
> 日期：2026-08-06
> 状态：待评审
> 定位：不拦截购买，只把一次“想买”变成可回看的五问、可计算的真实成本和一次 24 小时后的二次决定。

## 1. 背景与问题

电商促销、限时折扣、免息分期和“手慢无”持续制造紧迫感。用户往往在下单后才意识到：为什么买、家里有没有同类、多久用一次、这相当于多少小时收入，全都没有想过。

| 场景 | 现状 | 问题 |
| --- | --- | --- |
| 限时促销 | “今晚 8 点开抢”，先下单再思考 | 紧迫感替代判断，买后发现并不需要 |
| 重复购买 | 家里已有同类但没做盘点 | 耳机、水杯、数据线等重复购买频繁 |
| 大额低频商品 | 相机、游戏机、课程包 | 客单价高，实际使用频率低 |
| 小额高频商品 | 奶茶、盲盒、低价 App | 单次不贵，累计金额被忽视 |
| 收入感知弱 | 只看绝对价格 | 不换算成工作时长和月收入占比 |
| 冲动后后悔 | 退货流程长，或懒得退 | 消费决策缺少一次低成本复核机会 |

FunBox 已有账号体系、JWT、SQLite、工具注册、主题系统和消息能力。冲动消费冷静器不需要引入第三方价格抓取，所有核心数据都来自用户真实填写与系统真实时间。

## 2. 对原始想法的补充

原始想法是：用户输入想买的东西和价格，系统询问五个问题，并在延迟 24 小时后再次确认。在此基础上补充十点：

1. 五个问题从“连续弹窗”升级为“一份可回看的冷静记录”。新增时一次填完，冷静期内和 24 小时后都能返回查看。
2. 24 小时冷静期以服务端时间为准。前端只展示倒计时，不自行判定过期，避免改系统时间或切后台导致状态失真。
3. 用户始终拥有决定权。冷静期内允许“仍然现在买”或“现在放弃”；产品不锁死购买，只创造二次确认。
4. 支持“再想想”。24 小时到期后可选延长 24 小时，最多 3 次；每次延长生成真实事件，不做无限循环。
5. 真实时薪换算。时薪来自用户填写的税后月收入和月工作小时，或直接填写的时薪；价格除以时薪得到等价工时。未设置时薪时显示“待填写”，不调用地区平均工资。
6. 冷静提示由公开规则生成。提示等级只根据用户答案和真实计算结果计算，规则在详情页展示，不使用黑盒 AI 评分。
7. 决策闭环。24 小时后选择“仍要买 / 不买了 / 再想想”；每个动作写入事件流，误操作可在 5 分钟内撤销。
8. 统计只统计真实结果。“已放弃金额”只累计用户确认不买的记录，“待决定”和“冷静中”不计入。
9. 可选真实凭证。用户可上传订单截图或填写商品链接，仅作为自己的真实证据保存，不抓取、不校验第三方价格。
10. 隐私与可删除。数据只属于当前用户；支持导出 CSV/JSON 和清空全部冷静数据，不做公开分享或排行。
11. 一期全量。首页、新增、五问、24 小时提醒、详情决策、统计、设置、导出、删除全部在同一次版本内完成，不设分期。
12. 无 mock 回退。上线后没有任何种子记录、演示商品、固定示例、AI 编造价格或占位统计；空状态就是真实空状态。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户 30 秒内完成一次“新增冷静记录”。
2. 用户能清楚说出这次购买相当于多少小时工资，以及 24 小时后自己的真实答案。
3. 冷静期结束时用户不遗漏决定，系统通过真实通知和应用内待办承接。
4. 所有数字都可解释、可追溯：来源是用户填写，计算规则公开，状态来自系统时间。

### 3.2 设计原则

- 真实优先：价格、时薪、答案、倒计时、统计全部来自用户或系统，缺数据时显示“暂无”，不补造。
- 决策权在用户：冷静器只提供提醒和二次确认，不阻止支付，不替用户判断“该不该买”。
- 规则透明：提示等级由公开条件计算，不隐藏判断依据。
- 一屏可查：首页直接给出冷静中、待决定、已放弃金额和新增入口。
- 一期全量：本方案所有功能在同一版本内一次交付。
- 隐私克制：数据仅属于当前用户，不公开、不排行、不分享。
- 风格一致：沿用 FunBox 浅蓝画布、白色表面、深藏青标题、蓝色主操作和现有 320-430px 移动布局。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 促销敏感用户 | 看到限时折扣想立即下单 | 先记录五个答案，再进入 24 小时冷静 |
| 重复购买用户 | 已有类似物品但还想买 | 明确回答同类数量和是否在用，生成提示 |
| 大额低频用户 | 相机、游戏机、课程包 | 展示等价工时和月收入占比 |
| 小额高频用户 | 奶茶、盲盒、低价 App | 累计已放弃金额，建立真实感知 |
| 收入敏感用户 | 不清楚“价格到底值多少” | 用自己填写的真实时薪换算 |
| 决策拖延用户 | 24 小时后仍犹豫 | 支持延长 24 小时，最多 3 次 |

```text
进入冲动消费冷静器

```

## 6. 功能设计

### 6.1 首页“冷静舱”

- 顶部：工具名称“冲动消费冷静器”和副标题“不拦你买，只让你多想 24 小时”。
- 摘要区：
  - 冷静中：真实 `status=cooling` 记录数；
  - 待决定：真实 `status=pending_decision` 记录数；
  - 已放弃：仅 `status=dropped` 记录的累计金额。
- 快捷入口：新增冷静记录、查看待决定、进入统计。
- 最近记录：展示最近 5 条真实记录，含名称、价格、状态和剩余时间；无记录时显示空态。
- 首次使用空态：只展示“还没有冷静记录”和“新增冷静记录”入口，不预置任何示例商品。

### 6.2 新增冷静记录

#### 第一步：商品与价格

- 商品名称：必填，用户手写。
- 价格：必填，仅支持数字，单位默认人民币元，保存为 `price_cents` 整数分，避免浮点误差。
- 可选凭证：
  - 上传订单截图或支付截图，最多 3 张；
  - 填写商品链接；
  - 凭证只作为用户自己的真实来源保存，不参与价格生成。
- 来源标记：手动填写 / 订单截图 / 商品链接。系统显示“来源：用户填写”或“来源：用户上传”，不做第三方断言。

#### 第二步：五个问题

1. 为什么想买
   - 选项：需要 / 奖励自己 / 被促销吸引 / 跟风 / 情绪缓解 / 其他
   - 选“其他”时补充一句话。
2. 是否已有类似物品
   - 选项：没有 / 有 1 件 / 有多件
   - 若选“有”，继续回答：这件同类物品是否经常使用？是 / 否。
3. 预计使用频率
   - 选项：每天 / 每周 / 每月 / 偶尔 / 可能不用。
4. 相当于多少小时工资
   - 系统根据已设置的真实时薪自动计算：`等价工时 = 价格 / 时薪`。
   - 未设置时薪时，本项显示“设置时薪后可计算”，并提供设置入口。
5. 延迟 24 小时后是否还想买
   - 选项：是 / 否 / 不确定。

所有问题必须回答后才能开始冷静；保存时把答案原样写入记录，后续可回看。

#### 第三步：计算结果与开始

- 等价工时：如 `1299 元 / 42.8 元/小时 = 30.4 小时`，展示公式和数值。
- 月收入占比：用户设置了税后月收入时展示 `价格 / 月收入 × 100%`；未设置时不展示。
- 提示等级：由公开规则计算，展示触发原因。
- 开始按钮文案：`开始 24 小时冷静`。
- 提交前说明：真实数据提示“冷静期从服务端保存时刻开始计算，到期后需要你回来做最终决定”。

### 6.3 冷静详情与 24 小时倒计时

- 商品卡：名称、价格、来源、创建时间。
- 倒计时：以 `cool_ends_at - server_now` 为真实剩余时间；后端每个接口返回 `serverNow`，前端不做本地猜测。
- 五问回看：按五个问题逐条展示用户当时的真实答案。
- 计算过程：等价工时、月收入占比、提示等级和规则触发项。
- 冷静中操作：
  - 主操作：等待 24 小时；
  - 次级操作：现在放弃（立即进入 `dropped`）；
  - 保留操作：仍然现在买（记录为 `bought`，来源含 `early`）。
- 24 小时到期后：
  - 状态变为 `pending_decision`；
  - 展示“冷静期已结束，请做最终决定”；
  - 操作：仍要买 / 不买了 / 再想想 24 小时。

### 6.4 决策与事件流

#### 仍要买

- 弹出确认页，默认带入原价，用户可修改最终成交价；
- 购买日期默认今天，可修改；
- 保存后状态为 `bought`，累计到“最终购买金额”；
- 若在冷静期结束前选择“仍然现在买”，记录 `bought_early`，统计中标注为提前购买。

#### 不买了

- 保存后状态为 `dropped`；
- 累计到“已放弃金额”；
- 可补充一句“为什么改变主意”，保存为真实事件备注。

#### 再想想

- 状态回到 `cooling`，`cool_ends_at = server_now + 24h`；
- `extend_count + 1`；
- 最多延长 3 次，之后仅提供“仍要买 / 不买了”；
- 每次延长生成 `extended` 事件。

#### 撤销

- 用户做出决策后 5 分钟内可撤销，恢复决策前状态；
- 撤销写入 `undone` 事件，不删除原决策事件，保证可追溯。

### 6.5 提醒

- 24 小时冷静期结束时，服务端扫描 `cooling` 中 `cool_ends_at <= now` 的记录，将其置为 `pending_decision`，写入 `notified` 事件。
- 应用内通知：首页“待决定”区域始终可见。
- 系统通知：用户授权后，在冷静期结束时刻发送本地通知；若权限未授权，只显示应用内待决定，并提示去设置开启。
- 可选提前提醒：用户可在设置中开启“结束前 1 小时提醒”，仍按 `cool_ends_at - 1h` 的真实时间触发。
- Web 端没有系统推送权限时，使用站内提醒和首页待办，不伪造“已推送”状态。

### 6.6 历史与统计

#### 统计口径

| 指标 | 计算方式 |
| --- | --- |
| 累计冷静金额 | 所有已创建记录的价格之和 |
| 已放弃金额 | 所有 `dropped` 记录的价格之和 |
| 最终购买金额 | 所有 `bought` 记录的最终成交价之和 |
| 冷静完成率 | 已决定记录数 / 已结束冷静记录数 × 100% |
| 平均等价工时 | 已决定记录等价工时之和 / 已决定记录数 |

`pending_decision` 和 `cooling` 不计入已省或完成率。

#### 图表

- 近 30 天：按真实记录日期聚合新增、放弃、购买数量与金额。
- 无记录时图表显示“完成第一次冷静后生成”，不绘制占位曲线。
- 支持按状态筛选：全部 / 冷静中 / 待决定 / 已购买 / 已放弃。

### 6.7 设置与数据来源

- 时薪设置：
  - 方式一：税后月收入 + 月工作小时，自动计算时薪；
  - 方式二：直接填写时薪；
  - 保存时写 `wage_source`，旧记录保留创建时的时薪快照，不受后续修改影响。
- 通知设置：系统通知开关、提前 1 小时提醒开关、当前真实授权状态。
- 真实数据说明：列出所有数据来源和计算规则，明确“无 mock、无种子数据、无第三方价格抓取”。
- 导出：导出当前用户自己的 CSV/JSON。
- 清空：删除当前用户全部冷静数据，需二次确认；删除不产生云端残留展示。

## 7. 真实数据方案

### 7.1 数据来源

| 数据 | 来源 | 展示规则 |
| --- | --- | --- |
| 商品名称 | 用户输入 | 原样保存，仅去除首尾空白 |
| 价格 | 用户输入 | 保存为分，展示为元 |
| 商品链接/截图 | 用户上传或填写 | 作为用户自己的证据，不解析、不抓取 |
| 五个问题答案 | 用户选择/输入 | 原样保存，可回看 |
| 时薪 | 用户填写月收入/工时或直接填写时薪 | 记录创建时快照，旧记录不随设置变化 |
| 等价工时 | 系统按公式计算 | 展示公式与数值，字段缺失时不展示 |
| 24 小时截止时间 | 系统 `server_now + 24h` | 只允许延长，不允许手动改成过去时间 |
| 提醒状态 | 系统时间 + 用户授权状态 | 未授权显示“未开启”，不假装已推送 |
| 统计与图表 | SQL 聚合真实记录 | 无数据时显示真实空态 |

### 7.2 计算规则

```text
时薪 = 税后月收入 / 月工作小时
等价工时 = 商品价格 / 时薪
月收入占比 = 商品价格 / 税后月收入 × 100%
```

- 价格为 0 或负值不允许提交。
- 时薪为 0 或负值不计算等价工时。
- 所有金额使用整数分存储，展示时保留两位小数。
- 等价工时保留一位小数，展示原始计算公式。

### 7.3 提示等级规则

| 条件 | 触发等级 |
| --- | --- |
| 已有类似物品且不经常使用 | 高 |
| 等价工时 >= 20 小时 | 高 |
| 24 小时后答案是“否”或“不确定” | 高 |
| 使用频率为“偶尔”或“可能不用” | 中 |
| 购买原因是“被促销吸引”“跟风”或“情绪缓解” | 中 |
| 以上条件均不满足 | 低 |

任一“高”条件触发即显示高提醒；“中”条件触发且无“高”条件时显示中提醒；否则显示低提醒。每条触发原因都在详情页展示。

### 7.4 无 mock 保障

- 不预置种子商品、演示价格、演示时薪或演示统计。
- 不调用地区平均工资替代用户真实时薪。
- 不抓取未授权电商页面生成“同款低价”。
- 不使用 AI 生成“建议购买/不购买”结论。
- 外部数据不可用时显示错误、重试或真实空态，不回退演示数据。

## 8. 数据模型与接口

### 8.1 核心数据对象

- `cooling_settings`：用户设置。字段含 `user_id`、`monthly_salary_cents`、`monthly_work_hours`、`hourly_wage_cents`、`wage_source`、`notify_before_hours`、`notification_enabled`、`created_at`、`updated_at`。
- `cooling_items`：冷静记录。字段含 `id`、`user_id`、`name`、`price_cents`、`currency`、`source_type`、`source_text`、`answers_json`、`hourly_wage_cents`、`monthly_salary_cents`、`equivalent_hours`、`income_ratio_percent`、`risk_level`、`status`、`cool_ends_at`、`extend_count`、`decided_at`、`final_price_cents`、`final_purchase_at`、`created_at`。
- `cooling_events`：事件流。字段含 `id`、`item_id`、`event_type`、`note`、`happened_at`。事件类型：`created`、`extended`、`notified`、`decided_buy`、`decided_drop`、`bought_early`、`dropped_early`、`undone`、`deleted`。
- `cooling_evidence`：真实凭证。字段含 `id`、`item_id`、`user_id`、`storage_path`、`original_name`、`size`、`created_at`。

### 8.2 主要接口

| 方法 | 接口 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/cooling/home` | 首页摘要、待决定、最近记录 |

### 8.3 状态机

```text
cooling --24h到期--> pending_decision --仍要买--> bought
cooling --24h到期--> pending_decision --不买了--> dropped
pending_decision --再想想--> cooling
cooling --冷静期内仍然买--> bought (bought_early)
cooling --冷静期内放弃--> dropped (dropped_early)
```

## 11. 一期范围与验收标准

### 11.1 一期交付清单

- 首页冷静舱：摘要、待决定、最近记录、真实空态。
- 新增冷静记录：商品与价格、五个问题、等价工时、提示等级。
- 冷静详情：倒计时、五问回看、计算过程、规则依据。
- 24 小时提醒：服务端到期判定、应用内待办、可选系统通知。
- 决策：仍要买、不买了、再想想、5 分钟撤销。
- 历史与统计：状态筛选、累计已省、完成率、近 30 天图表。
- 设置与数据来源：时薪、通知、真实数据说明、导出、清空。
- 后端四张表、全部接口、到期扫描任务。
- 单元测试与接口测试，覆盖真实数据规则、空态、状态机和撤销。

### 11.2 验收标准

1. 未登录用户无法访问或提交数据；所有接口走 JWT 鉴权。
2. 新增记录必须包含商品名称、价格和五个问题答案；缺少字段不允许提交。
3. 未设置时薪时，等价工时和月收入占比区域显示真实空态，不出现任何替代数值。
4. 24 小时以服务端时间计算；到期后状态变为 `pending_decision`，通知事件只写一次。
5. 用户可完成仍要买、不买了、再想想；撤销窗口为 5 分钟。
6. 已放弃金额只包含 `dropped` 记录；冷静中和待决定不计入。
7. 近 30 天图表无数据时为空态，不绘制占位曲线。
8. 导出、单条删除、清空全部数据均可用，删除后接口不再返回已删数据。
9. 系统通知未授权时显示真实状态，不提示“已通知”。
10. 浅色/深色主题在 320-430px 视口内无重叠、无空白、无控件错位。

## 12. 明确不做

- 不做 AI 判断“该不该买”，不做黑盒购买建议。
- 不做第三方价格抓取和“同款最低价”比较。
- 不做种子数据、演示数据、mock 数据回退。
- 不强制阻止支付，不绑定支付链路。
- 不做公开分享、好友排行、社区种草。
- 不做分期实施；本方案所有页面和后台能力一期一次交付。
- 不重做 FunBox 主题、底部导航和工具注册体系。
