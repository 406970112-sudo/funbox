# FunBox 安静到家 产品设计方案 V1

> 版本：V1 完整一期
> 日期：2026-08-06
> 状态：待评审
> 定位：一个“报平安、不追踪”的晚归提醒工具。用户出发时设置出发地点和预计到家时间，到家后主动点“我已到家”；超时先提醒本人，较久未报平安再按用户授权提醒指定联系人。

## 1. 背景与问题

晚上独自回家或和伴侣约好到家时间时，常见的担心是：路上不方便发消息、到家后忘记报平安、家人或伴侣等不到消息也不知道该不该联系。

| 现状 | 问题 |
| --- | --- |
| 口头约定到家时间 | 容易忘记，等待方只能反复看手机 |
| 持续共享位置 | 不必要且侵犯隐私，用户很难接受一整晚被追踪 |
| 到点手动发消息 | 本人容易忘记，联系人也不清楚什么时候该主动询问 |
| 通用闹钟提醒 | 只能提醒一次，无法在“仍未到家”时升级处理 |

FunBox 已有账号体系、好友关系、JWT、SQLite、工具注册、WebSocket 实时消息和 `expo-notifications` 能力，新增“安静到家”可以直接复用，不需要引入新的核心基础设施。

## 2. 对原始想法的补充

原始想法是：出发时设置出发地点、预计到达时间，到达后点报平安，超时先提醒本人，较久后提醒指定联系人。

在此基础上补充十点：

1. 定位为“报平安”工具，不是定位追踪工具；默认不读取、不保存、不转发位置。
2. 出发地点和到达地点优先使用用户真实输入，仅在用户主动授权时读取一次当前位置或启用“仅本次到达检测”。
3. “到达后点击报平安”是主交互，不依赖位置也能完整使用；到达检测只是可选的辅助提醒。
4. 超时提醒不是一次性闹钟，而是“本人提醒 -> 再次提醒 -> 联系人提醒 -> 安全到达同步”的升级流程。
5. 指定联系人必须来自真实 FunBox 好友，且对方同意接收；没有好友或对方未同意时显示真实空态，不预置联系人。
6. 联系人收到的晚归提醒只包含用户允许的字段：姓名、预计到家时间、出发地点；位置默认不包含。
7. 用户可以选择“晚归时共享一次位置快照”，触发时只发送一张带时间和说明的静态快照，不发送路线，不持续追踪。
8. 每一条提醒、通知、报平安和取消操作都写入真实事件记录，并展示真实发送状态，失败不伪装成功。
9. 首次进入没有任何默认行程、默认联系人、默认历史和默认“家”，所有数据都来自用户真实输入或系统真实事件。
10. 本方案所有功能在一个版本内一次做完，不设二期、不设分期上线项。

## 3. 产品目标与设计原则

### 3.1 产品目标

1. 用户 30 秒内完成一次“安静到家”设置，到家后一键报平安。
2. 超时后先提醒本人，用户长时间未操作时再按授权提醒联系人。
3. 产品运行期间没有任何 mock 数据、种子数据或预置示例行程。
4. 默认不追踪位置；任何位置能力都要求用户主动开启，并在行程结束后自动失效。

### 3.2 设计原则

- 报平安优先：一键完成，不要求填多余信息。
- 隐私克制：默认不读取位置，不保存轨迹，不自动通知联系人。
- 真实优先：只展示用户真实输入、系统真实事件和通知真实状态。
- 可解释：每次提醒都说明触发原因和下一步时间。
- 安静陪伴：界面低打扰，不制造焦虑，不推送无意义通知。
- 一期全量：核心页面、提醒调度、联系人授权、历史与隐私管理一次交付。

## 4. 目标用户与场景

| 用户 | 核心场景 | 产品应满足 |
| --- | --- | --- |
| 独居青年 | 晚上加班或聚会后独自回家，想让自己记得报平安 | 到家后一键报平安，超时先提醒本人 |
| 情侣/室友 | 约定 23:20 到家，希望对方不用一直追问 | 超时较久时按授权提醒对方 |
| 关心家人的用户 | 希望知道家人是否安全到家，但不愿全天看位置 | 只接收“已安全到家”或“仍未到家”的明确事件 |
| 数据敏感用户 | 担心功能持续追踪位置 | 默认不读取位置，位置能力按次开启、行程结束即失效 |
| 拒绝假数据的用户 | 不希望在工具里看到预置联系人、历史或提醒 | 首次进入为空态，所有内容来自真实输入与事件 |


## 6. 功能设计

### 6.1 首页空态

- 顶部显示“安静到家”和当前数据状态：“暂无进行中行程 / 通知未开启 / 定位未开启”。
- 空态文案为真实状态，例如“还没有到家行程，今晚需要报平安吗？”。
- 主要按钮为“开始安心到家”，次要入口为“历史记录”“联系人与隐私”。
- 首次进入不显示任何预置行程、默认联系人或历史统计。

### 6.2 创建行程

字段与规则：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 出发地点 | 是 | 用户输入真实地点名称，可点击“使用当前位置”一次性填入当前位置 |
| 到达地点 | 是 | 用户输入或从“我的家”选择；首次使用“我的家”为空 |
| 预计到家时间 | 是 | 必须晚于当前时间，精确到分钟，默认不预填 |
| 本人提醒 | 否 | 默认开启；关闭后超时只显示应用内状态 |
| 升级提醒联系人 | 否 | 从真实 FunBox 好友中选择，且对方需同意接收 |
| 宽限时间 | 否 | 默认 30 分钟，可选 10 / 30 / 60 / 不升级 |
| 晚归共享位置快照 | 否 | 默认关闭；开启后仅在联系人提醒触发时发送一张真实静态快照 |

说明：

- “使用当前位置”只读取一次，用于填充出发地点，不启动持续定位。
- “我的家”来自用户真实保存，首次使用为空，不预置默认家。
- 创建后立即进入“行程进行中”，行程 ID 和创建时间写入真实记录。

### 6.3 行程进行中

- 展示“出发地点 -> 到达地点”、预计到家时间、当前距离预计时间的剩余时间。
- 主按钮为“我已到家”，尺寸大、可单手点击。
- 页面展示本次隐私状态：“不持续追踪 / 仅本次到达检测 / 已关闭位置”。
- 如果用户开启了“仅本次到达检测”，系统在行程期间监听到达区域；报平安、取消、超时结束后立即停止。
- 提供“延后到家”“取消行程”两个次要操作，均需要用户确认。

### 6.4 报平安完成

- 点击“我已到家”后，系统记录真实 `checkedInAt`。
- 如果晚于预计时间，展示“比预计晚 X 分钟”和真实到达时间。
- 提供“告诉联系人我到了”和“不通知”两个选项；选择通知时只发送“已安全到家”事件。
- 如果此前已触发联系人提醒，报平安后自动向已通知联系人补发“已安全到家”，并展示真实发送状态。

### 6.5 超时提醒

升级时间线（默认值）：

| 时间点 | 动作 | 内容 |
| --- | --- | --- |
| 预计到家时间 | 提醒本人 | “到家了吗？点一下我已到家报个平安。” |
| 预计到家时间 + 15 分钟 | 再次提醒本人 | “还在路上吗？可以延后到家时间。” |
| 预计到家时间 + 30 分钟 | 提醒联系人 | “用户仍未报平安，方便时请留意联系。” |
| 联系人提醒后每 60 分钟 | 再次提醒联系人 | 重复提醒，直到报平安、取消或用户主动停止 |

规则：

- 本人提醒通过系统通知和应用内横幅触达；通知权限未开启时，只展示应用内状态，不伪装成已发送。
- 联系人提醒发送前再次校验对方同意状态；对方撤回同意则不发送。
- 每条通知记录 `status: pending / sent / failed` 和真实时间，失败可重试。
- 用户报平安、取消或延后后，所有未触发的提醒自动撤销。

### 6.6 联系人与隐私

- 联系人列表只包含真实 FunBox 好友，状态为 `待同意 / 已同意 / 已拒绝 / 已移除`。
- 添加联系人时向对方发送真实邀请，对方同意后才可用于提醒。
- 隐私中心展示通知权限、定位权限、联系人授权、数据保留期限四项真实状态。
- 数据默认保留 30 天，用户可改为 7 天或立即清除。
- 提供“查看我授权过的位置事件”入口，展示每次位置读取的真实时间和用途。

## 7. 隐私与授权设计

### 7.1 位置

1. 默认不读取位置；首次进入不会申请定位权限。
2. 用户点击“使用当前位置”时，才读取一次当前位置并填入出发地点。
3. 用户主动开启“仅本次到达检测”时，才在本次行程期间使用到达区域检测。
4. 行程报平安、取消、超时结束或超过 24 小时后，位置监听立即停止。
5. 服务端不接收轨迹，只接收用户授权后的文本标签、可选到达事件和可选静态快照。
6. 位置快照只在“晚归共享位置快照”开启且联系人提醒触发时发送一次。

### 7.2 联系人

1. 联系人必须是用户真实 FunBox 好友。
2. 对方需要主动同意接收“安静到家”提醒，同意状态可随时撤回。
3. 联系人提醒默认只包含：用户名、预计到家时间、出发地点、提醒时间。
4. 位置快照默认不包含，需要用户在本次行程中单独开启。
5. 被提醒人不会获得持续位置访问能力。

### 7.3 数据

1. 行程数据只保存在用户账号下，其他用户只能看到被授权的事件摘要。
2. 通知日志记录真实发送状态，不伪造成功。
3. 历史记录只来自真实行程，可单条删除或全部清除。
4. 数据保留期限结束后自动删除行程标签和位置事件，不保留匿名副本。
5. 用户可导出自己的真实历史记录，导出内容不包含其他用户隐私。

## 8. 真实数据原则（硬性要求）

1. 首次进入“安静到家”不展示任何预置行程、默认联系人、默认历史或默认“我的家”。
2. 出发地点、到达地点、预计到家时间全部来自用户真实输入或用户主动授权的当前位置。
3. 到达时间、超时提醒时间、联系人通知时间全部来自系统真实事件。
4. 联系人来自真实 FunBox 好友，授权状态为真实双向状态。
5. 通知日志只展示真实发送状态；失败时展示失败原因，不显示“已发送”。
6. 历史记录只包含用户真实创建并结束的行程。
7. 统计数字只从真实记录计算，未发生过的报平安、晚归或通知不出现。
8. 设计稿中的填写内容仅用于表达界面状态，正式产品首启为空。

## 10. 技术方案

### 10.1 前端

- 新增 `frontend/features/tools/quiet-home-screen.tsx`，在 `ToolDetailScreen` 增加路由映射。
- 使用现有 `SurfaceCard`、`PageHeader`、主题色和底部导航组件，不引入新视觉体系。
- 本地通知使用已接入的 `expo-notifications`；未授权时显示真实状态入口。
- 位置能力使用系统定位 API，只在用户点击“使用当前位置”或开启“仅本次到达检测”时调用。
- 联系人选择复用 FunBox 好友列表与好友授权接口。

### 10.2 后端

- 新增 Go 模块 `backend/internal/quiethome/`，包含行程、联系人、通知日志与历史存储。
- 复用 JWT 鉴权和 SQLite，新增接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/quiet-home/state` | 当前行程、联系人、设置、权限状态 |
| POST | `/api/v1/quiet-home/trips` | 创建真实行程 |
| PATCH | `/api/v1/quiet-home/trips/{id}` | 延后到家或更新宽限设置 |
| POST | `/api/v1/quiet-home/trips/{id}/check-in` | 到家报平安 |
| POST | `/api/v1/quiet-home/trips/{id}/cancel` | 取消行程 |
| GET | `/api/v1/quiet-home/history` | 真实历史记录 |
| GET | `/api/v1/quiet-home/contacts` | 真实联系人及授权状态 |
| POST | `/api/v1/quiet-home/contacts/{userId}/consent` | 发起或更新双向授权 |
| DELETE | `/api/v1/quiet-home/contacts/{userId}` | 移除联系人授权 |
| GET | `/api/v1/quiet-home/privacy-status` | 通知、定位、数据保留状态 |

- 新增 `QuietHomeScheduler`，每 30 秒扫描有效行程并幂等触发到期提醒，不重复发送。
- 通知渠道复用现有 WebSocket 站内信、系统推送和邮件能力；渠道不可用时记录真实失败状态。

### 10.3 测试

- 首次进入空态：无默认行程、联系人、历史或“我的家”。
- 创建校验：出发地点、到达地点、预计时间必填，时间必须晚于当前。
- 提醒调度：到点、宽限时间、重复提醒均只触发一次，报平安后撤销未触发提醒。
- 联系人授权：未同意不发送，撤回后不发送，发送状态真实记录。
- 隐私：默认不请求定位，位置监听在报平安/取消/超时后立即停止。
- 历史：只包含真实创建行程，统计由真实记录计算。
- UI：320px 起所有手机视口不重叠、不溢出。
- Go 测试、前端 Node 测试、TypeScript 检查和 lint 全部通过。

## 11. 一期验收标准

1. 首次进入为空态，不出现任何预置行程、联系人、历史或默认家。
2. 用户可创建行程并设置出发地点、到达地点、预计到家时间。
3. 行程进行中显示路线摘要、预计时间和一键报平安按钮。
4. 到点提醒本人；宽限时间后按授权提醒联系人。
5. 报平安后记录真实到达时间，可选同步“已安全到家”。
6. 联系人必须为真实 FunBox 好友且对方同意，授权可撤回。
7. 默认不读取位置；“使用当前位置”和“仅本次到达检测”均需用户主动开启，行程结束即失效。
8. 所有通知状态真实展示，失败可重试，不伪装成功。
9. 历史只包含真实行程，可单条删除或全部清除。
10. 前端、后端和调度器全部在同一版本完成，不设二期。

## 12. 关键风险与决策

| 风险 | 决策 |
| --- | --- |
| 用户担心持续追踪 | 默认不读取位置，所有位置能力按次开启并自动失效 |
| 联系人提醒被滥用 | 双向授权、可撤回，默认只发送文本事件 |
| 用户忘记报平安却不想打扰联系人 | 宽限时间默认 30 分钟，可在创建时改为不升级 |
| 通知渠道不可用 | 展示真实失败状态，不伪装成功，并提供重试 |
| 后台被系统杀死导致提醒不准 | 本人提醒使用系统本地通知，联系人提醒由服务端调度兜底 |
| 历史数据敏感 | 默认保留 30 天，用户可清除或缩短保留期 |

## 13. 一期必须包含的完整范围

- 首页空态、创建行程、行程进行中、报平安、超时提醒、联系人与隐私、历史记录。
- 本人提醒、联系人提醒、宽限时间、延后到家、取消行程。
- 真实 FunBox 好友联系人及双向授权。
- 默认不读取位置、一次性当前位置、仅本次到达检测、晚归位置快照。
- 通知日志、真实发送状态、失败重试、数据保留与清除。
- 前端、后端、调度器、测试、工具注册和搜索关键词。

以上全部在本期完成，不设置任何二期拆分的功能项。
