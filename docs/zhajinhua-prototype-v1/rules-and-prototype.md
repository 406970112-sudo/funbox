## 项目现状

- 小程序首页已有炸金花场景，点击后仍提示“敬请期待”。
- Expo 前端已有简化流程：轮流加注、弃牌、按剩余人数强开；开牌费等于最近一次加注额。
- 现有流程没有独立的闷／看状态、规范化单注档位、轮数封顶。
- 延续现有定位：线下实体牌，小程序只记录动作、公共积分池和积分结果。每人用自己的手机操作，原型随当前行动者切换视角以便体验。

## 规则调研：共性与变体

炸金花没有本项目可直接照搬的唯一统一口径。以下区分常见玩法与本次产品提案，不把平台规则当成所有线下牌局的标准。

1. 常见基础：52 张牌去掉大小王，每人三张；先投入底注，依次跟注、加注或弃牌。剩一人时获得积分池。
2. 闷牌是未看自己的实体牌；看牌只改变自己的信息与后续投入倍率，不公开牌面。常见口径是闷牌 1 倍、看牌后 2 倍。看牌不单独扣分、不结束行动，之前的投入不追补。
3. 跟注按当前基准单注和自己的状态计算，不照抄上一人的实际投入。例如基准 5，闷牌投入 5，看牌投入 10；这不是德州扑克的补齐历史投入差额。
4. 加注提高“基准单注”，然后按本人倍率支付一笔新单注，不是额外再支付一次跟注。原型允许从 1、2、5、10、20 档中选择高于当前值的档位。
5. 封顶至少有不同语义：单次投入上限；最多行动轮数；个人累计投入上限；或触发其他玩家跟注后立即开牌。必须明确，不能只放一个没有单位的“封顶”输入框。
6. 比牌／开牌同样有变体：可开人数、最低轮数、发起费用、同牌胜负不同。多人局比牌通常只淘汰败者，不代表整手结束。看自己的牌与向对手发起比牌是两种动作。
7. 常见牌型顺序：豹子 > 顺金（同花顺）> 金花（同花）> 顺子 > 对子 > 散牌。A23 的顺序、235 是否吃豹子、同牌是否发起者输，均应提前约定；本产品不自动裁定。

## V1 建议口径（全部是待确认提案）

| 事项 | 原型默认值／行为 |
| --- | --- |
| 人数 | 沿用房间 2–8 人；演示 4 人 |
| 底注 | 每人每场 1 分，开手统一投入 |
| 每分金额 | 房主创建时设置，支持最多两位小数的正数；演示为 1 元／分；积分池同时实时显示积分与金额 |
| 闷／看 | 闷 1 倍，看后 2 倍；允许从第一轮看牌 |
| 行动顺序 | 按座位顺时针；房主第一场先行动，之后上一场赢家先行动 |
| 基准单注 | 初始等于底注，跟注不改变它；加注才提高它 |
| 单注封顶 | 基准最多 20 分，即闷最多 20，看最多 40；达到后禁止继续加注，并启动后续 3 圈倒计时 |
| 跟注圈数 | 封顶前不限总圈数；仍在局的人各行动一次算一圈，看牌本身不算一次行动 |
| 封顶后三圈 | 触顶的那次行动不算进后续 3 圈，从下一位起按座位完整进行；第三圈结束强制开牌 |
| 比牌人数 | 房主设置剩余在局人数上限，满足后才显示比牌入口；原型示例为 3 人，不再限制至少第 2 轮 |
| 比牌投入 | 先支付一次本人应跟分，计入积分池；不再收额外开牌费，也不再设置开牌倍率 |
| 比牌交互 | 确认跟注 → 解锁选择在局对手 → 现场比较 → 录入主动方大／对方大／同大小 → 确认结果 |
| 同大小 | 主动比牌者输并出局，不允许录为平局或继续在局 |
| 比牌后轮转 | 不论主动方输赢，从其原座位的下一位仍在局玩家继续；败者出局；仅剩一人则本场结束 |
| 弃牌 | 不退已投入积分；本场不再行动 |
| 牌局得分 | 赢家＝池总分－本人投入，其他人＝－本人投入；不含喜钱 |
| 喜钱 | 亮出豹子或顺金即收，与本场输赢无关；本场其他所有参与玩家分别给分，包含已弃牌者 |
| 最终净得分 | 牌局得分＋喜钱净收支；全体合计必须为 0 |
| 规则修改 | 等待或两场之间可改，从下一场生效；进行中的一场冻结规则 |
| 散场 | 当前手必须完成或取消，再查看本场积分与已有散场结算流程 |

不在首版加入个人累计投入上限、余额不足全下、边池、自动牌型识别。当前积分从 0 记净增减，因此不存在“余额不足自动弃牌”的隐含规则。多人同牌按桌上事前约定裁定，本版只允许录入一个赢家；若约定平分，需在下一版增加拆池流程，不能伪装为已支持。

## 原型页面与决策

推荐“积分池＋玩家列表＋本人行动区”：比纯手动填输赢多记录过程，比完整虚拟牌桌更贴合实体牌记分，且容易查看所有人的投入。纯结果记账无法覆盖闷／跟／封顶；虚拟发牌桌超出当前目的。此推荐由设计者提出，尚未得到用户确认。

原型提供 7 个可切换节点：

1. 建房规则：基本资料、底注、倍率、单注封顶、每分金额、比牌人数门槛；豹子、顺金的每人喜钱分数。移除总圈数上限。
2. 等待入桌：房间码、加入状态、规则摘要，至少两人可开手。
3. 本场记分：公共积分池、基准与本人应跟值、每个人的闷／看／出局状态、跟注／加注／看牌／弃牌／比牌、动作流水。比牌仅满足人数条件时出现。
4. 封顶开牌：用确定的示例数据展示停止投入、选择在局赢家、零和预览、确认入账。
5. 喜钱登记：本场结束后，为亮出牌型的玩家登记“豹子／顺金”，展示每人应给分数和全员喜钱净收支；可登记多名玩家。
6. 本场账单：分列“牌局得分／喜钱净收支／最终净得分”，展示喜钱转移明细；主操作为开始下一场；散场只通过房间更多进入。
7. 整桌账本：累计全部已完成场次，保留逐场账单；查看账本不触发散场。

## 喜钱规则（本轮用户已确认）

- 触发牌型为豹子、顺金（同花顺）。只要亮出对应牌型即收喜钱，与是否赢下本场无关。
- 本场冻结名单中的其他所有玩家都要给，包括已弃牌、比牌出局的玩家；拿牌者不付给自己。旁观者、未参加本场的人不参与。
- 房主建房时分别填写“豹子喜钱：每位其他玩家给多少分”和“顺金喜钱：每位其他玩家给多少分”，使用非负整数。原型 20／10 分仅为可改的示例，非用户指定默认值；0 表示该牌型不收。
- 喜钱不进入公共积分池，不改变基准单注，不受闷／看倍率、比牌跟注或单注／轮数封顶影响。
- 为避免提前暴露牌型，提议在本场结束后统一登记：玩家向全桌亮牌，房主现场核对、选择玩家和牌型，再确认入账。普通玩家只能查看，不能自行选择牌型后直接扣其他人的分；首版不增加全员逐一点击确认。房主自己拿到牌时也须先向全桌亮牌再登记。此登记权限为对用户追问的推荐方案，尚待用户评审。
- 原型支持切换房主／普通玩家视角；房主需勾选“已现场核对亮牌及本场所有喜钱”才可入账，修改任一登记会清除该勾选。该勾选是登记声明，不等于小程序自动验证牌面。
- 提议同一玩家同一场只登记一个牌型且只收一次，多次比牌不重复收。不同玩家各自有符合的牌型时，分别记账，玩家之间互付后净额汇总。
- 例如 4 人局，阿杰即使输掉本场，只要亮出顺金且顺金喜钱为 10 分，小林、小周、阿宁仍各给阿杰 10 分：阿杰喜钱 +30，其余各 -10；喜钱账本合计 0。
- 账单分别保存牌局得分与每笔喜钱（给分者、收分者、牌型、每人分数、适用规则版本），最终总分相加。规则开手冻结，后续修改从下一场生效；取消整手时牌局和喜钱均不入账。

原型中的普通行动可连续体验；页面导航可以直接查看封顶示例。所有演示只在本地变化，无真实建房、分享或同步。

## 后续详细设计需要覆盖的边界

- 网络中断时按钮禁用、草稿保留；重连先获取最新状态；不因超时替人弃牌。
- 比牌跟注和比牌结果是前后两步，各自幂等；跟注只扣一次，结果只应用一次。支付完成后保留待比牌状态，重连恢复选人与录结果，不重复支付，不提前轮转。
- 取消本场保留取消原因和动作记录，所有本场投入不进累计账。
- 已入账账单不可静默修改，错分通过可追踪修正处理。
- 等待视角、弃牌视角、比牌失败视角、长昵称、8 人列表、历史展开、设置下一场生效及房主取消手牌弹层将在高保真阶段补齐。
- 新玩家只在两场之间入座，玩家可在场间离场；断线不自动移除座位；名单与规则开局冻结。场间管理细则见文末。

## 本轮评审重点

先确认“闷 1／看 2、基准封顶 20”等示例设置。圈数按最新要求：封顶前不限，封顶后最多继续 3 圈，之后强制开牌。每分金额由房主设置并实时换算积分池。比牌保留人数达标、先跟注再选人、同大小主动方输、从发起者下一位继续的规则。确认后再继续更详细的视觉稿与状态设计。


## 连续开场与散场（2026-10-30 评审修订）

本轮统一产品用语：一轮是仍在局的玩家各行动一次；一场是一次发牌到分出胜负，内含多轮；整桌是一个房间内连续进行的所有场次。原始实现中的 hand 在产品界面称为“场”，不新增多余的中间层级。

正常循环：房主开始第 N 场 → 多轮跟注／加注／弃牌／比牌 → 分出胜负 → 房主登记喜钱 → 本场入账并更新整桌累计 → 房主开始第 N+1 场。

- 每场账单页的唯一主按钮为“开始第 N+1 场”；次入口为“查看整桌账本”，不把散场作为每场结束后的并列选择。
- 开始下一场只重置积分池、当前基准、轮数、闷／看／出局状态、喜钱草稿。房间码、玩家座位、逐场账单和整桌累计均保留；不重新建房。
- 下一场由房主点击开始，才收取下一场底注，不在账单出现时自动开场。场间等待期间可核对账目及调整下一场规则。
- 入账按房间和场次去重；同一场确认重试不能累计两次。整桌总分始终来自所有已完成场的牌局得分加喜钱净收支。
- “更多 → 散场结算 → 确认结束整桌”才是真正散场；当前场次或喜钱未完成时不可散场。房主需先完成本场，或按取消流程撤销整场后再散场。
- 散场后不再开始下一场，账本只读，最终按整桌累计提供结算；页面返回、切到后台或短暂离开都不等于散场。个人中途退出与整桌散场是不同操作，详细设计时分别处理。
- 连续开场流程支持完成多场后继续下一场、查看逐场记录及房主散场确认。最新原型默认展示 8 人桌第 4 场进行中的状态，不实际执行支付。

## 比牌规则（2026-10-30 用户新增）

- 房主建房设置“剩余在局人数 ≤ N 时可比牌”，可选 2–8 人。统计排除弃牌与比牌出局者；未满足时完全隐藏入口，不显示一个不可点击的比牌按钮。N 开场冻结，调整从下一场生效。
- 玩家只能在自己的行动回合发起，自己选择任一仍在局的其他人，不得选择自己、旁观者、弃牌或比牌出局者。
- 先确认支付本人应跟分，进入公共积分池；支付成功后才出现对手列表。本次只收这一次跟注，不再叠加旧版开牌费。闷／看仍沿用本人倍率：本人应跟 10 分就支付 10 分；若看牌后的应跟分为 20 分，则支付 20 分。
- 支付不会立即让出回合，尚未选择对手／尚未录入结果时继续保持“待比牌”。原型在支付前可返回；支付后须完成本次比牌，异常取消整场走独立流程，不静默退款。
- 录入三个明确结果：主动方大、被动方大、同大小。同大小固定由主动方输，败者标记“出局”，不再行动，已投入积分不退。
- 被动方本次不额外跟注；如果比牌后仍在局且恰是发起者的下一位，仍轮到他正常跟注。比牌胜者不会获得额外连续行动机会。
- 从发起者的原座位往后找到下一位仍在局玩家；跳过所有出局者。比牌算发起者本轮一次行动，不把被动参与算作对手已经完成跟注。若全场仅剩一人，直接结束本场并进入喜钱登记，无须再跟注。
- 看牌只改变闷／看状态；比牌是两人比较；强制开牌是基准单注封顶后再进行 3 圈的全体结束流程。三个入口明确区分。
- 原型初始处于第 4 场第 2 轮，3 人仍在局，比牌门槛为 3、基准 10 分。可验证小林先跟 10 分后任选阿杰／小周，平手时小林出局并轮到阿杰。历史 3 场及喜钱、整桌累计继续保留。

## 每分金额与封顶后三圈（2026-10-30 用户新增）

- 房主设置每分多少钱。原型在创建页填写人民币元数，要求大于 0、最多两位小数；以整数分（人民币分）保存换算率，避免浮点累加。为统一整桌口径，本版提议在创建／第一场开始前设置，整桌开始后固定，不逐场重算历史金额。
- 公共积分池同时显示分数、当前折算金额和每分金额；每次跟注、加注、比牌跟注完成后同步更新。例：每分 0.50 元，积分池 44 分显示 ¥22.00；再投入 10 分后为 54 分／¥27.00。
- 账本仍以积分为事实数据。喜钱不进入公共积分池；整桌累计（牌局＋喜钱）也按同一个每分金额显示折算金额。
- 删除原“最多 10 轮”等固定总圈数设置。未达到基准单注上限前，可持续跟注任意圈数。
- “封顶”沿用基准单注上限的含义，不是积分池总分或某人本场累计投入。若基准上限 20 分，闷注到 20 或看牌按基准 20 投入 40 时触顶；看牌按基准 10 投入 20 不算触顶。
- 触顶动作完成后，从下一位仍在局玩家开始进入后续第 1 圈；触顶动作自身不占这 3 圈。每圈当时仍在局的人各行动一次，完成后减一；不受原先的圈数边界干扰。
- 后续 3 圈内继续允许跟注、弃牌、满足人数条件的比牌；不能再提高基准。看牌不占行动次数；比牌先跟注、选人、完成结果合起来算发起者一次行动，被动参与比牌不算已经完成跟注。
- 出局者从当前圈尚未行动名单移除，后续圈不再计入。若只剩一人在局，提前结束本场并登记喜钱；否则第 3 圈最后一次行动完成后，立即隐藏投入入口、强制现场开牌并录入赢家，不额外收取任何费用。
- 原型显示“封顶前不限圈数”或“已封顶，第 N/3 圈，本圈还需 X 人行动”，并在动作流水记录触顶及每圈完成。未完成比牌时不提前消耗圈数或切换回合。

## 本场玩家布局（2026-10-30 用户修订）

- 用户要求根据实际人数自动改变布局，不让房主或玩家手动选择排版。布局同时适应手机可用宽度。
- 2–4 人采用 2 列宽松座位卡，5–8 人采用 3 列，9–12 人在空间足够时采用 4 列；容器宽度不超过 320px 时，4 列回退为 3 列，更窄时回退为 2 列。
- 保持真实座位顺序和座位号，不把当前行动者挪到第一个位置。卡片仅显示座位号、昵称、行动／在局／出局、闷／看状态和本场投入，当前行动者高亮。
- 出局玩家保留座位并减弱显示，仍能核对其投入；总人数与仍在局人数分别标明。比牌对手列表继续只列仍在局的其他玩家。
- 完整姓名、出局原因及详细账目放进可展开的全员明细，避免多人桌用一人一整行占满记分页。长昵称在座位卡中省略，可在明细中查看全名。
- 原型上方“预览人数”可演示 2／4／6／8／10／12 人效果，属于评审控件；实际产品根据入座人数自动选择列数，无布局设置项。切换预览会重置演示状态，以便对比。
- 项目现有房间上限为 8 人；10／12 人是本轮原型的布局扩展演示，尚不代表后端已支持。用户没有指定新上限，实施前需同步确定人数上限并更新入房校验、座位表和相关账本边界。此轮不修改业务代码。

## 场间加人与离场（2026-10-30 用户追问的推荐方案）

允许操作的时机是本场胜负、喜钱均已确认入账，且下一场尚未开始、整桌尚未散场的“场间等待”。最新自适应玩家区原型尚未绘制以下管理页面，本节记录推荐交互供继续评审，不表示业务代码已实现。

### 场末主页面

保留“开始第 N+1 场”作为主按钮，辅助入口为“管理玩家”和“整桌账本”。管理页分为“下场入座名单”“待入座申请”“已离场玩家”。总人数上限只统计下场入座人数，历史账本中的离场玩家不占座位。

### 加人

新玩家通过现有扫码、邀请链接或房间码加入后显示为待入座，房主确认并安排座位后进入下场名单。只参加之后的场次，初始净分为 0，不分摊之前的积分池和喜钱。房间满员时保留明确的满员状态，不静默替换他人的座位。

房主点击开下一场时，以服务器最新名单和人数校验后冻结本场参与者集合。加人与开场同时发生时，以这份冻结名单为准；客户端过期时提示重新核对。

### 离场

普通玩家在场间点“退出后续场次”，确认弹层显示自己的累计积分、喜钱及折算金额，并说明离场后账目继续保留。确认后移出下场名单、释放座位，不删除身份与历史，也不清零应收／应付。

离场只是停止参与后续场次，默认不代表已经结清，不自动触发转账，不自动结束整桌。最终散场汇总所有曾参与者，包括已经离场的人。若未来增加提前个人结算，须单独记录已收付及剩余应收付，不能用清零历史总分来替代；该扩展不默认加入当前版本。

### 返回与身份

离场者回到同一房间，恢复原参与者 ID、历史账目及累计分；申请重新入座后从下一场继续。不能仅凭相同昵称认领旧身份，应依赖原房间身份凭证或已绑定账号。座位号可以重新分配，但账目关联稳定参与者 ID，不能关联可被新玩家占用的座位号或列表下标。

### 房主离场

房主须先选择一位仍入座的在线玩家并获得对方接受，完成房主转让后再退出后续场次；接任者承接开场、喜钱核对和散场权限。无人接任时不能留下无人管理的进行中房间，可继续等待，或由房主明确结束整桌。房主断线不等于主动离场，不自动随机转让。

### 人数变化与账目不变量

- 少于 2 人时保留房间与账本，禁用开始下一场，显示等待入座；不自动散场。
- 自适应玩家区以本场冻结名单排布；场间名单以即将参加下一场的人排布，离场玩家移到单独区域。
- 每场人数、座位顺序、喜钱给分范围、分数倍率与比牌门槛分别保存快照；后来加入或离场不能追溯改变之前的账。
- 新加入者不因全房间历史玩家数组变长而被计入此前喜钱；离场者也不参与之后的喜钱。每笔喜钱只在对应场次参与名单内生成。
- 原型 2–12 人布局仅为视觉容量演示。实施加退场前需扩展现有只读／房主权限、房间参与状态、转让流程及历史快照，不能只增删界面上的玩家卡片。
